# MCPTT 带话权私呼：拒接、忽略和结束有什么区别？

**拒接和忽略都不等于挂断一通已经建立的私呼。** 忽略手动来电时，条文说不向主叫发送呼叫失败原因。只看到没有原因，不能反推被叫选择了忽略。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，§5.6.4，印刷页 27。第 5 章是共用要求，带话权私呼支持在网和离网；这里不规定两种运行方式各自怎样传信令。（§5、§5.6.1、§6.7.0，印刷页 22、25、44–45）

## 被叫未接起来：拒接不等于忽略

| 动作 | 服务须提供什么 |
| --- | --- |
| 拒接带话权私呼（R-5.6.4-001） | 让 MCPTT 用户能拒接。§5.6.1 在手动开始的例子里把接受、拒接和忽略列为不同选择。-001 本句没有写“手动开始”或“获授权”限定，也不说明自动开始时实际走哪个分支。 |
| 忽略另一位 MCPTT 用户发来的手动带话权私呼请求（R-5.6.4-002） | 让获授权的 MCPTT 用户能忽略该请求。注 2 说，发生忽略时不向主叫 MCPTT 用户发送呼叫失败原因。这不等于不发任何呼叫状态，也不是说发送了但主叫没收到。 |

拒接可以作为状态报告；失败原因说明为什么没建立。§5.6.2-001 要求向**作为该次私呼参与者的相关 MCPTT 用户**提供状态，示例包括振铃、接受、拒接、活跃。§5.6.2-003 给获授权的被叫限制向主叫提供建呼失败原因的机制；§5.6.5-006 让管理员在其权限范围内配置哪些被叫可以这样做。不能从这两条推定每次拒接都会发原因，也不能从一份无原因的记录判定发生过忽略。只看到没人接、计时到期或转移也不够：手动来电在配置期内未接可另有转移配置（R-5.6.3-015，印刷页 27），不等于用户执行了忽略。

## 呼叫已经建立：结束整通不等于停止说话

R-5.6.4-003 要求服务提供手段，让 MCPTT 用户结束**自己参与的**带话权私呼。是否正在发话、此刻是否持有话权，不是这条列的前提。若只看到结束一次发话，转查[在网话权结束](floor-permission-end-and-transmit-limit.md)或[离网话权结束](off-network-transmit-stop-and-time-limit.md)，不能认作私呼已经结束。建呼前取消请求是 R-5.6.3-003（印刷页 26）；管理员可配置的超时适用于本条所说没有发送或接收的 MCPTT 用户的私呼（R-5.6.5-005，印刷页 27），不是参与者主动结束。

## 无话权私呼另查本版条款

无话权私呼只在网。§5.6.4 注 1 说两节意图相应，仍要读 §6.7.5（印刷页 47）的实际编号：R-6.7.5-002 要求服务让获授权用户能忽略**另一位 MCPTT 用户**的无话权手动私呼请求，注也说不向主叫发送失败原因；R-6.7.5-001 和 -003 在 TS 22.179 本版是 **Void**。资料性附录 A1（印刷页 77）分别指向 **TS 22.280 的 R-6.7.6-001 和 R-6.7.6-002**。这里仅核映射，未核目标正文；不能据此说无话权私呼禁止拒接或结束，也不把带话权的活条直接套过去。

如果要查手动接受和自动收件确认，读[在网私呼开始方式](private-call-commencement-evidence.md)。 若问题是管理员能配哪些权限和时限，读[带话权私呼管理](private-call-administration.md)。以上是业务要求，不规定拒接、忽略、取消或结束各自用什么 SIP 消息、状态码或设备界面。

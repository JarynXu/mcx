# MCPTT 在网呼叫优先级：优先接入，等于能抢占旧呼吗？

**不等于。**接入优先级用来区分主叫发起呼叫的尝试。系统能不能停止已经建成的旧呼，还要看新旧呼叫的应用层优先级和两边各自的抢占条件。

依据：3GPP TS 22.179 V20.0.0，Release 20 Stage 1，在网 §6.8.1 与 §6.8.6.2（印刷页 33、47–48）。

| 要判断的事 | 该查什么 |
| --- | --- |
| **一次 MCPTT 主叫发起（MO）尝试怎样获得优先处理？** | MCPTT 服务**须**提供接入控制机制，支持多个接入优先级，并按尝试的接入优先级区分优先处理。这条不保证呼叫建成，也不把接入优先级当成应用层优先级。（R-6.8.1-002，页 47） |
| **能不能为新呼停止旧呼？** | 旧呼已经建成、具备可被抢占能力、且应用层优先级低于新呼；新呼的抢占能力已启用。满足这些条件，MCPTT 系统**可以**停止旧呼，让新呼得以建立，不是**必须**停止，也不保证新呼建成。（R-6.8.6.2-004，页 48） |

**旧呼可被抢占，新呼启用了抢占。**两边是不同条件。条文对旧呼写的是可被抢占能力，没有另列旧呼的启用开关；对新呼不能只核“支持”。旧呼还在建立、优先级相同，或只有接入优先级较高，都不能满足该条相应条件。缺配置或优先级记录时，结论是条件尚未核实，不是直接判定条件不满足。

例如，B 已建成并可被抢占。A 的 MO 接入优先级较高，但没有 A、B 的应用层优先级关系：只能按接入控制查 A 的发起尝试，不能认定可以为 A 停 B。若核实 B 的应用层优先级更低且 A 已启用抢占，则进入“可以停 B”的分支。要判断这次有没有停 B、停 B 的原因、或 A 有没有建成，仍须分别查事件记录。

## 三种容易查错的地方

- **同一呼叫里换发话人。**话权控制在单一呼叫中处理参与者的发话许可，本节说的是停止已经建成的另一通呼叫。撤掉发话许可不能证明呼叫被停止。（§4.6.3，页 21；查[普通发话申请结果](ordinary-floor-request-outcomes.md)或[组内抢占与插话](group-audio-cut-in.md)。）
- **承载、调度与拥塞。**§4.6.4 是传输层控制的概述。§6.8.2–.5 的对应要求在本版标为 Void。两条在网要求没有给出承载阈值、统一优先级排序、拥塞触发条件或 SIP 报文。（页 21、48）
- **带话权紧急私呼。**按下节查该类私呼的优先级和例外，不能从一般的可选停呼或紧急标记推定已经抢占。

## 带话权紧急私呼的优先级

依据：TS 22.179 V20.0.0 第 6 章在网，§6.8.7.2（印刷页 49）。先区分，在排的是**呼叫**，还是服务在为这通呼叫的**参与者**请求提高优先级。

| 条款 | 在网带话权紧急私呼 |
| --- | --- |
| **私呼之间的优先级（R-6.8.7.2-001）** | 服务须保证该类紧急私呼相对所有其他 MCPTT 私呼处在最高优先级。只比较私呼；不排系统呼叫、组呼或两通同类紧急私呼谁先。 |
| **为参与者请求提高（R-6.8.7.2-002）** | 服务须能为这通紧急私呼的参与者请求提高优先级。是服务的请求能力，不把对象只限主叫；不等于每次要请求、这次已发出、请求已获准或优先级已提高。 |
| **跨呼叫类型的抢占优先级（R-6.8.7.2-004）** | 该类紧急私呼**包括呼叫内容和信令**，对其他 MCPTT 呼叫类型享有抢占优先级。三类例外：**System Calls、MCPTT 紧急组呼、其他带话权紧急私呼**。 |

System Call 是标准定义的一种广播组呼，不是泛指系统发起的一切呼叫；普通广播组呼也不因名称就进入这个例外（§3.1，印刷页 11）。**不属于这项抢占优先级的覆盖范围，不等于对方一定优先，也不据此判一律禁止抢占。** 例如，对普通 MCPTT 组呼查 -004，不用 -001 的私呼排序；只换成紧急组呼，-004 就不授予这个相对的抢占优先级。哪一通真的停了，另查事件；既不推媒体、信令或承载实现，也不直接用一般的 R-6.8.6.2-004 可选停呼条件改写这里的三项例外。发生了参与者移出，读[在网呼叫终止](on-network-call-termination.md)的条件与通知。

[紧急私呼状态](emergency-private-call-state.md)另查：R-6.8.7.2-003 是把正在进行的带话权私呼转为带话权紧急私呼的能力，仍在原主题维护。请求提高参与者优先级不证明某通已转换，也不表示参与者本人进入紧急状态、已发告警或组处在紧急状态。离网不沿用此在网排序或例外。

**查到 Void 时不要补写规则。**资料性附录 A1 把 §6.8.2–.5 的四个条目指向 TS 22.280 的同号条目。页 77 右侧的 TS 22.280 R-6.8.1-002 则来自本版空条目 R-6.8.1-003，不是上表仍有效的 R-6.8.1-002。页 78 的 TS 22.280 R-6.8.7.2-004 也不是同号的本版紧急私呼正文：那里映射的是本版空条目 R-6.8.6.2-005。A1 对本地 §6.8.7.2 自己只列 NA（印刷页 78），不使印刷页 49 的活条变成 Void。这里只核同版引言和 A1 的查找指针，不据此复述目标规范。（页 8、69、77–78）

# 两台 MCPTT 终端都有网络信号，还能离网通话吗？

**能。看这次 MCPTT 的用户传输走哪条路，不是看手机有没有信号。** 离网模式用 ProSe 直通：用户传输从一台终端直接到另一台，不经过网络基础设施。两端要在 ProSe 直通通信范围内。仅知道两台终端都有覆盖，不能判断它们选了哪条路；仅知道它们离得近，也不能判断通话已经建立。（TS 22.179 V20.0.0 §7.1，印刷页 61–62）

## 谁来选路？

| 情形 | §7.1 怎么说 |
| --- | --- |
| 终端检测到已失去覆盖 | 终端具有自动切到 ProSe 直通的能力。这说的是能力；单看失去覆盖，不能断定这次切换成功或对端可达。 |
| 用户仍在覆盖内 | 获授权用户可手动选择直通。要是这次确实选了直通，用户传输直接往来于终端；与网络及 MCPTT 服务的信令仍**可能**可用，例如无线资源分配、用户档或密钥管理更新。收到其中一项不能证明话音经网转发。 |

离网时，由终端上的 MCPTT 应用提供业务；在网时，终端应用与 MCPTT 服务器及网络协作。两种模式不能靠“抓到过网侧信令”区分。（印刷页 62，含注 2）

**还要区分用户权限和终端能力。** 注 4 写明：覆盖外使用 ProSe 直通，只适用于已启用公共安全 ProSe 的终端。对于已启用 ProSe、但不属于公共安全 ProSe 的终端，选直通、经本地基站还是走 3GPP 网络，受网络控制，以运营商偏好为依据。“获授权用户可手动选”不能解释成任何 ProSe 终端都能在覆盖外自行选路。（印刷页 62–63，注 4）

## 离网前，终端要备好什么？

MCPTT 管理员和／或获授权用户为终端准备两类东西（印刷页 62–63）：

- **为每位预期使用该终端离网操作的用户准备一份 MCPTT 用户档。** 档内包括用户的字母数字别名（最小长度记为 N3）、该用户可用的离网组、获准使用的离网组的字母数字别名、该用户获准与之私呼的离网用户，以及可获得时与预期用户或管理员关联的任务关键组织名称。
- **认证密钥和端到端安全密钥。** 它们与用户档是两项。注 3 说明，终端既可在覆盖外配置，也可通过接入网络完成配置；不必等失去覆盖才准备。配过档或备有密钥，不证明随后那通呼叫用了直通，更不证明对方收到话音。

本页核的是 **Release 20 Stage 1 的离网业务概述**，不是选路算法、切换时限或设备实测。若要查外设通过 IP 给终端配置，读[离线配置的 CMS/GMS 分工](../identity/offline-ue-configuration.md)；这是另一种操作，不是离网通话必须连接外设。若要查迟入者能否获得发话者位置，读[离网发话者位置与组呼位置更新的区别](imminent-peril-location-update.md)。

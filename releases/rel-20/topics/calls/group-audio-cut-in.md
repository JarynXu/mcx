# MCPTT 在网组呼插话：谁拿话权，被打断的人要重新申请吗？

TS 22.179 V20.0.0，Release 20，Stage 1。这里的插话（audio cut-in）是指定在网组的组内话权规则。

**已配置插话的组，话权给选中该组、提出最新发话请求的组员。当前发话人若因此被打断，他原来的请求就结束，不排队，也不会等对方说完后自动继续。要再发话，得重新申请。**（§6.2.3.6.2，R-6.2.3.6.2-002/-004/-005，注 3；印刷页 38）

| 场景 | 按这组要求怎样判断 |
| --- | --- |
| 系统提供插话配置；不知道该组有没有启用。 | R-6.2.3.6.2-001 要求组可配置插话，不能当作它已经启用。获授权的参与者须能在已配置插话的组里申请发话；可以申请不等于已拿到话权。（§6.2.3.6.2/.3，R-6.2.3.6.2-001、R-6.2.3.6.3-001；印刷页 38） |
| A 正在说，B 选中该组并作出可辨先后的最新发话请求。 | 话权给 B。已配置插话的组同一时刻只允许一人发话；该模式不支持任何话权排队及相关功能。A 因请求被打断时，他的请求结束；不是结束整个组呼。（§6.2.3.6.2，R-6.2.3.6.2-002 至 -005；印刷页 38） |
| 两个发话请求同时收到。 | 注 2 把同时接收的请求交给厂商实现处理，没有指定谁拿话权。单人发话、不排队的要求仍在。两个终端显示相同的按键时间，不等于话权侧同时收到请求。（§6.2.3.6.2，R-6.2.3.6.2-002 后注 2、-003/-004；印刷页 38） |
| 某已加入该组（affiliated）的成员在自己选中的插话组发起请求，实际获准。 | 须向该申请者给出允许发话的提示。只看到申请，不能当作已经获准；获准提示也不说明其他成员已听到音频。（§6.2.3.6.3，R-6.2.3.6.3-003；印刷页 38） |

单人发话不等于打开了插话。仅知插话未启用或配置不明，也不能确定走普通抢占。核实是适用[普通话权抢占的在网组呼](on-network-group-floor-override.md)时，按参与者的相对话权优先级及呼叫类型优先级判断；组可配置成只留抢占者，或让抢占者和被抢占者都发话。不把普通抢占的更高优先级门槛加到插话的最新请求规则上。已配置多发话者控制的组走 §6.2.3.7；其概述将 §6.2.3.6 的插话规则排除在该模式之外。（§6.2.3.3.1/.2、§6.2.3.7.1，印刷页 36、39）

这是同一组内的话权，不是[另一呼叫打断环境监听](ambient-listening-interruption.md)，也不是[非 3GPP 互通私呼抢占](interworking-private-call-override.md)。

## 谁能停止这次发话，结束提示给谁？

以下只看已配置插话的在网组。

| 要查的事 | 业务要求 |
| --- | --- |
| 有人要终止正在使用的话权 | 服务须让**获授权的 MCPTT 用户**能随时终止一个正在发话的参与者的发话许可。原文没要求两人一定不同，也没指定只能由调度员操作。（R-6.2.3.6.4-001，页 38） |
| 正在发话的人想停 | 他须能向 MCPTT 服务表示自己不再想发话。该条的注说明：这种情况下停止向接收参与者传音频，直到有获授权参与者随后申请发话。再次申请不等于已获准，也不是恢复原许可。（R-6.2.3.6.4-002 及注，页 38） |
| 发话者已经结束发话 | 服务须给**接收参与者**发话结束的提示。这条并未把提示限于发话者主动停。只看到音频停了，不等于接收方获得了提示。（R-6.2.3.6.4-003，页 38） |

## 一次发话已经说了多久，离上限还有多久？

服务须让 MCPTT 管理员能配置**一次发话申请所对应的发话时长上限**；话权功能须具备这个可配置上限。它不量整通组呼，也不把申请后的等待算成发话时长。（R-6.2.3.6.5-001/-002，页 38–39）

| 还在发话时 | 话权功能须做什么 |
| --- | --- |
| 离上限的时间进入可配置的提前量内，尚未到上限 | 提示**正在发话的人**快到上限。提前量和发话时长上限是两个量；这条没指定谁设置提前量。（R-6.2.3.6.5-003，页 39） |
| 发话已达到上限 | 提示**正在发话的人**已到上限，并撤回其发话许可。两项都须做，原文没规定先后。提示发话者不代替发话结束时给接收参与者的提示。（R-6.2.3.6.5-004/-005，页 39） |

上限到期不需要等另外一人插话，也不能据此判整通组呼已结束。不是比较终端显示的按键时间，条文没规定默认时长、精确计时事件或提示形式。读[在网同名条款](floor-permission-end-and-transmit-limit.md)或[离网单次发话](off-network-transmit-stop-and-time-limit.md)时，用各自的适用条件；[在网整通呼叫何时结束](on-network-call-termination.md)另查 §6.2.4。（页 37、40–41、64–65）

验收后来者接管话权时，把该组生效配置、实际同组请求、谁获准与原请求是否结束对到同一次事件。§6.2.3.6.1 的概述称最新请求立即获得话权，但没有给出毫秒门槛。本页不定义 SIP/话权报文、UI 样式、请求的精确排序时钟或音频交付，也不套用到离网组；离网时查[话权抢占条件和撤权](off-network-floor-override.md)。

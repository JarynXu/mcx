# TETRA 互通：按组重组、按用户重组和用户标识

**先分清你在组合谁。**合并两边的组查 -008；把 MCPTT 用户和 TETRA 移动台组成一组查 -009。两边的用户标识要能互通，是另一个要求。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，第 6 章在网。以下三条在 §6.18.3.3、印刷页 59，针对 MCPTT 与符合 ETSI TETRA 标准的系统互通。

| 要验什么 | 本条要求 | 别混成什么 |
| --- | --- | --- |
| **按组重组（-008）** | 支持同时包含 **MCPTT 组与 TETRA 组**的按组重组。输入是组。 | 成功组合已有组，不证明也能按用户重组。一次普通互通组呼接通，也不证明已执行重组。 |
| **按用户重组（-009）** | 支持同时包含 **MCPTT 用户与 TETRA 移动台**的按用户重组。本条没列 TETRA 控制台。 | 控制台能参加普通组呼或私呼，不表示本条也将它列入；这里没列，也不表示规定禁止控制台参与。 |
| **用户标识互通（-010）** | 支持可互通的 **MCPTT User ID 和 TETRA ID**。§3.1 的 User ID 是 MCPTT 用户的主要唯一标识。 | 不替 TETRA 侧指定某种具体标识、号码格式、两端同号或一一映射；不拿组 ID、别名或 P25 subscriber ID 代替，也不凭标识判用户已注册或获授权。 |

§3.1 的术语把前两项分成“临时组合多个组”和“把多个用户临时组成新组”（印刷页 10、12）。§6.6.2.1 和 §6.6.4.1 是原生 MCPTT 的业务说明（印刷页 43–44），不代填 TETRA 的建组、自动归属或撤组流程。知道互通支持，不等于这个组已经激活、撤销，或这台移动台已经归属。

查[组呼和发起抢占](tetra-group-call-interworking.md)走 -001 至 -007。P25 的[重组、组广播和标识](p25-regrouping-broadcast-and-user-ids.md)不能搬到 TETRA；这三条也没规定 P25 公告组呼那种业务。

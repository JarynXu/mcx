# 离网 MCPTT 音频性能：接入、口到耳和迟入分别从哪算？

**三段能定义起止，离网限值仍留待研究。** 发话接入看发话者什么时候得到可开口的信号；口到耳看同一段话什么时候从接收者扬声器播放；迟入从接听者决定监听算。以下按 TS 22.179 V20.0.0，Release 20 Stage 1，§7.11，印刷页 66–67。

| 测什么 | 从哪里计到哪里 |
| --- | --- |
| **发话接入（KPI 1）** | MCPTT 用户**请求发话**，通常按终端上的 MCPTT 控件，到**同一用户得到可开口的信号**为止。不计接收用户的确认；不用等对端扬声器播音。（§7.11.1.1，页 66） |
| **口到耳（KPI 3）** | 从发话用户说出一段话，到**同一段话**在接收用户的扬声器播放。话权许可、发送端开始采集、接收端收到媒体包，不是条文定义的口到耳端点。（§7.11.1.1，页 66） |
| **组呼迟入（KPI 4）** | 从已归属成员**决定监听**这通进行中组呼，到**其终端扬声器开始播出该通话的音频**。迟入活动指已归属成员加入这通已有其他已归属成员活跃的组呼。性能要求另看该用户**加入时**有没有正在传送的语音。不从建呼、加入成功或收到第一个媒体包计起，也不在那里停表。（§7.11.2.1，页 67） |

页 67 的示意图把发话接入画在 PTT 请求与许可之间，把口到耳画在发话和接收播放之间。页 66 正文把图号写成 7.11.1.1.1，图题写成 7.11.1.1-1。图上的许可和采集起点贴在一起，不能据此规定每次许可时人就已经开口，也不能规定具体报文、提示形式或音频采样点。

## 迟入时丢了开头，算进多久？

§7.11.2.1 说，迟入的接收组员**可能**错过当前话音段的开头。迟入计时仍用上面的一对端点；是否丢了开头另核。条文没有规定把丢掉的时长自动加到或减出 KPI 4，也没有把可能丢音写成一个允许的限值。就算加入时没有语音，也仍可能是迟入活动；它只不满足本段的性能适用条件。本节没有规定静默时加入的样本如何计时。（页 67）

**三个离网指标都标 FFS（留待研究）。** §7.11.1.2 的注一起列接入和口到耳；§7.11.2.2 的注另列迟入。这两节没有给离网三项的数值门槛。知道怎样计时仍不能用本节给测值判达标。第 6 章的[在网接入和口到耳](mcptt-access-clock.md)、[在网迟入阈值](late-call-entry-kpi.md)及相应丢音要求不移作离网标准。（页 67）

## 音质条款的 Void 指向哪里？

TS 22.179 V20.0.0 的 R-7.11.3-001 标为 Void。同版资料性附录 A1 的 **§7.11.3** 对应行是 NA，没有给出迁移目标。这和旁边从 §7.13 终端功能条目指向另一份规范的 §7.11 编号不一样。只据这里能定位 Void，不能补写离网语音质量要求，也不能断定其他规范都没有相应要求。（引言、§7.11.3、附录 A1，页 8、67、69、82）

# MCPTT 与 P25 互通：重组、组广播和用户标识怎么验？

**先看操作对象。**按组重组处理两边的组，按用户重组处理 MCPTT 用户和 P25 用户台。组广播看两端呼叫类型，标识互通看两端各自的用户标识。一次普通组呼接通，不能替代这四项验收。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，在网 MCPTT 与符合 TIA-102 的 P25 系统互通。下列四条均在 §6.18.3.2、印刷页 58。

| 要验什么 | 本条要求 | 不能由本条判定 |
| --- | --- | --- |
| **按组重组**（Group Regrouping，-010） | 须支持同时包含 **MCPTT 组和 P25 组**的按组重组。输入是组。 | 两个已有组能组合，不证明也能按用户重组，也不说明某个组已被加入、激活或撤销。 |
| **按用户重组**（User Regrouping，-011） | 须支持同时包含 **MCPTT 用户和 P25 用户台**（subscriber unit）的按用户重组。不以整组为输入。 | 本条没列 P25 控制台。普通组呼或组呼抢占条款列了控制台，不能据此扩充本条，也不能据本条断定控制台不支持按用户重组。 |
| **组广播互通**（-012） | 须支持 MCPTT **Group-Broadcast Group Call** 与 P25 **announcement group call** 互通。 | 普通组呼通了，不等于这对广播呼叫也通。支持广播互通不等于发起了广播、终端已收到，也不等于完成重组、激活或撤组。 |
| **用户标识互通**（-013） | 须支持可互通的 MCPTT **User ID** 和 P25 **subscriber ID**。 | 这不是组 ID 或别名的规则；没规定两侧同号、一一对应、格式、映射办法或信令字段。看见一个标识不证明身份已注册、获授权或已经收到通话。 |

## 别把原生业务的说明变成 P25 流程

MCPTT 的术语说明区分了两种重组：临时组合多个组；把多个用户临时组成新组。Group-Broadcast Group 则是由 MCPTT 管理员定义、用来接收广播的组集合。组集合不是重组操作。原生按用户重组的说明提到自动归属取决于配置；不能拿来规定 P25 用户台默认归属或撤组流程。（§3.1，页 10、12；§6.6.2.1、§6.6.4.1，页 43–44，仅作术语和原生业务对照。）

查[普通、应急、加密组呼和抢占授权](p25-group-call-interworking.md)走另一组条款。不要套用 [GSM-R 互通](gsm-r-voice-interworking.md)的业务对象，或用[在网广播 ad hoc 组呼的时长配置](../identity/ad-hoc-broadcast-hang-time.md)判断 P25 广播的建呼、结束或接收。本页没有验证设备和协议实现。

# MCPTT 在网组呼话权抢占：谁能打断，原发话人还能说吗？

**B 抢占了正在发话的 A，A 还能不能说，看该组生效的配置。**只许抢占者发话，就撤掉 A 的发话许可；若允许两人发话，哪些听众能听到哪一路，要看接收权限和配置。能发话与谁能听，是两项设置。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1。这里讲第 6 章在网的一通 MCPTT 组呼，按 §6.2.3.3 的普通优先级抢占处理。指定插话、多发话者控制、离网另看各自规则。（印刷页 33、36–39、64）

## 谁可以打断正在发话的人？

服务须让 MCPTT 管理员建立**至少四级**的优先级层级，用来判定哪些参与者、参与者类型和紧急发话类型的抢占请求可获准。四级说的是抢占优先级，不是四人同时发话。（R-6.2.3.3.1-001/-005，页 36）

谁发话，要按参与者的相对话权优先级**和**呼叫类型的优先级判断，例如紧急呼叫的类别。原文要求提供抢占正在进行的发话的机制：请求方参与者**或**呼叫类型的优先级排在当前发话方参与者**或**呼叫类型之上。不是说两项都要更高，也不是只见其中一个等级较高，就能判实际请求获准。条文不设两项冲突或同级时的裁决顺序。（R-6.2.3.3.1-006/-007，页 36）

## 抢占后，谁能继续发话，谁能听？

| 查哪件事 | 按什么判断 |
| --- | --- |
| 该组只准抢占者发话，B 实际抢占 A | 服务须撤掉 A 的发话许可。撤掉的是话权，不是让 A 离组或结束整通呼叫。（R-6.2.3.3.1-003、R-6.2.3.3.2-001，页 36） |
| 该组允许抢占者与被抢占者同时发话 | 获授权的接收参与者须能按配置听这两路。双发配置不等于每位听众都获授权、都配置收两路，或当时确实听到了。（R-6.2.3.3.1-003、R-6.2.3.3.3-001，页 36–37） |
| 一位获授权的参与者实际完成抢占，要给其他人什么？ | 管理员可为接收参与者配置接收抢占一路、被抢占一路或两路。服务还须提供方式告知**被抢占者**其发话被抢占。收听配置不是通知名单；请求已发或角色获授权都不证明实际抢占或通知已送达。（R-6.2.3.3.1-002/-008，页 36） |

## 两人正在发话，又来了第三个抢占请求

同一通组呼已经有 A 和 B 在发话。MCPTT 用户 C 请求继续抢占，且 C 的**话权优先级高于当时两位发话人**，服务须允许继续抢占。若 C 只高于 A、却与 B 持平，不能按这条要求判 C 可继续抢占；只有更高的呼叫类型或接入优先级，也不能替代这里的话权比较。（R-6.2.3.3.3-002，页 37）

连续抢占后，服务只启用两路：**优先级最高的 MCPTT 用户的抢占发话**，以及按配置从**两位被抢占者**中选出来的一路。若 C 是最高者，第二路可以选 A 或 B，不能默认留最近发话的人或优先级次高的人。原文举例可以按用户优先级、保留应急发话，或设规则不让两位调度员同时处于这两个发话角色；这些是配置示例，不是必选规则。启用两路不等于每位听众都放音两路，也不是别的话权模式的上限。（R-6.2.3.3.3-003，页 37）

## 相似的现象查哪一页？

- 只剩一位发话人，不能认定是[指定组的插话](group-audio-cut-in.md)。插话看最新请求等专有规则；[多发话者控制](group-multi-talker-control.md)已配置时，§6.2.3.7.1 明确排除本页 §6.2.3.3。（页 37–39）
- [同一终端在组呼和私呼同时收发](mixed-group-and-private-call-reception.md)的 §5.15-001 至 -003 说的是跨呼叫的组合，不是一通组呼里的两路发话。同页 N5、N7 数接收，也不是这里启用的发话数。带话权的在网私呼也有单双发话配置机制（R-6.2.3.3.1-004），但组内收听授权和三人连续抢占的规则不能搬给私呼。（页 32、36–37）
- [离网话权抢占](off-network-floor-override.md)另有终端预配置及发端控制失效时的接收呈现规则（§7.3.3）。为新呼停止旧呼则是[应用层优先级](on-network-call-access-priority-and-preemption.md)的问题，不是这一通呼叫内的发话切换。（页 48、64）

查一次实际事件时，把同一通组呼的模式、当时的发话人、抢占是否成功与听众的配置分开核对。条文是业务要求，不指定信令、发话者音频如何混合或某台终端实际收到的音频。

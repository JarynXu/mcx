# MCPTT 在网组呼：等谁确认，没等齐还能继续吗？

**「已经归属目标组」和「已经确认收到本次建呼请求」不是一回事。** TS 22.179 V20.0.0，Release 20，Stage 1，§6.2.1（印刷页 34–35）分别规定建呼能否继续和音频传输前的确认条件。支持一种条件，不等于本次呼叫用了它。

## 先区分建呼门槛与音频门槛

- **建呼。**服务须有不等组内任何用户先确认就能让建呼请求继续的方式（R-6.2.1-001）。也须支持两种基于当前归属的建呼门槛：已归属人数达到下限（-001a），或所指定的组成员当前已归属（-001b）。不能把最低归属人数当成最低确认人数。
- **已归属者被服务要求确认。**他须确认收到建呼请求（-002）。可由人经 UE 操作，也可由 UE 自动做，按管理员策略（-003）。发出确认要求不等于已经收到确认。

| 若配置要求确认后才传音频 | 查谁的确认 |
| --- | --- |
| -004 | 达到最低人数的**已归属组成员**。 |
| -005 | **指定 MCPTT 用户**，不以其原来已归属为条件。注 1 说：服务先让尚未归属目标组的指定用户归属该组，传输结束后恢复他们原先的归属状态。 |
| -006 | **同时已归属该组、又在指定地理区域内**的所有用户。 |
| -007 | 管理员通过服务提供的机制，从**已归属组成员**中指定要确认的子集。 |

注 2 把其中一项或多项适用的情形称为「要求建呼确认」。四项都针对确认收到建呼请求后才继续音频；不是在规定话权授予、媒体已送达或 SIP ACK。

## 要求已归属组成员确认，却没在时限内收齐

- **到时继续还是放弃。**服务可继续呼叫，也可放弃。两种分支随后都可告知发起用户确认未收齐，不是必须通知（-008、-009）。超时时长和到期行为由管理员设定（-011、-012）；还须支持无限超时（-013）。本条没有给默认时长或默认到期动作。
- **发起用户不用等到期才有选择。**在要求已归属组成员确认的组呼中，发起者须能随时选择不等确认，让通话转成无需确认的呼叫（-010）。有这个选项不等于已经转换。
- **通知不等于名单。**所需成员没有在配置时限内确认时，服务须能向发起者提供未确认成员名单（-010a）。另一个场景是无需确认的组呼：服务已知有已归属成员不能参加，须提示请求者呼叫将在缺少部分成员的情况下继续，并按管理员策略提供缺席名单（-014）。不要拿一场没有确认要求的呼叫去统计「超时未确认」。

要从日志判断，先查本次建呼采用了什么条件，再查相关确认、到期或实际转换的证据。若只问秒表从哪开始、何时停，另查[发话接入 KPI](mcptt-access-clock.md)。

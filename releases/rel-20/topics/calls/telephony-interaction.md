# 普通电话遇上 MCPTT：谁能配置，谁先接？

**MCPTT 服务须提供机制，让 MCPTT 管理员为某个 MCPTT 用户配置电话呼叫与 MCPTT 呼叫如何相处。**TS 22.179 V20.0.0 的 `R-6.17-002` 要求的是这项配置能力，没有定下来电时应该让哪边让路。（Release 20 Stage 1，在网 §6.17，印刷页 57）

## 怎么判断这一次有没有按配置处理

| 手头只有什么 | 能判断到哪一步 |
| --- | --- |
| 条款或管理员配置入口，未见该用户的生效策略和这次呼叫记录 | 能查标准要求或配置入口；不能判断普通电话进来时是否打断组呼，反方向也一样。 |
| 已确认该用户的生效策略，没有这次呼叫的执行证据 | 可以说明策略怎么设，不能说本次已经按它处置。 |
| 只看到一次中断、暂停或并行，没有策略证据 | 可以描述这一次观测，不能认定是哪条策略造成，也不能写成全体用户的默认行为。 |
| 同一用户的生效策略，且这次记录能把策略判定和实际结果连起来 | 可以确认这一例按该策略处置；不据此推论另一方向、另一用户或系统默认。 |

§6.17 没给抢占顺序、默认值、配置载体或 SIP 流程。§4.1（印刷页 13）把用 MCPTT 终端与非 MCPTT 用户打普通电话列为使用背景；用的是同一终端，不代表电话就是 MCPTT 私呼。也不要把[环境监听遇到其他呼叫的规则](ambient-listening-interruption.md)直接套进来：那里的条件是被监听用户开始收发 **MCPTT 私呼或组呼**（§6.16.2.2.1，印刷页 56）。

## 两条 Void 去哪里查

| TS 22.179 V20.0.0 §6.17 | 本版正文及资料性附录 A1 |
| --- | --- |
| `R-6.17-001` | `Void`。附录 A1 指向 TS 22.280 的 `R-6.16-001`。 |
| `R-6.17-002` | 管理员配置机制要求仍在本节正文；不在这两条映射内。 |
| `R-6.17-003` | `Void`。附录 A1 指向 TS 22.280 的 `R-6.16-002`。 |

正文在印刷页 57，映射在印刷页 80。注意目标编号尾缀 `-002` 来自本规范的 `R-6.17-003`，不是同尾缀的 `R-6.17-002`。这些是定位指针，本页未核 TS 22.280 目标正文，不能填出迁移后的来电、抢占或接听行为。

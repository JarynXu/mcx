# MCPTT 带话权私呼：管理员能配置哪些权限和时限？

**手动、自动发起权限要分开查。** 某人能发起带话权私呼，也不能据此判断他能呼叫谁。整通最大时长和没有发送或接收用户时的超时，是两项设置。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，§5.6.5，印刷页 27。第 5 章是在网与离网共用的业务要求；带话权私呼支持两种运行方式，无话权私呼只在网（§5、§5.6.1、§6.7.0，印刷页 22、25、44–45）。

## 谁能呼叫，能呼叫谁

| 要配置什么 | 服务须给管理员什么手段 |
| --- | --- |
| **手动发起（R-5.6.5-001）** | 在自身管理权限范围内，配置哪些 MCPTT 用户可发起手动带话权私呼。 |
| **自动发起（R-5.6.5-002）** | 在自身管理权限范围内，配置哪些 MCPTT 用户可发起自动带话权私呼。 |
| **这位主叫能呼叫谁（R-5.6.5-003）** | 给特定的已获授权 MCPTT 用户配一组同一管理权限范围内的目标 MCPTT 用户。 |

已有手动授权，不证明自动也获准；只有目标名单，不能替代发起授权。三个条款都在讲配置能力，不证明本次呼叫已发出，也不规定授权冲突或名单缺项时怎么处理。要判断[手动来电接受、自动来电收件确认](private-call-commencement-evidence.md)，按实际用的模式查。

## 两种时限各管什么

- **整通最大时长（原印编号 R-5.6.5004）：** 管理员能为其权限范围内的 MCPTT 用户配置带话权私呼的总时长上限。原文编号没有最后一道连字符，这里照录。
- **当前没有发送或接收的 MCPTT 用户（R-5.6.5-005）：** 管理员能为其权限范围内的 MCPTT 用户配置超时值，这种带话权私呼在该超时下结束。只有无人发话的记录或一段静音，不能证明没有发送**也没有接收**的 MCPTT 用户。

这里没有给出默认值、开始计时的事件或两种设置的优先顺序。不能把任何一项换成[单次发话限时](floor-permission-end-and-transmit-limit.md)，也不能凭已配时限判断整通已经结束。参与者主动结束私呼是 [§5.6.4-003](private-call-user-termination.md#呼叫已经建立结束整通不等于停止说话) 的另一件事。

## 能否不披露建呼失败原因

**R-5.6.5-006 配的是权限。** 服务须让管理员能配置：在其权限范围内、作为带话权私呼被叫的 MCPTT 用户，能否限制向主叫 MCPTT 用户提供建呼失败原因。R-5.6.2-003（印刷页 26）另说获授权被叫可实际限制披露。允许限制，不证明被叫这次选了限制，也不证明原因已发、未发或已经送达。被叫[拒接或忽略手动来电](private-call-user-termination.md#被叫未接起来拒接不等于忽略)另查 §5.6.4；不从缺少失败原因倒推任何操作。

## 无话权私呼要另查

§5.6.5 的注说两节管理要求有对应意图，-005 则特指带话权私呼。无话权的 §6.7.2（印刷页 45）八个编号在 **TS 22.179 本版都为 Void**；不能抄这六项当作无话权活条，也不能据 Void 判为禁止。资料性附录 A1 在带话权 §5.6.5 处标 NA（印刷页 71）；无话权 §6.7.2 的映射指向 **TS 22.280 §6.7.3**（印刷页 77）。这些是来源导航，未核 TS 22.280 目标正文，不据映射猜配置功能。

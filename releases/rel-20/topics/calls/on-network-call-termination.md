# MCPTT 在网拆话：参与者被抢占、静默到期和整通时限

**组呼里有人被抢占，不一定拆掉整通。**若呼叫继续，服务须向发话者提示有一个或多个接收参与者被抢占。静默到期、达到整通时限、组呼的终止条件，是另外的拆话依据。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，第 6 章在网，§6.2.4 印刷页 40–41。

## 参与者被抢占，分清给谁提示

| 当时发生什么 | 服务须做什么 |
| --- | --- |
| **MCPTT 组呼的一个参与者被抢占（-001）** | 结束整通，或者继续这通。若继续，须向**正在发话的参与者**提示有一个或多个接收参与者被抢占。触发句写的是“参与者被抢占”，不是“只有接收者被抢占才触发”；接收者是续呼提示所讲的对象。原文未给两条分支的选择策略。 |
| **进行中的 MCPTT 呼叫因容量不足，无法让用户继续参加，他们因此被抢占移出（-002）** | 须确保**被移出的用户收到**通知，说明他们因为容量不足被移出呼叫。只见服务发出通知不证明用户收到；也不由这条推出整通结束。 |

若同一件事满足两条，例如接收方因容量不足被移出而组呼继续，两项要求都要核。给发话者的续呼提示，不能替代被移出者收到的容量原因通知。仅撤去某人的发话许可，不等于将他从呼叫中移出；也不要把[为新呼停止另一通旧呼的可选条件](on-network-call-access-priority-and-preemption.md)移到这里。

## Hang Time 和整通时限分开查

| 已核实的时点 | §6.2.4 的要求 |
| --- | --- |
| **Hang Time 已过期（-003）** | 结束呼叫。§3.1 的 Hang Time 是同一呼叫两次连续传输之间可配置的静默上限。 |
| **离呼叫总时限只剩一段可配置的提前量（-005）** | 向**参与者**提示快到总时限。可配置说的是这条提示的提前量；本条没给总时限默认值或配置方法。 |
| **呼叫已达到总时限（-006/-007）** | **释放整通呼叫**，并向**参与者**提示已到总时限。两项都要求，未写提示和释放的先后。快到的提示不等于已到，也不能替代已到的提示。 |

§4.3 的组呼概述说明，前一次传输结束开始计静默。下一次传输在该静默期间内开始时，停表并复位；这次传输结束再开始计。只见发话申请或许可，不等于传输已开始。到期后才看见新传输，不由这段说明判为旧呼已复位。只听到录音无声，也不能认定 Hang Time 已到期。进行中的应急或紧迫险情组状态下，概述把不活动期视为在概念上无限，并提到资源可能因抢占而释放。不能按普通静默直接认它到期，也不能用这段概述裁决它与呼叫总时限的关系。（§3.1、§4.3，印刷页 10、16）

[单次发话达到时限](floor-permission-end-and-transmit-limit.md)管的是一项发话申请所对应的发话许可，不是整通呼叫；[离网呼叫不活动后结束](off-network-inactivity-call-termination.md)另读 §7.4，不能沿用在网的时点或配置。§6.4.9-002 的管理员预设无流量时段只写带话权的呼叫；[在网 ad hoc 组呼配置](../identity/ad-hoc-broadcast-hang-time.md)是 Stage 3，不能代填这里的运行时点。

## 组呼另有两个各自成立的释放条件

**任一适用的终止条件成立，或在场的已归属 MCPTT 组成员达不到最低数，服务都须释放组呼（-008）。**末位参与者离开、倒数第二位离开、发起者离开是终止条件的例子，不是每个组呼一律采用的三条规则。达到最低人数只说明人数这条未触发，不能排除另一个终止条件。只数实际在场且已归属的组成员。符合这两项的成员，正在发话也计入。登记人数、终端数或发话人数都不能替代这个计数。也不要套[建呼与音频前确认的门槛](group-call-setup-acknowledgement.md)。

-004 在本版为 Void；资料性附录 A1 在 §6.2.4 只列 NA，没有给它一个迁移编号（页 41、75）。本节没定义计时器的实际报文、容量阈值、分支排序、默认人数或设备已拆话的证据。

# MCPTT 私呼来电：没接到什么时候可以转给别人？

**手动开始的私呼，在配置期限内没有应答，可按未应答这一项转发。** 这不是看到一次“未接”就能判定自动转发，也不是所有来电转发都限于手动开始。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，R-5.6.3-015（印刷页 27）。这是第 5 章在网与离网共用的**带话权私呼**要求；不由此推离网怎样传信令或分发配置。（§5、§6.7.0，印刷页 22、44–45）

## 来电转发的四项配置

MCPTT 服务须让**获授权的 MCPTT 用户**能把自己的带话权私呼来电配置转给**另一位 MCPTT 用户**。这里配置的是来电由谁转给谁，不是主叫为本次呼叫挑选候选用户。

| 可配置情形 | 怎么判断这项 |
| --- | --- |
| 始终转发 | 用户可选择这一项；标准未规定默认是否开启。 |
| 原被叫不可达 | 查原先接这通来电的用户；仍在等应答不等于已经不可达。 |
| 手动开始，配置期限内未应答 | 两件事都要核。没到配置期限，或者原被叫已在期限内应答，都不能判这项成立。 |
| 按用户手动输入转发 | 是配置支持的一种触发依据。条文没把该输入限定成按拒接或要求来电本身是手动开始。 |

只有第三项明写手动开始。启用了某项配置，或满足一项业务条件，不能证明这次转发实际执行、目标已应答或收到媒体。条文没给缺省时长、从哪件事开始计时、多个条件的先后或转发成功如何通知。

## 不用拒接、忽略或组呼替私呼判断

[带话权私呼的拒接、忽略和结束](private-call-user-termination.md)各有条文。R-5.6.4-002 允许获授权 MCPTT 用户忽略来自另一位 MCPTT 用户的手动请求，注 2 说不向主叫发失败原因；这不是未应答时限届满，也不从缺少失败原因反推忽略或转发。不能仅从拒接确认已经作了本次转发的手动输入，也不能据此说某个实现不允许用按键作输入。

[在网 ad hoc 组呼转发](ad-hoc-group-call-forwarding.md)须另看 §6.20.1（印刷页 61）：R-6.20.1-001 明写**手动开始时接收用户拒接**，并以接收者的用户身份或关联功能别名作为配置依据；R-6.20.1-002 另有**成功转发后**告知发起者目标身份和／或功能别名的机制。这两项不能搬进私呼 R-5.6.3-015。

## 来电不是一通已经进行的私呼

**已经在进行的私呼**要转给另一位用户，查获授权用户的转接机制：带话权是 R-5.6.3-014（印刷页 26），无话权是 R-6.7.4-015（印刷页 46）。不要给这两条加手动开始、未接或配置期限的条件。主叫指定不同候选用户则另读[在网首应答](private-call-first-to-answer.md)。

**无话权私呼只在网。** 它的来电转发是 R-6.7.4-016（印刷页 46–47）：服务须让获授权的 MCPTT 用户能把自己的无话权私呼来电配置转给另一位 MCPTT 用户，也列相同四种情形。同节的 -015 是同节前一条的进行中转接，不是来电转发。这里不规定 SIP 转发、接通或媒体路径。

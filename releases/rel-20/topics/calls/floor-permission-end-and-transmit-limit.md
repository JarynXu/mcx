# MCPTT 在网话权：这次发话为何停止，谁该收到提示？

**发话结束不等于通话结束。** TS 22.179 把发话者主动停、获授权用户终止发话许可、单次发话达到时长上限分开。发话结束提示给接收者；快到上限和达到上限的提示给发话者。

依据：3GPP TS 22.179 V20.0.0，Release 20，Stage 1，第 6 章在网话权控制，§6.2.3.4、§6.2.3.5（印刷页 37）。

## 主动停话和获授权终止

- **获授权 MCPTT 用户终止发话许可。**服务须让获授权用户能随时终止一个正在发话的参与者的发话许可（R-6.2.3.4-001）。有这个权限不等于本次已撤权；条文未限定获授权用户是调度员、管理员或发话者。
- **发话者主动停。**正在发话的参与者须能向服务表明自己不再想发话（-002）。紧随的注说，这种情况下停止向接收参与者传音频，直到有获授权参与者再申请发话。再申请不等于已获准，也不表示原来的许可恢复。注不规定其他并发音频如何处置。
- **给接收者的结束提示。**服务须提示接收参与者该发话者已经发话结束（-003）。只见音频停不能代替这个提示；该条也没有把提示限定于发话者主动停。

## 单次发话快到上限和已经到上限

服务须让管理员能配置一次发话申请对应的发话时长上限，话权控制须有这个可配置上限（R-6.2.3.5-001/-002）。

| 已知时点 | 话权控制的动作 |
| --- | --- |
| 距上限进入可配置的提前量内（-003） | 提示**正在发话的参与者**快到上限。这不是已经到期或已撤权。 |
| 发话时间达到上限（-004/-005） | 提示**正在发话的参与者**已到上限，并撤掉其发话许可。两项都要求，条文未规定先提示还是先撤权。 |

上限按**一次发话申请对应的发话**计，不按整通呼叫时长计。本节没有给默认值、计时从哪个协议事件开始、提示的形式或下一位会不会获准。§3.1（印刷页 10）的 **Hang Time** 管同一呼叫连续两次发话之间的静默上限，和这里的发话时长上限不是同一个条件。若问的是[离网整通呼叫何时因不活动结束](off-network-inactivity-call-termination.md)，查 §7.4。

若发话者是因后来的人抢到话权而停止，另查[配置了插话的组](group-audio-cut-in.md)；别把插话条件当作到时撤权。

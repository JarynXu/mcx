# 主 MC 系统在线配置：初始配置和默认用户配置档何时更新？

**初始配置和默认用户配置档各自判断是否更新。**初始配置和终端本地版本不同，就下载更新的初始配置。默认档有两个条件：初始配置里有 `default-user-profile`，且它指向的默认档相对于终端保存的版本已变化。初始配置自身没变，不妨碍下载已更新的默认档。

依据：3GPP TS 24.484 V20.1.0（Release 20，Stage 3）§4.2.2.1.1。这里讲主 MC 系统的终端在线配置。图 4.2.2.1.1-1 用 MCPTT 终端示意。迁入伙伴时的配置和认证另查[伙伴迁移](partner-migration-profile.md)。

## 认证前：查两个对象，不查一个开关

| 要查的对象 | 何时下载更新 |
| --- | --- |
| **MCS UE 初始配置管理对象（MO）** | 它相对于终端保存的版本已变化。它的格式由 TS 24.483 定义。有没有默认档引用，不影响此项判定。 |
| **默认 MCS 用户配置档（MO）** | 初始配置含 `default-user-profile`，且该元素所指的默认档相对于终端保存的版本已变化。只看到引用，或只有初始配置变了，都不能证明所指默认档也需要更新。 |

例如，终端保存的初始配置仍是 A，`default-user-profile` 指向配置档 D；若 D 已换版而 A 未变，仍会下载更新的 D。反过来，若初始配置已换版但没有这个元素，只能套用初始配置的更新条件，不能从本条推出默认档也要下载。此条以终端已保存的版本作比较，没有定义首次无本地版本时的处理或这两次下载的报文。

默认用户配置档说明了认证前可用的业务及其默认身份。注 1 以紧急 MCPTT 为例。这不是认证成功的记录，也不意味着每台终端必然具备该示例业务。

## 认证后：用取得的身份订阅，文档变了再核对本地副本

1. **认证。**终端从主系统的 **UE 初始配置**读取 IdMS 的 HTTPS URI，按 TS 24.482 做 MCS 用户认证。地址来自初始配置，不是默认用户配置档。
2. **订阅。**终端用**用户认证时取得的身份**，经 CMS 订阅代理订阅每项已启用 MCS 的 UE 配置、用户配置档和业务配置。这里用的是认证所得身份；认证前的默认身份不能替代对其来源的确认。多文档订阅见 §6.3.13.2.2，本节不展开报文。组文档订阅另按 TS 24.481；终端按通知中的 HTTPS URI 取回，文档格式也由 TS 24.481 定义。收到 URI 不等于取回成功。
3. **查变更。**若订阅的文档相较终端本地版本已有更新，终端会收到带 XCAP Diff 的 SIP NOTIFY，配置管理客户端（CMC）更新本地副本。发出订阅不能证明有变更。要判断某份档案，需将收到的通知对到该订阅和文档；收到差异通知和确认副本已更新是两步，业务是否已采用新配置又是另一项证据。变更通知在使用 MCS 期间也可到达（注 2）。

**图示的用词。**图 4.2.2.1.1-1 把前两类管理对象画在 Bootstrap 下，标了业务授权，并把一项业务配置标作离网。正文在这里写的是用户认证及用认证所得身份订阅各项已启用业务的配置。不要从图的标签推定一笔额外授权报文、授权结果，或把正文中的业务配置限于离网。

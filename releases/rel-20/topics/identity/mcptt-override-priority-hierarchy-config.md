# MCPTT 抢占优先级层级：字段名、取值与缺项

**明确该看哪份业务配置，再核字段的精确名字。**以 TS 24.484 V20.1.0（Release 20，Stage 3）为准，MCPTT 在网和离网都可用这个配置表示抢占活动发话的优先级层级；它不是参与者已经获配的优先级。

### 看原名、类型和缺项

| 查什么 | 原文怎样写 |
| --- | --- |
| 字段到底叫哪个名字？ | §8.4.2.1 在网、离网的项 3 都列短名 `num-levels-hierarchy`。§8.4.2.3 的两处 Schema 声明和 §8.4.2.7 的语义都写长名 `num-levels-priority-hierarchy`。保留差异，不把短名当别名或判断服务是否接收。 |
| 值能写多少？ | 在网、离网的长名各自 `minOccurs="0"`，共用 `priorityhierarchyType`。该类型限制 `xs:unsignedShort` 为 **4 到 256，含两端**。3 和 257 不满足这个类型的边界。§8.4.2.6 要求文档符合 Schema，没有为这一字段另写具名错误响应；不要移用其他字段的诊断。 |
| 没写字段，为什么看 4？ | 确认相应的在网或离网块存在，且其中没有长名字段时，§8.4.2.7 说用 Schema 允许的最低值表示层级，合读 §8.4.2.3 得到 **4**。这是语义规则，不是 XSD 声明了默认值，也不保证会回填 XML。整个模式块未出现、只拿到不完整片段，或仅看到名字不一致，都不能据此断言设备实际用了 4。 |

资料性附录 A 表 A.2.3-12 的在网 HTTP 响应示例填了 `6`。示例不是缺项所用的最低值，也不为另一模式指定或继承参数。

### 层级配置不等于给谁授予抢占

§8.4.2.7 在网项 6、离网项 5 说明该层级用于决定哪些参与者、参与者类型和紧急传输类型的请求可获准抢占活动发话。注 2、注 4 说的是**分配给参与者的层级值**越高，抢占活动发话的优先级越高；不是配置里层级数越大，某个人就越优先，也不是并发发话人数。这里不决定授权、同级裁决或某次抢占结果。

只在离网项 5 有 TS 24.483 §7.2.17 的 `NumLevelHierarchy` 指向。该指向不转到在网；本页未核目标正文或版次，不补外设配置、运行流程和模式间取值规则。

同属 Release 20 的 TS 22.179 V20.0.0 是 Stage 1：已配置[多发话者控制的在网组](../calls/group-multi-talker-control.md)另查并发发话上限与层级；[离网话权抢占](../calls/off-network-floor-override.md)另查至少四级和业务条件。这些业务要求不是本页的字段声明或缺项规则。

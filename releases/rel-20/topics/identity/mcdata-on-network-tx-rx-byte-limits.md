# MCData 在网收发配置：四种字节上限

查 SDS 先分两件事：始发客户端在一条消息里能发多少数据，以及经控制面发送时负载能有多大。FD 消息和服务器向收方直接发送的自动接收场景，各查另一项限制。依据是 TS 24.484 V20.1.0（Release 20，Stage 3）的 MCData 在网业务配置。

| 想判断哪种上限 | `on-network/tx-and-rx-control` 的字段 | §10.4.2.6 未包含该字段时 |
| --- | --- | --- |
| 始发客户端在一条 SDS 消息中可发送的最大数据量（§10.4.2.7 在网项 1） | `max-data-size-sds-bytes` | 不施加这项 SDS 消息大小上限。 |
| 始发客户端经控制面在一条 SDS 消息中可发送的最大**负载**数据量（项 2） | `max-payload-size-sds-cplane-bytes` | 不为该 SDS 消息使用控制面程序施加这项大小上限。 |
| 始发客户端在一条 FD 消息中可发送的最大数据量（项 3） | `max-data-size-fd-bytes` | 不施加这项 FD 消息大小上限。 |
| 服务器向终止客户端发送数据，不请求该用户表明当前是否需要这份数据时的最大数据量（项 4） | `max-data-size-auto-recv-bytes` | 不施加这项自动接收大小上限。 |

同一条控制面 SDS 可同时涉及项 1 和项 2，查的量不同。一项未提供，只按该项读。没有控制面负载上限，仍可能有 SDS 消息大小上限；不能推出该消息会走控制面，或超出控制面上限便改走用户面。项 2 明写了负载，项 1 和项 3 写的是消息中的数据量。这里没有给出报头、封装或聚合如何计数的规则。自动接收一项也不规定超过阈值后一定会询问用户、拒收或改走其他流程。

### 元素未提供、填了零、只看到片段，结论不同

§10.4.2.1 在网项 1(a)–(d) 列出四个字段。§10.4.2.3 将 `tx-and-rx-control` 声明为 `on-network` 的直接可选子块，四个 `xs:unsignedInt` 字段都是该块的直接可选子元素，依 Schema 序列排列，均无 `default` 或 `fixed`。在所查的完整在网配置中，省略这个可选父块便没有提供其中四项；不用先有父块才能看 §10.4.2.6 的缺项句。

缺项句不把缺失换算成零或某个默认数字，也不把显式 `0` 或无值的元素当作省略。只看到局部片段时，要先确认是否能判缺项。省掉相应上限不保证不受其他规格、配置或实现约束，也不能保证整个文档通过。这里没有为四项的缺失或数值另写专属 409 或 `phrase`。

若查文件**可下载的时长**或缺默认时长的 409，见[文件可用性与业务配置校验](mcvideo-mcdata-service-config-validation.md)。§10.4.2.1 把两项时长也列在 `tx-and-rx-control` 下；确定其节点位置时仍按 §10.4.2.3/.7 的独立 `file-availability`，不把它们当作第五、第六个字节上限。

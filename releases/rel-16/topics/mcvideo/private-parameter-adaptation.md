# 在网一对一视频推送或拉取中，谁能提出改参数？接收端想要的分辨率用上了吗？

甲正在把视频发给乙。网络状况改变时，可能是甲的客户端提出调整，也可能是乙作为接收用户触发请求。**要看是谁提出这次修改，不能从“推送”或“拉取”猜。** 例如，乙请求改用 720p，只能记为“乙期望 720p”。即使后来有成功响应，也要另有这场通信实际应用 720p 的证据，才能写成“已用 720p”。

3GPP TS 23.281 V16.4.0（Release 16，Stage 2）给出两个在网示例，前提都是两端的私人视频通信正在进行。下面保持视频方向不变：甲发、乙收。原文在**两个示例中都把提出修改的一端叫客户端 1**，并没有固定叫发送方为客户端 1。两例都适用于推送和拉取。[§7.17.3.3 引言及前提，印刷页 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=167)；[§7.17.3.4 引言及前提，印刷页 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=168)。

| 谁先提出修改 | 服务器核谁的权限，获准后请求送到哪里 | 谁获通知、通知什么 |
|---|---|---|
| 发送方甲（客户端 1）检测到网络变化，例如丢包，向服务器提出新参数。 | 核甲用户是否有权更新参数；获准后发给乙端（客户端 2）。 | 乙用户获知参数变化。这是通知，不是已经切换的证据。 |
| 接收方乙（这次是客户端 1）因网络变化向服务器提出期望参数。 | 核乙用户是否有权更新参数；获准后发给正在发送视频的甲端（这次是客户端 2）。 | 甲用户获知的是**更新请求**。甲获通知不等于甲端已接受乙的期望值。 |

两条成功路径的后半程都要区分三件事：**对端的客户端 2 接受请求，向服务器应答**（步骤 5）；**服务器把结果回给提议方的客户端 1**（步骤 6）；**这场通信应用新参数**（步骤 7）。所以，若只看到服务器核过权限却没有核查结果，不能登记“已获准转送”；只看到通知或成功响应，也不能据此填写设备实际使用的编码、分辨率或帧率。没有后续记录同样不表示调整失败。[§7.17.3.3 编号步骤 1–7，印刷页 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=168)；[§7.17.3.4 编号步骤 1–7，印刷页 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=169)。

**如何读请求里的两个身份？** 请求表把提出更新的用户 ID 列为必选（M）。另有两个带注的可选（O）目标字段：组 ID 只用于组通信，另一项用户 ID 只用于私人通信，标识本次更新所针对的用户。表注要求这两项至少出现一项；读私人通信时，不能用组 ID 代替目标用户 ID。必选的新会话描述（SDP）写的是所提参数。响应表的必选结果表示成功或失败，不报告哪种编码已实际投入使用。[§7.17.2.1 请求表 7.17.2.1-1 及表注、§7.17.2.2 响应表 7.17.2.2-1，印刷页 164](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=165)。

核对接收方触发的原文时，有两处措辞容易读错。§7.17.3.4 标题写的是组通信，但它的**前提和图题**明确写私人通信。图中可提取的文字把第 1 项标为通知、第 2 项标为决定更新；**图后编号正文**的第 1 步是客户端 1 提交请求，第 2 步是服务器核查该客户端用户的更新权限。前面的两人示例按编号正文叙述；不由图中文字增设一次通知，也不把标题当作适用于所有组呼的依据。[条款标题及前提，印刷页 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=168)；[图 7.17.3.4-1 文字、图题及编号正文，印刷页 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=169)。

在网组呼进行中，先分清**组通信只允许一名用户发送视频**，还是**允许多人发送、此刻恰好只一人在发**。前者查[组呼参数适配](single-sender-parameter-adaptation.md)；后者的参数适配，本版没有规定，不能照搬单发送用户组例或本页两人例。[§7.17.3.1 引言及注，印刷页 164](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=165)；[§7.17.3.2 引言，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=166)。若在网一对一通信还在建立，想知道谁能向谁发视频，分别查[一对一推送建呼](one-to-one-video-push.md)或[一对一拉取建呼](one-to-one-video-pull.md)。

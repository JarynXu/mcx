# 在网 MCVideo 终端能力：怎样上报本机能力、按用户或组查询、订阅变化？

甲要查乙的终端支持哪些能力，查的是 MCVideo 服务器已经保存的信息。乙的客户端负责上报本机能力；甲可以查询一次，也可以订阅获准接收的更新。这是 Release 16 的 Stage 2 在网流程。

## 乙怎样上报本机能力？

乙的客户端向服务器发送更新请求，必须给出**登录本机的用户的 MCVideo ID** 和**这台终端可用的能力列表**。服务器保存更新后的信息，并应答成功或失败。若乙同时登录多台终端，怎样标识具体是哪台设备提供能力，由 Stage 3 规定。[TS 23.281 V16.4.0，表 7.5.2.2.1-1（含注）、7.5.2.2.2-1，印刷页 106](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=107)；[§7.5.2.3，图 7.5.2.3-1 及步骤 1–3，页 107–108](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=108)。

## 甲查一个人或一个组，会拿到什么？

服务器须已收到并保存客户端的能力信息；甲有权访问能力信息，且与所查用户、组在同一 MCVideo 系统。甲的查询请求必须带**甲自己的 MCVideo ID**。目标可以用用户 ID 列表、组 ID 列表或两者指定。两项虽分别标为可选，表注要求至少出现一项；只填甲自己的 ID 不够。服务器还要核查甲能否读取**本次所请求的能力信息**。跨系统查询在本版 §7.5.2.4 中仍待研究（FFS）。[表 7.5.2.2.3-1 及注，印刷页 106](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=107)；[§7.5.2.4，图 7.5.2.4-1、步骤 1–3 及编者注，页 108](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=109)。

服务器响应中必有结果。成功时，目标用户 ID 与该用户终端的能力列表成对返回，可以有多对。按组查询只返回所请求组中**已归属（affiliated）该组**的成员，不是该组的全部成员。例如，只按组查询时，名单上的乙尚未归属该组，就不会因列在名单上而被返回。若结果为失败，响应中**不得出现**目标用户 ID 和能力列表。[表 7.5.2.2.4-1 及注，印刷页 106](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=107)。

## 甲要持续收到更新，订阅和通知各做什么？

服务器已保存一些能力信息时，甲可以请求订阅自己有权接收的更新。订阅请求必须带甲的 MCVideo ID，目标用户的 MCVideo ID 是可选项。服务器答复订阅成功或失败。成功表示订阅已被接受，不表示乙的能力刚发生变化。[表 7.5.2.2.5-1、7.5.2.2.6-1，印刷页 107](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=108)；[§7.5.2.5，订阅前提、图 7.5.2.5-1 及步骤，页 108–109](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=109)。

甲已订阅，且服务器已收到并保存新的或更新的能力信息时，由**服务器向甲的客户端**发通知。通知请求必须带**登录目标终端的用户 ID 和该终端的能力列表**；如果变化的是乙的终端，带的就是乙的 ID 和该终端的能力，而不是订阅者甲的 ID。甲的客户端向服务器回复通知结果（成功或失败）。收到通知后，甲还**可以**按 §7.5.2.4 再查，但再次查询不是通知流程的必做步骤。[表 7.5.2.2.7-1、7.5.2.2.8-1，印刷页 107](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=108)；[§7.5.2.5，通知前提、图 7.5.2.5-2 及其后说明，页 109](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=110)。

若要判断一次录像回放能否快进或快退，见[从服务器回放录像时怎样协商遥控](stored-video-server-pull.md)。那是具体回放的协商问题，这里查询的是终端上报给服务器的能力。

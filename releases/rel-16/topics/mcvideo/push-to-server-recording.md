# 向 MCVideo 服务器推送录制：拿到文件 URL，录像就录完了吗？

没有。服务器在**接受推送请求**时就把文件 URL 给主叫。这个地址说明接下来要把视频写到哪里；此时还不能断定服务器已收到视频，更不能断定录像已经录完。这里是主叫与服务器之间的在网私呼，接收视频并录成文件的是服务器，不是另一名用户。[3GPP TS 23.281 V16.4.0（Release 16，Stage 2），§7.4.2.4.1，印刷页 94](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=95)；[§7.4.2.4.2，图 7.4.2.4.2-1、步骤 1–5，页 95](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=96)。

**谁能开始录？** 主叫用户已经通过身份认证、获准使用 MCVideo 服务，主叫客户端也已注册。发起时，客户端向服务器发送推送请求，带上主叫的 MCVideo ID 和媒体参数提议（SDP offer）；还可以提出录制时长和应用优先级。即使满足了前提，服务器仍要检查这个客户端是否有权向它推送视频。[§7.4.2.4.2，前提及步骤 1–2，页 94–95](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=96)；[表 7.4.2.2.4-1，页 92](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=93)。

**从接单到写入，中间还有两步。** 步骤 3，服务器接受请求，响应中带主叫的 MCVideo ID、选定的媒体参数（SDP answer）和录制文件的 URL。双方可协商最长传输时间；响应里的时限是可选项，若给出，表示服务器接受或设定的上限，不是已经录下的时长。步骤 4，客户端和服务器建立媒体面与传输控制。步骤 5，客户端才向服务器传送视频流，服务器把收到的流写到步骤 3 指定的文件。看到步骤 4 还不能证明文件里已经有画面；看到步骤 5 可以说明正在录制，但不说明传输已经结束。[表 7.4.2.2.5-1，页 92](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=93)；[图 7.4.2.4.2-1、步骤 3–5 和注 1，页 95](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=96)。

**谁来结束？** 图中步骤 6 是主叫用户停止推送，或客户端按预设条件（例如时长）停止，由客户端向服务器发完成请求。步骤 7 是服务器回送完成应答，确认这次通信结束，不是对录像完整性或观看情况的确认。另一种可能是服务器按自己的条件结束传输，例如达到录像时长上限。完成请求和完成应答的信息表都允许两个方向；主叫的身份不会因服务器发起结束而改变。完成请求必须带主叫的 MCVideo ID 和结束原因；完成应答表只列主叫的 MCVideo ID。仅凭应答里的这个 ID，不能判断谁先停止或为什么停止。[§7.4.2.4.2，步骤 6–7 和注 4，页 95](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=96)；[§§7.4.2.2.6–7，表 7.4.2.2.6-1、7.4.2.2.7-1，页 92–93](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=94)。

**别人怎样看到这段录像？** 发起推送的用户或服务器可以用该 URL 通知其他客户端有新媒体可用；收到通知的客户端可以在方便时用通知里的 URL 另行发起[从服务器拉取录像](stored-video-server-pull.md)。通知不是必经步骤，收到通知也不等于已拉取或已经观看。推送的初始响应或完成应答都不能代替接收方的这些动作。[§7.4.2.4.2，注 2–3，页 95](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=96)。

如果视频的目的地是另一用户而非录制服务器，查[一对一视频推送](one-to-one-video-push.md)；如果主叫要求另一用户向自己发视频，查[一对一视频拉取](one-to-one-video-pull.md)。这两种私呼都不是本页的服务器录制程序。[§7.4.2.3.1，页 93](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=94)；[§7.3.2.3.1，页 85](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=86)。

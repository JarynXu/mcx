# MCVideo：同一用户换一台终端申请业务授权，服务器要怎样答复？

假设甲已在平板上获准使用 MCVideo，现在又从手机申请使用同一业务。**不能沿用平板的结果，直接判定手机也已获准；同样不能仅从平板已获准，推断手机这次必被拒绝。** 服务器须按业务授权程序处理新请求，并在给甲的业务授权响应中说明：甲已在另一台 MCVideo 终端获准使用这项业务。[3GPP TS 23.281 V16.4.0，Release 16，Stage 2，§7.13，印刷页 161](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=162)。

这里有两个容易混淆的步骤。在 §7.12 描述的单域流程中，先按 MC 业务的通用程序**认证用户身份**；然后，MCVideo 客户端利用这次认证的结果，与 MCVideo 服务器办理**该用户的 MCVideo 业务授权**。如果记录只写“身份认证成功”，就还看不出 MCVideo 业务是否已经获准。[§7.12 高层流程说明，印刷页 160](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=161)；[图 7.12-1 后的步骤 1–2，印刷页 161](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=162)。

怎样核对手机收到的答复？先核对两件事：平板上的业务授权属于**这次申请的同一用户**，而平板和手机是**不同终端**。若这两个条件成立，服务器收到手机的业务授权请求后，单单回复该请求的处理结果还不够，必须加上另一台终端已有授权的提示。如果平板获准使用 MCVideo 的人其实是乙，或查到的只是甲在平板上完成了身份认证，就不能凭这条记录要求服务器给甲加上同样的提示。[§7.13 第二段，印刷页 161](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=162)。

**提示说的是另一台终端已有的授权，不是这次申请的结果。** 规范允许一个用户从多台终端获准使用 MCVideo，但看到这条提示，不能断定手机这次已获准，也不能断定平板已经退出或平板上的通话已转到手机。这两节没有给出可同时授权的终端数上限；“可在多台获准”不能读成“数量不限”。[§§7.12–7.13，印刷页 160–161](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=162)。

若要辨认业务 ID 与终端标识，见[同一用户跨业务、跨终端的身份](../identity/cross-service-user-mapping.md)；若要判断另一台终端是否也切换了配置，见[用户配置档切换](../identity/user-profile-switch.md)。要查手机支持哪些视频能力，见[在网终端能力共享](onnetwork-capability-sharing.md)。

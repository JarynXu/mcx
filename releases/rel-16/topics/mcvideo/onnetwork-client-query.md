# 在网 MCVideo：按区域查哪些客户端符合条件，还是按已知用户查终端能力？

看两份虚构记录。第一份问：“演示区里，哪些客户端带有‘蓝灯’标签？”答的是**哪些客户端符合条件**。第二份问：“已知用户乙的终端支持什么？”答的是**服务器为乙保存了哪些能力**。即使第一份结果中有乙的 ID，也不能把那一项当作乙的完整能力清单。

**区域查询先看区域，不先点名目标。** 按 3GPP TS 23.281 V16.4.0（Release 16，Stage 2）§7.16，请求里必填的 MCVideo ID 是请求人的 ID。另一个必填项是查询适用的区域，不是请求人的位置。筛选条件可省略；若填写，可以是视频能力、类别标签，或两者的组合。表中没有要求先给出要找的用户 ID。[§7.16.1、表 7.16.2.1-1，印刷页 162](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=163)。

这是**同一 MCVideo 系统内的在网程序**，前提是服务器已经收集了客户端上报的视频能力。收到请求后，服务器先查请求用户是否有权执行这类查询，通过才检索。若请求还列了组 ID，服务器只从所列各组已归属的成员中，找出区域内符合条件的客户端。比如虚构的甲、乙、丙均在演示区：甲已归属所列的蓝组且符合标签，乙符合标签却没有归属蓝组，丙已归属蓝组却不符合标签。只列蓝组时，三者中仅甲符合。**请求表没有组 ID 列表这一行**，并没有给它标必填或可选；“请求带了组列表时怎么筛”写在程序步骤 2。若请求人和所查用户或本次所查的已归属组分属不同系统，本版把这种情形列为待研究。[§7.16.3 范围、前提，印刷页 162](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=163)；[步骤 1–3 及编者注，印刷页 163](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=164)。

**怎样读结果？** 服务器向请求客户端返回查询响应。其中的 MCVideo ID 列表是可选项。列出甲，表示甲是此次查询的匹配项，不表示已经与甲建立视频通话；没有这个字段，只能说这份响应没有给出名单，不能由此断言区域内没有客户端。这张表也不提供各客户端的坐标或移动轨迹。[表 7.16.2.2-1，印刷页 162](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=163)；[§7.16.3 步骤 3，印刷页 163](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=164)。

若问题本来就是“乙支持什么”，应看[按指定用户或组读取已保存的能力](onnetwork-capability-sharing.md)：请求须带请求人自己的 ID，还须给出目标用户列表、目标组列表或两者。服务器必须核查请求人是否有权读取**所查对象的能力**；光知道此人有区域查询权，不能替这次核权作答。

能力读取的响应一定有结果字段（Result）。成功时，响应给出能力所属用户的 ID 和该用户终端的能力；按组指定目标时，只返回所列组中已归属的成员。失败时，**目标用户 ID 和终端能力这两个字段都不能出现**，只留下其中一个也不符合表注。这个失败规则属于按指定对象读取能力，不适用于上面的区域查询响应。[表 7.5.2.2.3-1、7.5.2.2.4-1 及表注，印刷页 106](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=107)；[§7.5.2.4 前提、步骤 1–3，印刷页 108](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=109)。离网时不要沿用这里的服务器查询；另见[离网能力发现](offnetwork-capability-discovery.md)和[离网活动状态通告](offnetwork-activity-status.md)。

# 在网 MCVideo：接收授予重发到上限，是谁拒绝了接收？

单凭到限，不能说有人拒绝。**C6 限制的是服务器重发接收授予响应的次数**，不是拒绝码，也不统计已经收到响应或看到画面的人数。这里看普通在网预安排组呼：传输控制服务器的一般接收仲裁已处于 **Gr: Reception accepted**，即这通呼叫里已有用户接受媒体接收邀请。这个状态属于呼叫，不是某个客户端的收件记录。[3GPP TS 24.581 V16.9.0，Release 16，Stage 3；§6.3.1–2.2，印刷页 52](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=53)；[§6.3.6.4.1，印刷页 88](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=89)。

### 同一次 T6 到期，先看 C6 当时的值

假设服务器已准许乙接收，授予计时器 T6 正在运行；这一例把 C6 上限设为 3。

| 到期时的服务器记录 | 仲裁应做什么 |
| --- | --- |
| C6 为 2，尚未到限 | 向**已获准的乙**再发一份 Receive Media Response (Granted)，重新启动 T6，C6 加 1 变为 3；仍处于接收已接受状态。此次加到 3，不撤销刚才这次重发。 |
| T6 再次到期时 C6 已是 3 | 不再重发这份授予。到限分支要求保持接收已接受状态，没有要求再启动 T6 或继续增加 C6。 |

程序标题用 **Gr**，两条到期程序末行写 **G**；末行说的都是保持接收已接受状态，没有另列一次状态转换。到限也不证明乙已收到或拒收、乙在播放、发送者停发，或整场呼叫结束。[§§6.3.6.4.8–9，印刷页 90](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=91)；[表 11.2.3-1，C6 行，印刷页 212](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=213)。

### 什么记录才是拒绝？

若服务器在同一状态下**拒绝一项 Receive Media Request**，它发送 Receive Media Response (Rejected)，Result=0；若授予，响应是 Granted，Result=1，授予分支列有启动 T6。无论拒绝还是授予，**服务器都必须保持 Gr: Reception accepted**；不能因为拒绝这一项请求就转入接收空闲，也不能因为授予就转入别的状态。Result=0 是**服务器拒绝这项请求**，不是用户拒绝观看；服务器记录了发送 Granted，也不等于乙端记录了收到它。[§6.3.6.4.3，第 1、2 分支，印刷页 88–89](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=89)

### 一个默认值不能还原一次通信

表 11.1.3-1 给 T6 的默认时长是 **1 秒**，表 11.2.3-1 给 C6 的默认上限是 **3**，两者都能配置。不能据此倒推乙实际等了多久、服务器实际发了几份。T6 表的启动栏写的是：参与者**曾排队且协商了排队**，服务器授予其接收许可。上面 Gr 已接受状态的授予程序列“启动 T6”时未重列这两个条件；Gr 空闲状态的授予程序则未列启动 T6。只看到一次 Granted，不能断定 T6 必已启动并到期。

重启的文字也不完全一致：T6 表的启动栏写服务器在 T6 到期时**收到 Transmission Granted** 后重启，到期动作栏写发送新的 Reception Granted；程序 §6.3.6.4.8 则写未到限时服务器**发送 Receive Media Response (Granted)** 并重启。C6 表的到限栏限定在排队者获准接收的情形。要解释上表里的到期记录，应按具体状态和分支读；不要据这些不同的消息名另拼一个收发或等待确认的过程。[§6.3.6.3.6，印刷页 87](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=88)；[表 11.1.3-1，T6 行，印刷页 208](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=209)。

若问“为什么乙的接收请求没有获准”，请查[预安排组的接收许可与接收人数、流数限制](prearranged-group-reception-server.md)。若记录写的是发送控制空闲，查[发送侧的 T1/T2](transmission-idle-timers.md)，不能用接收授予的 C6 解释。

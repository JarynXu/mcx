# 离网 MCVideo 手动私呼：主叫能区分拒绝和忽略吗？

**只收到拒绝响应，不能断定对方点了“拒绝”。** 乙主动拒绝，或乙在配置的时限内没有应答，乙的客户端都会向甲的客户端发送拒绝响应。超时由乙端判定；响应可以注明“已忽略”，但不一定注明。甲端收到带该说明的响应，才有这项明确的区分依据。反过来，甲端一直没收到响应，也不能凭自己的等待时间认定乙已忽略。[TS 23.281 V16.4.0（Rel-16，Stage 2），§7.2.3.5.3 步骤 5–7、注 2，印刷页 82](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=83)。

## 谁接这通私呼，谁提示振铃？

甲向乙发起离网手动私呼。两个客户端属于同一 ProSe 发现组，都支持 ProSe 一对一直通；甲端已经**通过 ProSe 发现程序**发现邻近且与乙关联的客户端。仅从其他途径得知乙端在附近或知道其 IP 地址，即使同组，也不足以满足这项发现前提。如果乙在多个客户端登录了 MCVideo，乙须已指定其中一个接收私呼。收到请求的客户端要检查自己是不是指定端。**乙已指定、甲已发现，与甲知道哪一个是指定端，是三件事。** 本版两条分支的编者注均将“甲端如何识别乙的指定端”留待研究（FFS）。§7.2.3.3 说明如何让 ProSe 层提供与目标用户关联的终端 IP 地址，不足以补出指定端的识别方法。[§7.2.3.5.2 的前提和编者注，印刷页 79](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=80)；[§7.2.3.5.3 的同项前提和编者注，页 81](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=82)；[§7.2.3.3，页 77](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=78)。

请求从甲端直接发往乙的客户端，带手动启动指示和甲提出的媒体参数（SDP offer）。通过指定端检查后，乙端向乙显示来电，并向甲端返回振铃响应；**显示来电和发送振铃响应不分先后**。甲端向甲提示的是振铃状态，这不是乙已接受的回执，更不是乙已看到视频。[§7.2.3.5.1，印刷页 79](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=80)；[§7.2.3.5.2 步骤 1–4、注 1，页 80](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=81)；[§7.2.3.5.3 步骤 1–4、注 1，页 82](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=83)。

## 振铃以后，看哪份响应？

- **乙接受。** 乙端向甲端返回接受应答，带乙接受的媒体参数（SDP answer）。之后两端建立媒体面；再下一步才是甲端向乙端发媒体、乙端向乙呈现。单有接受应答，能判断乙已接受，不能证明媒体面已建立或乙已看到画面。§7.2.3.5.1 总述还提到客户端无须用户进一步操作便建立会话，但同段仍允许用户接受、拒绝或忽略；判断手动接受和媒体进度时，应分别看 §7.2.3.5.2 的步骤 5、6、7、8。[总述，印刷页 79](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=80)；[接受分支步骤 5–7，页 80](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=81)；[步骤 8，页 81](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=82)。
- **乙拒绝，或到时未回应。** 乙端发拒绝响应，甲端把请求被拒绝或忽略的结果通知甲。乙不操作是用户层的“忽略”，不是说乙端不发消息。拒绝响应不必携带“忽略”说明；本分支也没有接受应答、建媒体面或呈现视频的步骤。[§7.2.3.5.3 步骤 5–7、注 2，印刷页 82](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=83)。

请求表和接受应答表都把甲、乙两方的 MCVideo 用户 ID 列为必填；请求表另列必填的 SDP offer，接受应答表另列必填的 SDP answer。手动启动指示见两条流程的步骤 1。接受应答表不是拒绝响应的字段表，不能用它要求乙拒接时也返回 SDP answer。[表 7.2.3.2.1-1 和表 7.2.3.2.2-1，印刷页 76](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=77)。

要查邻近视频终端是否通告了某项能力，见[离网 MCVideo 能力发现](offnetwork-capability-discovery.md)；能力通告不是这通私呼的应答。语音业务另见[MCPTT 离网手动私呼](../calls/offnetwork-private-manual-client.md)，不能用它代替这里的视频流程。

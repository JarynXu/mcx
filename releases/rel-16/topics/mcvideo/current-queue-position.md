# 在网 MCVideo：已排队的甲收到当前位置，就能开始发视频了吗？

不能。服务器告诉甲“你的发送请求现在排第几”，并没有授予甲发送许可。即使报的是第一位，也不能据此记作甲已获准、甲已发出视频，或乙的许可已被撤销。发送许可有单独的授予消息。[3GPP TS 23.281 V16.4.0，Release 16，Stage 2，§7.7.1.2.1，印刷页 123](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=124)

**谁在问谁？** 这里是同一 MC 系统内已建立的在网 MCVideo 会话。乙已获准且正在发送视频；甲是多名已向传输控制服务器请求发送、请求已排队的参与者之一。甲想知道自己的当前位置，于是甲端向传输控制服务器单播查询。它问的不是全队名单，也不必先知道自己的名次。[§7.7.1.1，印刷页 123](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=124)；[§7.7.1.3 标题，印刷页 129](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=130)；[§7.7.1.3.4 引言及步骤 1–3，印刷页 136–137](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=138)。

**区分三个记录。** 甲端发出查询，只能说明甲在问。服务器从视频发送队列中查出甲的当前位置，再把位置消息单播回甲端。最后是甲端用户获知位置。若记录止于服务器发出答复，不能把用户已获知也记作已观察到；同样，缺少后续记录不证明用户没有获知。所报的是服务器这次查出的队位，不是未来名次、等待时长或新的发送许可。该节引言虽提及服务器作撤销判定，六个编号步骤并没有服务器向乙发撤销消息的动作。[§7.7.1.3.4 引言，印刷页 136](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=137)；[步骤 1–6，印刷页 137](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=138)。

| 在网传输控制信息流 | 这张表列了什么？ |
| --- | --- |
| 甲端 → 服务器：队位查询（Queue position request） | 表中只列可选的媒体标识，且仅在媒体复用时出现。请求表没有要求甲填报当前位置。 |
| 服务器 → 已排队的甲端：队位信息（Queue position info） | 已排队请求的当前位置必选。媒体标识可选，且仅在媒体复用时出现；“是否要求确认”也可选。这个字段说明是否要求甲端确认，不是甲端已经回了确认。 |

这两张表规定：支持相应请求排队的 MCVideo 服务器和客户端须支持对应信息流；不能反过来推断所有设备总是启用排队。两表描述 Stage 2 信息流，不是完整的线上报文格式。[§7.7.1.2.11、表 7.7.1.2.11-1，印刷页 126（查询）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=127)；[§7.7.1.2.9、表 7.7.1.2.9-1，印刷页 125（答复）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=126)。

要撤回甲尚在等待的申请，查[取消排队中的发送请求](queued-request-cancellation.md)；要结束乙已经在发的一路视频，查[结束正在进行的发送](end-transmission-sender-server.md)。若问题是普通预安排视频组呼里客户端该启动哪个计时器、收到队位后进入什么状态，应查[该组呼的 Stage 3 协议处理](prearranged-group-queue-position.md)，不能把特定组呼的协议状态当成本示例的通用前提。

# 在网 MCVideo 组呼映射到 MBMS：什么时候必须带 TMGI，解除映射又解除了什么？

先看映射消息和组呼媒体各走哪条承载。服务器在 A 上发映射，若媒体走另一条 MBMS 承载 B，映射消息就必须带上 B 的标识 TMGI；若媒体也走 A，消息可以带 TMGI，也可以不带。因此，单看消息里有 TMGI，分不出两者走的是不是同一条承载。[3GPP TS 23.281 V16.4.0，Rel-16，Stage 2，§7.10.1.2 表 7.10.1.2-1，TMGI 行及表注，印刷页 156](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=157)。

**先认组和流，再判承载标识。** 服务器发给客户端的映射消息（MapGroupToBearer）说明这场组呼要用哪条承载上的哪些流。组 ID 和视频媒体流标识都是必填项（M）：前者标识在哪个组发起呼叫，后者标识会话描述中的视频流。音频流标识列为可选（O），供音频和视频采用独立编解码器时使用。呼叫应答指示也列为可选；它表示需要接收端确认组呼，不是接收端已经回了确认。TMGI 标识承载，不替代视频流标识。它在表中虽列为 O，却不能略过表注：只有在知道映射和媒体走哪条承载后，才能判定是否要求填写。[§7.10.1.2 导语及表 7.10.1.2-1，印刷页 156](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=157)。

**通告、映射和发媒体是三件事。** 承载已激活并已通告，不等于这场组呼已经与它关联。服务器要经 MBMS 发这场组呼的媒体包，须先发送组呼与承载的关联信息。如果发送记录到映射为止，能确认的是服务器发了关联信息，不能登记为已经发出首包，更不能据此判断哪个客户端收到了映射、收到了视频或播放完整。[§7.10.4.1 首段，印刷页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=159)。

**解除的是这场组呼与承载资源的临时关联。** 该组呼在这条承载上的通信结束时，不再维持这项关联。服务器发给客户端的解除映射消息（UnmapGroupFromBearer）在表中只有一项必填的组 ID，指明哪个组不再使用这条承载。它不是停用整条承载的通知，也没有说明其他组的映射是否改变。[§7.10.1.3 导语及表 7.10.1.3-1，印刷页 157](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=158)；[§7.10.4.1 首段，印刷页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=159)。

# 离网 MCVideo：谁会通告终端能力，谁会回答问询？

甲收到乙的能力通告，不一定是因为甲问过乙。离网时，乙可以定期向组内通告，也可以用同一种通告回答请求。收到通告的客户端保存或更新的是**发送方的在场信息（presence）、能力和随附资料**。这说明客户端听到了对方的通告，不能据此认定对方正在发视频或已经建立会话。[3GPP TS 23.281 V16.4.0（Release 16，Stage 2），§7.5.3.1，印刷页 109](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=110)；[§7.5.3.3.2，步骤 1–2，页 112](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=113)。

**等组内成员定期通告。** 参与的客户端属于同一个 MCVideo 组。发通告的客户端已预配该组的 ProSe（邻近服务）直连通信信息，以及该组到 ProSe 二层组 ID 的映射。它定期向组里发送自己的能力通告，其他组员收到后更新本地记录。这个流程不以先收到能力请求为前提。[§§7.5.3.3.1–2，前提及图 7.5.3.3.2-1 后步骤 1–2，页 111–112](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=112)。

**主动问组里谁符合条件。** 同样要求参与方同组；这次要预配该组直连通信信息及二层组 ID 映射的是**发请求的客户端**。甲向组内发问，例如只找支持某种视频能力的终端。收到请求且符合条件的客户端都用各自的能力通告回应；不设筛选条件时，**所有收到请求的客户端**都回应，并非组名单上的每一台都已收到。收到回应的客户端缓存各个通告发送方的信息。单凭没收到乙的通告，无法判定乙不具备所问的能力：并没有证据表明乙收到了请求、甲也收到了乙的回应。[§§7.5.3.4.1–2，前提、图 7.5.3.4.2-1 后步骤 1–3 及注 1，页 112–113](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=113)。

**只问同组、在附近的乙。** [问询总则 §7.5.3.4.1（页 112）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=113) 把对象限定为本组的其他成员。要单独问其中的乙，§7.5.3.4.3 另列两项前提：甲已预配**针对乙这个客户端**的 ProSe 直连通信信息，而且甲已通过 ProSe 发现程序发现乙就在附近。甲向乙发请求；乙收到后向甲回自己的能力通告；甲收到后缓存乙的在场信息、能力和随附资料。只知道组的映射，不能替代这两项前提。[§7.5.3.4.3，前提、图 7.5.3.4.3-1 后步骤 1–3，页 113–114](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=114)。

**请求和通告各自必须写谁？** 两条消息都有名为 MCVideo ID 的字段，要看它指谁。请求中，**发问用户的 ID 必填**；目标用户 ID、目标组 ID、筛选条件分别可选。通告中，**通告用户自己的 ID 必填**；目标用户 ID、目标组 ID、类别标签、视频能力、位置均为可选字段，位置字段指**通告用户本人所在的位置**（如已知），并非该用户知道的其他地点。例如，通告没列编解码器，并不等于该终端不支持任何编解码器。流程说明的是分享能力，不能据此把表中的可选能力字段改成必填。[表 7.5.3.2.1-1、7.5.3.2.2-1，页 110](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=111)。

这里问的是客户端能做什么。若要判断客户端此刻在做什么，规范另列活动状态通告（[表 7.5.3.2.4-1，页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=112)）。若问题是向服务器上报能力、查它保存的记录或订阅变化，见[在网 MCVideo 终端能力共享](onnetwork-capability-sharing.md)，不要把服务器加进这里的离网交换。

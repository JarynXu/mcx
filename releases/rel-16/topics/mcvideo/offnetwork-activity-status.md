# 离网 MCVideo：怎样问同组终端正在做什么？收到活动通告能说明什么？

甲想知道乙**能不能录像**，应查[离网终端能力](offnetwork-capability-discovery.md)；想知道乙**当时是否在录像**，要看乙的活动状态通告。它报告的是乙的终端当时在做什么，例如接收、发送或录制视频。收到这条通告，不等于甲收到了乙的视频。[3GPP TS 23.281 V16.4.0，Release 16，Stage 2，表 7.5.3.2.4-1，印刷页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=112)。

## 问组里哪些终端？

在这个离网流程中，客户端向**同一 MCVideo 组**的其他成员询问活动状态，不通过服务器查名单。向组内发问时，发问端甲已预配该组的 ProSe（邻近服务）直连通信信息，以及该组到 ProSe 二层组 ID 的映射。[§§7.5.3.5.1–2，总则与组内问询前提 1–2，印刷页 114](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=115)。

甲可以按用户 ID、客户端 ID、某组能力、某类能力或这些条件的组合来筛选。即使按能力筛选，**回答的仍是当前活动**。乙收到了请求并且符合条件，就用活动状态通告回应；丙收到却不符合条件，不属于应答者。若甲不设筛选条件，所有**实际收到请求**的客户端都回应，不是名单上每个成员都必然收到并作答。甲没见到丁的答复，单凭这个结果不能判定丁当时没有发送视频。[§7.5.3.5.2 正文，印刷页 114](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=115)；[图 7.5.3.5.2-1 后步骤 1–2 及注 1，印刷页 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=116)。

## 只问附近的乙，还需要什么？

乙仍须是同组成员。甲须已预配**针对乙这个客户端**的 ProSe 直连通信信息，并已通过 ProSe 发现程序发现乙就在附近。仅知道组的二层映射、或仅知道乙的用户 ID，都不能代替这两项前提。甲直接问乙；乙收到请求，向甲回报**乙自己的活动状态**；甲收到乙的通告后，缓存乙的在场信息（presence）和活动状态。[§7.5.3.5.1 的成员范围，印刷页 114](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=115)；[§7.5.3.5.3 正文与前提 1–2，印刷页 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=116)；[图 7.5.3.5.3-1 后步骤 1–3，印刷页 116](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=117)。

## 请求和通告各要写谁？

两张表都列了两个叫 **MCVideo ID** 的项目。先看描述认清是哪一端，再看必填（M）或可选（O）。

| 信息流 | 必填 | 可选 |
| --- | --- | --- |
| 活动状态请求 | 发问用户的 MCVideo ID | 目标用户的 MCVideo ID、目标 MCVideo 组 ID |
| 活动状态通告 | 发通告用户的 MCVideo ID、该终端的当前活动状态 | 视频细节（如类别标签或码率）、目标用户的 MCVideo ID、目标 MCVideo 组 ID |

“筛选条件”出现在**组内问询的过程描述**里。活动状态请求表没有单列这个字段，既不能说它是该表的必填项，也不要从隔壁的能力请求表抄一个字段进来。相应地，乙发通告时可以不写码率，但不能把“正在录像”换成“支持录像”。[§§7.5.3.2.3–4，表 7.5.3.2.3-1、7.5.3.2.4-1 均在印刷页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=112)；[§7.5.3.5.2 步骤 1–2 及注 1，印刷页 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=116)。

**缓存记录的是谁？** 组内问询时，收到其他客户端通告的各客户端缓存的是**通告方**的在场与活动状态；单问乙时，是甲缓存乙的信息。即使乙报告“正在发送”，缓存也不能证明甲已收到或核验某段视频，更不能证明乙现在仍在发送。要查的是服务器保存的终端能力，则是另一套[在网能力共享流程](onnetwork-capability-sharing.md)。[§7.5.3.5.2 步骤 3，印刷页 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=116)；[§7.5.3.5.3 步骤 3，印刷页 116](https://www.etsi.org/deliver/etsi_ts/123200_123299/123281/16.04.00_60/ts_123281v160400p.pdf#page=117)。

# MCVideo 的原因值 5 是“只能收”还是“只能发”？原因值 7 是排队吗？

日志只剩 `MCV1, cause=5`，**还不能填原因**。同是服务器发给参与端的消息，拒绝**发送请求**时，5 表示申请人只能收；拒绝**接收请求**时，5 恰好表示申请人只能发。若消息撤销的是**已有发送许可**，5 说的是终止这路 RTP 流，不是给参与者划分收发权限。[3GPP TS 24.581 V16.9.0，Rel-16 Stage 3，§9.2.3.4，印刷页 148](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=149) 规定，原因值要在携带它的消息中解释。

先找解码后的**消息名**。记录没保留名字，但保留了方向、消息族和子类型，也可以查表：在服务器到参与端的 MCV1 中，`x0001` 是 Transmission Rejected，`x0100` 是 Transmission Revoked，`x0111` 是 Receive media response。`x` 仅表示发送方是否要求控制应答，不区分原因。仅知道方向或 MCV1，仍选不出这三种消息中的哪一种。[§9.1.2，Name，印刷页 144](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=145)；[§9.2.2.1，表 9.2.2.1-2 及 x 的说明，印刷页 146](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=147)。

| 先分清是哪一条记录 | 原因 5 | 原因 7 |
| --- | --- | --- |
| **Transmission Rejected**：服务器拒绝申请人的发送请求。[§9.2.6.1，印刷页 159](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=160)；[§9.2.6.2，印刷页 160–161](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=161) | **只能收**：申请人只有接收权限，所以这次不能发。 | **本版这张清单未列 7**。若记录确实这样写，保留原值，不借另一条消息替它解释。 |
| **Transmission Revoked**：服务器向原先获准发送的人撤销发送许可。[§9.2.10.1，印刷页 164](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=165)；[§9.2.10.2，印刷页 165](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=166) | **终止这路 RTP 流**：消息表明发送许可被撤销；它不是最后一个媒体包，也不能证明整场呼叫已经挂断。 | **这位参与者的发送被排队**。7 是原因，不是第七位，也不是后续授予。 |
| **Receive media response，且 Result=0**：服务器拒绝这次接收请求。[§9.2.15.1，印刷页 170](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=171)；[§9.2.15.2，印刷页 171](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=172) | **只能发**：申请人只有发送权限，所以这次不能收。 | **同时接收的流数已达上限**。被拒的是这次接收请求，没有说申请人的发送被排队。 |

**接收响应要先读 Result。** Result=0 表示不准收，Result=1 表示准许接收所请求的媒体。若摘录只剩数字 1、连字段名都没有，就不能断言它是 Result=1；若已确认 Result=1，没有后续媒体记录，也只能记“获准接收”，不能记“画面已显示”。若摘录没有 Result，先补查同一响应的结果；若同一条既记 Result=1 又把 5 或 7 写成拒绝原因，把两项照录并标明矛盾，不能挑一项替另一项作解释。[§9.2.3.17，印刷页 154–155，取值见 155](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=156)；[§9.2.15.1，Result 与 Reject Cause，印刷页 170](https://www.etsi.org/deliver/etsi_ts/124500_124599/124581/16.09.00_60/ts_124581v160900p.pdf#page=171)。公共字段 §9.2.3.4 末段只回指发送拒绝和撤权；接收响应应查它自己指向的 §9.2.15.2。

若问**排队的人如何查自己的当前位置**，一个在网例子是：同一系统的会话已经建立，乙获准并正在发送视频；甲是多个已排队的申请人之一，向传输控制服务器查自己的队位。读[查询当前队位](current-queue-position.md)。若问题是**普通在网预安排组呼里，接收服务器怎样对某一路媒体作出许可、怎样处理接收流数上限**，读[组呼接收服务器](prearranged-group-reception-server.md)。例如，接收接口已有许可，又申请接收一路时，要看这个接口的同时接收流数是否已达上限。该页也解释状态机为什么要和消息清单分开读；这个状态下的满流限制不是所有控制消息共用的原因 7。

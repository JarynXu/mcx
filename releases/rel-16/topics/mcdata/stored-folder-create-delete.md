# MCData 消息存储：新建文件夹遇到重名怎么办？删除会连同哪些内容？

在本人的“值班”文件夹下新建“夜班”时，如果名称没有冲突，MCData 消息存储就使用“夜班”；如果已经重名，或者客户端没给名称，**由消息存储给新文件夹取名**。规范没有指定后缀，也没有要求覆盖原来的“夜班”。以后要删除哪一个，客户端须给出那个文件夹的**标识**。删除成功，指定文件夹及其所含的全部子文件夹和存储对象一并删除，同一父目录下的其他文件夹不在范围内。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§7.13.3.11.2 步骤 1–3、§7.13.3.12.1，印刷页 157](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=158)；[§7.13.3.12.2 步骤 1–3，页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=159)。

这两项操作都以用户已有 MCData 消息存储账户、账户按文件夹分层为前提，消息存储客户端与消息存储之间已经成功完成认证和授权。这里处理的是用户自己的存储区；仅知道同事的文件夹标识，并不能借这个流程处置同事的目录。[§7.13.1，页 140](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=141)；[§7.13.3.11.1–2，页 156](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=157)；[§7.13.3.12.1–2，页 157](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=158)。

| 消息 | 信息表中的必填项（M） | 可选项（O） |
| --- | --- | --- |
| 新建请求：客户端发给消息存储 | 用户的 MCData ID | 父文件夹标识（要建在哪里）、文件夹名称（希望叫什么） |
| 新建响应：消息存储返回客户端 | 用户的 MCData ID、结果（成功或失败） | 新建文件夹的标识，不是父文件夹标识 |
| 删除请求：客户端发给消息存储 | 用户的 MCData ID、要删的文件夹标识 | 无；不需要列子项或对象标识 |
| 删除响应：消息存储返回客户端 | 用户的 MCData ID、结果（成功或失败） | 无；表中不列文件夹标识、子项清单或内容 |

新建见[表 7.13.3.1.19-1、7.13.3.1.20-1，页 145](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=146)；删除见[表 7.13.3.1.21-1、7.13.3.1.22-1，页 146](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=147)。新建流程的步骤 1 描述请求带父标识和名称，步骤 3 描述响应返回新文件夹标识；对应信息表仍把这三项各列为可选。**省略父标识时建在哪儿，这两处没有说明**，不能据此认定是根目录或收件箱。要判断新建或删除是否成功，看各自响应中的结果：仅见一个标识、没见标识或仅见请求，都不能代替成功结果。[§7.13.3.11.2，页 157](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=158)；[§7.13.3.12.2，页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=159)。

如果只想删“夜班”里的一条记录，须按[单个存储对象的删除](stored-object-update-delete.md)办理，不能用文件夹标识代替对象标识。[复制或移动已有文件夹](stored-folder-copy-move.md)则另有命名规则：没给新名称时沿用源文件夹名，这两项流程并未规定遇到重名就让存储端另取名。[§7.13.3.13.2 步骤 2，页 159](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=160)；[§7.13.3.14.2 步骤 2，页 160](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=161)。文件夹删除说的是本人消息存储里的目录和对象；这项流程没有规定回收站、恢复期限或介质上的物理擦除方式。

# 在网 MCData 业务不经过 SIP 核心，还能申请网络资源吗？

可以。以 IP 互通为例：业务不经过 SIP 核心，不能借本地出站或入站代理的资源控制功能来申请资源。这类业务由 **MCData 服务器经 Rx 接口直接对接 PCRF**（策略与计费规则功能）管理资源。服务器与 PCRF 之间的这处参考点叫 **MCData-5**。因此，没在本地代理上看到资源请求，不能断定业务没有申请资源。这是 Release 16 对不经过 SIP 核心的在网 MCData 业务的说明，不是说所有 MCData 业务都绕过代理。[3GPP TS 23.282 V16.8.0，Stage 2，§7.12.2 首段，印刷页 139](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=140)

**可以申请什么？** 这类业务可沿用基于 SIP 的业务所用的三类资源管理程序：在业务启动时申请单播资源、申请修改单播资源，以及申请具有共享优先级的资源。第一类在基于 SIP 的情形对应会话建立，在这里对应业务启动。三项是按所需资源操作列出的程序类型，不是每次业务启动都要依次完成的三个步骤。[§7.12.2 次段及三项列举，印刷页 140](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=141)

比如，记录只显示某项 IP 互通业务启动时服务器申请了单播资源。可以认定的是**服务器提出了资源请求**：既不能据此断定资源已经获配，也不能断定对端已接受连接或收到 IP 包。要区分业务上的连接答复和数据交换，见[点到点 IP 互通](point-to-point-ip-connectivity.md)。要比较有本地代理参与的情形，见[在网单播资源申请与修改](../bearers/unicast-resource-establishment-modification.md)；若问题在于多个会话如何共享优先级，见[单播承载的优先级共享](../bearers/unicast-bearer-priority-sharing.md)。

查交叉引用时要注意：[§7.12.1，印刷页 139](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=140) 指向 TS 23.280 时，条号原样是 `10.x`，没有给出具体小节号。

# MCData 服务能力与功能角色

## 适用范围

- 固定 TS23.282 V16.8.0（2021-01），Rel16 Stage 2；本页解释在网服务能力与功能职责，不是协议实现或完整规范概览。
- 分别按能力、通信角色和存储用途适用；不要求所有能力已启用、所有角色同时存在或请求已成功才阅读各声明。

共同依据：TS23.282 V16.8.0 §1、6.1–6.2，印刷页13、22。

## 先区分能力与使用能力的服务

条件：判断本版 MCData 服务所用能力；不据此推定某终端已配置全部能力。

SDS、FD、DS、IPcon 是能力；会话管理、机器人控制、增强状态、数据库查询等服务利用这些能力。SDS 既可走信令面也可走媒体面；FD 可传文件或取文件用的 URL；DS 的数据尚未全部收到即可开始处理；IPcon 为数据主机提供透明 IP 数据通信，不限于一次事务。

强度：定义和功能描述；SDS/FD/DS 的支持要求按各条 SHALL，不推定单个部署全部启用。

- §1 的 sub-services 列表只列 SDS/FD；§6.4.1、§6.4.3.1.1–2 明确列四种能力。本页保留两处范围，不据前者删去 DS/IPcon，也不把上层服务名当作独立传输协议。
- 这里不定义 SIP/MSRP 报文、能力协商或交付证据；Stage 2 的能力支持不能替代 Stage 3 的实际调用条件。

依据：3gpp-ts-23.282-v16.8.0 §1 (scope-list comparison)；3.1；4；5.3–5.5；5.11；6.4.1 surrounding text；6.4.3.1.1–2，印刷页13,14,15,16,17,18,19,21,23,24。

## 按通信识别控制与参与角色

条件：解释一次私聊或组通信的服务器职责；组服务器一致性仅在该组内适用。

每次通信只有一个控制角色服务器，可涉及多个参与角色服务器；同一服务器可兼任两者。控制角色负责面向该通信用户的发送/接收控制、组 SDS/FD 分发及 IPcon 传输管理；参与角色负责用户侧发送控制、归属支持、消息中继和接收控制。同一组的客户端使用该组的同一服务器，多组用户可关联多个服务器。

强度：角色支持和单次控制唯一性为 SHALL；同一服务器兼任为 MAY；§5.1 拥塞措施为 MAY，若拒绝则通知为 SHALL。

- 这是功能角色及通信范围的约束，不给出物理机器或独立媒体 relay 的数量。平面关系转引 23.280；本页不据此补部署拓扑。
- 自动发送 SDS 不免除服务器拒绝；§5.1 对信令面 SDS 以外类型规定请求授权方式，并允许拥塞拒绝、排队或撤回自动发送许可。这里不指定相应协议错误码、阈值或仲裁算法。

依据：3gpp-ts-23.282-v16.8.0 §6.4.3.1.2；5.1；6.1–6.3.1，印刷页16,17,22,23,24。

## 文件存储与通信历史分别由谁负责

条件：按 FD 文件操作或已配置用户的消息历史操作分别判断；不把历史存储配置作为所有 FD 操作的前提。

FD function 处理文件分发请求/响应及分发；media storage client 协助上传下载，media storage function 保存文件并支持部分下载。MCData message store 则是按用户配置的持久通信历史存储，message store client 管理历史和设备同步；两组职责不能互相替代。

强度：功能描述；§5.2 临时存储与到期清除为 MAY；§5.10 授权和用户选择约束保留。

- 临时接收存储可有 TTL 并在到期清除；持久历史仍受账户授权和用户存储选择约束，不等于所有文件永久保留。
- 文件存储支持部分下载不等于已定义完整恢复算法；本页不展开存储接口、安全机制或同步报文。§6.4.3.3 将个人历史存储的安全访问/管理交由安全规范。

依据：3gpp-ts-23.282-v16.8.0 §3.1 (metadata/object)；5.2；5.10；6.4.3.3–4；6.6.3.1.1–4，印刷页15,17,20,21,25,32,33。

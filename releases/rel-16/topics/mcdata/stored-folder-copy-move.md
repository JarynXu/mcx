# MCData 消息存储：复制或移动整个文件夹，里面的子文件夹和对象去哪儿？

假设本人账户里的“五月”文件夹含有一条消息和一个“照片”子文件夹，目标文件夹是“归档”。**复制**成功，“归档”里多出一份完整的“五月”，原处仍有“五月”；**移动**成功，整份“五月”从原处移到“归档”下面。两种操作都包括源文件夹中的全部子文件夹和存储对象，不需要客户端逐个点名。若请求指定新名称“五月备份”，目的位置的文件夹就叫“五月备份”；省略新名称，则沿用“五月”。改的是被复制或移动的文件夹在目的位置的名字，不是把“归档”改名。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§7.13.3.13.1，印刷页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=159)；[§7.13.3.14.1，页 159](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=160)。

**先看是谁的目录。** 这两项操作只对采用文件夹层级的用户账户有意义。用户已在 MCData 消息存储中有账户，消息存储客户端与 MCData 消息存储之间已成功完成认证和授权。源和目标属于该用户自己的存储区；知道另一位用户的文件夹标识，并不能把它作为这次操作的目的地。[§7.13.1，页 140](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=141)；[§7.13.3.13.2 的前提，页 158](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=159)；[§7.13.3.14.2 的前提，页 159](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=160)。

| 要读哪一端的信息？ | 复制与移动各自的信息表 |
| --- | --- |
| 客户端向消息存储发请求 | 三项必填：用户的 MCData ID、源文件夹标识（“五月”）、目标文件夹标识（“归档”）。新文件夹名可选；表中的名称说明适用于两种操作。 |
| 消息存储向客户端回响应 | 三项必填：用户的 MCData ID、这次操作的结果（成功或失败）、新文件夹标识。成功时，最后一项标识“归档”下那份复制或移动后的文件夹，不是“归档”本身，也不是里面某条消息的标识。 |

两张请求表均在[表 7.13.3.1.23-1、7.13.3.1.25-1，页 146](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=147)。两张响应表见[表 7.13.3.1.24-1，页 146](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=147)和[表 7.13.3.1.26-1，页 147](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=148)。消息存储先执行操作，再把结果回给发起请求的客户端，见[§7.13.3.13.2 步骤 1–3，页 159](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=160)及[§7.13.3.14.2 步骤 1–3，页 160](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=161)。要确认成功，看响应的**结果**；发出请求、有响应或单看文件夹标识都不够。这些条款没有规定失败时标识该怎样填、移动前后的标识值是否相同、遇到重名是否覆盖，或失败后怎样回滚。

如果只想把“五月”里的一条消息移到“归档”，应读[单个已存对象的复制或移动](stored-object-copy-move.md)：那项请求用对象标识点名，和这里用源文件夹标识处理整份目录不同。只想给消息加标记或永久删除它，则见[已存对象的更新与删除](stored-object-update-delete.md)。

# 迁到伙伴系统后，能从伙伴消息存储读到主系统的历史消息吗？

不能通过伙伴消息存储读取主系统中已存的内容。但这不等于用户迁移后就再也不能读主系统的消息。要分清用户实际访问的是哪一座消息存储。

**访问伙伴系统的存储。** 用户迁移后，伙伴 MCData 系统**可以**让用户访问伙伴系统自己的消息存储，不是每次迁移都必须提供。访问这座存储时，标识用户的是该用户在**伙伴系统中使用的 MCData ID**。即使用户原来就能访问主系统的消息存储，伙伴的这座存储也不与它相连：本版没有定义连接不同 MCData 系统消息存储的参考点。能打开伙伴消息存储，不能据此判断主系统的历史消息已经同步过来，也不能把这个入口当成通往主系统历史消息的途径。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§7.13.6.1、§7.13.6.2 第一段，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=166)。

**另行访问主系统的存储。** 迁移用户可以另获访问主系统消息存储的途径。规范举出合适的接入点名称（APN）配合相应的 IP 路由，或使用 MCData IP 连通服务；这些是例子，不是必选方案。这样的访问不在本规范范围内。即使用户通过另一条途径读到了主系统里的消息，也不能反推两座消息存储已经互联。[§7.13.6.2 第二段，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=166)。

[消息存储开户](message-store-account.md)说明如何为用户分配存储区；[伙伴系统迁移授权](../identity/partner-migration-authorization.md)说明谁来判断用户能否在伙伴系统使用所选业务配置。两者都不是在两座消息存储之间复制历史消息的程序。

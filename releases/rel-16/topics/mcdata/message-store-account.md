# MCData 消息存储：开户成功，能证明第一份通信对象已经存下吗？

不能。开户成功只说明 **MCData 消息存储已为请求指定的用户分配专用的安全存储区**。它不是用户注册 MCData 业务的结果，也不说明其中已有某份通信。判断一份对象有没有存下，要看对应的**对象存入响应**，不能拿开户响应代替。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§7.13.3.7.1–2，印刷页 152–153](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=153)

**什么时候需要服务器开户？** MCData 服务器准备存入通信对象时，用户须已有存储区。若还没有，服务器须先开户，再存入后续通信。该开户流程有三个前提：服务器与消息存储之间已经成功完成认证和授权；该用户尚未获配存储区；服务器有权在该消息存储上创建用户账户。服务器与存储之间的认证和授权，不能单独证明服务器有开户权限。账户也可通过服务配置预先创建；本规范不规定这种配置怎么做。因此，没看到服务器发开户请求，不足以断定用户没有存储区。[§7.13.3.7.1 及注、§7.13.3.7.2 前提，页 152](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=153)

**怎样读开户记录？** MCData 服务器向消息存储发开户请求，必填的是**目标用户的 MCData ID**，不是服务器自己的 ID。消息存储向服务器返回该用户的 MCData ID 和开户结果，两项均为必填。例如，响应中写的是乙的 ID，表示这次开户针对乙；接收这条响应的是 MCData 服务器。仅凭这条记录，不能说乙的终端收到了响应，也不能说乙已获通知。结果可以是成功，也可以是失败；只看到请求，或只看到一条响应却没看到结果值，都不能把开户记为成功。[表 7.13.3.1.11-1，页 143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=144)；[表 7.13.3.1.12-1，页 144](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=145)；[图 7.13.3.7.2-1 所附步骤 1–2，页 153](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=154)。

**要确认第一份对象，找哪条记录？** 在活动通信期间，服务器另发存入请求，指明用户并附上对象。消息存储在对应的存入响应里返回用户 ID 和对象标识；对象标识有值才表明该对象存入成功，字段存在但值为空表示这次未存入。若只保留了开户成功记录，第一份对象可能已存，也可能未存，不能据此判断。若还要判断短数据是否送达收件人，见[在网 SDS：存入谁的账户，能否当作送达](sds-message-store-deposit.md)。[§§7.13.3.8.1–2，页 153–154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=154)；[表 7.13.3.1.13-1、7.13.3.1.14-1，页 144](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=145)。

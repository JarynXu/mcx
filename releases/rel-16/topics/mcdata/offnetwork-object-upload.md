# MCData：离网时留在终端的通信记录，重连后怎样存回自己的账户？

重新接入提供 MCData 服务的网络后，终端可以把离网通信记录上传到用户自己的 MCData 消息存储账户。重连只说明现在可以上传，不能证明已经发出请求，更不能证明存储成功。离网通信原先以对象形式保存在终端本地消息存储的特定文件夹。上传流程有两个前提：用户已有消息存储账户，消息存储客户端与 MCData 消息存储之间已成功完成认证和授权。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§7.13.3.16.1–2，印刷页 161](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=162)。

**账户里还没有目标文件夹，要先建吗？** 不用先单独建。消息存储客户端向 MCData 消息存储发上传请求，带三项必填信息：用户的 MCData ID、账户内的目标文件夹标识、本地要上传的对象。消息存储把对象存入指定文件夹；如果这个文件夹不存在，由消息存储创建它。**文件夹不存在**和**请求没给文件夹标识**是两种情况：前者有明文处理，后者缺必填项，不能按“存入根目录”或“自动取名”解释；本过程没给这种缺项指定错误码。[表 7.13.3.1.29-1，印刷页 147](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=148)；[图 7.13.3.16.2-1，步骤 1–2，印刷页 162](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=163)。

**什么记录能说明上传成功？** 看消息存储回给客户端的上传响应。用户的 MCData ID 和本次上传成功或失败的结果都必填；仅知道“收到一条响应”还不够，要看结果值。成功表示消息存储报告本次上传成功。表中没有逐对象结果或返回对象标识，不能据此编出各对象的回执。流程也没有删除本地副本或让其他设备同步的步骤。[表 7.13.3.1.30-1，印刷页 148](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=149)；[图 7.13.3.16.2-1，步骤 2–3，印刷页 162](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=163)。

两类相邻操作可以按**对象到哪里去**区分：

- [消息存储同步](message-store-sync.md)也由客户端发请求，但需要同步的对象由消息存储放进**响应**，发往终端。这里的上传则是客户端把新对象放进**请求**，发往本人的消息存储账户。[§7.13.3.6.2，图 7.13.3.6.2-1，步骤 1–2，印刷页 152](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=153)。
- [一对一 HTTP 文件分发](http-fd-client.md)是为了让另一位用户取得文件。文件先上传到 MCData 内容服务器的媒体存储功能，再用含文件 URL 的分发请求面向目标用户；要判断对方是否下载，应看接收端的下载完成记录，或在请求了完成报告时看相应报告。把对象存回自己的消息存储账户，不等于已发出文件 URL，也不能证明其他用户完成了下载。[§7.5.2.4.2，图 7.5.2.4.2-1，前提 2、步骤 1–2、9–10，印刷页 91–92](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=92)。

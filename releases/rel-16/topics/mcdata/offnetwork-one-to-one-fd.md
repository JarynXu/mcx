# 离网 MCData 一对一文件分发：对方已接受，文件就到了吗？

**不能仅凭肯定响应判断文件是否已到。** 这份响应只表明乙的客户端接受了请求。流程把接受请求、在媒体面上传送文件、记录下载完成列为不同的步骤；假如甲事后查到的记录只有肯定响应，就既不能说乙已下载，也不能说乙尚未下载。若甲要求下载完成报告，乙下载完后会发起另一份报告。这才是乙向甲报告“这笔下载已完成”的消息。[3GPP TS 23.282 V16.8.0，Rel-16，Stage 2，§7.5.3.3.2，图 7.5.3.3.2-1 下的步骤 4–6，印刷页 113](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=114)。

这里讲的是两个离网客户端之间的一次独立文件分发（FD）。程序开始时，甲用户已发起向乙用户发送文件的通信；两端属于同一个 ProSe 发现组，均支持一对一直连，而且甲已通过 ProSe 发现程序找到附近与乙用户关联的客户端。两端即使已配置在同一发现组，也不能由此推出甲已经发现乙，更不能推出乙接受了文件请求。[§§7.5.3.3.1–2，三个前提，页 112](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=113)。

## 谁决定接受？谁要求回报？

甲的请求指向一名选定的用户。请求里的两项可选指示回答不同的问题：**强制下载指示**让接收客户端自动接受这次媒体面建立请求；**完成报告指示**表达甲是否要收到下载完成报告。甲选了强制下载，不等于甲要求回报。[§7.5.3.2.1，表 7.5.3.2.1-1，页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=112)；[§7.5.3.3.2，步骤 1，页 113](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=114)。

乙收到请求后，先检查是否有策略限制哪些成员可接收这类消息或内容，再通知乙用户；请求若带有文件元数据，通知也包含这些信息。

- **未指示强制下载：**乙用户可接受、拒绝或忽略。用户明确接受或拒绝，乙客户端才按这一步向甲返回相应的 FD 响应。忽略不等于发出了拒绝响应。
- **指示强制下载：**乙客户端自动返回肯定响应，可以不征求乙用户同意、只通知文件正在下载。这个指示没有取消前面的策略检查；肯定响应也不能证明乙用户亲手点了“接受”。

响应表把接受确认和选定的媒体参数（SDP 应答）列为必填项。接受确认说明乙是否接受请求，选定的媒体参数不是已收到的文件数据。[§7.5.3.2.2，表 7.5.3.2.2-1，页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=112)；[§7.5.3.3.2，步骤 2–4，页 113](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=114)。

## 下载已完成，谁能知道？

实际的文件传送发生在步骤 5：甲通过已经建立的媒体面将文件传给乙。完成下载后，乙客户端在本地记录完成，并通知乙用户。如果甲请求了完成报告，乙客户端还会发起报告；如果甲没有请求，这次下载仍可完成，乙照样记录并通知用户。

甲收到报告时，可凭报告中对原事务的关联和下载完成确认，认定乙客户端报告了**那笔文件下载**已完成。这不证明乙用户打开、读过文件。反过来，甲没有收到报告，不能单凭沉默判定下载失败：先看甲是否要求过报告；即使要求过，手头仍缺乙报告完成的证据，不能把“未获确认”写成“未下载”。[§7.5.3.3.2，步骤 5–6，页 113](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=114)；[§7.5.3.2.3，表 7.5.3.2.3-1，页 111](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=112)。

换个问题要换个程序：发送时由服务器检查权限，见[在网强制与自愿下载](mandatory-consented-file-distribution.md)；从 URL 下载文件，见[私聊 HTTP 文件分发](http-fd-client.md)；重连后把离网记录存回自己的账户，见[离网对象上载](offnetwork-object-upload.md)。这些都不是本次离网媒体面传送的后续必经步骤。

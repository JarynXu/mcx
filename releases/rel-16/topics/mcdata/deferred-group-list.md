# MCData：组里有哪些暂存数据可供我下载？

在网接收方要查稍后还能取哪些组数据，可以向 **MCData 服务器**查询。返回的是**待下载数据的引用清单**。一项出现在清单里，只表示服务器列清单时它可供该客户端取回，不表示文件已经传到终端。

这一流程有版本限制：[3GPP TS 23.282 V16.8.0（Rel-16，Stage 2）§7.6.2.5.1，印刷页 120](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=121) 的编者注说，由于本版为 HTTP 文件分发（FD）引入了新的 MCData 内容服务器，**本查询程序仍待研究（FFS）**。以下说明该版实际描述的信息流，不把它当作已经定案的 HTTP FD 接口或产品符合性要求。

## 查谁的，谁来列？

前提是服务器已经暂存了延期的组通信数据。接收方先前推迟下载只是一个例子：非强制下载时，接收方可以接受、推迟（不响应）或拒绝；接收方一时不可达或网络拥塞时，服务器也可能暂存。因此，仅凭用户点过“稍后”或未响应，不能断定服务器一定存有该项。[§7.6.2.4.1、§7.6.2.4.2 步骤 6，印刷页 119–120](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=120)。

1. 接收用户发起查询；其客户端向 MCData 服务器发出查询请求（MCData get deferred list request）。请求表只列一个必填项：**请求用户的 MCData ID**。不要求用户逐个填组 ID。
2. 服务器为**该请求客户端**列出**其已归属组**中可供它下载的暂存数据。即使另一个组也有暂存数据，只是那个组的成员、却未归属该组，不能据此要求把该组的项目列给自己。
3. 服务器的查询响应（MCData get deferred list response）有两个必填项：同一请求用户的 MCData ID，以及待下载数据的引用清单（Deferred data list）。客户端把清单告知用户；是否取回对应数据，由用户再决定。

[§§7.6.2.1.3–4，请求及响应表，印刷页 115–116](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=117)；[§7.6.2.5.2，前提、图和步骤 1–4，印刷页 120–121](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=122)。这里没有规定引用必须长得像 URL，也没有给出下载完成回执或无可下载项时的应答方式。

## 如果要找的是自己的历史文件

要按对象 ID 取回本人存储区里的一个对象，或按条件搜索匹配对象，入口是 [MCData 消息存储](stored-object-lookup.md)。该处在客户端成功通过认证和授权后返回已存对象本身；这里查询的是哪些组数据尚可下载。两者不能按界面上都叫“清单”来判断，看响应里装的是对象还是引用。[§7.13.2、§§7.13.3.1.1–4，印刷页 141–142](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=142)。

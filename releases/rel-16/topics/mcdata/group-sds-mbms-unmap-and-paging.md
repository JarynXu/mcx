# 在网 MCData 组短数据：只有组 ID，是解映射还是应用寻呼？

**只看组 ID 分不出来。** 解映射（Unmap Group To Bearer）可以只带组 ID；应用寻呼（Application Paging）也只有组 ID 这项应用字段。先看完整记录里的 APP 名称和消息 Subtype，再判断字段有没有缺。日志没显示的字段，不一定是消息没带。

本页只查 TS 24.582 V16.3.0（Rel-16，Stage 3）的 MCData 广播组播（MBMS）子信道控制。组短数据（SDS）终接客户端收到解映射后怎样处理，另按本页末尾的条件查。

## 先辨消息，再看字段

参与 MCData 功能向客户端发送这两类控制消息。两者的 APP 名称都是 `MCDM`；表 11.2.2-1 将 Unmap 和 Paging 列为不同的消息 Subtype。Unmap 节对 Subtype 的回指写成了表 11.2.3.1-1，后者列的是应用字段的 **Field ID**。辨别消息时看表 11.2.2-1，不拿字段编号当消息类型。[§11.2.1–2、表 11.2.2-1 和 11.2.3.1-1，印刷页 37–38](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=38)；[§11.2.5 的 Subtype 回指，印刷页 42](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=43)。

| 已辨认的消息 | 组 ID 之外的应用字段怎么读 |
| --- | --- |
| Unmap Group To Bearer | 组 ID 必选。承载标识 TMGI 与媒体子信道（MBMS Subchannel）**一起出现，或一起省略**。表里画出三项，不代表三项都必选。只有组 ID 符合这一条字段规则；只带 TMGI 或只带媒体子信道都不符合。 |
| Application Paging | 表里只列组 ID 这一项应用字段，不要求 Unmap 的字段对。参与功能在准备把现有媒体传输切到单播、或准备在单播开始新媒体传输时发送它。看到寻呼，不等于看到单播已切换或新传输已开始。 |

依据：[§11.2.5 及表 11.2.5-1 后的字段要求，印刷页 41–42](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=42)；[§11.2.6 和表 11.2.6-1，印刷页 42–43](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=43)。

## Unmap 只带了字段对的一半，接收端会怎样？

§11.2.8 分开整条消息和单个字段。名称与 Subtype 的组合未知、消息太短或必选字段有错，接收端须忽略**整条消息**。未定义的字段、语法有错的可选字段，接收端须忽略**该字段**。

如果已确认是 Unmap，完整记录里组 ID 无误，且 TMGI 和媒体子信道只出现一项，**不符合成对要求**。即使在场的一项语法正确，也是如此。排除太短、必选字段有错等独立情形后，§11.2.8 没为这种缺一项的情形指定单独处置。不能据这两节断定接收端会丢整条、只忽略在场字段，或自行补齐缺项。[§11.2.5，印刷页 42](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=43)；[§11.2.8，印刷页 44](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=45)。

## 消息字段合规，能确认撤了哪条映射吗？

不能只凭组 ID 确认。§6.5.2.2 先要求终接客户端收到**指向当前通信**的 Unmap；存在相应关联才移除它。标准接着要求停止监听关联的承载和媒体子信道，原 SDS 会话仍在进行才恢复或继续单播。如果现场记录里同组出现两个可能的关联，这几节没有规定仅凭组 ID 选哪一个。不能默认撤最近一条、清空全组，或从字段合规推断已经执行。另有终端的当前通信与关联记录时，用那些记录核对。[§6.5.2.2 的 Unmap 段，印刷页 27](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=28)。

要核对该终端如何停听、何时续传，读[终接客户端的映射与解映射](group-sds-mbms-map-unmap.md)。要核对终接参与功能在会话结束时发送哪条通知，读[参与侧的映射与转发](group-sds-mbms-forwarding.md)。一条 Unmap 不能反过来证明 SDS 会话已结束，也不能证明下一条短数据已经收到。[§11.2.5 的发送场景，印刷页 41](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=42)；[§6.5.3.2 末段，印刷页 28](https://www.etsi.org/deliver/etsi_ts/124500_124599/124582/16.03.00_60/ts_124582v160300p.pdf#page=29)。

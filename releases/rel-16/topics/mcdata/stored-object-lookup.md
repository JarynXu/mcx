# MCData 消息存储：按对象 ID 取回，还是按条件搜索？

要打开一条已保存的消息，且知道它的**对象 ID**，消息存储客户端可直接取回它。要找某次会话里保存的消息和文件，即使一个对象 ID 都不知道，也可以用**会话 ID** 作搜索条件。两种请求都发给 MCData 消息存储（message store），由它直接返回对象；搜索不是直接取回的前置步骤。

这里的“对象”是连同元数据保存的消息或文件。客户端与消息存储之间须已成功完成认证和授权，访问范围限于该 MCData 用户自己的存储区。两种操作的请求和响应都必须带用户的 MCData ID；它标识用户，不是要取的对象 ID。[TS 23.282 V16.8.0，Rel16 Stage 2，§§7.13、7.13.1–2，印刷页 140–141](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=141)；四张信息表见下文。

| 要取什么 | 请求里除用户 MCData ID 外还须给什么 | 消息存储在响应中返回什么 |
| --- | --- | --- |
| 一个已知对象 | 对象存入时由消息存储生成的唯一对象 ID | 该 ID 标识的对象；若找不到，必填的单个对象信息元素（Stored object）须为空。 |
| 符合条件的对象 | 搜索条件。可用对象的任一部分，也可组合多部分；同一会话 ID 是一种条件。 | 所有匹配的已存对象，不只是它们的 ID；若无匹配，必填的对象集合信息元素（Stored object(s)）须为空。 |

例如，同一会话在本人的存储区留下两条消息和一个文件。若三者都符合搜索条件，搜索响应就返回这三个对象，不必再按三个 ID 逐一取回。若按已知对象 ID 取其中一条消息，响应不会因为另外两个对象属于同一会话而把它们一并带回。

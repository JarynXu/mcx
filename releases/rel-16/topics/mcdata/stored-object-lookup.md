# MCData 消息存储：按对象 ID 取回，还是按条件搜索？

## 调度员用自己的账户登录，能查另一位用户的通信历史吗？

要看调度员是否获准访问**那位用户的存储区**。在 TS 23.282 V16.8.0 的架构要求中，每个区由账户用户的 MCData ID 标识；消息存储只能开放获准访问的区。§5.10 明确要求：账户持有人以外的用户（如调度员）获授权时，应能访问该持有人的区。§6.4.3.3 也把可访问配置区的人限定为本人及获授权的用户。[§5.10，印刷页 20](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=21)；[§6.4.3.3，印刷页 25](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=26)。

例如，乙是调度员，已用自己的账户登录，也知道甲的一条消息的对象 ID。这三项都不能证明乙有权查甲的历史。若另有有效授权，明确准许乙访问甲的存储区，就满足了 §5.10 的非本人授权条件；这不证明乙已经取回那条消息，也不表示乙可以删除或同步甲的对象。

本人查询的四张表列了用户 MCData ID，没有把操作者和另一位账户持有人列为一对委托身份字段。不能从这两种查询推导出代查接口，也不能用 §7.13.1 的本人限制否定 §5.10 明载的授权情形。§6.4.3.3 的注把访问与管理的安全问题交给 3GPP 的安全工作组（SA3）；§7.13.2 的注把访问时的认证、授权及相关操作支持也列为 SA3 的职责。本规范没有给出这套安全机制的实现。[§6.4.3.3 注，印刷页 25](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=26)；[§7.13.2 注及两张取回表，印刷页 141](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=142)；[两张搜索表，印刷页 142](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=143)。

## 查询本人历史：已知对象 ID 与只知道查询条件

查询本人历史时，消息存储客户端与存储须先完成认证和授权。要打开一条已保存的消息，且知道它的**对象 ID**，消息存储客户端可直接取回它。要找某次会话里保存的消息和文件，即使一个对象 ID 都不知道，也可以用**会话 ID** 作搜索条件。两种请求都发给 MCData 消息存储（message store），由它直接返回对象；搜索不是直接取回的前置步骤。

消息或文件连同元数据一起保存，称为“对象”。在本人管理存储对象的流程里，§7.13.1 规定用户不能访问为其他用户存储的对象；这不是对上文非持有人获授权情形的否定。按 §7.13.2，消息存储须先鉴别 MCData 服务器或获准用户的凭据；认证和授权成功后，访问限于该用户的存储区。[TS 23.282 V16.8.0，Rel-16 Stage 2，§§7.13、7.13.1，印刷页 140](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=141)；[§7.13.2，印刷页 141](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=142)。

下表两种本人查询都以客户端与消息存储之间已通过认证和授权为前提。请求和响应都必须带用户的 MCData ID；它标识用户，不是对象 ID。两种流程和四张信息表的条款见表后。

| 要取什么 | 请求里除用户 MCData ID 外还须给什么 | 消息存储在响应中返回什么 |
| --- | --- | --- |
| 一个已知对象 | 对象存入时由消息存储生成的唯一对象 ID | 该 ID 标识的对象；若找不到，必填的单个对象信息元素（Stored object）须为空。 |
| 符合条件的对象 | 搜索条件。可用对象的任一部分，也可组合多部分；同一会话 ID 是一种条件。 | 所有匹配的已存对象，不只是它们的 ID；若无匹配，必填的对象集合信息元素（Stored object(s)）须为空。 |

例如，同一会话在本人的存储区留下两条消息和一个文件。若三者都符合搜索条件，搜索响应就返回这三个对象，不必再按三个 ID 逐一取回。若按已知对象 ID 取其中一条消息，响应不会因为另外两个对象属于同一会话而把它们一并带回。

# MCData 服务器预告释放：报了剩余量或申请延期，当前通信会继续吗？

**服务器批准延期，当前通信才按延期分支继续。** 预告面向发起通信的客户端，不表示所有参与方已经释放资源。即使服务器知道只剩很少的数据，或已经收到了延期申请，也不能据此认定它会批准。

这里讨论在网单播、一对一或组通信中，正在通过媒体面传送的短数据（SDS）或文件（FD）。依据是 [3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§§7.7.2.4.1–2，印刷页 130–131](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=131)。§7.7.2.4.1 的预告范围还包括 HTTP 文件分发，但下文的媒体资源释放步骤不适用于它。此处由服务器发起释放，不是由另一名获授权用户发起。

## 谁收到预告？报剩余量有什么用？

发起端的用户已注册 MCData 服务。管理员已配置参与者一次发送请求可传的数据量和时间上限，以及服务器等候延期申请的时长。承载容量不足，或一次请求传送的数据量或时间超限，都是释放条件的例子；满足其中一项即可触发服务器判断。根据配置，服务器可不预告而直接启动释放，也可先按会话标识找到这次通信，向**发起端**发送释放意向，由客户端告知用户。[§7.7.2.3.1，页 128](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=129)；[§7.7.2.4.2 前提、图 7.7.2.4.2-1、步骤 1–4，页 130–131](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=131)。

索要补充信息是预告中的**可选项**。若服务器询问剩余量，发起端以补充信息响应报告待传的数据量。这不是延期申请；预告没问时，也不能因没有这份回复就认为用户放弃了延期。对一对一和组通信，预告和补充信息响应均标明原发起用户的 MCData ID 和会话标识；组通信还标明组 ID。一旦发送补充信息响应，响应中必须有被询问的信息。[§§7.7.2.1.13–16，表 7.7.2.1.13-1 至 7.7.2.1.16-1，页 124–125](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=125)。

## 怎样判断是否延期？

- **只回剩余量。** 步骤 4 说服务器收到补充信息后，可以等到管理员配置的时限。不是每次都必须等满，也没有规定统一的秒数。若在配置的时限内未收到延期申请，按 §7.7.2.3 释放。
- **用户要求延期。** 发起端另外发送延期申请，申请表只列必选的会话标识。它标明哪次通信要延长，不表示延期获批，也没有承诺时长。
- **服务器作出决定。** 服务器按策略接受或拒绝，并向发起端返回延期应答。应答有两个必选项：会话标识、是否接受。接受则原通信继续；拒绝则按 §7.7.2.3 释放。条文未给出按剩余量自动批准的阈值；批准也不能证明数据已交付。

见 [§7.7.2.4.2 步骤 4–8，页 131](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=132) 和[延期信息流表 7.7.2.1.21-1、7.7.2.1.22-1，页 126](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=127)。

## 何时才是实际释放？

配置选择不预告时，服务器直接进入释放流程；有预告但延期被拒、或超时未收到申请时，也转入释放流程，无须再走一次预告。现在通知的不只是发起端：服务器识别当前参与者，向每个参与客户端发释放请求，用户获通知，各客户端向服务器回释放响应。图示成功末态是**所有参与者释放了与这次通信关联的媒体面资源**。释放请求带原因，释放响应指明是否已释放；收到单个响应不能证明其他参与者也已清理，更不是文件或消息的收件回执。这个版本把 MBMS 上的通信释放列作待研究，不能用单播步骤补全。[§§7.7.2.3.2.1–2，图 7.7.2.3.2.2-1、步骤 1–6，页 128–129](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=129)；[§§7.7.2.1.8–11，释放请求及响应表，页 122–123](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=124)。

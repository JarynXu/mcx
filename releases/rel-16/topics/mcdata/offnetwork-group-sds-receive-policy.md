# 离网 MCData 组的普通短消息：没提醒用户，是没收到，还是被策略拦了？

单凭没有提醒，两种结论都下不了。甲离网给组发一条普通短消息，乙客户端收到请求之后，还要看接收策略和消息是给谁用的。**乙客户端收到、乙用户获提醒、乙用户读过**是三件事。甲要判断丙的情况，也不能拿乙的回报代替丙的。

这里讨论 Release 16 在**离网信令控制面**向一个 MCData 组发送独立短数据（standalone SDS）的流程。这一过程预设 SDS 数据大小上限，条文未给出具体数值。另有组直通的预配置：例中甲、乙、丙是同一 MCData 组的成员；甲的客户端预先配置了本组的 ProSe（邻近服务）直通通信信息，以及本组到 ProSe 二层组 ID 的映射。甲用户发起组通信后，由甲客户端核查甲是否有权发送组独立数据请求，获准后才向组发送。同组并不自动取得发送权。[3GPP TS 23.282 V16.8.0，Stage 2，§7.4.3.4.1–2，印刷页 77–78，导语、前提及步骤 1–2](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=79)。

## 乙没看到提醒，先分清是哪一种通知

接到组请求后，乙、丙各自的客户端检查是否有策略限制某类消息或内容发给某些成员，例如按位置或用户权限限制。甲通过的是**发送**权限检查，不等于每个接收端的策略都允许。

- 对普通组短消息，如果乙端策略允许，而内容是给乙用户用的，客户端**可以**提醒乙，不是必须提醒。即使已收到并获准，也可能没有提醒。
- 如果内容不是给用户用的，例如供应用处理的数据，乙端**不得**就这份内容通知乙用户。没有提醒符合这条规则，不能反推策略拒绝。
- 如果乙端策略判定为负，步骤 4 后的注说明：**乙客户端向甲客户端发送适当通知**。这说的是发给甲端的通知，不是提醒乙用户。注没有指定通知的类型或格式，单凭这条记录不能认定乙已读，也不能断言某一种格式绝不可能使用。

依据：[§7.4.3.4.2，步骤 3–4 及步骤 4 后的注，印刷页 78](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=79)。

**如果业务是共享增强状态，就不能把提醒当作可省。** 甲选中组，并从该组预配的列表选了一个增强状态值。这个专门流程也是用离网组独立 SDS 传送，但明确写明通知例中接收端的用户。普通短消息的“可提醒”不能替代这一步；提醒了用户仍不证明他读过。[§7.9.4.1.1，前提及步骤 1–3，印刷页 138](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=139)。

## 甲怎样知道哪位成员收到了、读过了？

先看甲**要求什么**。组请求中的处置类型是可选的，甲用户可以要求报送达、报已读或两者都报，也可以不要求。请求中若带处置请求，就必须同时带**甲客户端的 IP 地址**；没有处置请求时，不能用这条条件要求认定缺地址就是错误，也不能由此推断绝不带地址。[§7.4.3.4.2 步骤 2，印刷页 78](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=79)；[表 7.4.3.2.3-1 的处置类型，印刷页 76](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=77)。

再看接收端**回报什么**。甲要求报送达时，接收客户端发起送达报告；甲要求报已读时，要等接收用户读了数据，该客户端才发起已读报告。发起报告，说的是接收端的动作，不等于甲已经收到了它。不要求相应报告时，甲手里没有回报也不说明消息没到或没人读。[§7.4.3.4.2 步骤 5–6，印刷页 79](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=80)。

例如甲在同一会话连续发了两条消息，手里只有乙的一份“已送达”。通知中的两个 MCData 用户身份分别标明发给谁、由谁发出；回复标识指出它答复的原事务，处置结果才说明送达、已读或两者。若乙这份通知答复第二条，只能记“乙报告第二条已送达”。第一条、乙是否读过第二条、丙的状态都不能据此补上。[表 7.4.3.2.2-1，印刷页 75](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=76)。

若发送的是按组预配的状态值，看[组增强状态共享](group-enhanced-status.md)；若问离网消息如何保存在个人历史中，看[离网组短消息的本地保存与上传](offnetwork-group-sds-history.md)。这两件事都不能替代本次消息的逐人判读。

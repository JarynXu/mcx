# 跨 MCData 系统发文件：收件人向谁下载，怎样判断已经下完？

收件人在伙伴系统接受服务，向**伙伴内容服务器**取文件。通知里出现伙伴地址，不表示伙伴已经有文件；发送方收到接受答复，也不表示收件终端已经下完。

**这个例子从哪里开始？** 两位用户均已获 MCData 服务授权，正分别在发送方的主系统和接收方所在的伙伴系统接受服务。两系统已互联，服务协议允许双方内容服务器共享文件。文件此前已上传到主内容服务器的媒体存储功能，尚未在伙伴系统下载过。这是一对一 HTTP 文件分发，不是组文件分发。[TS 23.282 V16.8.0，Release 16，Stage 2，§7.5.2.4.3 开头及前提 1–3，印刷页 92](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=93)。

**谁改取件地址？** 发送客户端给主 MCData 服务器的文件分发（FD）请求带的是文件 URL 和必要的访问授权信息，不是文件本体。主 MCData 服务器检查用户有权发送该请求、文件大小低于配置的 FD 上限；向伙伴 MCData 服务器转发时，给的是主内容服务器上的文件地址和必要的授权信息。**伙伴 MCData 服务器**再把**伙伴内容服务器**的 URI 加在文件 URL 前面，把指向伙伴侧的地址发给接收客户端。这是转发分发请求，不是复制文件。授权资料的内容及使用机制不在这份规范范围内。[同条，图 7.5.2.4.3-1 后步骤 1–5、注 1，印刷页 93](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=94)。

**接受答复和取文件哪个在先？** 接收客户端可以通知用户有文件要收；用户可以接受、拒绝或忽略通知。如果收到的请求带强制下载指示，客户端自动给伙伴 MCData 服务器发接受答复（步骤 7）。FD 答复由伙伴 MCData 服务器经主 MCData 服务器转回发送客户端（步骤 8–9）。接收客户端实际向伙伴内容服务器要文件是步骤 10，只须在步骤 7 之后，可以在步骤 8–9 之前或之后发生，不必等答复转回发送端。无论接受答复是否已转回，它都不是下载完成报告。[同条，步骤 6–10、注 2，印刷页 94](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=95)。

**伙伴什么时候向主系统取文件？** 伙伴内容服务器先查本地，有副本就不必为这次请求再向主系统取；没有才去掉取件 URL 上前加的本地路径，用还原出的主系统文件 URL 向主内容服务器请求文件。具体怎样证明这次请求已获授权，不在本规范范围内。主内容服务器在回复中发回文件，并记录已经把它发给了哪个伙伴系统。这条记录证明主系统已向指定伙伴发出文件；它不是伙伴另行确认收妥的回执，更不是接收客户端下载完成的记录。伙伴内容服务器**可以**为以后取件保留副本，直到主系统给出的文件过期时间，或收到删件请求；不是必须缓存，也不是永久保存。[同条，步骤 11–12、注 3–4，印刷页 94](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=95)。

**什么才是接收端完成的证据？** 伙伴内容服务器在下载响应中把文件发给接收客户端；客户端记录下载完成，并通知接收用户（步骤 13）。只有发送用户在**最初的 FD 请求**中要求完成报告，接收客户端才在下完后发起报告，经伙伴侧送至主 MCData 服务器，再转给发送方。最初勾选要报告，本身不能证明下载已完成；未要求报告而没收到报告，也不能据此说下载失败。主、伙伴 MCData 服务器均可为本系统获授权用户查询下载历史而保存报告，保存的报告不是缓存的文件。通知用户或出具完成报告都不证明用户打开过文件。[同条，步骤 2、13–16，印刷页 93–94](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=94)。

若要查普通在网、直接目标的协议职责，另见[私聊 HTTP 文件分发客户端](http-fd-client.md)及[服务端](http-fd-server.md)；要查后来删除服务器副本是否通知收件人，见[文件移除](http-file-removal.md)。这些不是本例下载完成的前置步骤。

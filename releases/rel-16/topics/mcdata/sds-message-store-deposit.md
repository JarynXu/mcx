# MCData：在网短数据存进了谁的账户？能据此判断对方已收到吗？

不能把存入账户当作送达。MCData 消息存储的响应说明**哪位用户的通信对象有没有存下**；SDS（短数据服务）请求是否到达某个收件人，要看该收件人的递送证据。这是两笔不同的记录，即使账户属于收件人也是如此。

这里讨论 [3GPP TS 23.282 V16.8.0（Release 16，Stage 2）§7.4.2，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=45) 所限的**单一 MCData 系统、在网 SDS**。对发出和收到的通信分别判断：用户受消息存储支持，已建账户，也已要求存储自己的通信，规范才要求把该方向的全部通信存入本人账户。不能拿发件人的设置替收件人作决定，也不能只凭账户存在认定已启用存储。[§7.13.4.1–2，页 163](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=164)；[§7.13.5.1–2，页 164](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=165)。

| 从哪一方看 | 服务器按什么顺序处理 |
| --- | --- |
| 发件人 | 客户端发起一对一或组 SDS 请求。MCData 服务器先把通信作为对象存入**发件人账户**，再检查并授权这项 SDS 业务请求，按 §7.4.2 向目标收件人继续处理。发件人的存入响应不能证明业务已获准，更不能证明组内任何人已收到。[图 7.13.4.2-1，步骤 1–3，页 164](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=165) |
| 收件人 | MCData 服务器先收到面向该用户的业务：它可能是任一发件人发来的新请求，也可能是对该用户此前所发请求的响应。服务器把通信作为对象存入**这位收件人的账户**，再按 §7.4.2 向该用户递送。服务器收到了业务，和收件人的终端收到了业务，不是同一件事。[图 7.13.5.2-1，步骤 1–3，页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=166) |

**谁能发起存入？** 在这里，发起者是 MCData 服务器，不是用户的存储客户端。活动通信期间，MCData 服务器与 MCData 消息存储之间须已成功完成认证和授权，用户也须已获配安全存储空间。服务器用通信信息构造对象，向消息存储发存入请求，必填两项：账户所属用户的 MCData ID、对象本身。这里的服务器间认证授权，不是上表发信流程中对某一项 SDS 业务请求的授权。[§7.13.3.8.1–2、图 7.13.3.8.2-1，页 153–154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=154)；[表 7.13.3.1.13-1，页 144](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=145)。

**怎样读存入响应？** 响应由消息存储发回 MCData 服务器，用户的 MCData ID 和对象标识都是必填项。对象标识有值时，表示该对象已存入，可用这个标识直接取回；不表示已经有人取过或读过。**标识字段在，但值为空**，明确表示这次没有存入。如果一份完整响应根本没有该字段，它就缺必填项；如果只是日志没记到响应或没展示该字段，则不能判断存入结果。空值、缺字段、没看到响应都不能代替接收端的递送记录。这些条款也没规定存入失败后 SDS 必须停止、继续或重试。[表 7.13.3.1.14-1，页 144](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=145)；[图 7.13.3.8.2-1，步骤 2，页 154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=155)。

已经拿到对象标识，要读回历史记录，见[取回或搜索已存对象](stored-object-lookup.md)。如果记录先留在离网终端，重连后由客户端存回自己的账户，见[离网对象上传](offnetwork-object-upload.md)。

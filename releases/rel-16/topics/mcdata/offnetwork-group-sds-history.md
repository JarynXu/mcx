# MCData：离网组里的短消息先存在哪里？重新联网后会自动上传吗？

不会仅因重新联网就自动上传。乙在离网组通信中收到一条供人阅读的短消息时，消息先保存在乙的终端。要把这次通信留作本人账户里的历史，还要看乙在通信结束、重新联网后是否决定保留。

**为什么只说乙？** 规范举的例子是用户 1 到 N 正在离网进行组通信，用各自的 MCData 客户端交换短消息（SDS，短数据服务）。这些客户端属于同一个 MCData 组，并且都已预先配置本组的 ProSe（邻近服务）直通通信信息，以及本组与 ProSe 二层组 ID 的映射。乙对应例中的用户 2，已在 MCData 消息存储开户。本节专门说明乙如何把离网通信纳入自己的历史；其他客户端按 §7.4.3.4 交换消息。不能因为大家同组，就推断人人都有账户或都把通信存到了网上。[3GPP TS 23.282 V16.8.0，Release 16，Stage 2，§§7.4.3.6.1–2，导语和前提 1–4，印刷页 80](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=81)。

**离网时，哪些消息在乙的终端保存？** 组内交换的 SDS 如果是供 MCData 用户使用的，就存入乙终端上的本地消息存储。这里按消息用途区分，并不要求乙已经打开消息。对于交给应用程序处理的 SDS，不能用这一步断言它也按同样方式保存，或断言它在别处一定没有保存。[§7.4.3.6.2，步骤 1–2，印刷页 81](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=82)。

**什么时候进入上传流程？** 离网组通信先结束，乙重新连上网络，随后决定把这次离网通信保留在**自己的消息存储账户**。这时，由乙的**消息存储客户端**从终端本地消息存储取出离网通信对象，上传到 MCData 消息存储。若只看到乙重连，既不知道乙作了什么决定，也不能断定已上传成功。为方便同步，可以在终端和本人账户两处预置存放离网通信对象的文件夹；这是可选安排，不能因为看到了这两个文件夹就认定已有对象传过去。[§7.4.3.6.2，步骤 2 后的注及步骤 3–5，印刷页 81](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=82)。

要核对上传请求的目标文件夹或响应是否报告成功，见[离网对象上传](offnetwork-object-upload.md)。若用户是晚加入正在进行的组会话，要查的是[服务器怎样替晚加入者保存此前的消息](late-group-conversation-history.md)，不是这里乙把自己终端上的对象传回账户。

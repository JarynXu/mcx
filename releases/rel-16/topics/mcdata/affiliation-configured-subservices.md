# 归属一个 MCData 组，短数据、文件分发和数据流要分别归属吗？

不用逐项归属。假设 G 的配置清单**只列短数据（SDS）和文件分发（FD）**。甲归属 G 时，两项都随之归属；数据流（DS）不在这次归属的范围内。若另一组的配置列有 DS，归属那组也就覆盖该组的 DS。判断依据是**该组配置的子业务清单**：组可配置一项或多项，清单须列入组配置数据。[3GPP TS 23.282 V16.8.0，Rel-16 Stage 2，§5.6 首段，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=20)。

**表 A.4-1 中，“为组启用的 MCData 子业务和功能”下的七行都是 Y/Y/Y，是这个组全开了吗？** 这是在网和离网共用的组配置表，不是某个组的配置导出。按列从左到右，Y 表示该行参数需要配置给 **MCData UE、MCData 服务器、组管理服务器**中对应的实体。例如“文件分发是否启用”一行的三个 Y，告诉你三方都需要这项参数，没有告诉你 G 填的是启用还是禁用。[§A.1 表列说明，印刷页 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=170)。

[§A.4，印刷页 178](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=179) 把这张表接到 TS 23.280 相应组配置表的 MCData 配置项下。在[表 A.4-1，印刷页 179](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=180)中，“为组启用的 MCData 子业务和功能”是父项，本身不取值。其下七个同级子项分别表示是否启用：短数据、文件分发、IP 连通、会话管理、发送控制、接收控制、增强状态。七行都是 Y/Y/Y。这是**子业务和功能**的混合清单；下一行“增强状态”已回到父项所在层级，不是第八个启用项。

**DS 没有单列，该怎么判？** 表 A.4-1 没有独立的“数据流是否启用”行；[§5.6 首段，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=20)却明确以 DS 为组可配置子业务的例子。只有制式表而没有 G 的配置时，G 是否启用 DS **未知**，不能填“禁止”，也不能拿 IP 连通或其他子项的值代填。若已取得明确完整的清单，则按清单判断，如开头的 G。

**归属后能做什么？解除归属又改变什么？** 已归属的用户可以选择该组发起相应的新消息、文件分发或数据流，接收参与子业务的通知、组邀请及相应的消息、文件、流或增强状态更新。这说的是服务应支持的行为，不是某项操作已获批或某个接收端已收件。[§5.6 三项服务要求，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=20)。

甲已归属 G，就可以收发 **G 的** MCData 媒体；甲解除 G 的归属后，就不能向 G 发送或从 G 接收这些媒体。只解除 G 不等于解除另一个组 H 的归属，也不是注销 MCData 或删除甲已存历史的动作。§7.2 在这里引用公共组归属程序：其中的客户端、服务器、组、业务 ID（MC service ID）、组 ID 分别对应 MCData 客户端、MCData 服务器、MCData 组、MCData ID、MCData 组 ID。[§7.2，印刷页 39](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=40)。

以下三个问题要换一篇读，依据仍是同一版 TS 23.282：

- 若问一次**在网 HTTP 组独立文件分发**中甲能否发这份文件、乙下载完了吗，查[本次发起权、文件大小与乙端完成记录](http-group-standalone-fd.md)（§7.5.2.6.2，印刷页 96–98）。
- 若问同组成员丙晚加入会话时怎样补短消息，查[无损通信组的代收与个人账户同步](late-group-conversation-history.md)（§§7.4.3.5.1–2，印刷页 79–80）。该例中**每位组成员都已开通自己的消息存储账户**；会话发起时，甲乙已注册并归属，另一台服务器服务的丙尚未归属。只知道丙有账户，或丙当时已经归属，均不能据这条例子认定服务器已替丙收件。
- 若只问**在网 MCData 服务支持哪些能力**，查[服务能力与功能角色](service-capability-and-functional-roles.md)（能力与功能，§§6.4.1、6.4.3.1.1–2，印刷页 23–24）。系统支持某项能力，不表示每个组都启用了它。

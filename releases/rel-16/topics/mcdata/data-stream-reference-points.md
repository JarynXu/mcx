# 在网 MCData 数据流：一份开始或停止报告，能证明谁发了命令、谁收全了数据吗？

不能。假设乙端通过 MCData-DS-1 报告「流 X 停止」。可以记下**乙端对 X 报告了停止**，不能据此写成「乙发出了停止命令」「服务器已停发」或「丙已收全 X」。反过来，这份报告也不能证明这些事没有发生。

这里讨论的是 Release 16 的[在网数据流（DS）应用面模型：TS 23.282 V16.8.0 §6.7.1 标题和首句，印刷页 34](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=35)。三个参考点连接终端客户端的 **DS 功能**与服务器的**数据流分发功能**：[§6.7.4.1.1 标题，印刷页 35](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=36)点名了 DS-1 两端的功能；[§6.7.1 图后第 2、3 项，印刷页 35](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=36)分别给出 DS-2 和 DS-3 的两端及流数据方向。判断一条记录，先看它传的是描述和报告、控制命令，还是流数据本身；再看是哪一端发、哪一端收。

**DS-1：报告说了什么？** DS-1 承载建立数据流会话的应用信令，也承载上下行单播的流下载报告；开始、停止都是报告的例子。该参考点还支持传流的元数据和 URL。发出了建会信令，不等于会话已经建立；发出了 URL，不等于已发出 URL 所指的流数据。核对报告时，要对上报告描述的终端和流。即便同时有乙对 X 的开始、停止两份报告，也不能把两个时点之间的内容逐段记为乙已收齐，更不能替丙确认。[§6.7.4.1.1 首段，印刷页 35](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=36)；[同条消息清单，印刷页 36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=37)。

**DS-2：发命令还是发数据？** 这条单播路径支持来自获授权终端的流控制，也传流数据。看到甲经 DS-2 发出一条控制命令，可以确认甲发出了这条命令，不能由此断定服务器已执行、数据已传，或另一端已经收到。对于**流数据**，方向很明确：终端 DS 功能发往服务器分发功能是上行，反向是下行。关于**控制**，功能清单有一项把「来自终端」与「下行」写在同一项启停描述中；不凭这一行替某条命令指定确切的起点、终点或报文名，要看该次操作本身的记录。[§6.7.1 图后第 2 项，印刷页 35](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=36)；[§6.7.4.1.2 首段及功能清单，印刷页 36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=37)。

**从服务器收到，到接收端收到，中间差什么？** 服务器分发功能经 DS-2 接收上行流；向使用单播的参与方分发时，按需复制，分别经 DS-2 下行单播。另一种分发方式是 **DS-3**：服务器分发功能向客户端 DS 功能下行组播流数据，不是终端向服务器上行组播。如果记录只写「服务器已从甲收到 X 的一段」，只能确认这段上行；还不能填写复制了几份、以哪种方式发给谁。如果随后确有服务器组播发出这一段的记录，就能再确认这次 DS-3 下行发送；要确认某端收到哪些内容，仍得有对应终端、流和内容范围的接收依据。[§6.7.3.1.2 分发功能四项，印刷页 35](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=36)；[§6.7.4.1.3 首段，印刷页 36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123282/16.08.00_60/ts_123282v160800p.pdf#page=37)。

若问哪种 MCData 能力允许在数据还没收全时就开始处理，查 [MCData 服务能力与功能角色](service-capability-and-functional-roles.md)。若判断的是在网文件分发中 FD-1 能否传某个小文件，查[文件分发参考点](fd-reference-points.md)；若比较的是在网短数据载荷与信令控制面 SDS 配置的上限，查[短数据参考点](sds-reference-points.md)。不要用这两种大小限制决定 DS 的流数据路径。

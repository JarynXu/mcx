# 离网 MCPTT：同一个组出现两通呼叫，已在通话的客户端选哪一通？

客户端不会因为后来收到一条公告，就改跟公告里的呼叫。它先确认这可能是**同组的另一通呼叫**，再按**呼叫类型、开始时间、呼叫标识**依次比较。这里说的是一个参加离网组呼的客户端收到合法的 `GROUP CALL ANNOUNCEMENT` 时的本地处理，不是服务器合并两条会话，也不是全组已经切换的证明。

**先确认比较对象。** 基本呼叫控制须已在 S3（已参加呼叫）。公告的 MCPTT 组 ID 要与本机保存的一致，而且**发起者的 MCPTT 用户 ID、呼叫标识（call ID）至少有一个不同**。同组同发起者也可能有另一通呼叫，只要 call ID 不同；若这两个标识都相同，即使公告类型不同，也不能走这里的合并分支。尚在探测、加入或维护同一通普通呼叫时，见[普通离网组呼](offnetwork-group-client.md)。[3GPP TS 24.379 V16.14.0，Release 16，Stage 3，§10.2.2.4.6.1，印刷页 331](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=332)。

**满足上述条件后，什么情况下改跟公告中的呼叫？**

1. **类型不同**：本机为普通组呼（BASIC），公告为迫近危险（IMMINENT PERIL）或紧急（EMERGENCY）；或本机为迫近危险，公告为紧急。紧急呼叫即使起得更晚、call ID 更大，在这三类中也优先。
2. **类型相同**：公告所载的呼叫开始时间早于本机保存的开始时间。比的是呼叫开始时间，不是公告到达时间，也不是最后一次变更类型的时间。
3. **类型和开始时间都相同**：公告的 call ID 数值更小，才改跟公告。若连 call ID 也相同，只有发起者不同，则通过了“另一通呼叫”的入口，却没有满足采用公告的任何一条。不能再拿发起者 ID 排大小。

以上都不满足，就没有依据按这两条合并程序替换本地呼叫；这不等于断言这条消息在其他程序中如何处理。[基本呼叫控制 §10.2.2.4.6.1，页 331](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=332)；[呼叫类型控制 §10.2.3.4.9，页 344–345](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=345)。

**选中后，基本呼叫控制更新的是哪一通？** 客户端须保存公告中的会话描述（SDP）、call ID、发起者 ID、刷新间隔和呼叫开始时间。它按新的 SDP 调整媒体会话，以**终接话权参与者**身份重新启动话权控制；然后先停再启最长通话时长计时器 TFG6，再先停再启呼叫公告计时器 TFG2，两者按各自被引用的规则取值。基本呼叫控制仍在 S3。重启话权控制不能当成本机已获发言权。[§10.2.2.4.6.1 动作 1–11，页 331](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=332)。

**类型控制另记什么？** 它与基本呼叫控制并行，在 T1（紧急）、T2（普通）或 T3（迫近危险）收到符合上述比较条件的公告时，须从公告保存**最后一次变更类型的时间、作出该变更的用户，以及当前呼叫类型**。这里记录的变更时间不是前面用来决胜的开始时间；变更用户也不必是呼叫发起者。[§10.2.3.1，页 332](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=333)；[§10.2.3.4.9，页 344–345](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=345)。

- **选中紧急呼叫**：须设置紧急组呼对应的 ProSe 逐包优先级；TFG14（迫近危险隐式降级）若正在运行就停止；TFG13（紧急隐式降级）若尚未启动才启动；进入 T1。如果 TFG13 已在运行，本条并不要求重新计时。
- **选中迫近危险呼叫**：须设置迫近危险组呼对应的 ProSe 逐包优先级；TFG14 若尚未启动才启动；进入 T3。本分支没有列出停止 TFG13 的动作。
- **选中普通呼叫**：仍须保存上述三项类型信息。该条在这三步后只为紧急和迫近危险另列分支，没有为普通类型另列优先级设置、计时器或转态动作。不能把另两种类型的动作套过来。[§10.2.3.4.9 动作 1–5，页 345](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=346)。

因此，本机同时记为 S3 和 T1（或 T2、T3）并不冲突：一个说明是否仍在参加呼叫，另一个说明呼叫类型。仅凭本机记录，不能断定其他成员收到了同一公告、完成了切换或收到了媒体。

# MCPTT 终端回到无线覆盖，怎样恢复 LMR 归属聊天组的媒体？

如果离开覆盖前用户已经在通话中，且回到覆盖时这场 LMR 归属聊天组呼仍在进行，恢复的是 **MCPTT 客户端与 IWF 之间的媒体面**。若当时有人持有话权，MCPTT 服务器还会向返回端转发 Floor Taken。本节没有重新办理组归属的步骤。这份占用通知也不表示返回用户获授话权。[§10.3.5.10 开头与前提，印刷页 67](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=68) [图 10.3.5.10-1、步骤 1–4 与注，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=69)

1. **检测返回。** 由 MCPTT 客户端或 MCPTT 服务器检测客户端回到覆盖。规范没有规定用什么信号或机制检测。[图 10.3.5.10-1、步骤 1–4 与注，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=69)
2. **重建媒体面。** MCPTT 客户端与 IWF 之间的媒体面通过媒体面控制信令重建。不能据此判断 SIP 用了哪条请求、路由，或是否新建了对话。[图 10.3.5.10-1、步骤 1–4 与注，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=69)
3. **核对当前占用。** 有人当前持有话权时，IWF 向 MCPTT 服务器发 IWF Floor Taken（3a），服务器再向返回的客户端转发 Floor Taken（3b）。如果当前无人持有话权，本节没有规定发送 Floor Idle 或其他替代消息。话权参与方继续使用话权控制（步骤 4）；不能据占用通知认定返回者已获话权。[图 10.3.5.10-1、步骤 1–4 与注，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=69)

图 10.3.5.10-1 的标题也写了“晚入”。这里的起点是同一位用户离开覆盖前已经在通话，不是用户刚归属后触发的[组归属触发的互通晚入](lmr-interworking-group-late-entry.md)。要核对是否办理归属，另查[LMR 定义组的归属](../groups/lmr-hosted-mc-affiliation.md)。本节不能回答本次聊天组恢复的 SIP ACK、Contact 或 Route；只有实际场景另为普通预安排组时，才用[普通预安排组的 SIP 重入条款](rejoin-late-entry.md)核对相应的 SIP 过程。

# 计费数据识别谁？在网、离网怎样区分，哪些信息要保密，谁能对账？

**计费数据须能识别参与一次通信的设备，不等于要识别谁来付款。** R-5.1.8-004 要求 MCX 业务生成这样的数据。若有多台设备参与，识别对象是这些设备；条款没有指定用哪个设备标识，也没有指定将数据发给谁。这里是 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）[第 5 章的在网、离网共用要求，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。[§5.1.8，R-5.1.8-004，印刷页 14](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=15)

**离网通信也要能生成计费数据。** R-5.1.8-010 要求业务能为在网模式生成计费数据，R-5.1.8-011 对离网模式提出同样的能力要求。前面 -004 说的是业务“须生成”可识别设备的计费数据，这两项说的是为各模式“须能生成”。不能由此认定终端在离网时写某种话单、恢复在网就上传或扣费。这两项没有指定在网或离网通信应采用哪种[计费方式](communication-charging.md)。[R-5.1.8-010、R-5.1.8-011，印刷页 14](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=15)

| 问题 | 业务须支持什么 |
| --- | --- |
| 什么计费要保密（R-5.1.8-005）？ | 服务提供方与网络运营商之间的计费须支持保密。这不是要求双方对彼此隐瞒计费。 |
| 谁的身份要保密（R-5.1.8-006）？ | 任务关键组织的身份须能保密。这里没列出向谁隐藏，也没有要求所有设备标识匿名。 |
| 哪两方对什么账（R-5.1.8-007）？ | 业务须支持服务提供方与网络运营商核对计费记录，本项未规定组织或终端用户核对自己的账单。 |

[R-5.1.8-005 至 R-5.1.8-007，印刷页 14](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=15) 所要求的是保密或对账能力，条款没有规定加密协议、谁先发送记录、多久核对一次，也不证明某次已结算。表 [A.1，印刷页 62](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=63)、[B.1，印刷页 73](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=74)、[C.1，印刷页 84](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=85) 的 §5.1.8 行均列出本页六个编号；MCPTT、MCVideo、MCData 均适用。

计费数据不等于审计日志。若问哪些参与者或传输内容需要留下记录，见[在网通信审计](../security/onnetwork-communication-recording-and-audit.md)；若问恢复在网后能取回什么审计元数据，见[离网审计元数据](../security/offnetwork-audit-metadata-retrieval.md)。后者的取回要求不能移作计费数据上传要求。

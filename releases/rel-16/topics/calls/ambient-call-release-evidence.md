# 在网按需 MCPTT 环境监听怎么停止？哪一路的 BYE/200 才能证明停止到哪一步？

终端没发 BYE，先查**本次呼叫的 Feature-Caps**；控制功能已发 BYE，先查**发给哪一方、谁回了 200**。下面只看已建立的在网按需环境监听呼叫如何停止，不用于建立呼叫或判断预建立会话的释放。[TS 24.379 V16.14.0 §§11.1.6.1、11.1.6.2.1.3、11.1.6.4.3，印 396、400、413](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=397)

## 用户点了停止，终端为什么可以不发 BYE？

先分清谁在听、谁被听，以及谁发起。听的一方可以发起释放；被听的一方只有在自己是本场发起人时，才在 §11.1.6.1 所列的用户发起释放范围内。按附录 F.1.3，`local-init` 是被听的一方发起，`remote-init` 是听的一方发起。不要把「呼叫发起方」当成固定的听方。[§11.1.6.1，印 396](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=397)；[附录 F.1.3 第 19(a) 项，印 549](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=550)

在客户端发起释放的入口，核对该客户端本场收到的 **SIP INVITE**，或它发出本场 INVITE 后收到的匹配 **SIP 200 (OK)**。只要适用来报的 `Feature-Caps` 带 `g.3gpp.mcptt.ambient-listening-call-release`，就有服务器声明能接收客户端释放 BYE 的证据。没有收到这个指示时，客户端必须跳过余下步骤；因此，确认来报完整却没有指示，就不能按这条程序要求终端发送 BYE。若只剩截断日志，尚不能判指示缺失。指示存在且走到释放程序时，客户端与媒体面交互，并在本场对话内发 BYE；指示本身不是发送或释放完成的证据。[§11.1.6.2.1.3，印 400](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=401)；[附录 D.3，印 543](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=544)

## 服务器主动停止，为什么第一路已经 200，第二路还没结束？

在 §11.1.6.4.3 的服务器主动释放流程里，控制 MCPTT 功能（CF）先按听方的 MCPTT ID、被听方的 MCPTT ID 和本场类型，找到要结束的会话。它先在**被听方**的对话发 BYE。收到与这一路 BYE 匹配的 200 后，才按本段生成带 `release-reason` 的 BYE，发往**听方**的对话。先收到的 200 只对应第一路，不是第二路的应答。要确认两路信令都结束，分别找两路 BYE 和对应的 200；要确认实际媒体停止，还须查媒体面记录。[§11.1.6.4.3，印 413–414](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=414)

### 定时器到期，为什么规范里有两个原因字符串？

同一固定版的写法不一致。§11.1.6.4.1 在私呼定时器到期时调用上述主动释放程序，并写明 `private-call-timer-expiry`；§11.1.6.4.3 给听方 BYE 列出的同一到期原因却是 `private-call-expiry`，附录 F.1.2 的 `releaseReasonType` 枚举和 F.1.3 的说明也用后者。不能把两串写成两个不同到期事件、说两串都通过本版 schema，或悄悄把一处原文改成另一处。排障时把私呼定时器到期记录、听方那一路 BYE 的原文和接收结果对上，保留实际看到的字符串。[§11.1.6.4.1，印 411](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=412)；[§11.1.6.4.3，印 413](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=414)；[F.1.2，印 546](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=547)；[F.1.3 第 19(b)(i) 项，印 549](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=550)

若会话是普通私呼，查[普通私呼客户端的挂断与回执](private-client-release.md)或[服务器触发的普通私呼释放](server-private-call-release.md)。本页的能力指示、两条对话的顺序和到期原因不能套到普通私呼上。

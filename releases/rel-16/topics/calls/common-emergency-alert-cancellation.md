# 取消紧急告警等于清除个人紧急状态吗？取消须分发给谁？

**取消个人业务紧急状态和撤销业务紧急告警，要分开判断。** 前者针对用户的状态，后者针对告警。两件事及告警取消的分发，分别见 [TS 22.280 V16.8.0 §5.6.2.4.2，-001 至 -003，印刷页 21](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=22)。

- **本机取消个人紧急状态（-001）。** MCX UE 提供的取消方式须限于本机，并只供**这台 UE 的获授权用户**使用。不能仅凭一名用户有业务撤警权，就认为他获准在这台终端取消个人状态。
- **取消业务紧急告警（-002）。** MCX 业务须支持**获授权的 MCX 用户**取消告警。本条没说只能由原发警者在原终端本机撤警，也没有规定具体的代撤权限怎么授予。
- **分发告警取消（-003）。** MCX 业务须把取消分发给**取消中标明的组的所有已归属成员**。例如，甲已归属这个组，但没有参加当前通信，他仍在分发范围内。乙只是组员，尚未归属这个组，不能只凭组员身份把他算进去。

本节没有规定按什么配置条件清除个人紧急状态，也没有规定清除个人状态和撤警必须联动，或紧急组通信何时恢复正常。单凭看到撤警，不能断定终端的个人紧急状态已取消、组状态已解除或所有已归属成员都收到了取消。

以上是 Release 16 的 Stage 1 要求，适用[第 5 章的在网和离网共用范围，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。[表 A.1（MCPTT），印刷页 63](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)、[表 B.1（MCVideo），印刷页 74](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)、[表 C.1（MCData），印刷页 85](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=86)均在 §5.6.2.4.2 的对应行列出三项。三表父标题 §5.6.2.4 行的 NA 不是这三项的适用性。

若问谁被授予在网代撤权限，查[在网紧急告警撤销](onnetwork-emergency-alert-cancellation-authorization.md)。若问离网组撤警怎样处理，按业务分别查 [MCVideo、MCData](offnetwork-group-emergency-alert.md)和 [MCPTT](offnetwork-mcptt-group-emergency-alert.md)。若要取消的是离网紧急组通信，查[离网紧急组通信](offnetwork-emergency-group-communication.md)。

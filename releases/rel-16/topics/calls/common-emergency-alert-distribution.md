# 紧急告警发给谁？组、紧急私通信和区域通知各看什么？

同一条告警所用的组、紧急私通信要找的人、配置的通知区域是三个不同的判断对象。3GPP TS 22.280 V16.8.0（Release 16，Stage 1）对前两种规定分发对象，对第三种要求业务让获授权的 MCX 用户能够配置通知。[§5.6.2.4.1，印刷页 20](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=21)

| 正在判断什么 | 该条要求发给谁 |
| --- | --- |
| 告警使用了一个业务组（R-5.6.2.4.1-004） | 须分发给**这次告警用到的组**的已归属成员。只有该组的成员资格，还不满足这里的归属条件。 |
| 针对 MCX 业务紧急私通信（R-5.6.2.4.1-004a） | 须分发给**这次紧急私通信发起所指向的 MCX 用户**。这里用通信目标判断收件人，不用组员名单，也不把发起人当成该目标。 |
| 配置按区域通知（R-5.6.2.4.1-005） | 业务须让获授权的 MCX 用户能够配置告警，就一名 MCX 用户进入业务紧急状态一事发送通知。接收人是**与这名进入紧急状态的用户相关联的可配置地理区域内的 MCX 用户**。这条区域通知不以业务组成员资格为条件。 |

例如，甲的告警使用 G 组。乙是 G 的已归属成员，丙是 G 的成员但尚未归属，丁不是 G 的成员。按 -004，须向乙分发，不因丙是组员就把他纳入这条要求。若甲发起的是指向丁的紧急私通信，丁属于 -004a 的分发对象。如果就甲进入业务紧急状态配置了区域通知，丁是与甲相关联的通知区域内的 MCX 用户，就不能只因丁不是 G 的成员而把他排除在 -005 的接收范围之外。这三条都不能证明丁已经收到通知。

配置者须获授权；与区域相关联的是进入业务紧急状态的用户。条文未要求两者是同一人，也没规定区域的中心、半径、划定方法或每次都启用这一配置。这里的区域用来确定谁在通知范围内，不是发警终端进区触发告警的条件。[§5.6.2.4.1，印刷页 20](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=21)

以上要求供[在网、离网共用，第 5 章标题，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。[表 A.1（MCPTT），印刷页 63](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)、[表 B.1（MCVideo），印刷页 74](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)、[表 C.1（MCData），印刷页 85](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=86) 的 §5.6.2.4.1 子行均列三项。-004a 在 -004 和 -005 之间占一个独立单元格，编号在格内折成两行，不是缺项。父标题行的 NA 不改变子行的适用性。

告警内的组 ID 怎么取，见[激活和告警内容](common-emergency-alert-activation-and-content.md)；要区分组员和已归属成员，见[成员资格、归属和所选组](../groups/group-membership-affiliation-and-selection.md)。若查具体流程，分别看[在网 MCVideo、MCData 的组告警下发](onnetwork-group-alert-location.md)、[在网 MCPTT 紧急私呼随呼告警](emergency-private-call-alert.md)及[发警终端进出预设区域的在网流程](emergency-alert-area-entry-exit.md)。这里的区域与进入业务紧急状态的用户相关联，用于筛选通知对象；最后一个流程的预设区域用于判断进出是否触发后续处理。

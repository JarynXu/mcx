# 个人紧急状态还在时，终端怎样发通信、应归属哪个组？

这里判断的是一名用户的 **MCX 业务紧急状态**，不是整个组的紧急条件。终端须掌握该状态，直至该状态取消（-006）。只看到一通组通信停止或一条告警结束，不能证明终端上的个人状态已取消。[§3.1，印刷页 10](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=11)

**状态还没在终端上取消，用户发起或继续发送组通信、私通信时怎么办？** -007 所说的是该用户发出的这两类传输：组通信传输为紧急组通信，私通信传输为紧急私通信。不能因为已经发过一次紧急通信，就把状态未取消期间的后续传输当作普通通信；也不能把另一名组员的传输一并改为紧急，或断言发起告警就建立了一次通信。

**终端向谁进行紧急通信？** -008 要求终端可配置紧急通信使用哪个组（用户所选组或专用紧急组）或哪个 MCX 用户。它没有指定谁来配置，也没有把通信目标等同于告警发往哪里。

**激活告警后，还要办理哪一个归属？** -009 看的是配置用于**紧急组通信**的组。终端激活一次紧急告警后，若尚未归属那个组，须立即归属；已经归属，不要求重做。假设告警目标是调度员，紧急组通信配置使用 G 组。判断是否需要立即归属，看的是 G 组，不是调度员。只开启告警能力、或等待收到告警回执，都不是本条所写的触发点。组归属也不等于把 G 组改成所选发送组、已参加某场通信，或证明某条消息执行成功。

依据 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）。短号均指 §5.6.2.4.1；这是在网、离网共用要求。[第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)；[§5.6.2.4.1，印刷页 20](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=21)。[表 A.1（MCPTT，印刷页 63）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)、[表 B.1（MCVideo，印刷页 74）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)、[表 C.1（MCData，印刷页 85）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=86) 的子条款行都列出本页各号；父标题 §5.6.2.4 的 NA 不是子条款的适用结论。

# MCPTT–LMR 互通私呼挂断：服务器要等谁回应？

MCPTT 终端发起时，服务器收到 IWF 确认后再回终端。LMR 经 IWF 发起时，服务器收到终端确认后再回 IWF。服务器发起时，MCPTT 终端和 IWF 各自确认服务器发给自己的请求。 这里说的发起方是**谁请求结束**，与原来的主叫是谁无关。

MCPTT 用户已为接收业务完成登记，正经 IWF 与 LMR 用户通话。私呼可用自动或手动方式开始，也可不启用话权控制。 这三节讨论已经建立、正在进行的通话，不讨论建立过程中取消。依据为 3GPP TS 23.283 V16.8.0（Release 16，Stage 2）§§10.4.4.1–.3。

| 谁发起结束 | 请求与回应 |
| --- | --- |
| MCPTT 终端 | 终端经 SIP 核心网向服务器发私呼结束请求。服务器向 IWF 发对应请求，按原请求指定的 MCPTT 客户端 ID 寻址。IWF 回服务器，服务器收件后再为终端的原请求生成响应。LMR 用户也会收到结束通知，本节未规定怎样通知。[图 10.4.4.1-1、步骤 1–2，印刷页 96](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=97)；[步骤 3–5 及注，印刷页 97](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=98)。 |
| MCPTT 服务器 | 私呼达到管理员配置的最长时长，或无收发达到允许时限，是两个触发例子。服务器经 SIP 核心网向终端发请求，也向 IWF 发对应请求；后者按与 LMR 用户关联的 MCPTT 客户端身份寻址。MCPTT 用户和 LMR 用户都会获通知。终端与 IWF 各向服务器回应各自收到的请求。一个回应不能替另一个，本节未规定两个回应谁先到。[图 10.4.4.2-1、步骤 1–2b，印刷页 97](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=98)；[步骤 3–4 及注，印刷页 98](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=99)。 |
| LMR 用户或系统 | IWF 向服务器发结束请求，服务器向原 IWF 请求指定的 MCPTT 终端发对应请求。MCPTT 用户收到通知，终端向服务器确认。服务器收到终端的确认后，为 IWF 的原请求生成响应。[图 10.4.4.3-1、步骤 1–4，印刷页 98](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=99)；[步骤 5–6，印刷页 99](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=100)。 |

三种流程均由 MCPTT 终端和 IWF 释放本次通话的全部媒体面资源；已建立话权控制时还释放话权资源，MCPTT 终端不能再为本次通话请求话权或发送媒体。 结束响应表明的是**对应请求**得到回应，单看它不能确认两端资源都已释放。本节没有定义线上报文的 SIP 方法、字段、状态码，或一侧不回应时如何处理。[§10.4.4.1 步骤 6，印刷页 97](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=98)；[§10.4.4.2 步骤 5，印刷页 98](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=99)；[§10.4.4.3 步骤 7，印刷页 99](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=100)。

若要查通话怎样用自动方式建成，读[互通私呼自动开始](lmr-interworking-private-auto-setup.md)。若要结束的是一场组呼，改查[宿主发起的互通组呼释放](lmr-interworking-group-release.md)。普通在网 MCPTT 私呼的 Stage 3 行为分别见[客户端结束](private-client-release.md)与[服务器结束](server-private-call-release.md)，不从这两页推定 IWF 的互通行为。

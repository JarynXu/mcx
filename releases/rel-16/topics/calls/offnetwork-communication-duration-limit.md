# 离网组通信与私通信的总时限怎样设，业务何时提醒参与者、释放通信？

离网时，**组通信和私通信的总时限可以分开设**。MCX 业务须给业务管理员提供预配置机制，不要求两个值一定不同。这里算的是一次通信的总时长，不是多久没发媒体。条款没有给默认值，也没有指定从哪个协议事件开始计时。[TS 22.280 V16.8.0（Release 16，Stage 1）第 7 章，印刷页 50](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=51)；[R-7.4-001，印刷页 53](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=54)。

| 何时 | MCX 业务须做什么 |
| --- | --- |
| 尚未到限，但已进入可配置的提前时段 | 向这次通信的参与者提示即将到限（R-7.4-002）。 |
| 达到总时限 | 向参与者提示时限已到（R-7.4-003），并释放这次通信（R-7.4-004）。 |

这里的参与者指当前在这次组通信或私通信中接收、发送或兼有两者的 MCX 用户；仅在组名册上，不能算作正在参与。到限时，**提示与释放都必须做**；条款没写两者的先后次序，也没要求等参与者确认才释放。看到提前提示不能判定已经到限，看到到限提示也不是哪一端已经完成释放的证据。[R-7.4-002 至 R-7.4-004，印刷页 53](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=54)；[§3.1 Participant，印刷页 11](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=12)。

**适用业务：** MCPTT、MCVideo、MCData 的规范性附表均在 §7.4 行列出全部四项。[表 A.1，印刷页 70](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=71)；[表 B.1，印刷页 81](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=82)；[表 C.1，印刷页 92](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=93)。

若查[离网 MCVideo 组通信因不活动而释放](../mcvideo/offnetwork-broadcast-inactivity.md)，判断的是持续无传输，不是总时长。若查[离网 MCPTT 私呼的释放消息与媒体清理](offnetwork-private-release-evidence.md)，看该业务的协议流程。另见[在网私通信的时长配置](onnetwork-private-termination-and-duration.md)；不能把在网条文的配置选项或某个终端的协议动作套用为 §7.4 的要求。

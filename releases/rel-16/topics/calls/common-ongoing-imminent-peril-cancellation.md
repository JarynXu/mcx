# 谁能取消组的进行中迫近危险状态？管理员的授权与准则有何区别？

**不只发起者能取消。** MCX 业务须支持获授权用户取消组的进行中迫近危险状态，也须支持迫近危险组通信的发起者取消这一状态。仅有组成员资格、已归属该组，或获准发起迫近危险通信，都不能代替取消授权。依据是 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）在网与离网共用的 [§5.6.2.3.2，印刷页 20](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=21)；工作模式见[第 5 章标题，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。

| 判断什么 | 业务要求 |
| --- | --- |
| 获授权用户（R-5.6.2.3.2-001） | 业务须让获准取消的 MCX 用户取消该状态，没有将这项权限限于发起者。 |
| 管理员授予权限（R-5.6.2.3.2-002） | 业务须提供机制，让 MCX 业务管理员授权 MCX 业务用户取消。管理员可以授予权限，不等于已经授权，也不等于必须亲自取消。 |
| 迫近危险组通信的发起者（R-5.6.2.3.2-003） | 业务须支持这名发起者取消进行中迫近危险状态。原有普通组通信的发起者不一定是这里所指的人；本节没有规定如何识别发起者，也没有规定这一项如何与管理员授权衔接。 |
| 管理员设定的准则（R-5.6.2.3.2-004） | 管理员规定的取消准则满足时，业务须支持取消。这里没有举超时为例，也没有规定定时器或必须自动取消。 |

**取消的是迫近危险状态。** 不能据此认定组已解除紧急状态、个人业务紧急状态已复位、独立告警已撤销或呼叫已释放。本节也没有规定取消要通知谁、是否带取消者身份，不能照搬紧急组状态的取消条款。若要查发起、升级或何时调整组的迫近危险优先级，另看 §5.6.2.3.1；这里回答的是谁能取消、什么条件满足时须能取消。

MCPTT、MCVideo 和 MCData 均适用。[表 A.1，印刷页 63](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)、[表 B.1，印刷页 74](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)、[表 C.1，印刷页 85](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=86) 的 §5.6.2.3.2 行逐项列出四个编号，父标题行的 NA 不覆盖子条款。

若问取消通知和他人取消后的发起端状态，按[第 7 章离网迫近危险组通信](offnetwork-imminent-peril-group-communication.md)所列业务适用性查。要判定一次实际取消，按工作模式和业务读[在网 MCPTT 已有组呼的迫近危险取消](onnetwork-imminent-peril-cancellation.md)、[在网 MCVideo 迫近危险升级和取消](../mcvideo/imminent-peril-upgrade-cancel.md)、[离网 MCVideo 组状态](../mcvideo/offnetwork-emergency-group-states.md)或[在网 MCData 组 SDS 或组文件分发](../mcdata/group-imminent-peril-sds-fd.md)的相应程序。

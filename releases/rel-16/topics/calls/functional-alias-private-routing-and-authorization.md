# 按位置找私通信接收方时怎样用功能别名？发出和接收各看哪张表？

**按位置选接收方，与谁有权通话，是两个判断。** 受理 MCX 私通信请求时，如果接收方取决于 MCX 用户的当前位置，业务须让管理员能定义一个关联了地理区域的功能别名。这个别名可再与用户关联，用于位置相关通信的路由（-019）。条文没说这里的位置取自发起者还是其他用户，也没规定多个区域重叠或查不到位置时怎么选。位置能帮助选择接收方，不能代替私呼授权。

**对登记到别名 A 的用户，发出和接收是两个方向。**

| 要判断什么 | 管理员可配置的集合 |
| --- | --- |
| A 一侧的用户能向哪些别名发起无话权控制私通信（-020） | 本管理权限范围内可打往的**目标别名**。 |
| 哪些别名能向 A 一侧的用户发起无话权控制私通信（-021） | 本管理权限范围内允许打入的**来源别名**。 |

例如，给别名 A 配了可打向 B，不表示 A 允许接收 B 打来的私通信。要判断 B 打 A，要看 A 的入向来源。条文不规定两侧名单怎样合并或哪一条优先，也不把别名登记等同于某个 SIP 注册动作。印刷页 23 的 -020 方括号前确有一个点；方括号中的编号仍是 `R-5.9a-020`。

**打给功能别名的私呼按哪一套授权？** -022 要用 §5.9a.2 的授权替代 §6.7.3 所定义的授权，不是把两套名单叠加。条件是**被叫为功能别名**。仅因主叫在使用一个别名，不能把替换套给所有私呼。-020 和 -021 的无话权控制条件仍属于这两项自身。[§6.7.3，印刷页 38（仅作授权对照）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=39)

3GPP TS 22.280 V16.8.0（Release 16，Stage 1）第 5 章是在网、离网共用要求，不是信令过程。[第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)；[§5.9a.2，印刷页 23](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=24)。

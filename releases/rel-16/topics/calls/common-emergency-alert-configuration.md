# 紧急告警怎样提示、发往哪里？能否自动触发紧急组通信？

“声音还是视觉提示”“把告警发到哪个组或用户”“发起告警时要不要连带触发紧急组通信”，是三个不同的设置。

| 要设置什么 | 谁能设置，业务须支持什么 |
| --- | --- |
| 用户怎样获知收到的告警（-010） | 业务须让 **MCX 业务管理员**能够配置用户获知入站紧急告警的方式，例如视觉或声音。 |
| 自己怎样获知收到的告警（-011） | 业务也须让 **MCX 用户**在业务策略约束下配置自己的提示方式。 |
| 用户发出的告警使用哪个组或用户（-012） | 业务须让 **MCX 业务管理员**能为该用户配置所选组、专用紧急组或一个 MCX 用户。调度员是用户目标的例子。 |

声音和视觉只是例子，不要求全部启用，也没有写管理员配置与用户设置冲突时的覆盖顺序。用户能为自己选择提示方式，不等于能改别人的提示或改告警发往哪里。向调度员发告警，也不能据此认定紧急组通信改为私通信，或终端无需归属已配置的紧急组通信组。

**发起告警是否还自动触发紧急组通信？** -013 要求管理员能配置是否联动；该项原文称配置者为 `MCX Administrator`。这里是**发起告警 → 紧急组通信**。没有给出默认选项，不保证某次联动成功建立通信。紧急组通信的发起也可能触发告警，但那是相反方向的另一条要求，不能用来规定本联动。[§5.6.2.2.1，R-5.6.2.2.1-002，印刷页 18](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=19)

以上要求不指定配置信令、告警报文或回执，也不能根据终端响了、转入紧急状态或发送了一条告警，就断定某个组成员实际收到了。

依据 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）。短号均指 §5.6.2.4.1；这是在网、离网共用要求。[第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)；[§5.6.2.4.1，印刷页 21](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=22)。[表 A.1（MCPTT，印刷页 63）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)、[表 B.1（MCVideo，印刷页 74）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)、[表 C.1（MCData，印刷页 85）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=86) 的子条款行都列出本页各号；父标题 §5.6.2.4 的 NA 不是子条款的适用结论。

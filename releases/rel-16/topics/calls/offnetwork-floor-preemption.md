# 离网话权抢占：正在发言的终端怎样判定并交出话权

在已建立话权会话的离网 MCPTT 组呼中，正在发言的终端是临时话权仲裁者。本文从该终端处于 `O: has permission`、实际收到另一成员的 Floor Request 开始，覆盖请求指示和当前呼叫类型可判为普通（normal）、迫近危险（imminent peril）或紧急（emergency）的情况。不讨论呼叫如何升级、在网服务器撤销、多发言者或尚在争取自己话权的终端之间如何竞争。

## 请求里的数字大，不一定能抢占

仲裁者先计算请求的数值优先级。Floor Priority 字段存在时，取字段值、请求者在该组的 `UserPriority`、服务配置的 `NumLevelHierarchy` 三者的最小值。缺少 Floor Priority 字段时，用允许的最小值 0。这个缺省只用于数值，不替 Floor Indicator 判定呼叫类型。

仲裁者看请求的 Floor Indicator 所指示的类型，再决定是否进入数值比较：

| 请求指示 \ 当前呼叫类型 | 普通 | 迫近危险 | 紧急 |
| --- | --- | --- | --- |
| 普通 | 比较数值 | 不抢占 | 不抢占 |
| 迫近危险 | 抢占，不比数值 | 比较数值 | 不抢占 |
| 紧急 | 抢占，不比数值 | 抢占，不比数值 | 不抢占 |

需要比较时，基准是**授予当前讲者话权时确定的有效优先级**。请求经取最小值后的结果必须高于基准；等于或低于基准不抢占。例如，普通请求携带 7，请求者组配置为 3，服务配置为 5，当前讲者获准时的有效优先级为 3：用 3 比 3，不抢占。该例若只把请求者组配置改为 4，就用 4 比 3，按此规则须抢占。若请求指示和当前呼叫类型同为紧急，不进入这个比较，不能凭较大数值抢占。

对不抢占的请求，优先级条款按组配置 `QueueUsage` 分流。持有者的实际排队或拒绝还要按 §7.2.3.5.4 检查请求的 Floor Indicator/F-bit 和队列容量，见[普通离网话权的持有者仲裁](offnetwork-floor-participant.md)。不把同优先级但 SSRC 更大的待申请者竞争规则套给现任讲者。

依据：TS 24.380 V16.9.0 §4.1.1.5、§7.1、§7.2.1.2、§7.2.3.5.1/.4、§8.2.3.2，印刷页 21–22、119–121、128–129、149。

## 判为抢占后，旧讲者请求停止 RTP 并等待接管

收到的请求满足抢占条件时，旧仲裁者须停止仍在运行的 T206 和 T207，请求本机 MCPTT 客户端停止向其他客户端发送 RTP，然后向其他话权参与者发送 Floor Granted。该消息的 User ID 使用请求者的 MCPTT ID。组配置 `QueueUsage=true` 时，还随消息带现有排队者的 ID、SSRC、队列位置和优先级。旧仲裁者启动 T205、将 C205 初始化为 1，把本地保存的当前仲裁者 SSRC 设为获准者的 SSRC，进入 `O: pending granted`。这个分支直接授予，不以旧讲者先收到在网 Floor Revoke 为前提。

发出 Floor Granted、更新本地 SSRC，都不是对方已开始发媒体的证据。§7.1 以获准客户端实际开始发送媒体作为它成为新仲裁者的条件。旧终端的本地观察是：它在 `O: pending granted` 实际收到 RTP，且包的 SSRC 与已保存的当前仲裁者 SSRC 一致。此时它须请求本机播放这些包，停仍在运行的 T205/T233，启动 T203，转入 `O: has no permission`。这只说明本机收到匹配的 RTP 并执行该分支，不能证明所有听众都收到或听到。重发及等待期满见[普通离网话权的交接](offnetwork-floor-participant.md)。

报文编码有一处需要单独核对：§7.2.3.5.7 第 4b 项把请求者的 SSRC 指到 `SSRC of floor control server` 字段；§8.2.5 把 RTCP 头部 SSRC 定义为离网仲裁者的 SSRC，并另列获准者 SSRC 字段。本页保留这两处写法，不据此给出完整报文，或用报文字段替代上述本地 RTP 判断。

依据：TS 24.380 V16.9.0 §7.1、§7.2.3.5.7、§7.2.3.7.1/.2、§8.2.5 及表 8.2.5-1，印刷页 119、131、138、162–163。

# 单播 MCPTT 组呼：从 MBMS 收到“进行中”，能确认什么？

能确认的是：服务器报告**这个组有组呼正在进行**。例如，甲已归属 G 组，准备晚入该组的聊天组呼。甲通过多媒体广播组播业务（MBMS）收到 G 组的“进行中”，可以据此决定要不要加入。通知没有说服务器已准许甲加入，更没有说甲已经入会。准备重入呼叫的已归属客户端也可以这样使用组状态。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.7.3.13，印刷页 146](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=147)。

**组呼建立时用的承载，和通知走的承载，可以不同。** 这项程序说的是以单播承载建立的 MCPTT 组呼；服务器可以用 MBMS 承载告知组状态。即使甲确实从 MBMS 收到了通知，也不能据此把通话媒体记为“已切到 MBMS”。反过来，没收到通知不等于没有组呼：服务器并非必须用 MBMS 告知状态。[§10.7.3.13，首句，印刷页 146](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=147)。

**把组 ID 和状态一起读。** 这条信息从服务器发给客户端。表 10.7.2.12-1 把两项都列为必填：MCPTT 组 ID 标明说的是哪个组，组状态说明该组有无正在进行的组呼。所以收到“H 组无进行中的组呼”，只说明服务器对 H 组作了否定报告；若 G 组没有记录，G 组的状态仍不能从这条消息判断。[§10.7.2.12，表 10.7.2.12-1，印刷页 121](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=122)。

如果问题是“客户端该监听哪条承载”，查[MBMS 承载通告与撤告](../bearers/mbms-bearer-announcement.md)。如果要核对普通在网按需预安排组重入时的准入处理，查[预安排组重入与晚入](rejoin-late-entry.md)；该页不是聊天组晚入的流程。这里的组状态通知条款点名 MCPTT，不能据此推定 MCVideo 或 MCData 也有相同规则。[结构化条件与声明](mcptt-mbms-group-status.json)。

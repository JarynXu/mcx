# MCPTT 和 LMR 的互通组呼已开始，另一侧的用户怎样晚入？

**互通组呼正在进行，参与侧成功完成组归属，才触发这里的晚入流程。** 只发出归属请求不能算成功归属；成功归属也不能代替晚入完成的证据。每名用户是否会触发图中的跨 IWF 流程，要看组是哪一侧定义的，以及下文所列的适用情况。先查组是由 MCPTT 系统还是由陆地移动无线电（LMR）系统定义。这个区别决定互通功能（IWF）和 MCPTT 服务器中谁发呼叫请求、谁报告当时的话权状态。一般条款的附注说明流程适用于各种组呼，例如紧急组呼、紧迫危险组呼和广播组呼。[3GPP TS 23.283 V16.8.0，Release 16，Stage 2，§10.3.3.7.1 及附注，印刷页 46（PDF 第 47 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=47)。

两图都以 MCPTT 服务器与 IWF 已知互通组信息、IWF 已配好两侧组和用户标识映射为前提。两节的注 1 把跨系统信令的身份转换和协议翻译交给 IWF，并未规定 LMR 无线侧消息。[§10.3.3.7.2 前提与注 1，印刷页 46](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=47)；[§10.3.3.7.3 前提 1，印刷页 47](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=48)；[前提 2、3 及注 1，印刷页 48](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=49)。

## 组定义在 MCPTT：电台用户加入进行中的呼叫

第一名 LMR 用户归属时，**IWF 代表归属和逐人转达归属**两种方式都适用。随后有 LMR 用户归属同一个组时，本条流程只在 IWF 把各人的归属逐人转达时触发；第二名用户即使已在 LMR 本地归属，只用代表归属且未逐人转达时，也不触发这条跨 IWF 流程。条款不裁定 LMR 本地会不会让第二名电台用户加入。[§10.3.3.7.2 适用范围及首人示例前提，印刷页 46](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=47)。

图中已有两名 MCPTT 用户在呼叫中。满足上面的适用条件，且 IWF 向 MCPTT 服务器办理组归属成功后，**MCPTT 服务器发起晚入并向 IWF 发组呼请求**。IWF 回送组呼响应，确认这份请求；下一步才记载 **IWF 和 LMR 用户加入**正在进行的呼叫。原有的 MCPTT 用户**可以**收到新用户加入的通知，通知不属于必须用来确认晚入的回执。IWF 怎样把呼叫请求送给 LMR 系统不在本条范围。[图 10.3.3.7.2-1、步骤 1–5 与注 2，印刷页 47](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=48)。

加入后，若话权在另一名用户手中，**MCPTT 服务器 → IWF** 发 IWF Floor Taken（6a）；若没有任何一方持有话权，发 IWF Floor Idle（6b）。消息说明当时占用或空闲，不是授予新加入者话权。[§10.3.3.7.2 步骤 6a、6b，印刷页 47](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=48)。

## 组定义在 LMR：MCPTT 用户加入进行中的呼叫

图的起点是**只有 LMR 用户**在通话；它画的是第一名 MCPTT 用户归属并晚入。正文明确同一流程也适用于后续 MCPTT 用户归属同一个组。因此“原呼叫只有 LMR 用户”是首人示例的前提，不能用来否定后续用户进入。[§10.3.3.7.3 适用范围，印刷页 47](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=48)；[前提 3 和图 10.3.3.7.3-1，印刷页 48](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=49)。

MCPTT 用户归属该组后，**IWF 向 MCPTT 服务器发组呼请求**。服务器先为这名新归属用户的客户端发起建呼流程，并在建呼成功后向 IWF 回组呼响应作确认；接着图文记载该客户端加入正在进行的组呼。IWF 怎样把归属送到 LMR 系统、LMR 系统怎样办理晚入不在本文所引流程的范围。[图 10.3.3.7.3-1、步骤 1–5 与注 2，印刷页 48](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=49)。

加入后，**IWF → MCPTT 服务器** 发 IWF Floor Taken 或 IWF Floor Idle（6a、6b），分别对应另一用户已获话权或无人持有话权；**MCPTT 服务器 → 新归属客户端** 再发相应的 Floor Taken 或 Floor Idle（7a、7b）。第二跳转达的是话权状态，不代表新加入者取得话权，也不能凭它认定 MCPTT 服务器重新做了仲裁。[§10.3.3.7.3 步骤 6a–7b，印刷页 48](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=49)。

判读记录时，把**归属结果、互通组呼响应、加入结果和话权状态**分别核对。两图给出功能步骤顺序，不据此确定第一包媒体何时发送或语音已送达；本页不展开编解码条件、SIP 映射、接管或终端发言许可。若查的是[代表归属和逐人归属本身](../groups/mc-hosted-lmr-affiliation.md)、[有竞争请求时谁做话权仲裁](../media/lmr-interworking-group-floor-arbitration.md)，或[普通 MCPTT 预安排组的 Stage 3 重入](rejoin-late-entry.md)，分别读相应主题。

# 在网隐蔽监听：授权针对用户还是业务组，对方的传输也算吗？

隐蔽监听（discreet listening）接收的是**指定用户的业务通信，或指定业务组的传输**。即使获准接收某位用户的通信，与该用户通信的其他人也不会因此成为独立的监听对象。

| 授权范围内的对象 | 业务须让获授权的 MCX 用户接收什么 |
| --- | --- |
| 某一指定用户的私通信 | 发给该用户和该用户发出的私通信传输。[R-6.15.1-001，印刷页 45](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=46) |
| 某一指定用户的组通信 | 发给该用户和该用户发出的组通信传输。[R-6.15.1-002，印刷页 45](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=46) |
| 某一指定业务组 | 来自该组的组传输。这一项没有授予接收组员私通信的权限。[R-6.15.1-004，印刷页 46](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=47) |

**与目标用户通信的其他人呢？** 如果对方本身不是监听对象，业务须允许配置为不向听方提供**对方发出**的传输。该配置受监管限制和运营商安全策略约束。条文要求能够作此配置，没有指定默认值，也没有把目标用户自己发出的传输一起排除。[R-6.15.1-003，印刷页 46](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=47)

**谁不应察觉？** 业务须使目标用户或目标组的成员，以及所有其他未获授权的 MCX 用户，不受可察觉的影响，也不知晓这项监听。[R-6.15.1-001a，印刷页 45](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=46) 条文后的[注，印刷页 46](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=47)说明，启用权限可能涉及多层授权，其层级不由 3GPP 规定；这不是一项新增的审批要求，也不是授予实际监听权限。

这些是[TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)的在网要求。规范性表 [A.1（MCPTT），印刷页 68](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=69)、[B.1（MCVideo），印刷页 79](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=80)、[C.1（MCData），印刷页 90](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=91) 在 §6.15.1 下均列出这五项。这里说的是业务传输；从终端所在处向听方单向传送信息，则是[环境监听](onnetwork-ambient-listening.md)。

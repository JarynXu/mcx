# 谁能远程发起或终止从另一位用户终端开展的 MCX 通信？下行拉取又是谁发给谁？

这里的**远程发起**是让另一位用户的 MCX 终端发起通信，不是让请求者自己的终端发起。3GPP TS 22.280 V16.8.0（Release 16）的概述指出，远端终端可自行发起，不需要该终端的用户亲自按键发起；调度员是获授权用户的例子，不是唯一角色。下面只读 Stage 1 的业务要求。[§5.21.1.1，印刷页 28（PDF 第 29 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

## 把请求、访问决定、发起和终止分开

| 想做什么 | 业务须提供什么机制 |
| --- | --- |
| 让另一位用户的终端发起私聊或组通信 | 让**获授权的 MCX 用户**远程发起从另一位用户的 MCX 终端开展的私聊或组通信。[R-5.21.1.2-001，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。 |
| 请求另一位用户的终端启用组通信 | 让**获授权的 MCX 用户**请求从另一位用户的 MCX 终端远程启用组通信。发出请求不等于已经启用。[R-5.21.1.2-002，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。 |
| 决定是否允许访问从自己终端开展的组通信 | 让**获授权的 MCX 用户**接受或拒绝对从其本人 MCX 终端开展的组通信的访问。[R-5.21.1.2-003，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。 |
| 请求把通信发到 MCX 终端（下行拉取） | 让一个 MCX 用户向**获授权的 MCX 用户**提出请求，请对方向 MCX 终端发送 MCX 通信，例如视频或数据。这次发送的目标是 MCX 终端。条款没有指定发送内容要来自哪里。[R-5.21.1.2-004，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。 |
| 终止从另一位用户终端开展的私聊或组通信 | 让**获授权的 MCX 用户**远程终止从另一位用户的 MCX 终端开展的私聊或组通信。对象是通信，不是单独一路视频。[R-5.21.2.1-001，印刷页 29（PDF 第 30 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。 |

远程启用请求和终端用户接受或拒绝访问是两项能力。条款没有把它们定成每次远程发起都要串行完成的一笔事务，也没有规定提示时机。下行拉取一项明列获授权的是**被请求发送**的一方；不能从该项认定请求者已通过所有适用的权限检查。机制存在不等于请求已获准、通信已发起或已终止，也不证明取得了媒体。概述中的使用场景不授予不限目标、时段或范围的访问权。这些条款不规定授权策略、协议、信令结果或部署支持。[§5.21.1.1，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)；[§§5.21.1.2、5.21.2.1，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。

## 别把 MCPTT 的两项适用结论合并

**MCVideo 和 MCData** 的表 B.1、C.1 列出以上五项。**MCPTT** 的表 A.1 对 §5.21.1.2 标 **NA**，却列出远程终止的 **R-5.21.2.1-001**。不能把远程发起部分的 NA 扩大到远程终止，也不能由 NA 否定其他条款或规范定义的 MCPTT 过程。同版在网要求另见[§6.15.3.2，印刷页 47](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=48)；不将其条件并入本节。[MCPTT，表 A.1，印刷页 65](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=66)；[MCVideo，表 B.1，印刷页 76](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=77)；[MCData，表 C.1，印刷页 87](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=88)。

若问题是 MCPTT 如何传送[远程发起私呼](remotely-initiated-private-call.md)或[远程发起组呼](remotely-initiated-group-call.md)的请求和结果，分别查 TS 24.379 的程序，不把它们当成本页 Stage 1 的实现映射。若查 MCVideo，区分[一对一视频推送](../mcvideo/one-to-one-video-push.md)与[只远程结束某一路视频](../mcvideo/end-transmission-sender-server.md)。建呼消息或单路视频停发的答复，不能直接代替对这里的通信是否已发起、终止的判断。

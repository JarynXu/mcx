# 组通信开始后，已归属但缺席的人与刚归属的人怎样加入？

**甲原已归属，只是建呼时没参加；乙也是组成员，但在这场通信开始后才归属该组。** 只要这场通信还在进行，甲变得可用时，业务**须尝试把甲加入**；乙在通信进行中归属该组，业务**须把乙加入**。-004 要求尝试，不保证甲成功加入；对乙，-005 不能改写成“尝试即可”。后者也不是乙已经收到媒体的证据。[3GPP TS 22.280 V16.8.0（Release 16，Stage 1）R-5.3-004、R-5.3-005，印刷页 15（PDF 第 16 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=16)

§5.3 面向在网和离网。业务须提供一种机制，让**已归属该组的成员**能够加入正在进行的组通信（-001）。例如，甲在建立时暂时失去覆盖，或正参加更高优先级的通信，都可能导致原通信先在缺少甲的情况下继续。-004 的条件是通信仍在进行且甲变得可用，不要求甲重新归属，也没有规定先由哪一方发消息。[第 5 章标题，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)；[R-5.3-001、R-5.3-004，印刷页 15](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=16)

**迟入的终端应得到谁的信息？** 对象是这场通信中**正在发送的组成员**，不一定是建呼发起人；信息由业务提供给**迟入的 MCX 终端**，方向不是迟入者向原有成员通告自己。

| 信息 | 提供条件 |
| --- | --- |
| 正在发送的组成员的身份、MCX 业务组的身份 | 须提供这两项；不以别名或组织身份是否可得为条件。 |
| 正在发送的组成员的别名、任务关键组织的身份 | 可获得时须提供。-002 没有要求在此提供组别名。 |
| 正在发送的组成员的位置信息 | 受权限约束（-003）。加入通信本身不能当作位置披露许可。 |

[R-5.3-002、R-5.3-003，印刷页 15](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=16)。本节没有规定由哪个节点发现成员可用、邀请或应答报文、重试周期，也不能据此断定某台终端已经接收或呈现了媒体。

**适用业务：** 规范性表 [A.1（MCPTT，印刷页 62）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=63) 与 [B.1（MCVideo，印刷页 73）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=74) 在 §5.3 行均列出全部五项。[表 C.1（MCData，印刷页 84）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=85) 将该行标为 **NA**；不能援引这五项要求 MCData，也不能据此断言 MCData 禁止迟入。

要查具体的在网预安排组呼，分别读 [MCVideo 的服务器邀请与客户端重入（Stage 2）](../mcvideo/prearranged-late-entry-rejoin.md)或 [MCPTT 的定向重入与服务器晚入（Stage 3）](rejoin-late-entry.md)。这两页按各自业务和进入条件使用，不能用其中一种流程解释所有 §5.3 场景。若问题发生在组通信刚建立时，见[建立提示、参与者类型与发送内容源](common-group-transmission-and-setup.md)。

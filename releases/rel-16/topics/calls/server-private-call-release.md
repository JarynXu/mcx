# 在网 MCPTT 私呼：没人按挂断，服务器什么时候必须结束通话？

先看这通私呼是否使用**话权控制**。这里说的是呼叫采用哪种模式，不是此刻有没有人持有话权。无话权控制的私呼只能由 MCPTT 客户端发起结束；不能把服务器主动结束的规程套到它上面。以下讨论有话权控制的在网私呼。依据：[3GPP TS 24.379 V16.14.0（Release 16，Stage 3），§11.1.4.1 注，印刷页 390](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=391)。若还不知道呼叫模式，见[怎样识别无话权控制私呼](private-no-floor-control-identification.md)。

## 三种情况，有一种就够

控制 MCPTT 功能（CF）遇到以下**任一项**，就必须释放这次私呼的 MCPTT 会话：

1. CF **收到媒体面发来的指示**，得知 T4 不活动定时器已经到期。某个用户听不到声音，并不等于 CF 已收到这个指示。
2. 这次私呼会话的持续时间**超过**私呼的最长时长。恰好等于上限，不满足这一项。
3. 这次会话只剩一名参与者，或者已没有参与者。数的是仍在这次会话里的人，不是正在说话的人。

例如，仍有两人在通话，且没有 T4 到期报告，只要通话已超长，CF 也必须释放。反过来，只有一段静音记录，不能认定必须因 T4 结束私呼，更不能认定通话已经结束。[§6.3.8.2 第 1–3 项及结句，印刷页 136](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=137)。这段条文没有给出统一的秒数。

## 谁发起，谁只是处理收到的请求？

按上述策略需要释放时，§11.1.4.3.1（起始侧参与 MCPTT 功能，PF）和 §11.1.4.4（CF）都引用 §6.3.3.1.5 的发送 SIP BYE 规程。释放义务由 §6.3.8.2 赋予 CF；两个角色条款引用同一规程，不等于要为同一端编排两次独立挂断。[§§11.1.4.3.1、11.1.4.4，印刷页 390](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=391)；[§6.3.3.1.5，印刷页 106](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=107)。

**按需私呼。** 终接侧 PF 收到 CF 的 SIP BYE 后，先通过媒体面释放与 CF 的这段 SIP 会话相关的媒体资源，再生成 BYE，发给客户端。客户端实际收到私呼 BYE 后，与媒体面交互，向服务器回 200 (OK)。终接侧 PF 收到客户端对自己所发 BYE 的 200 后，才向 CF 应答原来的 BYE，随后通过媒体面释放与客户端这一段 SIP 会话相关的媒体资源。只看到 PF 已发请求，不证明客户端已收到；也不能从客户端收到 BYE 反推出是谁发起了整次挂断。[§§11.1.4.2、11.1.4.3.2.1，印刷页 390](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=391)；[§6.3.2.2.8.1，印刷页 102](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=103)；[§6.2.6，印刷页 61](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=62)。

**使用预建立会话的私呼。** 必须同时知道：终接侧 PF 已收到 **CF 的 SIP BYE**，且该 MCPTT 会话 ID 指向一名**与这个 PF 有预建立会话的用户**。这时 PF 按 §11.1.3.2.2.2 处理：断开面向 CF 的媒体资源，向 CF 回 200，再断开客户端侧与 CF 侧媒体资源之间的连接，**保留面向该客户端的预建立会话**。这里的 200 来自 PF，不是客户端确认已收到 BYE。仅知道某人有预建立会话，却无法对应本次 BYE 的会话 ID，不足以套用这条保留规则。[§11.1.4.3.2.2，印刷页 390](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=391)；[§11.1.3.2.2.2，印刷页 389](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=390)。若挂断是用户要求的，见[客户端发起私呼释放及共用的接收侧处理](private-client-release.md)。

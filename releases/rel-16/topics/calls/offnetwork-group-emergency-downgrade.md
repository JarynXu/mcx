# 进行中的离网紧急组呼怎样降级、恢复普通？

`GROUP CALL EMERGENCY END` 结束的是**紧急模式**，不是整通组呼。以下限 3GPP TS 24.379 V16.14.0（Release 16，Stage 3）：终端已参加进行中的离网 MCPTT 组呼，基本呼叫控制在 S3，类型控制在紧急状态 T1。类型控制与基本呼叫控制并行；本机转到 T2，表示本机按普通组呼处理这通既有呼叫。它不能证明其他终端也已降级，或话权、语音收发已改变。[§10.2.3.1，印刷页 332](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=333)；[§10.2.3.3.2–3，印刷页 334](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=335)；[§15.1.15.1，印刷页 484](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=485)。

## 用户解除紧急：谁能发 END，TFG11 为什么还会重传？

终端在 T1，收到用户要将该呼叫降级的指示。指示可来自**把这通呼叫升级的用户**，也可来自另一名获授权、用户配置档中 `/<x>/<x>/Common/MCPTTGroupCall/EmergencyCall/CancelMCPTTGroup` 为 true 的用户。原呼叫发起者并不因发起了呼叫就自动获得此权限。[§10.2.3.4.8.1，印刷页 341](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=342)。

1. 终端把已存类型改为 `BASIC GROUP CALL`，把已存 ProSe 每包优先级设为离网普通组呼对应值。它把当前 UTC 记为上次类型变更时刻，把**自己的 MCPTT 用户 ID**记为上次变更用户。
2. 终端构造并发送 END：从基本呼叫控制记录取呼叫标识、组 ID 和**原呼叫发起者**的 MCPTT 用户 ID，从类型控制记录取刚保存的变更时刻和变更用户。若甲发起呼叫、乙将它升级、获授权的丙发起降级，END 的原发起者是甲，变更用户是丙。
3. 发送后，终端停止 TFG13，将 CFG11 置为 1，启动 TFG11，进入 T2。[§10.2.3.4.8.1，印刷页 341](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=342)。

发端在 T2 **等到本地 TFG11 实际到期**时，用当时存着的字段重新构造并发送 END，不是照抄上一份报文。发送后将 CFG11 加 1；**增加后严格小于所配置的上限**才重启 TFG11，本端保持 T2。这条重传路径不等接收方 ACK。TFG11 默认 1 秒，CFG11 默认上限 5，均可配置；配置与计数不是某个成员实际收到多少条 END 的证据。[§10.2.3.4.8.2，印刷页 341–342](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=342)；[表 B.3.1.2-1，印刷页 535](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=536)；[表 C.2.1-1，印刷页 541](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=542)。

## 接收端仍在 T1：收到同一通组呼的 END 后记谁？

接收端在 T1，**实际收到属于同一通呼叫的 END**。状态图的 T1→T2 边明写 Call ID 相同；§10.2.3.4.8.3 正文只在入口写 T1 和收到 END，没有列出组 ID、原发起者或变更时刻的新旧检查。不要搬用公告的比较规则，也不能从正文的省略推出任意 END 都会被采纳。[图 10.2.3.2-1，印刷页 333](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=334)；[§10.2.3.4.8.3，印刷页 342](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=343)。

终端将来件的**上次类型变更时刻、上次变更用户**存入本地，设普通组呼类型及对应 ProSe 每包优先级，停止 TFG13，进入 T2。这条接收程序没有规定发送 END 确认或启动 TFG11。若下一条 END 到达时本端已经在 T2，不再满足这条 T1 接收程序；对当前状态没有处理规则的 MONP 消息，§10.2.3.4.12.1 要求丢弃。这不是跨状态的报文去重算法，也不能用发端记录代替本端实收。[§10.2.3.4.8.3，印刷页 342](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=343)；[§10.2.3.4.12.1，印刷页 346](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=347)。

## 没看到 END：TFG13 到期和收到普通公告要分开查

**TFG13 在本端 T1 实际到期**时，本机记录当前 UTC 和**已存的原呼叫发起者 MCPTT 用户 ID**，将类型和优先级改为普通组呼对应值，进入 T2。这里按原发起者的身份取值，不按本机用户或先前升级者的身份取值。这些身份可以落在同一人身上。该分支没规定发送 END 或启动 TFG11；这条记录不是原发起者当时操作过的证据。[§10.2.3.4.8.8，印刷页 344](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=345)。

TFG13 值为组配置 `EmergencyCallCancel` 减去“当前 UTC 减上次类型变更时刻”，单位为秒。§10.2.3.4.1.1 对公式里的变更时刻列出公告或 END 的同名信息元素，不用呼叫开始时刻。不要据公式认为实收 END 会重启 TFG13：上述 END 接收分支要求停止它。这里不补负值或时钟不同步的处理。[§10.2.3.4.1.1，印刷页 334](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=335)；[§10.2.3.4.8.3，印刷页 342](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=343)。

**本端仍在 T1、已存类型紧急，实收同组且呼叫标识相同的普通类型 `GROUP CALL ANNOUNCEMENT`**，也有正文规定的降级入口。图 10.2.3.2-1 的这条 T1→T2 边没有列出普通公告；查正文 §10.2.3.4.7.2 的两个分项。比较的是来件与本地保存的上次变更用户，不是原呼叫发起者。

| 上次变更用户 | 按哪条条件处理 | 本地变更记录 |
| --- | --- | --- |
| 相同 | 只有来件的变更时刻严格晚于本地，才满足第 1 项。先按 1(a)，再按 1(d) 降级。 | 保存来件的变更时刻。 |
| 不同 | 来件为普通、本地非普通时，2(d) 不要求来件时刻更新。2(a) 是来件与本地类型相同的另一条件。 | 2(d) 没有规定写入来件的变更时刻或变更用户。 |

两条都设置普通组呼类型和相应 ProSe 每包优先级，若 TFG13、TFG14 正在运行则停掉，进入 T2。一次普通公告符合条件，不代表任何一条漏收的 END 一定会有后续公告补上；只见 T2 也不能反推一定是超时、收到了 END，或收到了普通公告。这些分支不规定并发事件的执行顺序。[§10.2.3.4.7.2 第 1(a)、1(d) 项，印刷页 339](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=340)；[第 2(a)、2(d) 项，印刷页 340](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=341)。

若要确认上一次怎样从普通变为紧急，查[既有离网组呼的升级](offnetwork-group-emergency-upgrade.md)。若要判断终端是否真的离开组呼，查[普通离网组呼的基本呼叫控制](offnetwork-group-client.md)；呼叫释放清除类型记录并回 T0，与保留呼叫、回 T2 不同。这里不覆盖在网取消、紧急告警撤销、迫近危险或初始紧急建呼。[§10.2.3.4.10，印刷页 345](https://www.etsi.org/deliver/etsi_ts/124300_124399/124379/16.14.00_60/ts_124379v161400p.pdf#page=346)。

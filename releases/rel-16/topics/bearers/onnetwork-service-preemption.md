# 在网 MCX 业务抢占：哪些组有权限，资源不足时怎样供给资源？

**资源不足时，是否须抢占，要看这次通信的目标组有没有抢占权限。** 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）§6.8.1 -002 至 -006 规定在网 MCX 业务能力，没有按有无话权控制限定这五项。这里查的是业务要求，不是话权撤销、承载配置或调度流程。[第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)；[§6.8.1，印刷页 39（PDF 第 40 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。

| 要查什么 | MCX 业务须支持什么 |
| --- | --- |
| 抢占优先级 | 支持多种抢占优先级。条文未给出确切级数或某次争用的胜者。[R-6.8.1-002，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| 谁能建立抢占层级 | 须提供机制，让 MCX 业务管理员为 MCX 业务组传输及其关联用户建立抢占层级。便于本地管理是用途说明，不是机制只在某次管理情形下才需要的条件。[R-6.8.1-003，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| 哪些组有权限 | 支持具有抢占权限的 MCX 业务组。该权限的对象是其他 MCX 业务通信，不是所有组自动获得的权限。[R-6.8.1-004，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| 资源不足时怎样供给资源 | **如果资源不足，且通信是向有抢占权限的组发起的，须通过抢占较低优先级的通信，给这次通信分配用于完成它的资源。** [R-6.8.1-005，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| 排队和保留 | 支持按优先级排队，也支持按优先级保留。条文未把这两项绑定到某次已触发的抢占，也未规定队列规则、等待时限或承载生命周期。[R-6.8.1-006，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |

例如，资源已不足，甲向有抢占权限的组发起通信。-005 不是说业务「可以」另行决定是否给资源；它要求通过抢占较低优先级的通信提供资源。若只知道资源不足，或者只知道目标组有权限，不能仅凭一项套用该义务。-005 后的附注说明：需要抢占的通信仍须满足建通信要求。该附注不是另一条独立的 SHALL；获得资源不等于已经建通或端到端通信必然完成。这里也没有规定由谁执行、如何挑选较低优先级的通信，或怎样处理同优先级争用。[§6.8.1 -005 后的 NOTE，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。

**适用业务：** 表 A.1（MCPTT）、B.1（MCVideo）、C.1（MCData）的 §6.8.1 行均列这五项。[表 A.1，印刷页 67](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=68)；[表 B.1，印刷页 78](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=79)；[表 C.1，印刷页 89](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=90)。

若查的是[组通信](../groups/onnetwork-group-communications-priority.md)或[私通信](../calls/onnetwork-private-communication-priority.md)的相对传输、呈现优先级，分别看 §6.4.7、§6.7.4。它们不替代此处的抢占触发条件。[§§6.8.2–6.8.5，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41) 的接入、准入和调度控制，以及[在网单话权的抢占与撤销](../media/on-network-preemption-revoke.md)，按各自范围查；不能据此给这五项指定承载参数、网络节点、标志或报文。

# MBMS 承载通告里有前向纠错信息，谁负责编码？丢包已经恢复了吗？

**单看通告，两个问题都答不了。** 多媒体广播多播业务（MBMS）的应用层前向纠错（FEC）有两种独立做法：MC 业务服务器可以让广播多播业务中心（BM-SC）编码，也可以自己编码。两种做法都由业务服务器发承载通告，都由 MC 业务客户端解码。通告让客户端知道怎样处理媒体，不是某个丢包已被恢复的回执。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.7.3.11.1，印刷页 142](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=143)；[§10.7.3.11.2 步骤 3、6–7 和 §10.7.3.11.3 首段，印刷页 143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=144)。

## 业务服务器请 BM-SC 编码

这条流程的前提是业务服务器已激活 MBMS 承载，预建立和动态承载均可适用。服务器经 MB2-C 发出 Setup FEC 请求，指定要保护的承载（用 TMGI 标识）和媒体流，给出修复包流的目的 IP 地址和端口，以及 FEC 所能增加的时延上限。同一承载上若有不同组的媒体流，服务器可以分别申请保护。[§10.7.3.11.2，适用范围、前提和步骤 1，印刷页 142–143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=143)

**BM-SC 能满足请求时**，应答带回更新后的媒体信息列表、FEC 信息，以及一个 FEC 处理实例标识。业务服务器在承载通告的会话描述（SDP）中放入更新后的媒体信息和 FEC 信息。它随后经 MB2-U 把下行媒体交给 BM-SC；BM-SC 按通告的算法和参数编码并经 MBMS 发送，客户端按通告解码，再把解码后的流交给播放器。[§10.7.3.11.2 步骤 2–3、5–7，印刷页 143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=144)

实例标识可用于解除**相应媒体流**的 FEC 保护。若同一承载还运送另一组媒体，仅凭这个标识或相应实例的释放，不能判定另一组也停止保护，更不能判定整条承载已释放。至于媒体传输期间，业务服务器能否要求 BM-SC 暂停或恢复生成修复包，本版编者注说还需讨论，没有给出可直接执行的开关程序。[§10.7.3.11.2 步骤 1–2、步骤 7 后编者注，印刷页 142–143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=144)

## 业务服务器自己编码

业务服务器在承载通告中给出 FEC 信息。来自发端终端的媒体经服务器的媒体分发功能处理，再由**服务器**按选定算法编码。它把源包和修复包都经 MB2-U 交给 BM-SC；这时 BM-SC 原样转发两类包，不再编码，客户端负责解码。不能把上一种做法的 Setup FEC 请求、成功应答及实例标识当作这里规定的前置步骤。[§10.7.3.11.3 首段及步骤 1–5，印刷页 143–144](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=145)

## 旧承载的监听报告能说明新承载的效果吗？

对 MC 业务服务器和客户端，支持 FEC 都是可选的。业务服务器在新承载上发送时，**可以**参考此前承载质量检测所得的监听状态报告来调整 FEC 参数，不要求先有旧报告才能启用。编码会增加端到端媒体传输时延，这部分时延必须受限，以满足任务关键业务的低时延要求；本款没有规定一个通用毫秒数。历史报告能帮助选参数，不能证明新承载上某个客户端已经收包、解码或成功恢复了哪一个丢包。[§10.7.3.11.1，印刷页 142](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=143)

如果要查 MCVideo 组播中加密与 FEC 的先后，或参与侧自行编码时修复包采用哪个流标识，见 [MCVideo 组播媒体的 FEC 与加密顺序](../mcvideo/mbms-media-fec.md)。那是 MCVideo 的 Stage 3 条款，不是本文两种公共编码流程的额外步骤。

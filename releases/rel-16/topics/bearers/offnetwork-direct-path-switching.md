# MCX 终端什么时候能自动切到离网直连？有网络覆盖时，谁能手动切？

**出覆盖，是终端自动切换能力的触发条件；有覆盖，不妨碍获授权用户选择离网直连。** 这里的另一条路径是终端与终端的 ProSe 直连。把终端的网络接入改为经附近中继，并不是本节说的“切到离网直连”。[TS 22.280 V16.8.0，Release 16，Stage 1，§7.13，印刷页 56](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=57) 及[续页 57](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=58)。

| 谁切，处于什么条件 | Stage 1 要求 |
| --- | --- |
| MCX 终端检测到离网（超出网络覆盖） | 终端须具备自动切到 ProSe 直连路径使用 MCX 业务的能力。要求具备能力，不表示每次失去覆盖都已切换，也没有规定恢复覆盖时须自动切回。[R-7.13-001，印刷页 56](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=57) |
| 获授权的 MCX 用户，处在网络覆盖内 | 须提供手动切换手段，让用户可在在网运行与供离网 MCX 业务使用的 ProSe 直连路径之间切换。用户无需先离开覆盖区。[R-7.13-002，印刷页 56](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=57) |
| 获授权的 MCX 用户使用支持公共安全 ProSe 的终端，处在覆盖内或覆盖外 | 在**运营商策略和/或网络授权**的约束下，须提供在上述两种路径之间手动切换的手段。用户本人获授权没有取消策略或网络授权这一层条件；覆盖外可以手动选择，不表示当地有可用网络，或选择后就一定能接入。[R-7.13-003 起于印刷页 56](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=57)，[覆盖条件续于印刷页 57](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=58) |

后两条分别规定条件。“使用支持公共安全 ProSe 的终端”和“覆盖内或覆盖外”是第三条的原文限定，不要把第三条读成任何终端、任何用户都能在任何地点切换。用户主动选择了离网直连，也不能据此反推现场没有网络覆盖。

**切换时如果已有一场通信呢？** 终端把与同一次进行中 MCX 业务通信的连接从在网改为与另一台 MCX 终端的离网 ProSe 直连，MCX 业务须把该通信的中断降到最低（[R-7.13-004，印刷页 57](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=58)）。从与另一台终端的离网 ProSe 直连切回在网，同一场通信也受这项要求保护（[R-7.13-005，印刷页 57](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=58)）。返程的减中断要求并不是返程的自动切换要求。看到终端在新路径上线，只能确认接入；要判断原通信有没有停顿，还得看这场通信换路前后的记录。两条都没有规定多久内必须恢复，也没有要求零中断。

如果离网一侧走的是 **UE 到 UE 中继**，请查[中继、直连和在网路径之间的换路](prose-relay-streaming.md)。若从一个网络换到另一个网络而始终在网，请查[在网跨网移动](onnetwork-inter-network-mobility.md)；不能把那里的两网授权套到这里。若两种接入最终都连到网络中的 MCPTT 服务器，要核对原 SIP 会话怎样转移，读[锚定会话的 Stage 2 示例及 Stage 3 程序](anchored-session-transfer.md)。

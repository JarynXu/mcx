# 在网 MCX 应用优先级：事件如何参与，每次通信须分配什么？

同一个组的两次通信可能处理不同事件。组相同不意味着系统只能给两次通信同一种应用优先级。这里查的是 [TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章在网要求，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。

| 要判断什么 | 标准要求 |
| --- | --- |
| 应用优先级按什么映射，谁执行？ | 在网 MCX 业务须支持多种业务应用优先级。这些应用优先级按网络运营商的策略映射到优先级等级。本条未指定执行映射的主体或组件，也不要求一一映射。条文没有给出确切级数、固定映射表或协议字段。[R-6.8.1-001，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| 组已给定优先级，事件还起什么作用？ | 在网 MCX 业务系统在按组给定的优先级之外，还须能根据事件为每次通信给出应用优先级。条文未规定组优先级与事件优先级谁优先，也未定义两者如何合成。[R-6.8.7.2-001，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。 |
| 每次通信须分配哪些属性？ | 在网 MCX 业务系统须为每次通信分配三项：应用层抢占能力、可被抢占的能力、应用层优先级值。抢占别的通信与自身可被抢占是两个属性，不能用应用层优先级值替代。分配这些属性不证明本次通信已发起抢占、已被抢占或已取得资源。[R-6.8.7.2-003，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。 |
| 可配置等级至少有几个？ | 在网 MCX 应用层优先级须有至少 8 个可配置等级，30 个是优选数量。30 个不是强制数量，也不是上限；可配置等级数不等于一次通信须分配多个优先级值。[R-6.8.7.2-005，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。 |

例如，系统可以按事件为同一组的不同通信给出不同的应用优先级；这种能力并不规定其中哪一次一定更高。若记录只给了优先级值，就还不能判断这次通信能否抢占其他通信，或它自身能否被抢占。若系统支持 12 个可配置等级，它满足的是本条的最低数量；不能因未到 30 个就判这条不合格，也不能据此判实际抢占已发生。

四项均适用于在网 MCPTT、MCVideo、MCData。表 A.1（MCPTT）分别列在[印刷页 67：优先级映射](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=68)与[印刷页 68：事件、通信属性和级数](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=69)；表 [B.1（MCVideo），印刷页 78](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=79) 和 [C.1（MCData），印刷页 89](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=90) 各在同一页列出四项。

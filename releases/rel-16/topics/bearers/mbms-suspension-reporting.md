# MC 公共业务的 MBMS 承载暂停：没被选为上报者，还要检测吗？

**要检测。** 在本次暂停中，未被要求上报的 MC 业务客户端仍须检测无线接入网（RAN）发出的暂停指示，但不发暂停报告，也不得改发监听报告或其他报告。服务器没收到某个客户端的报告，单凭这点既不能断定它没检测到，也不能断定承载没暂停。

这是多媒体广播多播业务（MBMS）的公共流程，不限于 MCVideo。它假定至少有一条活动 MBMS 承载。若这一前提不成立，就不能用本流程判断客户端应该有什么动作。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.7.3.8.2 前提、步骤 2–4 及后文，印刷页 135–136](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=136)

## 谁来选上报者？客户端如何知道自己是否要报？

MC 业务服务器可以只选广播区域内的一部分终端上报。选取时须考虑终端位置；终端会移动，上报指令可能需要定期更新，但这不等于每次移动都要重发。服务器可以把暂停上报指令放进承载通告，不要求它一定随通告发送。[§§10.7.3.8.1–2，选择上报者的段落、步骤 1 及注，印刷页 135](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=136)

- **单播给一个客户端：** 表里有两个必填项。MC service ID 表示 MC 业务身份；暂停上报设置（Suspension reporting）对这条单播指令所针对的客户端启用或禁用上报。例如，服务器单播给甲并关闭甲的上报，不能因此把 MC service ID 读成“甲这台终端的标识”。[§10.7.2.3，表 10.7.2.3-1，印刷页 119](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=120)
- **多播给多个客户端：** 指令的必填字段指定一个能唯一确定的上报客户端子集（Suspension reporting client subset）。收到多播指令不等于入选；要看自己是否在该子集中。[§10.7.2.3，表 10.7.2.3-2，印刷页 120](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=121)

## 一次暂停，哪几件事不能混为一谈？

例如，甲和乙都收到多播上报指令，指令只选了甲。**发指令的是业务服务器，决定暂停承载的却是 RAN。** RAN 通过 MSI（MCH 调度信息）发送暂停指示。甲检测到暂停后向业务服务器发暂停报告；乙也须检测 RAN 的指示，但不能因这次暂停发另一种报告来替代。也就是说，暂停指示来自无线侧，暂停报告来自获选的客户端，指令本身并不是暂停已经发生的证据。[§10.7.3.8.2，步骤 1–4 及步骤 4 后的规定，印刷页 135–136](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=136)

禁止改报的限制针对上述未获指示的客户端和这次暂停，并非永远不许发送监听报告。同一程序也**可**用于 MBMS 恢复或客户端能检测到的其他 MBMS 事件；条款没有要求每次恢复都走此程序。[§10.7.3.8.2 末两段，印刷页 136](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=137)

若手里是 MCPTT 客户端的 SIP MESSAGE，读[即将暂停与撤回的报告条件、待暂停业务的 MCH 分报和 TMGI 计数](mcptt-mbms-status-message-rejection.md#suspension-report)。其中的 `not-suspending` 指撤回尚未生效的决定，不是本页所说的承载恢复。

若要查的是 MCVideo 组内谁通过哪个子信道接收视频，见[组播子信道映射](../mcvideo/mbms-group-downlink.md)；若要判断何时可以释放一次视频传输的组播实例，见[组播转单播](../mcvideo/mbms-to-unicast.md)。这两项都不是判定本次暂停必须由谁上报的依据。

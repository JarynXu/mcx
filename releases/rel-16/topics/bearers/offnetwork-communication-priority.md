# 离网 MCX 的优先级属性分给谁？应用优先级怎样映射到 ProSe？

离网 MCX 业务须为每个 MCX 业务组或每项私通信分配三项属性：**应用层抢占能力、可被抢占的能力、应用层优先级值**。知道优先级值，不能代替另外两项；分配抢占能力不代表已经发生抢占。[TS 22.280 V16.8.0，R-7.6-001，印刷页 53](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=54) 的清单续到[印刷页 54](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=55)。

原文列的对象是“each MCX Service Group or Private Communication”。[§3.1，印刷页 10](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=11) 将 MCX 业务组与 MCX 业务组通信定义为不同的术语；[印刷页 11](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=12) 将私通信定义为两名用户间的一对一通信。本条没有要求同一业务组的每次组通信都重新分配三项属性，也没有规定语音和数据采用相同还是不同的优先级。这里的离网按通信路径判断：终端在网络覆盖区内选用 ProSe 直通路径，也属于离网使用。[第 7 章、§7.1，印刷页 50](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=51)。

| 要判断什么 | 离网 MCX 业务须做什么 |
| --- | --- |
| 可配置几个等级？（R-7.6-002） | 支持至少 8 个可配置的优先级等级。8 是下限，不是固定总数。 |
| 应用优先级映射到哪里？（R-7.6-003） | 支持多种 MCX 业务应用优先级，按网络运营商策略映射到 ProSe 优先级等级。这里没有给出映射表，也没有要求一一对应；不能从前一项的下限推出 ProSe 有 8 级。 |
| 谁能给组排序？（R-7.6-004） | 让 MCX 业务管理员能设定一个 MCX 组相对于其他 MCX 组的优先级，传输和呈现两个方面都要支持。条文没有要求两个方面采用相同的排序。 |
| 一次通信的优先级依据什么？（R-7.6-005） | 确定通信优先级时，既要用 MCX 用户／参与者的属性，也要用 MCX 组的属性。前者的例子有第一或第二响应人员、主管、调度员、是否当班；后者的例子有组类型、所属组织、MCX 紧急、迫近危险。条文没有把这些例子列为逐项必填字段，也没有给出权重或计算公式。 |

四行条文同见 [§7.6，印刷页 54](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=55)。例如，已知甲组的传输优先级高于乙组，仍不足以断定接收端会先呈现甲组，也不知道某次通信映射到哪个 ProSe 等级：映射要看运营商策略，但条文没有要求终端为每次映射实时向运营商查询。若要判断资源不足时是否必须抢占其他通信，另见[离网组的抢占权限与资源分配](offnetwork-service-preemption.md)。

以上是 Release 16 的 Stage 1 要求。规范性[表 A.1（MCPTT），印刷页 70](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=71)、[表 B.1（MCVideo），印刷页 81](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=82)、[表 C.1（MCData），印刷页 92](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=93)均列出这五项。若查在网业务，另见[应用优先级与等级数](onnetwork-application-priority-assignment.md)、[组优先级配置](../groups/onnetwork-group-priority-administration.md)及[通信和传输的优先级属性](onnetwork-priority-attributes.md)。离网的 R-7.6-002 没有指定优选 30 级，R-7.6-005 说的是一次通信，没有另外规定每次传输都须执行相同的计算。

# LTE 站点回传中断：IOPS 下的本地 MCPTT 要保留哪些能力？

**先分清终端是仍在孤立 LTE 网覆盖内，还是已经离网直连。** IOPS（Isolated Operation for Public Safety）这里指公共安全场景下的孤立 E-UTRAN 运行。正常回传断开，不等于手机离开了无线接入网。一个孤立 E-UTRAN 可以由一座或多座 (N)eNB 组成；同一孤立网不等于同一个站，也不把两个各自孤立的网合成一个。若终端实际走离网直连，查 [Stage 3：普通离网组呼](../calls/offnetwork-group-client.md)，不要套本页。[TS 22.346 V16.0.0 §5.2.3、§5.3.2，印 9](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=10)。

本页是 **Release 16 的 Stage 1 业务要求**。TS 22.280 R-10-001 要求 MCX 业务能在 3GPP 网络的 IOPS 模式提供业务；附注说明能提供的业务可能减少，例如回传不足。它没有承诺视频、数据或 SDS 与正常回传时相同。应保留哪些最低本地 MCPTT 能力，用 TS 22.346 §5.2.3，且只看**处在同一孤立 E-UTRAN 覆盖下**的用户，以及**在非孤立运行时就支持 MCPTT 通信**的 (N)eNB。[TS 22.280 V16.8.0 §10，印 61](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=62)；[TS 22.346 §5.2.3，印 9](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=10)。

## 同一孤立网里，测试哪些本地组呼能力？

| 项目 | 验收时看的能力和条件 |
| --- | --- |
| 预配置组 | 须支持预先配置组成员资格，包括 MCPTT 紧急组成员资格。这不是说失去回传的那一刻才从远端取到组。 |
| 紧急组呼 | 公共安全用户须能发起 MCPTT 紧急组呼。按接收方**预配置为已归属组成员**的条件，它能到达调度员（可直连 (N)eNB 或经 UE）、孤立网覆盖内的组员，和／或覆盖内所有 UE 这一配置范围。这些列举范围按实际配置适用，不要求一通呼叫同时覆盖所有类别。仅在覆盖内不等于已归属，网外接收方不在本条范围。 |
| 每组最低语音能力 | 孤立运行时，每组须能发起**至少一项** MCPTT 语音组通信；组内获授权的成员都被允许加入，以可用无线资源为限。这是组能力和准入条件，不等于每次所有成员都已接通，也没给共同能开多少路。 |
| 语音与视频、数据竞争 | MCPTT 语音组通信须具备抢占视频通信或其他数据业务的能力。本条不要求每次语音开始都自动抢占，也不保证视频或 SDS 能继续。 |

依据：[TS 22.346 §5.2.3，印 9](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=10)。若冲突的是一台终端的扬声器或显示器，而不是孤立网服务能力，另查 [Stage 1：不同 MC 业务争用终端资源](../media/concurrent-services-ue-resources.md)。

## 回传断开的现有通信，会自动无缝续上吗？

**能检测和能启动，不等于当即自动切换。** 支持孤立运行的 eNB 须能检测回传连接丢失，并能启动孤立 E-UTRAN 运行；NeNB 在运营方控制下也须能启动。没有由此确定的自动切换时限。进入孤立运行后，在覆盖区内的公共安全 UE 须有业务支持，但不能据此要求恢复每一项常态业务。[TS 22.346 §5.3.2，印 9](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=10)。

**先判断能不能支持，再判断中断能否减小。** 对进入孤立运行前、在该 eNB 服务的公共安全 UE 之间已经建立的业务，运营方策略允许时，eNB 须具备尽量减小中断的能力。另对 eNB 转入孤立运行时已经在运行的业务，若孤立网本地不能支持，且没有能支持它的可用有限回传，eNB **须终止**这项业务。只有有限回传、却不能承载该业务，不算有支持途径。反过来，有一个支持途径也不能承诺无缝继续、沿用同一 Call-ID 或复用同一媒体会话。[TS 22.346 §5.3.2，印 9](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=10)。

## 用户怎样知道现在只有本地服务，还是仍有有限回传？

- **网到终端：** 孤立 E-UTRAN 须向覆盖内的公共安全 UE 指示有限带宽回传服务是否可用，或是否仅支持本地业务；该网须具备持续提供此指示直到孤立运行结束的能力。
- **终端到人：** 受孤立网服务的公共安全 UE 须向用户指示正在孤立 E-UTRAN 内通信，并说明有限回传是否可用或是否仅有本地业务。看到网络侧的发送证据，不能代替用户侧的提示证据。

这两项是不同对象的义务，不指定消息字段、通知频率、图标或实现。依据：[TS 22.346 §5.3.2，印 10](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=11)。本页不展开联合建网、运维配置、回传恢复或后续版本中的 Stage 2 机制。

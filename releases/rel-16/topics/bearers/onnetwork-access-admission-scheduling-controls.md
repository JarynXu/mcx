# 在网 MCX：谁能影响网络接入、承载准入与保留、承载调度？终端能改什么？

**先看要控制的对象，再看谁能操作。** 对网络接入、承载准入与保留、承载调度，3GPP 系统须在运营商策略约束下提供手段，让 MCX 业务能影响相关控制。对终端临时修改特定接入参数，允许该操作的是 MCX 业务，终端按管理员制定的配置执行。依据是 TS 22.280 V16.8.0（Release 16，Stage 1）[第 6 章的在网范围，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。规范性表 [A.1（MCPTT），印刷页 67](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=68)、[B.1（MCVideo），印刷页 78](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=79)、[C.1（MCData），印刷页 89](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=90) 均列出下列四项。

| 要查的控制 | 条文要求 | 相邻附注举出的可能做法 |
| --- | --- | --- |
| **网络接入** | 在运营商策略约束下，3GPP 系统须提供手段，让 MCX 业务能**影响修改**网络用来准许指定区域内的 MCX UE 接入的接入参数。该项没有以用户或组的优先级判定属性为条件。[R-6.8.2-001，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 | 可考虑复用已有的 UE 网络接入机制。 |
| **承载准入与保留** | 对已分配或即将分配给 MCX UE 的承载，在运营商策略约束下，3GPP 系统须提供手段，让 MCX 业务能依据 **MCX 用户和 MCX 业务组**用于确定优先级的属性，影响承载准入与保留控制的**选择、修改或两者**。[R-6.8.3-001，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 | 可考虑复用现有的 3GPP 网络优先级和 QoS 机制。 |
| **承载调度** | 对已分配或即将分配给 MCX UE 的承载，在运营商策略约束下，3GPP 系统须提供手段，让 MCX 业务能依据 **MCX 用户和 MCX 业务组**用于确定优先级的属性，影响承载调度控制的**选择、修改或两者**。这项查调度，不查准入与保留。[R-6.8.4-001，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 | 可考虑复用现有的 3GPP 网络优先级和 QoS 机制。 |
| **终端修改接入参数** | 按 MCX 业务管理员制定且与运营商策略一致的配置，MCX 业务须允许 MCX UE **临时修改选定的** 3GPP 系统接入参数。[R-6.8.5-001，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 | 可考虑复用已有网络接入机制，例如 ACDC。附注指向 TS 22.011 和 TS 23.122。 |

附注说的是可能的做法。四项条文没有要求采用某一种机制，也没有认定现有机制在某一部署中已经满足要求。

例如，某区域的 MCX 业务能影响网络接入参数的修改，但该终端当次没有接入成功。接入结果不等于系统没有提供 §6.8.2 要求的手段，也不能用该手段反推终端已获准接入。若另有一条已经分配给 MCX UE 的承载，仅证实业务能影响它的调度控制，还不能把它算作准入与保留控制也已具备。即使管理员的配置允许终端临时修改某个接入参数，也不能据此认定终端已完成修改，或能永久修改其他参数。

[哪些属性用于确定通信和传输的优先级](onnetwork-priority-attributes.md)、[何时须通过抢占供给资源](onnetwork-service-preemption.md)各有适用条件。应用优先级映射另查 [§6.8.1 -001](onnetwork-application-priority-assignment.md)。若要核对[在网单播资源建立或修改的 Stage 2 流程](unicast-resource-establishment-modification.md)，按流程取证，不能把本页的控制能力当成网络授予资源、建立承载或实际执行调度的证明。

# 在网会话申请或修改单播资源，客户端回了 OK 能证明什么？

**OK 确认的是客户端收到的请求。** 建立会话时，只有这条 OK，不能断定单播资源已分配；修改进行中的会话时，即使服务器已经收到转发的 OK，也不能只凭它断定呼叫已经用上修改后的资源。要分清两种程序各自的最后一步。这是 MCPTT、MCVideo、MCData 共用的在网资源管理流程。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.11.1，印刷页 184](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=185)。

## 新建会话：资源请求、客户端应答与分配结果

客户端请求建立呼叫或会话。MC 业务服务器评估需要什么网络资源、是否共享媒体资源，再发送带资源请求的会话进展请求。即使有并行会话，服务器也只是**可以**利用资源共享能力；同时有两场会话，不足以证明它们共用资源。[§10.11.2 首段，印刷页 184](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=185)；[步骤 1–3，印刷页 185](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=186)。

SIP 核心网的本地入站／出站代理经 Rx 参考点发起策略与计费控制（PCC）程序，再将呼叫控制请求转给客户端（步骤 4–5）。客户端用 OK 确认会话进展请求（步骤 6），代理把这条 OK 转给业务服务器（步骤 7）。**步骤 8** 描述的才是呼叫或会话已建立、资源已分配。步骤 8 是程序的结果，不是另一条客户端确认消息；这组步骤也没有给出网络内部实际完成分配的精确时刻。[§10.11.2 步骤 4–8，印刷页 185](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=186)。

## 会话已在进行：改什么，何时能说已经用上？

修改以 MC 业务呼叫或会话**已经在进行**为前提。业务服务器决定调整单播承载，例如要改变其分配和保留优先级。它须通过 SIP 核心网向终端发送携带待改参数的资源修改请求；这次请求放在会话更新中。代理经 Rx 发起 PCC 程序，将更新请求转给客户端。客户端回 OK 确认请求（步骤 5），代理将 OK 转给业务服务器（步骤 6）。**步骤 7** 才描述原呼叫使用修改后的单播资源继续，不是又建立了一场呼叫。[§10.11.3 开头及适用场景，印刷页 185](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=186)；[前提及步骤 1–7，印刷页 186](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=187)。

## 释放媒体资源，会不会同时拆除 SIP 会话？

**可以保留 SIP 会话，也可以拆除。** 释放媒体面资源时，流程应允许这两种选择。聊天模式下，可以在两次 MC 业务呼叫之间释放和恢复资源；当终端能通过组播接收该呼叫时，也可以释放和恢复单播资源。若呼叫已转到组播，注 1 说原来的单播资源**可以临时释放**。这不是必须释放的命令，释放对象也不是所有承载。仅有“媒体资源已释放”的记录，判断不了 SIP 会话的去留，也得不出恢复需要多久。[§10.11.3 适用场景及图前说明，印刷页 185](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=186)；[步骤 7 后注 1，印刷页 186](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=187)。

同一终端接收多路音频时，已建立的会话还**可能**需要额外承载资源。建会时预先分配这些资源可能有用，但不是本条对每场会话的要求。[§10.11.3 注 2，印刷页 186](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=187)。

若要查网络何时通知 **MBMS 承载可用**，见[网络侧 MBMS 承载事件](mbms-network-bearer-events.md)；若要查 **MCVideo 从组播改回单播**时何时释放该次传输的组播实例，见[MCVideo 组播转单播](../mcvideo/mbms-to-unicast.md)。这些是另外的流程，不是本页两个 OK 的后续步骤。

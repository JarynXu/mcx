# LTE MCX 的 MBMS 承载怎样辨认？TMGI、上行单播和 MB2 各说明什么？

**两个记录的 TMGI 一样，不一定记录的是同一条承载，更不能据此认定是同一个业务组。** 另一个常见误判是：下行用了 MBMS，就要找一条对应的组播上行。Rel-16 的 LTE MC 业务把上行和下行分开。本页读 TS 23.280 V16.7.0 的公共架构和示例流程（Stage 2），不规定接口的报文格式。[§5.2.6，印 20–21](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=21)

## 同一个 TMGI，先看这张网用哪一种承载标识

§5.2.6 给出两种唯一标识 MBMS 承载（网络和无线部分）的方式：**TMGI**，或 **TMGI 与 flow identifier（流标识）组合**。例如，若这批记录按组合键标识承载，`(TMGI A, 流 1)` 和 `(TMGI A, 流 2)` 不能按 TMGI 合并。不清楚这次用哪一种，或只拿到了其中一侧不含流标识的摘要，就不能用 TMGI 相同来确认两条记录属于同一承载；也不必在只用 TMGI 标识的情形硬要求补一个流标识。[§5.2.6 承载标识和 MB2 请求段，印 20–21](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=21)

承载和业务组是两类对象。单条 MBMS 承载可以供同一组中的一项或多项 MC 业务使用，也可以承载并行的多场组通信。就算已经对上同一条承载，也还要查**本次业务会话用了哪条承载**，不能按承载标识给抓包填上组 ID 或认定某场组呼已映射。客户端的监听状态报告按 TMGI 列状态，可选列质量等级；报告里的 TMGI 不是给网络承载标识规则新增或删减字段。[§10.7.1，印 118](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=119)；[表 10.7.2.2-1，印 119](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=120)

## 下行走 MBMS，终端上行查哪里？

这类 LTE MC 业务媒体承载的**上行总是单播**；下行可以单播、走 MBMS，或两种都用。给终端验上行时，不必找一条对称的组播承载。终端也可以在没有单播无线承载的情况下接收 MBMS 流量。这只回答下行接收的能力，不说明某台终端已经收到，也不取消对应业务的注册、上行或会话条件。[§5.2.6 上、下行段，印 20](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=21)；[§5.2.7.1，印 21](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=22)

| 看的是哪条记录 | 它能证明什么 |
| --- | --- |
| 业务服务器在 **MB2-C** 上发出承载激活请求 | 在网络承载事件示例中，服务器已请求激活。激活答复、网络可用通知和终端实际接收仍是三件事。 |
| 业务服务器在 **MB2-U** 上向 BM-SC（广播多播业务中心）发送下行媒体 | 例如 BM-SC 编码 FEC 的流程步骤 5；能证明的是服务器把媒体发往 BM-SC，不是证明某台 UE 收到。 |
| 业务服务器经 **GC1** 收到已归属组成员的小区标识或有关报告 | §5.2.6 说它可以用小区标识决定广播区，也可以据报告决定给某用户切回单播。看到报告不是看到切换；先核报告内容再判断提供了什么接收证据。 |

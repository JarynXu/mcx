# 在网 MCX 用户为一次通信请求优先级，系统在建立时如何处理？

用户可以为这一次通信请求一个等级。判断系统该分配什么，要看建立通信时用户有没有提出请求；如果提出了，再看它是否超过授权上限。依据是 [TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章的在网要求，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。

**用户能请求什么？** 在网 MCX 业务须让 MCX 用户能为每一次通信单独请求优先级。“每一次”说的是请求按通信区分，不限于一对一私通信，也不要求用户每次都提出请求。 [R-6.8.7.2-006，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。在网 MCX 业务系统须提供机制，让 MCX 用户能请求授权等级以内的任一优先级，包括授权等级本身。能请求某个等级，不等于系统须按请求值分配。 [R-6.8.7.2-007，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。

**建立时检查什么？** 建立通信时，在网 MCX 业务系统须对照最高授权等级核验这次通信的优先级。这项核验不以用户显式请求等级为前提；没有请求时也须核验。 [R-6.8.7.2-008，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。

| 建立通信时的情况 | 能从这五项得出什么 |
| --- | --- |
| 用户没有请求等级 | 若 MCX 用户在建立通信时没有请求优先级，在网 MCX 业务系统须给这次通信分配已定义的优先级。条文没有给出这个已定义等级的值，也没有指定由谁定义或从哪里取得；不能假定它就是最低等级或最高授权等级。 [R-6.8.7.2-009，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。 |
| 用户请求的等级高于上限 | 若 MCX 用户在建立通信时请求的优先级高于最高授权等级，在网 MCX 业务系统须给这次通信分配最高授权等级。超限时须分配上限，不能用拒绝代替这项分配。 [R-6.8.7.2-010，印刷页 41](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=42)。 |
| 用户请求的等级恰好等于上限，或低于上限 | 用户能这样请求，系统仍须核验。此时既不是“没有请求”，也不是“高于上限”；这五项没有说一定按请求值分配。 |

例如，某次通信的已定义等级是“普通”，用户的最高授权等级是“高”。如果建立时没提要求，系统须分配“普通”；如果请求比“高”还优先的等级，系统须分配“高”。如果请求的就是“高”，不能引用超限条款断言它一定获配。这两个名称只为区分例中的等级，不表示标准要求已定义等级和上限不同。这里比较的是优先级高低，没有规定整数编码或数字越大、优先级就越高。等级分配不能证明通信建立成功或网络已分配资源。

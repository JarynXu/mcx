# IOPS 下哪些终端和组能本地通信？本地互通能证明公网可达吗？

**能在孤立 LTE 网里通信，不等于能到运营商核心网（EPC），也不等于能通过现场网关上公网。** 这里讲 Release 16 的 Stage 1 业务要求，限面向公共安全的孤立 E-UTRAN 已在运行、问题仍在该接入网的场景。没有正常回传，不等于 UE 已离开 LTE 覆盖或正在离网直连。[TS 22.346 V16.0.0 §3.1（印刷页 5，PDF 6）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=6)；[§4.1（印刷页 7，PDF 8）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=8)。

## 本地能提供什么？

**孤立网须能为覆盖内的公共安全 UE 建立本地路由和 ProSe 组通信。** 网也须能向覆盖内的所有公共安全 UE 和组提供语音与数据服务，并允许覆盖内的公共安全 UE 与同一覆盖内的其他公共安全 UE 和组发起、保持语音和数据通信。两个 UE 在同一孤立网，不要求同接一座基站；一张孤立网可以由多个相连基站组成。这里规定的是网要支持的能力，不是说每台处于覆盖的 UE 已接入、每次具体通信已建立、语音已送达，或正常回传时的所有业务都能继续。[§4.1 第三段（印刷页 7，PDF 8）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=8)；[§5.2.2 本地路由、组通信与语音数据三段（印刷页 8，PDF 9）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=9)。

**同网换站看 UE，站点加网看站。** §5.2.2 要求支持公共安全 UE 在组成该孤立网的 eNB 之间移动。已经运行时，§5.4.2 分别要求孤立网接纳公共安全 UE、管理公共安全 UE 在本孤立网成员 (N)eNB 之间的移动。接纳和移动管理是两项要求；它们不规定先后、附着或切换消息、如何建立活动上下文，也不承诺一次移动中的通话无缝。相邻站点可以联系，或 UE 移到另一个尚未合并的孤立网，都不能当作同网移动的证据。[§5.2.2 移动性段（印刷页 8，PDF 9）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=9)；[§5.4.2 接纳与移动性两段（印刷页 10，PDF 11）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=11)。

## 没有 EPC 回传，还可能有其他出口吗？

先看表 4.1-1 的两列，再读备注。**两列是回传状态，备注里经本地网关访问公网只是可能的支持。** 表中前三行都列有本地 UE–UE 路由；第二行说用户流量在 E-UTRAN 本地分流，第三行说可选择用户流量在本地分流。三行的备注都写了可能支持经本地网关访问公网，包括第一行。[§4.1 表 4.1-1（印刷页 7，PDF 8）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=8)。

| IOPS 场景 | EPC 信令回传 | EPC 用户数据回传 |
| --- | --- | --- |
| 无回传 | 无 | 无 |
| 只有限信令回传 | 有限 | 无 |
| 信令与用户数据回传都有限 | 有限 | 有限 |

**§5.2.2 的要求不能用那张表改写。** 首段写：仅由孤立网服务的公共安全 UE，因缺少到移动运营商网络的回传，没有到外部 IP 网络的用户面连接。同一段另写，有回传连接（可以是有限回传）时，孤立网**可**支持本地网络的选择性 IP 流量分流（SIPTO@LN）来提供外部 IP 连通。保留这段的适用条件，也保留总览表里独立的本地网关可能性。两处没有共同定义在无回传时启用 SIPTO 的操作，也不能靠它们判某个现场已部署出口或必无任何其他公网路径。[§5.2.2 首段（印刷页 8，PDF 9）](https://www.etsi.org/deliver/etsi_ts/122300_122399/122346/16.00.00_60/ts_122346v160000p.pdf#page=9)。

例如，只看到同网两台 UE 本地传数据，不证明哪台 UE 能到外部。看到某个公网地址能访问，也先查这次用的是哪一条路径；不能把经本地网关的可达当成 EPC 用户面已恢复。尤其是只剩有限信令回传时，表的 EPC 用户数据列仍是“无”。这些是分类和证据边界，未规定网络实现应选哪个网关、怎样分流或如何检测回传。

普通回传刚丢失，要查[初进 IOPS 和已有业务处置](iops-local-mcptt-service.md)；若查同一孤立网的最低 MCPTT 能力，也读该页，并先确认相关 (N)eNB 在非孤立运行时支持 MCPTT。若实际问题是[有限 EPC 回传、恢复尝试、活动上下文转移或退出 IOPS](iops-backhaul-restoration.md)，按 EPC 控制面、用户面及相应触发查，不从公网可达猜恢复。若对象是[站点或孤立网加入、联合/分网、网络授权或连接时的双向认证](iops-topology-and-join.md)，查实际加入、网络关系或认证对象；这些不能代替公共安全 UE 在同一已运行孤立网内的移动记录。

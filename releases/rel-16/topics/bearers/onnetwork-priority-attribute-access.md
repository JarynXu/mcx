# 在网 MCX：能查看影响自己优先级的属性吗？能影响别人的属性吗？

**能监看用来确定自己优先级的属性。涉及另一名用户时，条文要求向经授权的 MCX 用户提供监看和促成属性变更的手段。** 这里要查的是用于确定通信和传输优先级的属性，不是算出的优先级。以下是 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）[第 6 章的在网要求，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)。

| 对象 | MCX 业务须提供的手段 |
| --- | --- |
| **本人**的通信和传输 | 须让 MCX 用户能监看用于确定本人**通信和传输**优先级的属性。本项没有写额外的授权条件；它也没有要求让用户编辑本人的属性或查看实际优先级值。[R-6.8.1-015，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 |
| **另一名** MCX 用户的通信和传输 | 须让**经授权的 MCX 用户**能监看用于确定他人**通信和传输**优先级的属性，并能促成这些属性发生变化。监看和促成变化都在本项内，但不能从本项断定用户能直接写入任意属性，或每次操作都一定会改动属性。[R-6.8.1-016，印刷页 40](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=41)。 |

例如，看到系统用「是否在岗」参与优先级判定，只知道了一项输入。要判断优先级实际是多少，需要查优先级结果；只凭监看画面不能得出结果。经授权的用户能促成属性变化，也不表示同一操作直接设置了优先级。-016 没有把经授权的用户限定为管理员，也没有规定授权策略、可变更字段、界面、协议或生效时间。

规范性表 [A.1（MCPTT），印刷页 67](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=68)、[B.1（MCVideo），印刷页 78](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=79)、[C.1（MCData），印刷页 89](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=90) 均列出这两项。要查[通信和传输用哪些属性、多台关联终端和漫游有何要求](onnetwork-priority-attributes.md)，读 -010 至 -014。要查[管理员可配置哪些业务组优先级](../groups/onnetwork-group-priority-administration.md)，读 -007 至 -009；这不是 -016 的角色定义。应用优先级按运营商策略映射到等级另见 -001。

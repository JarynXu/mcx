# 组成员由伙伴系统服务，组通信的端到端安全参数从哪个系统取？

看**谁定义了目标组**。假设 G 组定义在甲系统，一名成员当前由乙系统服务。G 组通信的端到端安全仍须以从甲取得的参数为依据。条款明确包括伙伴系统中的情形；它没有把参数来源改为成员当前所在的系统，也不要求先发生漫游或临时重组。[§6.17.2，R-6.17.2-007，印刷页 49](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=50)

“参数来自甲”没有回答“甲内哪个实体生成了哪把密钥”，也不能证明某台终端已经拿到密钥，或这次组通信已经启用了哪种保护。若要认证的是在伙伴业务中使用服务的**用户**，应另查用户认证的要求，不能拿组参数来代换。

这是 [3GPP TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30) 的在网要求。[表 A.1（MCPTT），印刷页 69](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=70)、[表 B.1（MCVideo），印刷页 80](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=81)、[表 C.1（MCData），印刷页 91](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=92)均列出R-6.17.2-007。

若是跨域**临时重组**的组主密钥，见[GMK 的生成、转交与分发](../groups/partner-regroup-gmk.md)；若手里是一份组成员配置，要解释其中按业务区分的密钥管理服务器地址，见[成员 KMSUri](../groups/member-kms-uri.md)。

# 用户配置档管理消息与配置档本身，各须得到哪些保护？

一条消息在更新用户配置档，更新后的配置档留在终端上。这涉及两个不同的保护对象：

- **管理交换。** R-5.12-008 针对某些可能干扰目标 MCX 终端运行的信息交换。用户配置档管理、终端禁用指令是条文给的例子。受监管约束，业务须提供手段，支持这些交换的**机密性、消息完整性、来源认证**。验证的是交换信息的来源；只证明用户已经登录，不能回答这个问题。这不是所有消息的共同要求；受监管约束也不等于部署方可自行省略这项能力。[§5.12，印刷页 25](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=26)
- **配置档本身。** R-5.12-014 要求业务给 MCX 用户配置档提供**端到端机密性和完整性保护**。无论是传往或传出 MCX 服务器、MCX 终端，还是保存在其中一方或双方，都要保护。只说明传输受保护，还不能回答终端里那份档如何受到保护。本条没有要求两端都保存副本，也没有给配置档本身另列来源认证或监管限定。[§5.12，印刷页 26](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=27)

这两条属于 [TS 22.280 V16.8.0（Release 16，Stage 1）第 5 章的在网、离网共同要求，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。-008 在三项业务的规范性适用表内都按原号出现。[附录 A 的表前说明（印刷页 62）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=63)说明，表 A.1 穷尽列出适用于 MCPTT 的要求。核对 -014 时要看印项：[表 A.1（MCPTT，印刷页 64）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65) 的 §5.12 在 `R-5.12-013` 后印的是 **`R5-12-014`**；[表 B.1（MCVideo，印刷页 75）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76) 和 [表 C.1（MCData，印刷页 86）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87) 则写作 **`R-5.12-014`**，与正文一致。A.1 的印项可从所在节和尾号与正文对照，但不能说三表逐字相同，也不能把这一处写法读成 MCPTT 明确不适用。

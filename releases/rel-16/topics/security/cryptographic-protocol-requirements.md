# 在网业务引入新密码方法，所有终端都得一起升级吗？

不必。假设调度中心要引入新的密码方法，但部分终端下个月才能升级。MCX 业务须允许分批升级：不能因为引入了新的密码运算和方法，就使原有的运算和方法作废；也不能把所有终端同时升级作为前提。[R-6.13.2-002，印刷页 44](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45) 没有规定旧方法要保留多久，也没有保证随便选两台不同版本的终端就能互通。

**新方法可以怎样选？** MCX 业务须采用开放的密码标准，选用时还要遵守当地适用的政策。[R-6.13.2-001，印刷页 44](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45) 以 FIPS 140-2 为例，不能据此把 FIPS 140-2 认证列为所有部署的统一门槛。

**允许多套共存，指谁要支持？** [R-6.13.2-003，印刷页 44](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45) 要求的是 MCX 业务能让多种密码套件共存。不能据此要求每台终端都用多套，也不能要求一次会话同时用多套。本项没有规定对端怎样协商或选中某一套。

这里的“一套”有明确含义：一组能配合使用的密码操作，合起来覆盖 MCX 业务需要的全部密码运算。比如业务若需要流加密、消息认证码和安全散列，单列一种加密算法还不算完整的一套。[§6.13.2 注 1，印刷页 44](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45) 用这三类运算举例，并未指定必须选用示例中的算法。套件和算法怎样定义、怎样标识，也不必全部由 3GPP 规定。见[§6.13.2 注 2，印刷页 44](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45)。

**适用范围：**[TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)限定在网业务。规范性表 [A.1（MCPTT），印刷页 68](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=69)、[B.1（MCVideo），印刷页 79](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=80)、[C.1（MCData），印刷页 90](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=91) 都把这三项要求列给相应业务。它们回答业务须支持什么，不规定密钥管理或具体报文：要查终端重启时哪些密钥要保留，读[终端密钥的保留与删除](../identity/ue-key-persistence.md)；要查实际保护的对象，读 [MCData 负载保护与认证](../mcdata/payload-protection-and-authentication.md)或 [MCPTT 在网单播语音与话权保护](../media/on-network-unicast-media-protection.md)。

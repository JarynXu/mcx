# HTTP-1 怎样认证，HTTP-1 和 HTTP-3 对 TLS 各有什么要求？

HTTP-1 的两端须采用规范列出的三种认证方式之一，HTTP-1 也必须支持 TLS。§6.1.3 建议 HTTP 代理之间的 HTTP-3 支持 TLS，采用时须符合指定的 TLS 配置规范。依据是 3GPP TS 33.180 V16.13.0（Release 16）§§6.1.1–6.1.3。

## HTTP-1：谁和谁认证，用哪种方式？

认证发生在 MC 终端（MC UE）内的 HTTP 客户端与 HTTP 服务端点之间。服务端点可以是 HTTP 代理、身份管理服务器（IdM server）或密钥管理服务器（KMS）。须采用下列一种机制；条文不要求三种全用，也没有指定默认项。

- **服务端证书单向认证**：以服务端证书认证 HTTP 服务端点。
- **双向证书认证**：客户端和服务端用各自的证书做双向认证。
- **预共享密钥（PSK）双向认证**：用预共享密钥做双向认证。

证书认证须遵循 TS 33.310 §§6.1.3a、6.1.4a 的配置规范。证书使用的公钥基础设施（PKI）结构不在本规范范围内。TS 33.222 附录 B 提供双向证书认证的指导。TLS 预共享密钥密码套件的用法见 TS 33.310 附录 E，不是第四种认证方式。[§6.1.1，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

## HTTP-1：须支持 TLS；PSK 有额外条件

HTTP-1 必须支持 TLS。TLS 的实现和使用须遵循 TS 33.310 附录 E。**若支持基于 TLS 的 PSK 认证**，MC UE 内的 HTTP 客户端和 HTTP 代理还须支持该附录指定的 TLS 版本、PSK 密码套件和 TLS 扩展。这个条件不是要求所有部署都支持 PSK，也不改变上一节列出的服务端点。[§6.1.2，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

## HTTP-3：代理之间建议支持 TLS；用了就须符合配置规范

HTTP-3 在此是两个 HTTP 代理之间的参考点，不是 HTTP/3 协议，也不意味着使用 QUIC。该参考点**建议**支持 TLS。**使用 TLS 时**，实现和使用须遵循 TS 33.310 附录 E。[§6.1.3，印刷页 66](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=67)

只凭这些要求，不能认定某次会话已通过认证、用户已获业务授权，或某段 TLS 覆盖代理后的链路。若要核对有无代理、在哪终止 UE 的 TLS 或两台代理能否转交请求，查 [TS 23.280 的 HTTP 代理与参考点拓扑](../identity/csc-http-proxy.md)。那一页的功能拓扑与本页的安全要求回答不同的问题。

# KMS 初始化、取新密钥和取证书：直连与经代理有什么区别？

在 TS 33.180 V16.13.0（Release 16）里，**用 KMSInit 初始化，按需取新的身份密钥材料用 KMSKeyProv，请求外部域证书用 KMSCertCache**。前两种请求可以发给归属 KMS（Home KMS）或迁移 KMS；KMSCertCache 只能发给归属 KMS。请求类型和连接路径是两件事。发请求的密钥管理客户端可以在 MC 终端、MCX 服务器或组管理服务器上，这三类客户端用同一套程序。[§5.3.3 与图 5.3.3-1、5.3.3-2，印刷页 56–57](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=57)

## 先确认这次连接是否经 HTTP 代理

**经过代理。** 客户端经 HTTP 代理建立到 KMS 的安全连接。请求包含用于认证用户的访问令牌，必须带传输密钥标识 TrK-ID，可以带完整性密钥标识 InK-ID。KMS 根据已认证用户和请求应答。公共安全用途下，KMS 必须用 256 位传输密钥 TrK 加密密钥材料本身；响应还可以用 TrK 或 InK 签名。KMS 与代理之间的连接另按 §6.1 保护。[图 5.3.3-1 及步骤 0–2、注，印刷页 56–57](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=57)

**不经过代理。** 客户端直接与 KMS 建立 HTTPS 连接，下表各类请求同样可用。直接连接的请求步骤把 TrK-ID、InK-ID 都列为可带项；KMS 仍按已认证用户和请求应答。可以用 256 位 TrK 另行加密密钥材料，响应也可以用 TrK 或 InK 签名。不能把代理路径的必带标识或公共安全用途下的加密要求直接搬到直连路径，也不能把直连读成无需认证。如果这次使用 TrK 保护材料传输，另核对 [§5.3.2 在印刷页 56 的条件](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=57) 对标识的要求。[图 5.3.3-2 及步骤 0–2，印刷页 57](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=58)

两条路径的 TrK、InK 和各自的 32 位标识（TrK-ID、InK-ID）最初都通过带外渠道分发。

## 按请求目的区分返回内容

下表列的是 §5.3.3 明列的请求目的和成功材料或应答类型。收到地址、证书或新材料，不能据此认定 SIP 注册、MC 业务授权或后续密钥交换已完成。

| 请求 | 用来做什么、发给谁 | 条款列出的应答 |
| --- | --- | --- |
| KMSInit | 向归属或迁移 KMS 发出的首笔用户初始化请求。 | 域参数；可以另带新的 TrK 或 InK，也可以两者都带。 |
| KMSKeyProv | 向归属或迁移 KMS 取新身份密钥材料；可以带所需身份，也可以带所需时间。 | 新密钥材料；也可以另带新的 TrK、InK 或两者。 |
| KMSCertCache | 只向归属 KMS 取外部 KMS 的证书缓存；可以附客户端已收到的最新缓存版本信息。 | 用于和外部安全域通信的新证书或更新后的证书，可能涉及归属 KMS、外部 KMS 或两类。 |
| KMS Cert | 按指定 KMS URI 取一份 KMS 证书。这一项没有另指定接收该请求的 KMS 角色。 | 采用 KMSCertCache 响应，返回单份证书或错误。 |
| KMS Lookup | 用 SIP URI 查应该使用的外部 KMS。SIP URI 是查询输入。 | 返回这个用户应使用的 KMS URI，或允许使用某个特定外部 KMS。 |
| KMS Redirect Response (KRR) upload | 把收到的 KRR 上传给归属 KMS。本步骤只允许向归属 KMS 发这类上传。 | 这里未另列应答。 |
| KMS Redirect Upload | 把收到的发现请求应答上传给 KMS 作审计。这一项没有另指定接收该上传的 KMS 角色。 | 这里未另列应答。 |

依据：[请求步骤 1(a–f)，印刷页 56](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=57)；[请求步骤 1(g) 与应答步骤 2(a–e)，印刷页 57](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=58)。KMSKeyProv 的可选时间说明这笔请求可指明所需时间，不能据此推定固定轮询时间、换证期限或撤销流程。两种上传不是同一个请求；不能用收到一条上传日志证明 KRR 已处理、发现结果被采纳或审计已入库。

若问题是[跨域交换时谁生成 KRR、怎样选择安全域](../identity/kms-redirect-response.md)，查交换程序。若要核对[HTTP 参考点认证与 TLS](http-reference-point-security.md)，按该连接查对应范围。若问题是[终端已有密钥在重启、退出或过期后该留还是该删](../identity/ue-key-persistence.md)，查存放材料的规则。

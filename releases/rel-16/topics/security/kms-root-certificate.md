# KMS 根证书更新时，需要换 KMS URI 吗？

如果需要更新的是 KMS **自己的根证书**，TS 33.180 V16.13.0（Release 16）建议设立新的逻辑 KMS，使用新的 KMS URI 和新的根证书。这是 **SHOULD**，不是必须更换物理服务器的要求。条款没有规定什么事件触发根证书更新，也没有给出新旧 KMS 的切换步骤。[附录 D.3.2.1，印刷页 147](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=148)

## 先确认哪张证书是这个 KMS 的根

KMS 证书适用于一个域的用户，包含给该域用户加密消息和核验该域用户签名所需的信息。同一个 KMS 在任一时刻有且只有一张根证书。根证书含该 KMS 使用的公钥。在它供应的 KMS 证书中，只有自己的根证书对应由它持有的私钥。它可据此签发与用户身份关联的密钥材料。

本段假设一名用户由单一 KMS 管理。给该用户加密消息、核验其签名，需要这个管理方的根证书。KMS 还可以供应外部 KMS 的证书，用于跨域通信。它能供应外部证书，不表示它有外部根证书的私钥，也不表示这个 KMS 同时有多张自己的根证书。[附录 D.3.2.1，印刷页 147](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=148)

## 对照：收到相同 CertUri 的证书，替换的是记录

[§5.3.5，印刷页 58](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=59)说的是客户端处理新收到的证书：证书由 KMS URI（`KMSUri`）和唯一的证书 URI（`CertUri`）标识。收到的证书与已有证书的 `CertUri` 相同，客户端须用收到的证书替换已有证书。这是证书记录的处理规则，不能据此认定根证书发生了更新，也不能拿它代替 D.3.2.1 对根证书更新的建议。

如果要查[证书缓存与单张证书分别怎么请求](kms-provisioning.md)，读供应流程；如果要查[外部 KMS 的证书向谁取得](kms-domain-roles.md)，按 KMS 角色判断。这里只给出根证书更新时的建议，不规定何时续期、撤销或删除旧证书。

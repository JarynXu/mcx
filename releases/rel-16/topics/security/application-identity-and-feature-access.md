# MCX 用户身份与 IMSI 有什么关系？一次认证后可以使用哪些功能？

**IMSI 标识移动网络订户，不能代替 MCX 用户身份。** R-5.12-002 要求 MCX 业务支持具有全球唯一身份的用户，这些身份独立于 3GPP 运营方分配给终端的 IMSI。接下来的两条说的是 **MCX 业务身份**：它们属于 MCX 业务的应用服务域（R-5.12-003），是该业务应用层安全的基础（R-5.12-004）。本节没有规定标识符的格式；能指认一个身份，也不等于已经验证了该身份。[§5.12，印刷页 25](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=26)

**终端已经获授权，用户还没认证。** 业务须有办法让这台终端访问**选定的功能**（R-5.12-006）。不能省掉“终端已获授权”这个条件，也不能把“选定”读成“全部”。本条没有列出这些功能或指定由谁选择。[§5.12，印刷页 25](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=26)

**何时能访问这个用户获准使用的全部功能？** 授予这项访问权之前，业务必须先要求认证用户（R-5.12-007）。紧随其后的附注说明，可用功能取决于已认证的用户身份。业务还须为用户提供一次认证便可访问所有**已获授权**功能的机制（R-5.12-005）。举例说，甲只有两项功能的权限，规范要求甲能通过一次认证使用这两项，并未借这次认证授予甲第三项权限。它也没有规定认证永久有效或多台设备共用一次登录。[§5.12，印刷页 25](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=26)

这里认证的是用户。若终端要求验证在网 MCX **业务自身**的身份，认证对象已经变了。本主题属于[TS 22.280 V16.8.0（Release 16，Stage 1）第 5 章的在网、离网共同要求，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。这些编号均见规范性[表 A.1（MCPTT，印刷页 64）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65)、[表 B.1（MCVideo，印刷页 75）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76)和[表 C.1（MCData，印刷页 86）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87)。

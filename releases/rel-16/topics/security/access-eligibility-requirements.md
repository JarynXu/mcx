# 用户配置档被暂停，还能用它接入吗？用户能归属或选定已禁用的组吗？

**不能再用那份档接入，也不能归属或选定已禁用的组。** 判断一次访问受什么限制，要先看受限的是终端、用户、一份配置档，还是用户要操作的组。

| 控制哪个对象 | 业务必须满足什么要求 |
| --- | --- |
| 终端或用户的业务访问 | 业务必须支持暂停或禁用来自一台 MCX 终端或一名 MCX 用户的业务访问。这是业务要有的能力；条款没有要求每次都执行，也没有要求删除用户配置档。见 [R-6.13.4-001](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45)。 |
| 一份 MCX 业务用户配置档 | 如果用户的这份档已删除或暂停，必须阻止该用户用**这份档**访问业务。即便同一用户另有一份档，本条也不能判定另一份档可用或不可用，更不能据此判定终端已被禁用。见 [R-6.13.4-002](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=45)。 |
| 用户要归属或选定的业务组 | 业务只可允许用户归属到**已启用的组**，或选定已启用的组。启用是必要条件：单凭启用状态，不能判定该用户已经获准、已经归属或已经选定该组。见 [R-6.13.4-004](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=46)。 |

组从禁用改为启用，并不会仅因这条要求就自动成为某人的选定组。反过来，-004 也没有说明一个已有归属的组被禁用时，是否要解除原有归属。若问谁能按条件自动归属或选定，见[在网动态组参与](../groups/onnetwork-dynamic-group-participation.md)。

如果改的是一份**仍可使用**的用户档，见[用户配置档的修改和安装](../identity/user-profile-management-requirements.md)；如果要判断整台终端暂时或永久禁用后的结果，见[终端禁用](ue-disable-requirements.md)。

这些是 [TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30) 的在网要求。规范性表 [A.1（MCPTT），印刷页 68](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=69)、[B.1（MCVideo），印刷页 79](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=80)、[C.1（MCData），印刷页 90](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=91) 均列出 §6.13.4 的十项要求。

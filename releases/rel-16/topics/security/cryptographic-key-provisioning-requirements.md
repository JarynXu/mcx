# 密钥管理须支持哪两种供给方式？经空口交付时要保护什么？

**只支持预置，不支持从空口提供密钥，并不满足对密钥管理服务的要求。** R-5.12-011 要求 MCX 业务在监管约束下提供一项或多项密码密钥管理服务。对这些服务，R-5.12-012 要求**同时支持**预置和空口供给两种方式；没有要求同一把密钥用两种方式各交付一次，也没有要求另设一台独立服务器。[§5.12，印刷页 26](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=27)

若密钥经空口交付，R-5.12-013 要求服务确保**所交付的密钥**得到机密性和完整性保护，并经过认证。只有保密措施不够，用户或终端已经通过认证也不能替代对密钥的认证。这一条给空口交付规定了三项保护，不是让管理员任选一项，也没有借此规定预置密钥使用同一套方法。[§5.12，印刷页 26](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=27)

这里的在网、离网共通要求不等于离网终端随时能连上在线服务，条文也没有指定密钥格式、协议消息或特定算法。本主题属于[TS 22.280 V16.8.0（Release 16，Stage 1）第 5 章的在网、离网共同要求，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。这些编号均见规范性[表 A.1（MCPTT，印刷页 64）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65)、[表 B.1（MCVideo，印刷页 75）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76)和[表 C.1（MCData，印刷页 86）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87)。

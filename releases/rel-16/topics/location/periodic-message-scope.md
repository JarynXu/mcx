# 同组有多项业务，终端又归属多个组：一条周期位置消息适用于谁？

先分清问的是**哪项业务**，还是**哪个组**。Rel-16 要求 MC 业务提供配置和相应能力，使已发的位置消息可以适用于条款列出的全部对象，也可以只适用于一个指定对象。“部分或全部需要周期位置消息”是这项要求成立的条件，不是这条消息的收件人名单。

| 条款 | 什么时候适用 | 每条已发的位置消息适用于谁 |
| --- | --- | --- |
| R-8.4.6-001：按业务 | 终端已归属一个共用 MC 业务组，该组使用的 MC 业务中有部分或全部要求周期发送位置消息。 | 可配置为适用于该组使用的全部 MC 业务，或只适用于其中一项指定的 MC 业务。 |
| R-8.4.6-002：按组 | 终端已归属多个组，部分或全部组要求周期发送位置消息。 | 可配置为适用于终端已归属的全部组，或只应用于某一个指定的组。 |
| R-8.4.6-003：按共用 MC 业务组 | 终端已归属多个共用 MC 业务组，其中部分或全部共用组要求周期发送位置消息。 | 可配置为适用于终端已归属的全部共用 MC 业务组，或只应用于其中一个指定的共用 MC 业务组。 |

这三项都是 [3GPP TS 22.280 V16.8.0 §8.4.6，Release 16，Stage 1，印刷页 60（PDF 第 61 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=61) 的能力要求。条款没有指定默认选哪项，也没有给出三条之间的优先级或业务范围与组范围的组合规则。

**只有一项业务要周期位置，“全部”包括谁？** 假设终端已归属共用组 G，G 使用 MCPTT、MCVideo 和 MCData，只有 MCPTT 要求周期位置。按 -001，适用范围仍可配置为这三项业务，也可只指定 MCPTT。不能把“全部”缩成提出周期需求的业务。若要把一条消息指定给语音和视频、排除数据，-001 没有说明必须支持这种任选两项的配置，也没有禁止它。

**“全部组”和“全部共用组”可能是两个范围。** 设终端已归属普通组 X，以及共用组 C1、C2、C3。若只有 C1 要求周期位置，-002 所说的全部已归属组包括 X 和三个共用组；-003 所说的全部共用组是 C1、C2、C3，不包括 X。若改为只有 X 要求周期位置，-002 的条件仍成立，-003 所要求的共用组周期需求却不成立。若终端仅提交了归属 C1 的请求，不能把请求当成已归属的证据。[归属请求、许可与实际归属状态](../groups/common-group-service-affiliation.md)要分开判断。

**抓到一条报告，没看到给每项业务各发一份，能判漏发吗？** 不能。要判断这条消息适用于谁，需要知道当时的归属、谁要求周期位置，以及为这条消息选定的适用范围。§8.4.6 没有规定每个周期发几包、如何编码或分发，也不以“适用于”授予读取位置的权限或证明已经送达。查终端何时上报，读[位置上报配置与触发](event-reporting-configuration.md)；查调度订阅了谁、何时有通知，读[用户位置订阅](user-subscription.md)；查 MCPTT 如何传送位置报告，读[参与功能与终端的位置消息](mcptt-participating-location-signaling.md)。

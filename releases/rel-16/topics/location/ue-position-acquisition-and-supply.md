# 终端位置必须有多准？由谁控制供应，传送时用哪一次取得的位置？

传送位置时，看的是**到传送那一刻为止，最近取得的是哪一份**。如果终端先后取得两份位置信息，就不能舍近用远。只有先前的一份时，[R-5.11-006，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25) 没有要求为这次传送再测一次，也没有规定位置最多能有多旧。这一条不能证明所传位置就是终端此刻的实际位置，也不要求保存位置历史。

## 普通位置与高精度位置

| 要判断的能力 | 业务要求 |
| --- | --- |
| 取得和传送描述 MCX 终端位置的信息 | 必须支持。见[R-5.11-001，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)。 |
| 取得和传送终端的高精度位置 | 建议支持（should）。见[R-5.11-002，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)。 |
| 提供取得高精度位置的机制 | 必须能提供（shall be able to provide）一种融合多个外部来源定位信息的机制。磁力计、姿态传感器、GNSS 是示例，不是必装清单。见[R-5.11-002a，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)。 |

后二者约束不同：有义务提供多来源融合的**取位机制**，不等于每次都要靠它取位，或每次都要**传送高精度位置**。这几项没有给精度指定米数。至于格式，[R-5.11-003，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25) 要求传送能力能适应将来的位置信息格式，未指定一种必选编码。

## 谁管隐私，谁控制供应？

**管理员**须有手段管理其职权范围内 MCX 用户的位置信息隐私；这没有赋予所有管理员读取任何用户位置的权利。**获授权的 MCX 用户**须能控制终端为 MCX 业务通信提供位置信息。两条所说的操作者、被控制的事项都不同。见[R-5.11-004、R-5.11-005，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)。若问题是在网时哪些接收终端可得到位置、用户怎样限制自己位置的传播，另查[在网位置共享与报告控制](onnetwork-location-sharing-and-report-control.md)；若关心何时产生更新，查[终端位置更新的触发条件](update-triggers-and-predefined-areas.md)。

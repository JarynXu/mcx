# 初次注册会要求 LMS 下发位置配置吗？什么条件下终端才上报？

Rel-16 在网、单一 MC 系统的事件上报流程中，**首次提供上报规则或要更新规则时**，位置管理服务器（LMS）可以给位置管理客户端（LMC）发配置。规则已放在用户配置档里，就不需要另发这条消息。**初次注册是客户端可能据以发送位置报告的事件**，本程序没有要求 LMS 因注册成功就另发配置。如果生效的规则只按移动距离上报，注册本身既不要求 LMS 推配置，也不触发 LMC 报位置。这几条没有给首次配置绑定一个注册步骤或规定“注册后几秒必发”，也没有把这里的注册指定为 IMS 的 SIP 注册、向 LMS 的 HTTP 注册或 MC 业务授权。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.9 标题、§10.9.1：在网位置管理及按配置触发，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.1 注 1 及引言：单系统范围、触发示例，印刷页 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[步骤 1、注 2–3，印刷页 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)

**一份上报配置里，哪一行回答“报什么”，哪一行回答“何时报”？** 表 10.9.2.1-1 是 LMS 发给 LMC 的在网配置信息流。读普通配置时，先认目标，再看五个可选项。此处“普通配置”指供给或更新规则、并非取消；同一张表也列紧急场景。

| 普通配置中的信息 | 状态 | 怎么读 |
| --- | --- | --- |
| MC 业务用户标识或 MC 业务组标识 | M（必备） | 指定这份配置给哪个用户或组，不是二者都要填。 |
| 非紧急时请求的位置信息 | O（可选） | 除紧急呼叫、紧迫危险呼叫（imminent peril call）和紧急告警外，LMS 要 LMC 报哪些位置资料。 |
| 紧急时请求的位置信息 | O | 在上述三种情形中，LMS 要 LMC 报哪些位置资料。配置写的是所求资料，不是已经测得的位置。 |
| 非紧急时的触发条件 | O | 非紧急时，LMC 遇到什么事件才发送位置报告。 |
| 连续报告之间的最短间隔 | O | 限制同一 LMC 向 LMS 连续上报的间隔；这项不决定报告的内容，也不产生触发事件。 |
| 紧急时的触发条件 | O | 紧急时，LMC 遇到什么事件才发送位置报告。 |

**最短间隔取 0，不等于现在就报。** 确认拿到完整的普通配置，其中没有“最短间隔”一项，才可按缺省值 0 解读；其他元素在，不能作取消处理。只看了一段配置、没见这一行，还不知道它是否缺省。紧急呼叫、紧迫危险呼叫、紧急告警三种情况下，这个最短间隔都是 0，不沿用非紧急时的非零下限。0 表示不必为这个下限再等，并不约定上报周期。表中没有给这个数值标单位。[§10.9 标题、§10.9.2.1 及表 10.9.2.1-1（含表注），印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)。

在单系统事件上报程序中，仍要看生效的触发条件。假设终端只按移动距离上报，距离还未达到：即使最短间隔为 0，用户刚注册，也不能据此要求 LMC 立即发报告，或断言 LMS 已推配置。反过来，只为判断配置表的 M/O 和零值，不必先证明某个终端已经发生触发事件；“仅适用于单一 MC 系统”是事件程序注 1 的限定，不是该表另列的条件。[§10.9.3.1 注 1、触发示例，印刷页 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[步骤 1–3，印刷页 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)。

**若问的是调度方何时收到通知，要换一张表。** 终端上报的接收方是 LMS。单系统的用户位置订阅里，间隔是订阅请求表中的**必备项**，没填不能当成 0。已订阅且该项填 0 时，LMS **收到清单内某个用户的位置报告**，才按这条零值规则立即向订阅方发对应的位置通知，不是从订阅成功算起。只见终端发出，不证明 LMS 已收；要求 LMS 发通知，也不证明订阅方已收。见[用户位置订阅](user-subscription.md)及[表 10.9.2.5-1 及表注，印刷页 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)、[§10.9.3.5，印刷页 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)、[§10.9.3.6.1 步骤 1–2，印刷页 172](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=173)。

**没有看到发给甲的单播，要查什么？**给特定客户端可以走单播；给多个客户端同时更新，可以在 MBMS 承载上发组消息。还要查甲使用的用户配置档是否已含这套规则。例如，甲的档里已写明按移动距离上报，没看到注册后另发配置，不是缺陷。若更新发往甲所在的组，LMS 的发送记录能证明发出过组更新，但不能代甲确认收到；其他客户端也不必与甲使用同样的上报条件。[§10.9.2.1，表 10.9.2.1-1，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.1 步骤 1、注 2–3，印刷页 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)

**注册后看到一份位置报告，谁做了什么？** 看报告中记录的触发事件。初次注册、收到配置、移动达到设定距离、经过设定时间都属于可能的触发，不能凭两条记录时间相邻就选定原因。满足适用的触发条件后，LMC 向 LMS 发送报告，提供服务器要求且客户端能取得的位置资料。报告中的上报用户 MC 业务标识集合、触发事件、位置信息均为必备；功能别名为可选。单凭发送记录，不能说 LMS 已经更新位置。LMS **收到**后，要看有没有本次上报的这个 LMC 的旧位置：有就更新，没有就首次存入。即使同一用户名下另一台终端已有旧位置，也不能算作本次上报客户端的旧记录。即使存入，也只是本次上报的数据，不是对终端实际坐标的独立测量。[§10.9.2.2，表 10.9.2.2-1 及表注，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.1 引言，印刷页 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)及[步骤 2–4，印刷页 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)

**取消上报时，为什么仍叫“配置”？** 取消程序的前提是这个 LMC 已获得**位置上报配置**。LMS 再给它发一份同类型的位置上报配置，这次不带任何信息元素；该 LMC 停止向 LMS 发送位置报告。只知道终端先前有一般设备配置，或只见一条类型不明的空消息，都不能按此程序判定取消。普通配置表把目标用户或组标为必备，表注和取消步骤另说无信息元素代表取消。少一个可选项不是“所有元素都没有”，也不能用普通表的目标行推翻取消步骤。这里的“无信息元素”说的是 Stage 2 信息流，不是让开发者构造空 HTTP 请求或空 SIP 消息。停止这一路报告也不表示终端关闭定位、服务器删除旧位置，或另一业务的订阅被撤销。[§10.9.2.1 表及表注，印刷页 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.4 前提，印刷页 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)及[步骤 1–2，印刷页 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)

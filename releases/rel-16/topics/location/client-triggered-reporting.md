# 甲想知道乙的位置：甲发的上报触发，和向乙立即索要报告，是同一条请求吗？

不是。甲的位置管理客户端（图中 LMC 2）向位置管理服务器（LMS）发**位置上报触发**，请服务器启动程序，取得乙的位置。若 LMS 随后向乙的位置管理客户端（LMC 1）索要一份即时报告，发的是**位置信息请求**。前者说“请为乙启动上报”，后者说“现在向我报告”。即使甲在触发里明确要求立即报告，也没有把第一条变成第二条。这是 3GPP TS 23.280 V16.7.0、Rel-16 Stage 2 的在网位置管理；图示客户端触发程序只适用于单一 MC 系统。[§10.9 标题，印 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§§10.9.2.3、10.9.2.4 引言，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；[§10.9.3.3 注、图及步骤 1–2，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)。

## 甲发的触发里，怎样认出请求者、目标和要求？

表 10.9.2.4-1 连续两行都叫 MC service ID，第一行是**请求者**：须有已获授权的请求用户的 MC 业务 ID（M，必备）。第二行才是**目标用户**的 MC 业务 ID，标 O（可选）；其下一行是对应目标用户的功能别名，也标 O。注 3 要求目标 ID 或目标别名必须出现其一，不能两者都缺。只填目标别名可以满足这项要求，不能代填甲的 ID。表没有规定两项**同时出现**时如何处理；不能据此判同时带一定合规或一定违规。注 1 说请求用户和目标用户的身份**应**属于同一 MC 业务（should），如甲用 MCPTT ID，乙的身份也应属 MCPTT。这不是强制两行 ID 都出现，也没规定遇到跨业务 ID 时服务器必定怎样响应。[表 10.9.2.4-1 前三行、注 1 和注 3，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)。

下列六行分别标 O；**就这六行合起来看，至少一行须实际出现，也可多行并用**。身份或目标行不计入这六行。[表 10.9.2.4-1 后六行及注 2，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)。

| 触发中的项目 | 它告诉 LMS 什么 |
| --- | --- |
| 立即报告指示 | 这次是否要求立即报告；看到指示这一项，不等于它的值是“是”。 |
| 非紧急时请求的位置信息 | 除紧急呼叫、紧迫危险呼叫、紧急告警外，想取得哪些位置资料。 |
| 紧急时请求的位置信息 | 遇到上述三种情形时，想取得哪些位置资料。 |
| 非紧急时的触发条件 | 非紧急时，客户端何时发报告。 |
| 紧急时的触发条件 | 紧急时，客户端何时发报告。 |
| 连续报告之间的最短间隔 | 完整触发没有这项时，取 0；紧急呼叫、紧迫危险呼叫和紧急告警时为 0。 |

例如，完整触发只有甲的业务 ID 和乙的功能别名。目标已指明，但六行一项也没有，**不能拿缺省的 0 算作出现了一行**。改为显式带最短间隔 0，这一行就满足注 2；它没有要求“立即向乙索取报告”。只拿到删列的摘要时，不能凭未显示就判字段缺失。也别把空触发当作取消上报：取消用的是 LMS 给先前已获配置的 LMC 发的**无任何信息元素的位置上报配置**，方向和信息流都不同。[表 10.9.2.4-1 间隔行、注 2，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；[§10.9.3.4 前提，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)；[同节步骤 1–2，印 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)。

## 什么时候改按“立即索要报告”这张表验？

要同时看**谁发给谁**和**这条消息让收件方做什么**。表 10.9.2.3-1 描述的是索要一份即时位置报告的位置信息请求，方向是 **MC 业务服务器 → LMS** 或 **LMS → LMC**。对这张表，两行就够核对：所请求的目标用户 **MC 业务 ID 清单是 M**；所请求的一个或多个功能别名是 O。只有别名、没有目标 ID 清单，不满足这张表；不能借用触发表注 3。反过来，单凭 LMS 发给乙一份即时请求，不能认定此前一定是甲发了触发：在按需程序中，服务器也可依配置决定索取。验这两张信息流表本身，不必先证明现场已经运行了单系统示例。[§10.9.2.3 引言及表 10.9.2.3-1 全表，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；[§10.9.3.2 注及步骤 1–2，印 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)。

**只知道“甲的 LMC 发给 LMS，甲急着要乙的位置”，先不选表。** 若确认这条消息请 LMS 为乙启动上报程序，那才是客户端触发；若确认它是单系统 §10.9.3.6.2 的按需查询，甲是请 LMS 提供乙的最新位置。后一个程序也有 LMC → LMS 的位置信息请求，不能按这条箭头认成触发，更不能拿表 10.9.2.3-1 验这条表中未列的方向。查请求方实际发起了哪个操作，或查能与本次对应的程序记录。即使能确认 LMS 随后向乙取过位置，也不能反推出甲最初发的就是触发。[§10.9.2.3、§10.9.2.4 引言，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；按需查询见[订阅用户位置中的独立按需查询](user-subscription.md)及[§10.9.3.6.2 引言、图，印 172](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=173)、[步骤 1–4，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)。

反方向也一样：LMS 给乙发普通上报配置，写明非紧急时要报哪些资料、何时上报，是**配置规则**，不是正在向乙索要一份即时报告。同是 LMS → LMC，已经确认是规则配置，就查[终端上报配置](event-reporting-configuration.md)和[§10.9.2.1 引言及表 10.9.2.1-1，印 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；不知道消息作用，就不能只按方向断定是配置还是即时请求。

## 值班记录到哪一步，能确认什么？

在单系统示例里，LMS **查甲是否有权发这次触发**，再依触发内容，为乙启动**按需上报**或**事件触发上报**。甲的 ID 出现在触发里、甲的触发抵达 LMS、LMS 查明甲获准，是三件事。图没有给出把每种字段组合映射到分支的算法，也没有画出把乙的坐标交给甲的步骤。[§10.9.3.3 注、图 10.9.3.3-1 及步骤 1–2，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)。

- **选了按需。** LMS 向乙索取报告，乙的用户会被询问是否同意共享，可以同意，也可以拒绝。记录若只有“甲获准、LMS 已向乙发请求”，仍不知道乙的选择。若另有乙明确同意的记录，能确认许可，不能登记报告已到。乙的 LMC 发出的报告包含 LMS 所求且乙能取得的资料；只有能对应本次的 LMS 收件记录，才可据此确认它已收到。程序要求 LMS 收到后更新乙这个 LMC 的位置；此前没有就存入。要确认实际写入或甲已收到结果，还需相应证据。[§10.9.3.2 图及步骤 2–3，印 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)；[同节步骤 4–5，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)。
- **选了事件触发。** 查乙所用的上报规则和实际事件。例如规则只按移动距离触发，乙尚未达到门槛，不能因甲已获准就判乙该报了。达到门槛才有该事件；证明事件发生，仍不同于证明乙已发送或 LMS 已收到。不要把按需分支询问乙的步骤硬套在这个分支上。[§10.9.3.1 注 1、引言及事件示例，印 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[同节步骤 1–4，印 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)；[§10.9.3.3 步骤 2，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)。

若工单实际问的是 LMS 怎样给乙配置、更新或取消上报规则，读[终端上报配置](event-reporting-configuration.md)。要查按用户名单建立的订阅、通知或退订，读[订阅用户位置](user-subscription.md)。若 LMC 向 LMS 发的是 §10.9.3.6.2 的独立按需查询，也看该页的按需用位置段；LMS 可向目标取最新位置，也可从运营方取得。得到这次查询的结果，不证明原订阅发过通知。若甲要找的是**已激活同一功能别名的多个用户**，并需判定每人的位置、迟到的报告或别名交接后的周期上报，读[按共享功能别名查位置](active-alias-trigger.md)。这里核对的是功能角色和信息内容，不据此指定线上报文或注册方式。

# 乙、丙共用“北站值班”，甲查这个别名的位置，地图上该标谁？

“北站值班”用来找人，它本身没有一个供两人共用的坐标。乙、丙都在 MCPTT 中激活了这个功能别名，甲就能在**一次针对 MCPTT 的触发中**请求两人的位置；能否发起这次查询，要由位置管理服务器（LMS）检查。即使乙另有 MCVideo 身份，本次触发也不能顺带取那个身份的位置。一次性与周期性是两种取数方式，都只针对一项 MC 业务。[3GPP TS 23.280 V16.7.0，Rel-16，Stage 2，§10.9 在网范围，印 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.8.1 步骤 1–2，印 174](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=175)；[§10.9.3.8.2 步骤 1–2，印 175](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=176)。

**开始前已有一项订阅，但订的不是坐标。** 在这里讨论的同一 MC 系统内，MC 业务服务器已向负责控制该功能别名的 MC 业务服务器订阅别名的激活和停用更新。乙、丙既共享目标别名，也都已激活它。甲的业务客户端不必有自己的已激活别名；如果有，甲的位置管理客户端（LMC）可以把它一并带在发给 LMS 的触发里。甲自己的别名和甲用来指向乙、丙的目标别名用途不同。LMS 检查**甲的 LMC 有没有权发这个触发**。只看到业务服务器订了别名状态，不能登记甲已获准查询、已向 LMS 订阅乙丙的位置，或已取得任何人的位置。[§10.9.3.8.1 前提 1–4，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)；[同节步骤 1–3、§10.9.3.8.2 前提 1–4，印 174](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=175)；[周期步骤 1–3，印 175](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=176)。

## 只查这一次：乙先报，不必把乙的位置填给丙

获准后，LMS 分别对乙、丙的 LMC 启动按需上报，发给它们的位置请求含甲所查的“北站值班”。被调用的按需程序还会询问目标用户是否同意共享位置，用户可同意或拒绝；甲通过权限检查不等于乙、丙都已同意。LMS **收到哪一端的报告，就更新哪一端的位置**；此前没有该端的记录，就为该端存入这次报告的位置。[§10.9.3.8.1 图 10.9.3.8.1-1、步骤 2–4，印 174](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=175)；[§10.9.3.2 注及步骤 2–3，印 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)。

收到报告是上面所述正常流程的一步。若无法验证报告的访问令牌，另查[位置令牌与失败处置](lmc-lms-access-token.md)；不能凭收件断定该端位置已更新或存入。

LMS 给甲的响应汇集目标端**已经提供**的位置。若乙先报、丙迟报，可以先回乙的结果，丙报来后**可以**再发响应。“一次”指这次按需取位置，不是“必须只发一份响应”。不能把丙的沉默判成拒绝，也不能把第一份响应当作全员到齐。条文没有设定等待秒数或要求每个迟报者一定单独补发。若日志只到“LMS 收到丙的报告”，能确认的是 LMS 已收到；要证明补发或甲已收到，还得分别看到相应记录。[§10.9.3.8.1 引言，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)；[同节步骤 4–5，印 174](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=175)。

## 改为周期上报：丙停用、丁接班，分别改谁？

LMS 在检查甲的触发权限后，依触发内容采用事件触发上报程序，**立即向目标 LMC 发出带所求别名的位置请求**。“立即”指发请求，不是立即收齐位置，也不是立即给甲一组新坐标。LMS 收到各端报告后，更新各自的位置，再根据已收到的报告周期性地向甲发响应，列出目标 MC 业务 ID、关联别名及各 ID 自己的位置。这几步没有给出固定秒数。[§10.9.3.8.2 图 10.9.3.8.2-1、步骤 1–5，印 175](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=176)。

假设已确认“北站值班”对丙停用、对丁新激活，乙仍在使用。丙的 LMC 停止为这个别名发周期位置报告；LMS 为丁的 LMC 启动位置上报；乙的 LMC 继续报。多人同时共享时，各端报到该别名**对各自的业务 ID**发生状态变化为止，接管是一个例子。别名状态改变了谁应报告，但“丁已激活”不是“LMS 已收到丁的位置”。它也不要求把丙的历史位置删掉、让乙停报，或撤销另一个按用户名单建立的位置订阅。只有接管提议、没有已生效的状态变化时，不按已交班登记。[§10.9.3.8.2 注 1–3，印 175](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=176)；若要判断接管是否已生效，见[功能别名接管](../identity/functional-alias-takeover.md)。

周期步骤中，若收到的 LMC 报告无法验证访问令牌，另查[位置令牌与失败处置](lmc-lms-access-token.md)。TS 33.180 允许本地策略规定处置；仅见收件不能确定这份报告是否用于更新位置或周期响应。

**只有一份响应，没有激活记录，还能验什么？** 只要已确认这是按功能别名取位置时由 LMS 发给请求方 LMC 的位置响应，就能直接按表 10.9.2.10-1 核字段。即使没拿到乙、丙激活同一别名的记录，也没拿到业务服务器预先订阅别名状态的记录，仍可做这项核验。这些记录关系到能否确认上文两种程序的前提，不是读这张表的门槛。字段符合表，也不能反证多人已激活、服务器已订状态，或这就是一次周期响应。上报用户的 MC 业务 ID 集、触发报告的事件、对应的位置信息集三项必备（M）；功能别名这一行在通用表中可选（O）。表注把每份位置对应到所属业务，若有关联别名，还要对应这个别名。周期程序步骤 5 则明说其响应包括各目标业务 ID、关联别名和各自的位置：不能用表中一个 O 删掉这句，也不能把周期步骤倒推成所有响应的别名行都是 M。共享者名单用来确定要找谁；只有可对应到具体上报者的位置，才可作该人的本次位置记录。[§10.9.2.10、表 10.9.2.10-1 及注，印 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[§10.9.3.8.2 步骤 4–5，印 175](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=176)。

若输入是用户标识清单、问题是订阅和退订，读[向 LMS 订阅用户位置](user-subscription.md)；若查终端依据什么配置上报、怎样取消终端上报，读[位置上报配置](event-reporting-configuration.md)。只想查哪些用户激活了别名、不需要坐标，读[当前别名使用者查询](../identity/active-functional-alias-lookup.md)。本页依据指定版本的在网 Stage 2 流程，不据此构造线上报文或判断其他 Release。

如果问的是在网业务必须支持哪些报告对象，而非这个别名程序怎样运行，见[Stage 1：位置共享与报告启停](onnetwork-location-sharing-and-report-control.md)。

# LMS 按需查位置：请求方获准，等于目标同意吗？返回的位置从哪来？

调度问“乙现在在哪”，LMS 认定调度方有权查询，并不表示乙已同意在终端共享位置。LMS 很快返回一个点，也不能凭速度判断它刚从终端收到报告、从运营方取得结果，还是读到了之前的记录。下面只看 TS 23.280 V16.7.0 的**在网单一 MC 系统**按需流程，不是订阅或客户端触发另一项上报程序。

## 两道许可，分别是谁在作判断？

1. **请求方 → LMS：** MC 业务服务器或请求方的位置管理客户端（LMC）向位置管理服务器（LMS）提交按需位置查询。LMS 检查**发起这个请求的功能实体**是否获准，而不是在这一步代目标用户同意。表 10.9.2.3-1 列了业务服务器 → LMS 与 LMS → LMC 所用的即时位置信息请求：目标 MC 业务 ID 清单必备，功能别名可选。这张表未列请求方 LMC → LMS 的方向，不拿它为该方向增设字段。[§10.9.3.6.2，印 172–173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=173)；[附后步骤 1–4，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)；[表 10.9.2.3-1，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)。
2. **LMS → 目标 LMC：** 如果 LMS 走终端按需上报来取位置，它另向目标 LMC 索要报告。这个流程通知目标用户并询问是否同意共享；用户可同意，也可拒绝。调度已获准、LMS 发出请求、目标端实收及用户的决定，应分别记。§10.9.3.2 接着描述终端报告及 LMS 收件后更新或存入位置，但没有列用户拒绝时的回复、空报告格式、超时或向原查询方返回的错误。目标点了拒绝，不能把该记录登记为同意、报告已到或查询成功，也不应凭这条记录宣布调度收到某个错误码。[§10.9.3.2，图及步骤 1–3，印 169](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=170)；[步骤 4–5，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)。

**查协议先分用途。** 在这两类有明确端点的按需流中，LMC 与 LMS 是 CSC-14，业务服务器与 LMS 是 CSC-15。参考点把订阅／通知相关信令分给 SIP-1／SIP-2，其余信令分给 HTTP-1／HTTP-2。这里是非订阅用途，只据此选 Stage 2 的参考点；不补某个 HTTP 方法、错误码、LMS 注册或线上字段。[§§7.5.2.14–15，印 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)。

## 查到位置结果时，先查 LMS 这次用的是哪份数据

§10.9.3.6.2 步骤 3 列两种取最新位置的来源：启动 §10.9.3.2 的**终端按需上报**，或从 **PLMN 运营方**取得，例如 LCS（运营网位置服务）。随后步骤 4 描述 LMS 将所获位置立即回给查询方。原文没有指定两者的优先顺序，也没写“调度鉴权失败或目标拒绝时自动改用运营方”。不要把第二种来源当成绕过许可失败的分支。[§10.9.3.6.2，图及步骤 1–4，印 172–173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=173)（[取数及返回，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)）。

| 工单中的说法 | 找什么证据 |
| --- | --- |
| “取自这次终端上报” | 找到 LMS **实收**的目标 LMC 报告，核对目标、触发事件及实际位置，再对上本次查询用的值。LMC → LMS 的报告表列报告用户的 MC 业务 ID 集合、触发事件、位置信息为必备；不能把此表当成 LMS 回给调度的响应格式。终端报告可含它能取得的相关位置，不保证刚做一次 GPS 定位。 |
| “取自运营方” | 核对 LMS 从 PLMN 取得的目标结果，以及本次回给原请求方的位置确用该结果。没抓到 LMS 向目标发请求，不能证明运营方已经提供数据。 |
| “读了旧位置” | 核对这次是否真的读了已有记录并用它回调度。数据库先前有一行，或回来的值与旧值相同，不足以确定来源。§10.9.3.2 的更新／存入是 LMS 收到报告后的动作；§10.9.3.6.2 没把只读旧记录列为第三种取数分支，也没有规定位置有效期或缓存回退。 |

这里的对照是排障所需的证据，不给线上报文增加关联号或时间戳。LMS 处理完或发出响应，也不代替调度方实际收到响应。[表 10.9.2.2-1，印 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.2 步骤 4–5，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)；[§10.9.3.6.2 步骤 3–4，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)。

若实际是[用户位置订阅与后续通知](user-subscription.md)、[客户端发触发要求 LMS 启动上报](client-triggered-reporting.md)，或[按共享功能别名定位多人](active-alias-trigger.md)，分别查其请求和结果；不要仅凭另一条位置消息的方向把它们认成这次按需查询。

# 向 LMS 订阅谁的位置？订阅成功后，什么时候才有位置通知？

在 Rel-16 的在网单系统流程中，MC 业务服务器或位置管理客户端（LMC）可以向位置管理服务器（LMS）订阅一个或多个 MC 业务用户的位置。**订阅响应告诉请求方订阅结果，位置通知才携带目标用户的位置信息。** 例如，调度业务订阅乙、丙，收到成功响应时可以登记“订阅成功”，不能在地图上给乙、丙各添一个新位置点。[3GPP TS 23.280 V16.7.0，Stage 2，§10.9 标题，印 165](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=166)；[§10.9.3.5，图及步骤 1–3，印 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)。

**判断 SIP 还是 HTTP，先看端点，再看用途。** LMC 与 LMS 之间是 CSC-14；MC 业务服务器与 LMS 之间是 CSC-15。两条参考点的分法相同：与订阅或通知有关的信令用 SIP-1、SIP-2 传送和路由；其余信令用 HTTP-1、HTTP-2。LMC 向 LMS 报告本端位置，与 LMC 向同一个 LMS 订阅别人的位置，是不同用途。只凭地址相同不能给二者选同一种协议。这里定义的是 Stage 2 参考点与功能流程，不给出某个 SIP 方法、事件包、请求 URI 或 PSI，也不据此判定有无独立的 LMS 注册、注册协议或其他 Release 的做法。[§§7.5.2.14–15，印 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)。

**请求里谁是谁？** 订阅请求有三个必备项：请求用户的 MC 业务标识、目标用户的 MC 业务标识清单、连续报告间隔。单个标识代表“谁想知道”，清单代表“想知道谁的位置”。发请求的功能实体可以是业务服务器或 LMC；§10.9.3.5 步骤 2 明写 LMS 检查**该 MC 业务服务器**是否获准发起请求。这一步没有为 LMC 列出具体鉴权判据，既不能照搬成 LMC 的明文规则，也不能反推 LMC 免鉴权。步骤 3 由 LMS 回订阅状态；响应信息表按 LMS 回给业务服务器的情形列出请求用户标识和订阅状态，两者必备，表内没有位置。[§10.9.2.5 引言，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；[表 10.9.2.5-1、10.9.2.6-1，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)；[§10.9.3.5，印 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)。

**只有甲的标识和一个“成功”，该改谁的订阅？** 值班人员拿到一条位置订阅业务的响应摘要：LMS 发给 MC 业务服务器，请求用户是甲，状态是成功。摘要没保留操作名称，也没附原请求。订阅和退订都可能留下这条记录：两张响应表都把请求用户的 MC 业务标识和订阅状态列为必备项，都没有列出目标清单。甲是请求人，不能拿甲的标识代填目标。[表 10.9.2.6-1 及引言，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)；[§10.9.2.9 引言，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)及[表 10.9.2.9-1，印 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)。

把两张工单分开还原。每张都从同一情形开始：甲已订阅丙的位置，尚未订阅乙。两张工单保留下来的响应摘要完全相同。

- 第一张找回了与这条成功响应对应的请求：业务服务器代甲**订阅乙**，目标清单只有乙，并填写了连续报告间隔。按这次结果，应记甲订阅乙成功；这笔操作没有撤订丙。[§10.9.2.5 引言，印 166](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=167)；[表 10.9.2.5-1，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)；[§10.9.3.5 图及步骤 1–3，印 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)。
- 第二张对应的请求是业务服务器代甲**退订丙**，不再需要位置的清单只有丙。应记甲退订丙成功；不能据此给甲新增乙，也不能把其他人的丙从订阅中删除。退订响应表的引言写“LMS 或 LMC 发给业务服务器”；退订程序图和步骤 1–2 则是业务服务器或 LMC 发请求，LMS 回复发起方。两张工单都是业务服务器发起，LMS 回给业务服务器的方向相同。[§10.9.2.8 引言及表、§10.9.2.9 引言，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)；[退订响应表，印 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[§10.9.3.7 图及步骤 1–2，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)。

另看两张独立工单。两张都只留下甲的同向成功摘要，也都查不到操作前甲订阅了谁。第一张另外确认了操作是退订，没找回目标清单。可以记退订成功，却不能点名：假如甲原先订了乙和丙，单独退订其中任何一人都说得通。第二张只确认本次清单里仅有乙。若原先没订乙，新订阅乙可以成功；若原先已订乙，退订乙也可以成功。知道目标仍不能决定该新增还是移除。要改某个人的订阅记录，须把成功结果与**这一次**的操作及目标清单对上。甲同期还有别的请求时，不能把手边任一张清单配给这条响应。这里解释的是工单保留了什么，不是给线上报文增加必填字段。

**间隔为 0，从哪一刻算“立即”？** 从 LMS **收到清单中某个用户的位置报告**算，不从收到订阅请求或发出成功响应算。乙已向 LMS 报告、丙尚未报告：如果只有乙的发送记录，还不能判断 LMS 已收到；一旦确认 LMS 收到乙的报告，零间隔规则要求它立即发出对应的位置通知，不必等丙，也不能替丙记一笔新位置。要求发出不等于抓到了发出，更不等于订阅方收到。间隔是必备项，漏填不能当成填了 0。[表 10.9.2.5-1 及表注，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)。

位置从哪来，还要看通知程序。LMS 按配置触发通知，例如按订阅或周期定时器；给 MC 业务服务器或 LMC 的是一个或多个目标用户的最新位置信息。它可来自 §10.9.3.1 的上报，也可来自 PLMN 运营方（如 LCS 网络），不保证终端刚做了一次 GPS 定位。表 10.9.2.7-1 的引言写的是 LMS 向 MC 业务服务器发送通知；程序步骤 2 的接收方则可以是业务服务器或 LMC。表中目标标识清单、触发事件和位置信息均为必备项。另有一行是订阅者自己的 MC 业务标识，虽标为必备，表注明确**仅在 LMS 向已订阅的 MC 用户发送位置通知时使用**。收件功能实体是业务服务器，并不能单独回答这笔是否在通知已订阅的用户。图中第 2 步叫“通知”，编号正文叫“报告”，方向相同，都是 LMS 发给位置使用方。图和编号正文均止于第 2 步，注 2 虽提到第 3 步，不能据此另设收件确认。若调度现在就想查丙的位置，可发起另一个**按需查询**：LMS 查请求方权限，向目标按需取位置或从运营方取得，立即把所获位置发回请求方。一次按需查询的结果不是原订阅已通知的凭据。[表 10.9.2.7-1 及表注，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)；[§§10.9.3.6.1–2，印 171–172](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=173)；[§10.9.3.6.2 步骤 1–4，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)。

**退订乙，停的是哪一路？** 业务服务器或 LMC 告诉 LMS 自己不再订阅哪些人，LMS 回退订状态。退订请求表的请求用户标识、目标清单均为必备；退订响应表列请求用户标识和状态，不能凭响应宣布乙终端已停止上报。§10.9.2.9 的表前引言与 §10.9.3.7 的程序对响应端点的表述不完全相同；上述方向按后者的图和编号步骤判。要停的是乙终端向 LMS 发报告时，查另一程序：乙的 LMC 先前已获位置上报配置，LMS 给它发一份不带任何信息元素的同类配置，随后乙的 LMC 停止向 LMS 报告。[§10.9.3.4 前提，印 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=171)；[同节步骤 1–2，印 171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=172)。退订响应不代替这份配置，也不撤销其他订阅方的订阅。[§§10.9.2.8–9，印 167](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=168)及[响应表，印 168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=169)；[§10.9.3.7，印 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=174)。终端按什么事件上报、怎样取消上报，见[终端的位置上报配置](event-reporting-configuration.md)；位置已经送到 MC 业务服务器后，如何用它判断是否进出告警区，见[紧急告警区的进出](../calls/emergency-alert-area-entry-exit.md)。

若实际发起的是独立按需查询，查[请求方授权、目标用户许可和本次位置的数据来源](on-demand-location-consent-and-source.md)，不要拿订阅响应或通知代替。

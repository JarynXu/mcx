# SIP 用户库的“位置”和“授权”分别能证明什么？

**准许终端在访问网漫游，不等于这次来话已经路由，也不等于用户获准使用 MCPTT。** 查一次在网故障时，先分 SIP 核心为终接找用户、注册器选择应用服务、MC 客户端办理本项业务授权，以及位置管理服务器给调度返回业务位置。以下按 TS 23.280 V16.7.0 的 Stage 2 功能区分，不把接口职责当成抓包结果。[§7.4.3.2.2，印刷页 36–37](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=37)；[§10.6.1，印刷页 114–115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=116)

## 来话要找用户，查哪种“位置”？

SIP 数据库支持用户注册，也存有**跨系统层面的 MC 终端位置信息**。规范在此没有规定该位置的格式。终接呼叫或会话时，SIP 库提供**当前由哪个注册器服务该用户**的信息。另有一项给注册器查找功能（finder）的资料，讲的是这名用户需要什么样的注册器；不能把能力要求填成已经找到哪个注册器。[§7.4.3.2.1、§7.4.3.2.2(b)、(c)，印刷页 36–37](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=37)

注册器维护的是**用户身份与 SIP 联系位置的关联**，供 SIP 核心完成联系地址绑定和 URI 解析。已知道这次终接使用哪个注册器，再查它实际使用的联系绑定；不能只抄数据库里一个叫“跨系统位置”的值，当成用户的 Contact 地址、注册器名称或路由成功的凭据。[§7.4.3.1.3.4，印刷页 35–36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=36)；[§9.2.1.3，印刷页 49](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=50)

## 有漫游许可和过滤规则，还要核对什么？

| 已看到的记录 | 能说明什么，还缺什么 |
| --- | --- |
| 注册器查询用户能否接入，SIP 库给出允许在访问网漫游的结果 | 这是移动接入授权的一个例子。不替代本次终接所用的注册器、联系绑定或应用服务选择。 |
| SIP 库有终接或业务调用的基础授权信息，注册器有指向业务服务器的过滤条件 | SIP 库提供终接呼叫／会话建立和业务调用的基础授权，也**可以**用过滤条件更新注册器以触发 MC 业务服务器。库的信令面订阅档包括初始过滤条件，但仅看到规则不能证明实际触发；要判断本次是否触发，再找注册器对这笔事务实际选择应用服务及转交的记录。 |
| SIP 注册成功，或观察到可选的第三方注册 | 主系统中，相应 MC 客户端利用认证注册程序的结果办理该用户的业务授权。要确认允许用 MCPTT，核对该用户这次的 MCPTT 授权结果。用户认证可以独立于 SIP 注册，也可以安排在注册阶段，不能用一个固定先后来判断。 |

上表的“基础授权”是 SIP 数据库支持的功能，不是任何应用服务器已经接受请求的结论。[§7.4.3.2.2(g)、(h)，印刷页 37](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=38)；[§7.4.3.1.3.4，印刷页 35–36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=36)；[§10.6.1，印刷页 114–115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=116)

## 调度问“人现在在哪”，改查哪条链路？

SIP 库的跨系统位置属于信令控制面，看到它不能确认这个人的实际业务位置或终端是否刚定位。位置管理客户端向位置管理服务器（LMS）报告属于 CSC-14；MC 业务服务器向 LMS 请求及接收位置信息属于 CSC-15。要回答调度，核对本次位置请求的权限、LMS 实际取到什么以及实际用于返回的结果。这里不承诺一定有一份新终端报告。[§7.4.3.2.1，印刷页 36](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=37)；[§7.5.2.14–15，印刷页 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)

要查 finder 该用谁的库，回到[服务注册器的选择](registrar-selection.md)；要核对登录的各项时点，看[主系统认证和业务授权](home-system-authentication.md)；实际查人的位置，按[LMS 的请求方权限、目标许可与取数来源](../location/on-demand-location-consent-and-source.md)继续。

# MCPTT、MCVideo、MCData 的用户库能合设吗？

能合设。**每项 MC 业务都要有对应的 MC 业务用户数据库。** 本节列出 MCPTT、MCVideo 和 MCData 各自的用户库，分别指向 TS 23.379、TS 23.281 和 TS 23.282 的定义，也允许这些库合设。验收时先问每项业务的用户库功能由谁承担。只看见三个业务用同一处部署，不能判定缺少用户库；只知道三项业务各有对应的库，也不能据此要求三台服务器。条文没有指定数据库实例、表或进程的数量。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§7.4.2.3.3 第 2 段，印刷页 34](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=35)

## 库里查什么？谁决定配置档？

在 MC 业务提供方的应用面，用户库包含**与 MC 业务 ID 关联的用户配置档信息**。查某人的 MCVideo 配置档，先核对该业务的 ID，再按 MCVideo 业务用户库的角色找资料。这里的 MC 业务 ID 不用 SIP 身份替代。

配置档由任务关键组织和 MC 业务提供方决定，MC 业务用户也可能参与。这里没有把配置档字段的修改权或审批权分配给这几方，也不能因为某一方决定配置档，就认定它已完成一次写入。[§7.4.2.3.3 第 1 段，印刷页 34](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=35)

## 用户库和 CMS 都查得到档，业务服务器就有资料可用吗？

不能只看这两处。用户配置档数据存于 MC 业务用户库。§5.2.4 还要求用户档在配置管理服务器（CMS）可用，MC 业务服务器也须有相应的用户档信息可用。[附录 A.3 首句，印刷页 212](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=213)；[§5.2.4 第一组要求第 2、3 项，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=20)

例如，CMS 能查到甲的 MCVideo 用户档，仍要核对负责这项业务的服务器能否使用甲的对应资料。CMS 的查询结果不能替业务服务器确认可用。§5.2.4 的可用性要求不指定业务服务器如何取得资料，也不要求每个物理节点都保存一份完整副本。即使资料已可用，也不能据此确认本次已选用该档，或用户已获业务授权。

若查的是供下次业务授权使用的预选档更新，读[预选与当前配置切换](user-profile-switch.md#为下次授权做选择)。数据库更新后业务服务器怎样收到变更，见[§10.1.4.6 图后正文，印刷页 76](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=77)。

要查**配置管理服务器从哪里取档、何时交给终端**，看[用户配置档下载](user-profile-download.md)。若要核对**业务用户库、SIP 库与 HSS 怎样分设或合设、各在哪一方网络**，看[终端身份供应与 SIP 核心部署](identity-hosting-sip-core.md)。若采用 UDC 且选用 UDR 作业务用户库，也从这份部署说明查访问方式。两份资料各回答自己的问题；本节没有规定取档、授权或报文步骤。

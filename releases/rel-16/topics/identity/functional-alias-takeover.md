# 甲收到接管功能别名的提议，乙就失去这个别名了吗？

不能这样记。假设同一 MC 系统里，乙正在使用功能别名“北站值班”。甲的客户端已做过激活程序，甲从结果得知“北站值班”在用、可以接管。这个提议让甲有了选择，还不是服务器接受了接管。即使甲决定接管，也要由甲的客户端发出接管请求；服务器还要检查接管有无冲突。[TS 23.280 V16.7.0，§10.13.6 引言、前提 1–3，印刷页 199](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=200)；[步骤 1–2、注 1，页 200](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=201)。

**甲看接管响应，乙看撤销通知。** 甲接洽的 MC 业务服务器若不负责控制这个别名，就把请求转给承担该角色的 MC 业务服务器。甲获准接管所请求的别名时，服务器向乙的客户端发撤销通知，说明这个别名对乙已不再激活。服务器保存所请求别名的状态，并向发起接管的客户端返回响应；响应中该别名的结果可以是接受，也可以是拒绝。看到甲收到“接受”，能记甲的请求获准，不能据此记“乙的客户端已收到通知”。若另有服务器向乙发出撤销通知的记录，可记“已发，通知说明别名对乙已撤销”；要记“乙端已收”，还需能证明送达乙端的记录。缺送达证据也不能填成“未送达”。[§10.13.6 步骤 1–5、注 1，印刷页 200](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=201)；[表 10.13.2.9-1、10.13.2.10-1，页 195](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=196)。

## 三张表中的业务 ID 分别是谁？

下列三种信息流中的 MC 业务 ID 和功能别名均为必填项。看发送方向来认收件人，看表中那一行的说明来认 ID 所指的人。

| 信息流 | 本例发给谁 | MC 业务 ID 的定义 | 别名和结果 |
| --- | --- | --- | --- |
| 接管请求 | 甲端发给 MC 业务服务器 | 发起接管请求的用户 | 甲想接管的那个别名；请求不是结果 |
| 接管响应 | 服务器发给甲端 | 表 10.13.2.9-1 原文指发起**激活请求**（activation request）的用户 | 甲想接管的别名；另有必填的逐别名状态，本表指接管请求被接受或拒绝 |
| 撤销通知 | 服务器发给乙端，即原使用者的客户端 | 发起**接管请求**的用户，本例是甲 | 被撤销的那个别名；不是说甲自己的别名被撤销 |

响应表保留的是激活请求的发起人：在本例中，甲既做了先前的激活申请，又发起接管，但不能因此把表的定义改写成“接管发起人”。撤销通知最容易读反：里面是甲的业务 ID，接收方却是乙端。[表 10.13.2.8-1，印刷页 194](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=195)；[表 10.13.2.9-1、10.13.2.10-1，页 195](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=196)；[§10.13.6 前提及步骤 1、3、5，页 199–200](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=200)。

## 谁还要知道这次状态变化？

除了给乙端发撤销通知、给甲端回接管结果，条文还分开写了三件事：服务器保存本次所请求别名的状态；同一 MC 系统内，**已订阅功能别名状态的其他服务器**获通知；服务器告知**共享同一别名的所有其他 MC 业务用户**。例如，丙也共享“北站值班”，某服务器订阅了别名状态，丙与订阅服务器各有获知的依据。给丙的是共享别名的状态消息，不能就此记成对丙也撤销；也不能把范围扩到系统内每个人或每台服务器。一项保存记录本身不证明任何一方已经收到消息。[§10.13.6 步骤 3–6、注 2，印刷页 200](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=201)。

# 功能别名怎样标识组内参与者？用户迁到伙伴系统后，从哪里仍须能找到他？

“东区值班”可以标识组里的参与者，也可以用来找到正在执行这项任务的用户。要判断是哪项要求，先看动作：**为组指定别名**、**用别名标识参与用户**和**从某个系统按别名找到人**并不相同。

## 在组里用别名，标识的是谁？

MCX 业务系统须能把功能别名用作 MCX 用户作为业务组参与者时的唯一标识。显示发言人、在组成员名单中使用别名，都是例子；本项没有要求每次都显示或分发名单。另一项要求系统提供机制，让 MCX 用户为某个业务组指定一个功能别名供在该组使用；这种指定不等于给组改名、替换组 ID 或办理用户归属。见[R-5.9a-001a，印刷页 22](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=23)、[R-5.9a-001b，印刷页 22](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=23)。

## 本系统内，与迁入伙伴期间

| 寻址场景 | 对用户可达性的要求 |
| --- | --- |
| 从启用别名的系统内部发起 | 如果该 MCX 业务系统支持功能别名，从**启用该别名的这个系统内**须能通过该用户的功能别名找到他。见[R-5.9a-002，印刷页 22](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=23)。 |
| 甲已迁入伙伴系统，主系统有人找他 | 在甲迁入伙伴 MCX 业务系统期间，仍须能**从主 MCX 系统**通过甲的功能别名找到甲。不能把方向倒过来，或据此保证其他每个伙伴系统都能找到他。见[R-5.9a-002a，印刷页 22](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=23)。 |

两条都规定可达性，不指定怎样解析别名、用户是否需要在伙伴系统再启用一次，或某次呼叫能否接通。

## 组织内不重名，不等于岗位只许一人使用

MCX 业务须有机制，确保**一个任务关键组织内的功能别名**唯一。比如，组织要对“东区值班”这个别名判重；谁正在用它是另一个问题。概述指出，同一功能别名可按管理员设置供多名用户使用。一个别名可由多人使用，并不会凭空多出第二个同名别名。见[R-5.9a-030，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)、[§5.9a.1 概述，印刷页 22](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=23)。

这项组织内的要求引用 [§6.9，印刷页 43](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=44)。后者属于[第 6 章的在网范围，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)，另有针对 ID 和别名的一般判重要求，但没有给所有 ID 和别名规定统一的判重范围。不能把组织内的范围套给所有标识，也不能从本项推出跨组织必然禁止或允许重名。

要查候选名单、谁能查询或启停，见[功能别名启停和查询](functional-alias-user-controls.md)。在网 ID 分配与判重见[在网 ID 和别名管理](onnetwork-id-and-alias-management.md)。要查迁移时谁做授权，见 Stage 2 的[伙伴迁移授权](partner-migration-authorization.md)；授权程序不替代从主系统可达的 Stage 1 要求。

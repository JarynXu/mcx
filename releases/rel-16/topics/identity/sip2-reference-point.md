# SIP-2 是哪一段？注册通知能证明业务已获授权吗？

**SIP-2 连 SIP 核心与 SIP 应用服务器（SIP AS）。** 建立支持 MC 业务的会话时，这条参考点须使用 TS 23.002 定义的 **ISC 和 Ma** 参考点。这里描述的是功能接口，不规定某个部署的物理连接，也不说明具体事务如何选用接口。[TS 23.280 V16.7.0，Release 16，Stage 2，§7.5.3.3，印刷页 42](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=43)

SIP-2 的一项用途是**把 MC 终端的 SIP 注册通知给 MC 业务服务器**。收到的是注册通知，不是这项 MC 业务的授权结果。手上只有 SIP-1 的终端注册成功响应时，不能据此断定业务服务器已收到通知。§7.5.3.3 也没有说每次注册都必须另发通知，或指定某种第三方注册报文。

原文还列出五项用途：向业务层提供认证与安全支持、事件订阅与通知、传递多播所用的 TMGI、会话管理、媒体协商。传递 TMGI 不是已经送达多播媒体的证据；媒体协商也不是媒体传输完成的证据。

查[主系统登录、第三方注册与业务授权的区分](home-system-authentication.md)，看本次判断针对哪一步。若是迁入伙伴系统时要区分[终端到核心的 SIP-1 与核心查库使用的 Cx](migration-registration-reference-points.md)，先按实际端点判接口，不把这两段当成 SIP-2。

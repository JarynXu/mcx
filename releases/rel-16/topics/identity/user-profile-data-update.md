# MC 业务用户配置档：收到变更通知，还是把修改写回服务器？

配置管理服务器通知终端“配置有变”时，通知告诉客户端**到哪里取变更**；真正的新值在随后获取数据的响应中。方向反过来，终端要把修改写回服务器时，新值放在**客户端的更新请求**里，服务器用响应报告处理结果。两种操作改的是配置档（profile）的内容，都不能单凭一次数据更新断定正在使用的业务已切换配置档。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§§10.1.4.4–5，印刷页 74–75](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)

两条流程都从已有配置出发：用户已在身份管理服务器完成认证，终端可安全访问配置管理服务器，且终端已经取得至少一份 MC 业务用户配置档。**网络发起的流程还要求**配置管理服务器能够访问该用户的 MC 业务 ID 所关联的配置档；客户端写回的条款未把这一项另列为前提。[§10.1.4.4 的前提，页 74](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)；[§10.1.4.5 的前提，页 75](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=76)

## 网络通知后，客户端怎样取得新值？

配置管理服务器先取得更新后的数据，再向配置管理客户端发通知。通知的必填项是**指向已修改数据的指针**。收到通知，只能说明客户端得到了变更线索，不能据此判定它已取得新值。[§10.1.4.2.3、表 10.1.4.2.3-1，印刷页 69–70](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=70)

客户端随后向该服务器请求获取更新，必填**发起用户的 MC 业务 ID 和指向已修改数据的指针**。服务器返回请求所指的更新数据；这份数据是获取响应的必填项。因此，如果只看到通知和获取请求，尚不能判定客户端收到了数据。[图 10.1.4.4-1，步骤 1–4，印刷页 74](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)；[表 10.1.4.2.4-1、10.1.4.2.5-1，页 70](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=71)

## 客户端要把修改保存到网络呢？

配置管理客户端受触发后（例如用户操作），向配置管理服务器提交更新请求，必填**发起用户的 MC 业务 ID 和要写入的配置数据本身**。服务器在成功流程中先保存收到的数据，再向客户端答复。写回响应的必填项是本次更新的结果，区分成功和失败；它不是把更新后的内容再交还客户端的获取响应。只有请求、只知道收到了响应，或结果为失败，都不足以确认写回成功。[图 10.1.4.5-1，步骤 1–4，印刷页 75](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=76)；[表 10.1.4.2.6-1、10.1.4.2.7-1，页 70](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=71)

两个方向都可以只涉及某份配置档中的**一个参数**，也可以涉及一份配置档、一组配置档，或该 MC 业务 ID 下的全部配置档。具体有哪些参数由相应的 MC 业务定义，不能由“更新”二字推定每次都是全量替换。[§§10.1.4.4–5，两图步骤后的注，印刷页 74–75](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)

如果问题是**下次业务授权用哪一份**，看预选配置档的流程；如果问题是**某个客户端正在使用的一项业务现在改用哪一份**，看该业务客户端与业务服务器之间的当前选择流程。这两类选择以配置档索引指定对象，不是上述内容写回的成功回执。详见[预选与当前配置切换](user-profile-switch.md)。[§10.1.4.6，步骤 1 及图后说明，印刷页 76；§10.1.4.7，步骤 1、3，页 77](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=77)

若要判断业务是否须支持使用中改档、谁能指定新版何时安装，以及传送时须保护什么，查[用户配置档管理的在网业务要求](user-profile-management-requirements.md)。

# 功能别名：查谁正在用这个别名，还是查这个人正在用哪些别名？

调度员知道“东区值班”这个功能别名，想找出谁启用了它。此时要**按别名查用户**，不必先猜一个人的业务 ID。反过来，若已知某人的 MC 业务 ID，想列出他当前启用的别名，就**按用户查别名**。两种都是在网查询：客户端向 MC 业务服务器提问，服务器检查发起人是否有权执行这次查询，获准才按所给条件检索并向客户端返回信息。〔§10.13.1，页 192；图 10.13.3-1、10.13.7-1 的步骤 1–3，页 197、201〕

**按别名查用户。** 调度员的客户端发起使用情况查询（usage query）。请求必带两项：调度员自己的 MC 业务 ID，以及要查的一个或多个功能别名。响应必带三项：查询者的业务 ID、所查别名和查询结果。结果列的是**每个别名当前由哪些业务用户启用**，用这些用户的 MC 业务 ID 表示。名单不保证只有一人，也不是所有获准使用该别名的人员名册。若同时查询“东区值班”和“西区值班”，前者返回甲、乙，后者返回 `Null`，意思是甲、乙都启用了东区别名，西区别名当前无人启用。〔§10.13.7，页 200–201；表 10.13.2.1a-1、10.13.2.2a-1，页 192–193〕

**按用户查别名。** 调度员的客户端发起用户查询（user query）。请求同样必带两项，但这次第二项是**一个或多个待查用户的 MC 业务 ID**；第一项仍是调度员自己的 ID，不能用它代替被查者。响应必带查询者的业务 ID、所查用户的业务 ID 和查询结果。比如查到甲启用了“东区值班”，而丙对应 `Null`，只能说丙当前没有启用任何功能别名；不能说“东区值班”无人启用。〔§10.13.3，页 196–197；表 10.13.2.1-1、10.13.2.2-1，页 192–193〕

**怎样读空结果。** 两张响应表都把查询结果列为 M（必填），也都允许它取 `Null`。读到 `Null`，先看它对应的是别名还是用户；完全没收到响应、或响应缺少结果项，不能照此解释。空结果也不表示查询被拒，不能据此判断某个别名从未配给谁，或以后能否启用。读一次当前状态不会激活或接管别名，也不意味着已订阅后续变化。〔§10.13.1，页 192；表 10.13.2.2-1、10.13.2.2a-1，页 193〕

要看 MCPTT 客户端怎样持续观察指定用户、怎样申请变更，见[MCPTT 功能别名状态与变更](mcptt-functional-alias-client.md)。若问题是 MC 业务 ID 与其他身份怎样对应，见[跨业务与跨终端的用户身份](cross-service-user-mapping.md)。这两页都不是执行上述查询的前置步骤。

# 用户配置档：在主系统下载哪些，迁到伙伴系统又取哪一份？

在主系统，需要下载时，配置管理服务器返回**请求中的 MC 业务 ID 关联的全部用户配置档**。迁到伙伴系统时，终端向**伙伴系统**要档，主系统按**目标伙伴系统的标识**找出适用于这次迁移的档。前者按用户的业务 ID 确定下载范围，后者还要区分用户迁往哪里。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§§10.1.4.3.1–2，印刷页 72–74](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=73)

## 在主系统：有几份关联档，要送几份？

用户已在身份管理服务器完成认证，终端能安全访问配置管理服务器。终端的配置管理客户端向配置管理服务器请求取档，请求必带该用户的 MC 业务 ID。服务器取得相应配置信息，再向客户端答复。通用响应表把配置档数据列为必填，描述为与请求 ID 关联的一份或多份档；主系统流程第 3 步进一步说明：**需要下载时，响应包含该 ID 的所有关联档**。若该 ID 关联三份档且本次需要下载，就是三份。不能仅凭一次重连或响应的名称便认定每次都发生了全量下载，也不要由此推定不需要下载时有一个不带数据的响应。[表 10.1.4.2.1-1、10.1.4.2.2-1，印刷页 69](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=70)；[§10.1.4.3.1，前提及步骤 1–3，页 72](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=73)

## 迁到伙伴系统：谁取档，谁改档？

这条流程有三个前提：① 用户获准迁往目标伙伴系统，两边都已配置相关授权；② 用户已在伙伴系统完成 MC 业务用户认证，并取得读取配置、请求业务授权所需的凭据；③ 终端已有地址信息，让配置管理客户端能够访问伙伴的配置管理服务器。**能请求业务授权不等于已经获得该业务授权**：取迁移档在向伙伴业务服务器请求业务授权之前。[§10.1.4.3.2 的前提，印刷页 72](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=73)；[§10.1.4.1，页 69](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=70)

终端先向**伙伴配置管理服务器**要迁移档。伙伴服务器再向主系统的配置管理服务器请求；主系统按目标伙伴系统的标识，从**主系统的 MC 业务用户数据库**取出相应的档，交给伙伴服务器。因此，同一用户迁往不同伙伴时，可以用不同的档，并非一定不同。伙伴系统按本地配置信息修改收到的档，把修改后的档存入**伙伴系统自己的 MC 业务用户数据库**。此时证明的是伙伴侧已经保存，不是终端已收到。[§10.1.4.1，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=69)；[§10.1.4.3.2，步骤 1–5，页 73](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=74)

## 修改后必须回传主系统吗？验证失败还能交给终端吗？

主系统在交档时**可以**要求验证修改后的配置档（步骤 4）。**如果主系统提出了要求，伙伴服务器可以把修改档发回主系统**供验证（步骤 6）；提出要求也不能证明伙伴已经回传。步骤 7、8 描述主系统验证修改档、向伙伴返回验证结果；不能倒过来据此认定每次迁移都必须回传并验证。步骤 9 才是伙伴配置管理服务器把档交给终端配置管理客户端。条款明确说明：**如果验证失败，不执行步骤 9**。没有看到验证结果，也不能据此断定流程已失败或终端已经收到档。[§10.1.4.3.2，步骤 4–8，印刷页 73](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=74)；[步骤 9 及其注，页 74](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)

若终端已收到档，仍要分清问的是什么：要判断**下次授权预选哪一份，或某客户端当前已改用哪一份**，查[预选与当前配置切换](user-profile-switch.md)，不能用取档结果代替选择结果。若已有档，问题是**收到变更通知后怎样取得新值，或如何把修改写回**，查[配置档数据更新](user-profile-data-update.md)。[§§10.1.4.4–7，印刷页 74–77](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=75)

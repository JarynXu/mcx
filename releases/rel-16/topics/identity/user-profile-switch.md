# 改了预选配置，当前通话会断吗？同一人的另一台终端要不要跟着切？

不会仅因改预选配置而断话。**预选**是给下次业务授权用的；要在正在使用的业务中改用另一份用户配置档（profile），客户端要另向该业务的服务器请求切换。MCPTT、MCVideo、MCData 都可用后一个程序，但一次只针对其中一项业务、一个客户端。〔§§10.1.4.6–7，印刷页 75–77〕

## 为下次授权做选择

用户已在身份管理服务器完成认证，终端可安全访问配置管理服务器，且已取得至少一份用户配置档。用户操作或自动触发后，**配置管理客户端**把该用户的 MC 业务 ID 和要预选的配置档索引交给**配置管理服务器**。服务器先检查是否有权这样改；允许后保存选择，并答复客户端。保存与答复可交换先后或并行。两项请求字段均为必填，响应的必填结果区分成功与失败。〔§10.1.4.6，图及步骤 1–4、注，印刷页 75–76；表 10.1.4.2.8-1、.9-1，印刷页 71〕

数据库更新后，业务服务器取得变更，该用户关联的所有终端也收到更新后的配置档。**收到资料不表示启用资料。** 如果这时用户正在使用业务，当前活动配置不变。§10.1.4.6 的步骤和结尾写的是下次**业务授权**生效；请求表 10.1.4.2.8-1 用的却是用户**认证**。不能把认证和授权当成同一步。能否为同一用户的每台终端分别设置预选项，这一版明确留待研究（FFS）。〔§10.1.4.6，图后及编者注，印刷页 76；表 10.1.4.2.8-1，印刷页 71〕

## 在使用中改当前配置

以甲的手持机正在使用 MCVideo 为例。用户已完成身份认证，该机可安全访问 MCVideo 业务服务器，已取得多份用户配置档，并已完成该业务授权。手持机的 **MCVideo 客户端**受触发后，将业务 ID 和所选索引发给 **MCVideo 业务服务器**，两项都是必填。服务器为**这个客户端**保存所选索引，并以结果答复是否成功。手持机的 MCPTT 和车载客户端都不是本次请求的切换对象。每个客户端同一时刻只用一份活动配置；同一人的手持机和车载机可以使用不同的活动配置。〔§10.1.4.1，印刷页 68；§10.1.4.7，前提、步骤 1、3、5 及注 1，印刷页 76–77；表 10.1.4.2.10-1、.11-1，印刷页 71〕

两台终端使用不同配置是标准允许的状态，但**同一用户在不同终端同时使用两份配置时，业务服务器和客户端具体如何处理**，§5.2.4 注 3 仍留待研究。因此不能从按客户端保存索引，推出规范已经给出了跨设备同步或冲突处理办法。这与 §10.1.4.6 的另一项待研究问题不同：后者问的是能否为每台终端分别指定**下次授权的预选项**。〔§5.2.4 注 3，印刷页 19；§10.1.4.1，印刷页 68；§10.1.4.6 编者注，印刷页 76；§10.1.4.7 注 1，印刷页 77〕

**成功响应确认选中的配置已设置，不是组配置都已备齐的回执。** 若服务器缺少新配置所需的组配置数据，它要取得这些数据并订阅更新；这一步与回复客户端可以先后互换，也可以并行。客户端若也缺这些数据，需自行取得并订阅更新。不是每次切换都要重新下载。〔§10.1.4.7，图、步骤 4–6 及注 2，印刷页 77–78〕

## 旧组和现有呼叫何时清理？

只有在**业务服务器和终端成功协商**所选配置之后，双方才按新配置清理此前所选或预选配置留下的活动业务状态，包括解除相关组的归属、断开相应业务呼叫，再处理新配置所需的归属等。仅发出请求、收到失败结果，或另一台终端取得更新资料，都不能据此判定已执行清理。这里清的是当前业务状态，不是删除配置档或要求其他客户端断话。这两条不规定协商失败后的回滚或重试细节。〔§10.1.4.7，结尾，印刷页 78；表 10.1.4.2.11-1，印刷页 71〕

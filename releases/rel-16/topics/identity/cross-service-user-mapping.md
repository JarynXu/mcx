# 同一用户跨业务、跨终端时，怎样辨认身份？

同一串 URI 可能用于不同业务；同一人也可能从两台终端上线。要判断它指谁，先看它用于认证、标识业务用户，还是路由 SIP 信令。

**认证和业务。** 用户向身份管理服务器认证时使用 MC ID。应用层用 MC service ID 识别某项业务中的用户；它是 URI，表明该 ID 定义在哪个 MC 系统。两种 ID 可以同值。业务服务器可根据与业务 ID 关联的属性作授权判断；业务提供方要求时，业务 ID 对信令控制面隐藏。〔§8.1.1–8.1.2，印刷页 43–44〕

**跨业务与配置档。** 同一个人在同一项 MC 业务只有一个业务 ID，MCPTT 和 MCVideo 等不同业务的 ID 可以不同。如果为访问多项已授权业务配置同一个值，终端（UE）和业务服务器在通信中必须指明具体业务。每个业务 ID 至少关联一份用户配置档（user profile），用索引区分，名称可选。同一客户端一次只激活一份；同一人可在两台终端上用不同配置档，也可在同一终端的不同时刻换用另一份。每客户端一次一份也适用于向伙伴系统迁移。〔§10.1.4.1，图 10.1.4.1-1，印刷页 68〕

**SIP 路由与业务用户识别。** 注册时，私有用户身份用来查找信令用户代理的认证凭据。该代理经 SIP 核心向业务服务器发送信令时，消息用公共用户身份路由。业务服务器管理公共用户身份与业务 ID 的映射，两个方向都允许一对多。〔§8.2–8.3.1，印刷页 45–46〕

能否直接用公共用户身份识别应用层的业务用户，要看信任域。如果 MC 业务提供方和归属移动网络（PLMN）运营方在同一信任域，公共用户身份可以兼作应用层用户标识，但不是必须。如果要标识另一信任域中的 MC 业务用户，则不得用公共用户身份。禁止的是跨域标识用户，不能据此断言跨域 SIP 通信或路由映射一律禁止。〔§8.3.1，印刷页 46；§5.1.2，印刷页 18〕

**区分终端。** 支持一人多机或多人共用设备时，SIP 核心可以生成公共和临时两种 URI（GRUU）来区分 MC 业务终端。一个业务 ID 可对应多个公共 GRUU，由业务服务器管理；把临时 GRUU 映射到公共 GRUU 的则是 SIP 核心。〔§8.2、§8.3.1，印刷页 46〕

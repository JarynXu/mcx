# 多个任务关键组织共用 MCX 系统：管理员能看什么、改什么？

消防和急救可以由**同一个 MCX 业务系统**服务，各自有自己的用户和业务组。TS 22.280 V16.8.0 要求 MCX 业务支持这种部署。共用系统说明两家使用同一套业务系统，不给一家管理员取得另一家参数的权限，也不要求实际部署一定要有多家组织。[Release 16，Stage 1，§5.16.1 与 R-5.16.2-001，印刷页 26（PDF 第 27 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=27)。

## 谁设管理员，组织间为什么还要分开？

MCX 业务须提供办法，让任务关键组织**指定和管理 MCX 业务管理员**，包括增设、撤销管理员及变更其授权等操作。管理员职责可涉及用户、组、其他管理员、安全控制，以及影响任务的其他业务参数，例如授权和优先级。这条要求系统支持这些管理权限，不给任一管理员一揽子授权。[R-5.16.2-002，印刷页 26](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=27)。

有两件不同的事要查：

- **组织之间能否打通参数边界？** 为保护组织的运行隐私，业务须有效分隔各组织的管理和安全管理参数，例如密钥，除非相关任务关键组织授权例外。消防一方有权管理自己的参数，不能据此打通急救一方的参数边界。[R-5.16.2-003，印刷页 27（PDF 第 28 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28)。
- **这个人能否查看或操作这些参数？** 业务须阻止未获相应组织明确授权的人查看或操纵该组织的管理和安全管理参数。这包括组织内的人，也包括组织外的人。属于消防或担任管理员，不代替消防对这个人的明确授权。组织同意在某个范围共享，不等于每位接收组织的成员都可查看或修改。[R-5.16.2-004，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28)。

这两条分别约束组织间分隔和个人权限。它们没有规定每次操作都要重走一次审批，也没规定使用哪种角色模型、数据分库方式或物理拓扑。

## 可以只共享一部分吗？看见运行状态算不算已共享参数？

**可以只共享一部分。** 业务须给组织提供手段，把其管理及安全参数的子集与其他任务关键组织共享。是否共享由组织决定；共享能力不证明两家已经共享，也不会让未选中的参数自动公开。条文附注说明：保护组织运行安全的同时，仍可允许受这些组织控制的终端和用户互通。因此管理参数分隔不等于所有跨组织通信都要隔断。[R-5.16.2-005 及附注，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28)。

**能看业务运行状态，不等于能看或改管理参数。** 业务须给与某个任务关键组织相关联的 MCX 业务管理员提供查看业务运行状态的办法。原文用自然灾害时为例，没有把要求限于灾害，也没有在这里定义状态清单、呈现方式或每个管理员能看到的详细范围。比如消防值班员能看业务是否在运行，不能据此认定他获准查看急救的密钥或更改其优先级。[R-5.16.3-001，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28)。

六项要求在三种业务的适用表中均有列明：[MCPTT（表 A.1）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65)、[MCVideo（表 B.1）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76)、[MCData（表 C.1）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87)。这些是业务要求，不规定承载、接口、消息或部署方式。查的是[非组策略怎样配置到服务器或终端](service-policy-configuration.md)，按功能接口查；若实际有[两个分属不同信任域的 MC 系统](interconnection-authorization.md)，则查系统互连，不把这里的同系统管理边界当作互连流程。

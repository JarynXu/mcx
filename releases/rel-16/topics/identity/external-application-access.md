# 外部应用接入 MC 系统：须验证谁，TS 23.280 定义了接口吗？

对接一个位于 MC 系统之外的应用时，先确认它以什么角色发起这笔业务。系统能连通、应用通过认证、应用获准访问某项 MC 业务，是三件事。不要拿调度终端或伙伴系统之间的流程，替代外部应用的接入要求。

## 外部应用：MC 系统须支持应用认证和授权

TS 23.280 V16.7.0 要求 MC 系统支持**对外部应用的认证和授权**，以便应用安全访问 MC 业务。§5.2.8 的编者注说明，外部应用在 MC 系统之外，可以经 IP 连通接入。IP 连通只回答能否到达，不证明这一个应用已经通过认证或获准访问。认证对象是外部应用；仅凭某位 MC 用户已完成业务授权，不能登记该应用已通过自己的认证和授权。〔§5.2.8，印 22〕

**如何实现接入，以及如何定义服务和能力发现，这一版都标为待研究（FFS）。** 不能据本节要求对方提供某种 HTTP 或 SIP 接口、某个 API 路径、令牌格式、授权范围字段或发现响应。对接时需要拿到实际采用的接口约定；不能把这里的两项架构义务当成一份线协议。这个结论只限 TS 23.280 V16.7.0 的本节，不声称别处或别版也没有接口。〔§5.2.8 两条标为 FFS 的编者注，印 22〕

## 调度台、外部应用和伙伴系统：先按角色分流

在本规范的公共功能架构中，**调度台和 MC 业务管理员使用的设备被视作 MC 业务 UE**。调度或管理功能可由经 E-UTRAN 或非 3GPP 接入的 MC 业务 UE 支持；外部应用也可经这两类接入网使用 MC 业务。因此，走非 3GPP 网络不等于这笔业务是外部应用接入。若同一方案还含一个系统外的应用，单独核它的角色和访问权限。〔§4 正文及注，印 17；§5.2.8，印 22〕

也不能从“已经有 IdMS／MC 网关”推出外部应用该走哪条接口。CSC-1 的两端是身份管理客户端和身份管理服务器，规定公共服务核心向 MC 业务客户端认证，随后是用户向公共服务核心认证，后者代表应用平面的应用；这不是 §5.2.8 给外部应用选定的入口。MC 网关服务器的角色是为不同信任域的主、伙伴 MC 系统互连及隐藏拓扑，在互连的业务服务器之间转接信令和媒体；角色定义没有规定外部应用接入就要走这个网关。设备可以兼任角色，仍要查这笔交互实际办理的是用户认证、系统互连，还是外部应用接入。〔§7.5.2.2，印 38；§7.4.2.3.4，印 34；§5.2.8，印 22〕

若要查[用户向本系统认证](home-system-authentication.md)或[伙伴互连时的可达性和用户业务授权](interconnection-authorization.md)，读对应的程序。这两类记录都不能代替外部应用侧的接入与授权证据。

# 非 MCX 业务能使用功能别名或 MCX 用户身份寻址吗？谁来允许？

**可以，由 MCX 业务管理员允许。** 在网 MCX 业务系统须提供机制，让管理员允许非 MCX 业务将功能别名、MCX 用户身份，或两者用作寻址方式。机器类通信只是条文举的一个例子，既不限定只有机器能用，也不要求两种标识同时出现。[§6.17.3.2，R.6.17.3.2-001，印刷页 49](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=50)

例如，外部业务知道值班别名，不能因此认定管理员已允许它用这个别名寻址。即使已有寻址许可，也不能据此认定该应用已通过认证、已获准使用某项 MCX 业务，或某条消息已送达。本条没有规定外部接口或地址转换方式。

这是 [3GPP TS 22.280 V16.8.0（Release 16，Stage 1）第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30) 的在网要求。[表 A.1（MCPTT），印刷页 69](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=70)、[表 B.1（MCVideo），印刷页 80](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=81)、[表 C.1（MCData），印刷页 91](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=92)均列出R.6.17.3.2-001。 正文和三张表都把该编号写作 **R.6.17.3.2-001**。这是“外部系统”小节的要求；不要用它补齐 MCData 在“GSM-R”小节没有列出的其他条目。

若问外部应用如何安全接入 MC 系统，见[外部应用接入与认证授权](external-application-access.md)；若要查 MCX 用户 ID 或别名在系统内怎样分配，见[在网身份与别名管理](onnetwork-id-and-alias-management.md)。

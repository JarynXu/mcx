# 在网 MC 公共服务核心：哪些是公共服务，哪些负责信令控制？

3GPP TS 23.280 V16.7.0 的在网架构把公共服务核心中的功能分为两组。**HTTP 代理和 HTTP 服务器属于该清单的信令控制部分，不与 CMS、GMS、IdMS、KMS 混作同一类。** [§9.2.1.2.2，印刷页 48](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=49)

| 用途 | 本节列出的功能实体 |
| --- | --- |
| 公共服务 | 配置管理服务器（CMS，回指 §7.4.2.2.2）、组管理服务器（GMS，§7.4.2.2.4）、身份管理服务器（IdMS，§7.4.2.2.6）、密钥管理服务器（KMS，§7.4.2.2.8） |
| 信令控制 | HTTP 代理（§7.4.3.3.2）、HTTP 服务器（§7.4.3.3.3） |

这张表分的是功能，不是部署节点。本节没有规定这些功能是否合设，也不能因为表中有 HTTP 代理，就断定每笔身份认证或配置交易都经过它。同页图 9.2.1.1-1 只作在网架构背景，图中的应用服务层没有展开成这张组件表。

本节的清单没有列出位置管理服务器（LMS）。**这不等于本版没有 LMS，也不能据此决定 LMS 部署在哪里。** 要核对位置订阅及位置管理接口，从[用户位置订阅与位置管理参考点](../location/user-subscription.md)查起。要判断终端身份认证或密钥管理是否经过代理，读[身份认证和密钥管理的 HTTP 路径](csc-http-proxy.md)；要区分主系统的用户认证、SIP 注册与 MC 业务授权，读[主系统的用户认证、SIP 注册和 MC 业务授权](home-system-authentication.md)。

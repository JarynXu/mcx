# 两个 MC 系统互连：客户端要连到对端的谁，用户的业务授权又归谁？

林由甲系统提供 MC 业务，周由乙系统提供 MC 业务。甲乙属于不同信任域，两人使用 MC 业务互连通信。对林的客户端来说，**乙端要求可达的只有乙的身份管理服务器（IdMS）**；需要通过互连与乙通信时，**林的业务授权在为林提供业务的甲系统办理**。周若也使用这次互连，按周当前的服务系统判断，周的授权在乙。连接目标和授权地点回答的是两件事。[3GPP TS 23.280 V16.7.0，Rel-16 Stage 2，§5.2.10.1，印 23–24](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=24)；[§5.2.10.2，印 24](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=25)；[§10.6.2，印 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=116)。

## 验收连通性，要分两处查

| 从哪里查 | 互连要求什么 |
| --- | --- |
| 已由甲服务、使用互连与乙方用户通信的林所用的 MC 业务客户端 | 在乙系统中只要求能连到 IdMS。不要求林的客户端能连到乙的所有业务服务器；也不是说客户端在甲只需要连 IdMS，或禁止它有其他连接。 |
| 打算互连的甲、乙两个 MC 系统之间 | 需要系统间 IP 连通，用来承载提供 MC 业务所需的**信令协议和应用平面协议**。客户端在乙端只需连 IdMS，并不免除这项系统间要求。 |

例如，林的客户端已经测通乙的 IdMS，可以登记这一项可达。要确认系统间承载，还要看两系统间的 IP 连接能否承载所需的两类协议；不能把客户端的测试当成系统间的测试。即使这两处都通，也不能据此认定林已经获准使用某项业务，或某通呼叫已经放行。§10.6.2 指明办理用户业务授权的系统，不报告这次授权的结果，也不规定实际经过哪些设备。[§5.2.10.2 两项连接要求，印 24](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=25)；[§10.6.2，印 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=116)。

两系统分属不同信任域，是这里所说互连的条件；**系统间 IP 链路是否经过双方信任域之外**，要看实际承载。若确实经双方域外承载，需要采取适当安全措施，规范在此不规定措施的细节。互连还应有满足 MC 业务用户要求的性能；低分组时延只是例子，条款没有给出毫秒门槛。仅知两系统分属不同信任域，不能断定链路经过双方域外、措施已部署或性能已达标。[§5.2.10.1 续、§5.2.10.2 注 1、2，印 24](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=25)。

## 如果林已经迁到乙

现在换一个条件：甲是林的主系统，林已经迁到伙伴乙，**当前由乙服务**。林可以使用互连和仍由甲服务的用户通信。这里说的是迁移后允许的一种用法；单凭迁移不能判定本次用了互连，也不能证明现场能用其他方式同甲方用户通信。若林确实使用互连与甲方用户通信，林的客户端在甲端需要能连到的是甲的 IdMS；林的业务授权在乙办理，因为这时乙才是林的服务系统。若另一次通信的用户由第三个系统丙服务，乙、丙分属不同信任域，林实际用的是乙与丙的互连，他的客户端在对端只需能连到丙的 IdMS，不是甲的；林的业务授权仍在乙办理。反过来，只知道两人使用互连通信，也不能推断林迁移过。[§5.2.10.2–3，印 24](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=25)；[§10.6.2，印 115](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=116)。

要判林**能否按所选配置档迁入乙并取得相应业务授权**，查[伙伴迁移授权](partner-migration-authorization.md)。

要判**这一通 MCPTT 或 MCVideo 组呼能否放行**，先认清是谁的伙伴。例如，组 G 的主系统甲和伙伴乙互连；甲把 G 的配置给了乙，乙采用了本地设置。林已归属 G，由乙服务。这时乙是**组主系统的伙伴**，查[伙伴系统的组呼准入](../groups/partner-group-call-admission.md)。若只知道乙是林迁入的伙伴、存有 G 的配置，组主是谁还没查明，就不能据此转到组伙伴准入。若查明 G 就由乙主持，而林也由乙服务，乙是林迁入的伙伴，却是 G 的主系统。即使林已归属 G，也不能把他当成由 G 的伙伴系统服务的组员。无论谁办理林的业务授权，都不能据此判这一通组呼已放行。

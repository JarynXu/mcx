# 外部应用能通过开放接口做什么？MCVideo、MCData 按什么限制访问、认证谁？

MCVideo 和 MCData 须让外部应用能通过开放接口安全访问业务；**业务仍须按自身的权限和授权限制外部访问**。例如，事件管理应用获准接收通知，不等于它也获准修改参数或调高某次通信的优先级。[TS 22.280 V16.8.0 §5.18.1、§5.18.2 R-5.18.2-001，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28)；[R-5.18.2-002，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

这里的“访问”可以包括以下一项或多项：按需获取信息或通过通知获得信息、设置参数、控制业务的部分功能、向业务发送媒体或从业务接收媒体（例如视频）。这是对访问含义的说明，不是给每个应用授予全部能力的清单。[R-5.18.2-001 后的注，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

**通信优先级。** 开放接口须既能控制通信优先级，又能指示通信优先级。只显示当前优先级，不能证明接口也支持控制；接口支持控制，也不能证明某个应用有权改变优先级。[R-5.18.2-003，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

**用户认证。** MCX 业务须能认证通过开放接口连接到业务的 **MCX 用户**。只知道外部应用的身份，不能据此判定业务能认证该用户，更不能证明某人已经通过认证。[R-5.18.2-004，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。若问系统怎样区分应用的认证和授权，见 [Stage 2 的外部应用接入要求](external-application-access.md)；若问在网终端能否要求验证业务本身，见[业务身份认证](../security/service-authentication-requirements.md)。两者的认证对象都与本条不同。

这是 Release 16 的 Stage 1 业务要求，位于[在网和离网共用的第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。规范性[表 B.1（MCVideo），印刷页 75](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76)和[表 C.1（MCData），印刷页 86](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87)在 §5.18.2 行均列出 -001 至 -004；[表 A.1（MCPTT），印刷页 64](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65)在该行写 NA。不能把这四项当成对 MCPTT 的要求，也不能把 NA 读成禁止 MCPTT 提供类似接口。§5.18.2 没有指定接口协议或认证方法。

# 连续几天迁到同一伙伴系统：哪份配置档要留，哪份档在迁移期间用？

反复迁往同一伙伴时，用户有可能不必每次都重新取得初始配置。要这样复用，必须保留**主系统提供的用户配置档**，因为下次还要用其中的接入信息联系伙伴。仅仅看到终端留着这份档，不能断定其余准备都不用重做。迁入后，MC 业务客户端使用的是**伙伴系统下发的用户配置档**；主系统的那份只用来提供接入信息。终端留着两地的档，不等于用户同时在两地接受 MC 业务。同一用户同一时刻只能从一个 MC 系统接受 MC 业务。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§10.1.1.2 首段、注 1（印刷页 60）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=61)；[注 3（印刷页 61）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=62)

**迁移前可以准备什么？** 用户和终端先按主系统的配置和业务授权流程，取得一份或多份用户配置档。每份档分别列出用这份档允许迁往哪些伙伴系统，以及联系相应伙伴应用层服务器所需的信息。用户还取得在伙伴系统认证和获得业务授权所需的安全参数；如何取得由 TS 33.180 规定。准备到这里，用户已具备使用该规范所说的“有限服务”的条件，不表示已经获得伙伴业务授权。这些准备可以提前做。比如连续几天在同一伙伴区域工作，初始配置有可能跨几次迁入使用。必须保留主系统档，才能在下次迁入时从中取到接入信息；单凭档还在，不能断言这次的整套初始配置都可原样复用。复用初始配置也不等于这次已经通过伙伴认证或取得伙伴业务授权。[§10.1.1.2，图后首段及注 1，印刷页 60](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=61)

**这次迁入按什么顺序？**

1. 从**选定的主系统档**列出的伙伴中选一个，用档里的接入信息发起联系。选择可以由用户手动触发，也可由终端应用自动完成，例如根据终端位置或当前服务的移动网络选择。自动选择的对象是伙伴系统；应用作出选择不等于用户通过认证。[§10.1.1.2，注 2 及其前后正文，印刷页 61](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=62)
2. 用户在伙伴系统完成身份认证，随后**伙伴系统**把迁移期间要使用的一份或多份用户配置档下发给**终端的配置管理客户端**。在接下来的伙伴服务期间，用的是伙伴下发的档；MC 业务客户端不会把那份为接入伙伴而保留的主系统档当作业务使用的档。[§10.1.1.2，注 2 后正文及注 3，印刷页 61](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=62)
3. **终端的组管理客户端**再取得用户配置档中所列各 MC 业务组的组配置。以上配置步骤完成后，用户才在伙伴系统获得业务授权。只知道用户通过认证，或只知道终端收到了用户档，都不能断定已获该授权。

**获得授权后，如果伙伴没有发更新，用哪套配置？** 伙伴系统仍然要求使用本次配置流程提供的用户档和组配置。执行这项使用要求，不以伙伴再发一次更新为条件。至于是否提供后续配置变更，则由伙伴选择；一次更新都没有，也不能改用只供接入的主系统档。[§10.1.1.2，注 3 后两段，印刷页 61](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=62)

要追查伙伴下发前谁取得、修改或验证迁移档，见[用户配置档下载](user-profile-download.md)；要判断两侧各检查什么、哪份响应能确认授权，见[迁移业务授权](partner-migration-authorization.md)。

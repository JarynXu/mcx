# 在网 ID 和别名怎样分配、保持唯一？接收终端拿到哪些身份信息？

## 分配、判重和配置是三项要求

| 问题 | 在网 MCX 业务须支持什么 |
| --- | --- |
| ID 只能永久分配，别名只能临时分配吗？ | MCX 业务须提供分配机制：ID 可以永久分配，也可以临时分配；别名也支持这两种分配方式。本项没有规定临时分配的有效期、到期回收方式或标识格式。见[R-6.9-001，印刷页 43](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=44)。 |
| ID 和别名能否重复？ | MCX 业务须提供机制，确保 ID 和别名的唯一性。§6.9 没有给所有 ID 和别名划定一个共同的判重范围。另有一条引用 §6.9 的要求，要求同一任务关键组织内的**功能别名**保持唯一；不能把这个范围推广到所有标识。见[R-6.9-002，印刷页 43](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=44)、[R-5.9a-030，印刷页 24](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=25)。 |
| 谁能配置？ | MCX 业务须让 MCX 业务管理员能够配置 ID 和别名。在这四项中，只有 -003 点名管理员。本项未授予管理员排他权限，也不能凭配置入口认定管理员已分配或修改某个值。见[R-6.9-003，印刷页 43](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=44)。 |

要查的是授权方创建、删除用户别名，用户 ID 关联字母数字别名及其最小长度 `Nc3`，或终端可配置的显示能力，应查[§5.7，印刷页 21](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=22)。这些要求与 §6.9 的分配、判重和管理员配置分开判断。

## 发送时，接收终端拿到什么？

甲已归属 G 组，正在向 G 组发送。G 就是这次发送的**所选组**：规范把它定义为特定已归属成员用于发送的 MCX 业务组。乙和丙正在接收，业务须给乙、丙的终端都提供以下信息，供各自显示。不能把“正在接收”换成“已注册”或“已归属”，也不能从这项业务要求断定某台终端已收到或已显示这些信息。见[§3.1 所选组定义，印刷页 11](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=12)、[R-6.9-004，印刷页 43](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=44)。

- **谁在发：**甲的 MCX 业务用户 ID、与该 ID 关联的别名，或两者。-004 在这两类信息之间写的是“和/或”。
- **发向哪个组：**G 的标识。-004 没有要求同时给出组 ID 和组别名。
- **发送用户属于哪个组织：**如能取得甲的任务关键组织名称标识，就须给接收终端；取不到时，前两项仍须提供。

同一在网组通信还要查 [§6.4.3 的发送者身份与易读别名](onnetwork-group-sender-identification.md)。那里分别列出用户 ID **及**关联别名、组 ID **及**组别名，写明身份受限例外，并另行规定向用户呈现易读别名的最小长度。不能拿 R-6.9-004 的“和/或”替换那份清单，也不能因本项没写身份受限例外就披露受限身份。

若问题是某人**选了哪个组**或**谁能替他换组**，应分别查[选组状态查询](../groups/onnetwork-group-status-information.md)或[远程变更所选组](../groups/onnetwork-remote-group-change.md)。若需判读具体身份或配置过程，[跨业务身份映射](cross-service-user-mapping.md)说明业务用户 ID 与认证、路由身份的关系；[功能别名配置](functional-alias-configuration.md)区分配置通知与取档结果。这两个 Stage 2 主题都不改变 §6.9 的 Stage 1 要求。

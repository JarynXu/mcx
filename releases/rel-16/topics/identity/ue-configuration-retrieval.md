# 终端拿到的是设备配置，还是某人的用户配置档？

一份配置管理服务器的响应，不能笼统记作“配置完成”。先看响应的名称和内容：如果它是**获取 MC 业务终端配置**的响应，里面带的是终端（UE）的配置数据。即使终端收到了这份响应，也不能据此填上“已选用某人的用户配置档”“用户已获业务授权”“已下载某个组的配置”或“新设置已生效”。这些判断各自需要另外的记录。[§10.1.3.2，图后编号步骤 1、2，印刷页 67](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=68)

**设备怎样取得这份数据？** 终端使用该项 MC 业务前，必须先知道其终端配置。§10.1.3.2 讲的是一次获取：开始前，终端已经能安全访问配置管理服务器。随后，终端上的**配置管理客户端**向该服务器请求终端配置，服务器向这个客户端发送携带终端配置数据的响应。能安全访问，不表示已经请求；只见请求，不表示服务器已经答复；只见服务器发出响应，也不能替客户端确认已经收到。这两个步骤都没有给用户授予业务权限。[§10.1.3.1、§10.1.3.2 的前提及步骤 1、2，印刷页 67](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=68)

**初始配置和在线配置有什么区别？** 在主 MC 系统，引导过程先给终端上的客户端提供连接系统所需的信息，例如已配置业务对应的数据网络连接信息，以及终端需要联系的在线应用层服务器的标识。在线配置提供的是三类资料：终端配置、MC 业务用户配置档、组配置。使用业务期间还可能收到在线更新。这里列的是资料种类，不是说一份终端配置响应同时交付三类资料。具体某项业务的终端配置包含哪些项目，要查该业务对应的规范；公共架构条款没有列出一份适用于所有业务的字段表。[§10.1.1.1，图后前两段，印刷页 59](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=60)；[§10.1.3.3，印刷页 68](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=69)

**授权后到底用哪套？** 即使另有记录证明用户已获业务授权，而且终端拿到了授权后取得的配置，也不能仅据本版规范断言初始配置必被替换，或必然一直沿用。主系统条款末尾的编者注明确把这项决定留待研究。要判断某台终端实际用了哪套，需要它实际使用配置的记录。[§10.1.1.1，末条编者注，印刷页 59](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=60)

如果要查的是**某个用户**应下载哪些档，见[用户配置档下载](user-profile-download.md)；若问题是迁入伙伴系统后哪份档用来接入、哪份档用来接受业务，见[伙伴系统迁移配置时间线](partner-migration-configuration-timeline.md)。

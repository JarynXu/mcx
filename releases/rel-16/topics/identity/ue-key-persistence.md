# 终端重启、用户退出或访问令牌过期，哪些密钥和令牌要留，哪些要删？

甲关机再开机，终端必须为甲保留静态、半静态密钥及材料，例如组主密钥（GMK）；关机时却必须安全删除用于保护信令或媒体的动态密钥及其派生密钥。判断保留还是删除，要知道**是哪类材料、发生了什么事件**。以下规则来自 3GPP TS 33.180 V16.13.0（Release 16），对象是终端（UE）上保存的材料。[§5.11.2 第一、三段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

## 没有使用时，终端怎样存？

下列材料未在使用时，终端**必须以受保护的状态存储**。条款不指定存储方法。[§5.11.1，印刷页 64](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=65)

| 材料 | 条款列了什么 |
| --- | --- |
| 用于与 MC 域服务器建立安全通信的长期密钥和私有证书 | 例如 TrK、InK、TLS 私有证书，不限于这三种。 |
| CSK、GMK、MuSiK | 三类均明列。 |
| 基于身份的密钥材料 | 例如 KMS Key Set。 |
| 基于身份的令牌 | 例如 ID 令牌、访问令牌、刷新令牌、安全令牌。 |

MCPTT、MCData、MCVideo 用于保护信令或媒体的**动态密钥及其派生密钥**另有规定：终端**宜**按业务运行需要安全存储（should）；不再需要这些密钥时，**必须**安全删除（shall）。这里的“宜”只修饰存储，不修饰删除。[§5.11.1，印刷页 64](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=65)

## 同一人回来，还是另一个人来用？

**甲重启终端，或正常退出后仍由甲登录。** 终端必须安全保存静态、半静态密钥和材料，使其跨越这些状态仍得以保留。条款的例子包括 CSK、GMK、TrK、InK、TLS 和 IPsec 私有证书、KMS Key Sets，以及 ID、访问、刷新和安全令牌。保留这些材料有助于从在网转到离网，尤其是离网通信所用的身份密钥材料和 GMK。仅仅转入离网不等于令牌过期。这个保留清单是**举例**：MuSiK 没列在这些例子中，不能仅凭这一处就说重启必删或必留。存着令牌也不证明令牌有效、会话恢复或某项业务已授权。[§5.11.2 第一段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

**甲退出，乙随后登录同一台终端。** 对属于甲的全部密钥及材料，终端必须安全删除，或者把它们与其他用户的材料安全隔离。凡是跨登录周期或在多人使用期间仍保留的材料，都必须安全存储，且只有所属用户能访问。给记录加甲的名字或在乙的界面隐藏条目，本身不能证明乙无法访问。条款不指定隔离手段。这项选择不允许把本该在甲退出时删除的动态密钥隔离起来留用。同一个人切换业务配置档，也不等于另一个人登录。[§5.11.2 第二、三段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

## 动态密钥何时必须删？

终端关机、当前用户退出、相关访问令牌因技术或认证原因到期，或业务运行需要删除密钥，**任一项成立**，终端都必须安全删除相应的动态信令或媒体保护密钥及其派生密钥。动态密钥的例子是 MKFC、MSCCK、PCK；派生密钥的例子是 **DPCK**、SRTP 主密钥、XML 密钥和 AES 密钥。业务不再需要密钥时，§5.11.1已明确要求删除；§5.11.2 第 3 段把“业务运行需要删除”列为独立条件。当前用户退出也是触发条件，不必等乙登录。第 3 段的到期条件也不要求另外证明 IdMS 拒绝刷新。建立后续通信时可以重新协商动态密钥和令牌，不表示旧密钥可以继续用，或协商一定成功。[§5.11.1，印刷页 64](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=65)；[§5.11.2 第三段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

## 刷新没有成功，就要删除 GMK 吗？

要区分“没等到回复”和“令牌已经到期”。只有查明**访问令牌确实到期，而且是因为身份管理服务器（IdMS）出于技术或认证原因不能或不愿刷新现有访问令牌**，才据第 4 段要求终端安全删除以下材料：[§5.11.2 第四段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

- 密钥：CSK、GMK、MuSiK、MKFC、MSCCK、KFC、**DPPK**、PCK。
- 令牌：访问令牌、刷新令牌、安全令牌。

这一段明列的是 **DPPK**；上一段的派生密钥示例写的是 **DPCK**。两段同时适用时，第 4 段增加了删除范围，不取消第 3 段对动态密钥及其派生密钥的要求。第 4 段没有列 ID 令牌、TrK、InK、KMS Key Sets 或 TLS/IPsec 私有证书：不能据此要求把它们一起删掉，也不能保证它们在其他规则下始终保留。访问、刷新或安全令牌过期后，用户**可能**需要重新向身份管理服务和 MC 域认证，不是每次都必须。[§5.11.2 第三、四段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

例如，甲的终端暂时掉线，刷新请求没有收到答复，随后在原访问令牌到期前刷新成功。这不满足第 4 段的到期条件。SIP 掉注册也不能单独证明令牌到期。反过来，即使技术或认证原因导致的到期和不能刷新都已查实，规范说明的也是终端**应当怎样处理**，不是某台终端**已经删除**的证据。核对事件、材料类别和处理结果即可，不需要取得密钥或令牌的值。[§5.11.2 第三、四段，印刷页 65](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=66)

若争议是[登录后哪项业务已授权](home-system-authentication.md)、[同一人换了业务配置档](user-profile-switch.md)或[重启后 MCPTT 客户端 ID 是否保留](mcptt-client-id-lifecycle.md)，分别按相应主题判断；上述密钥条款不回答恢复出厂或重装应用后的行为。若触发事件是 CMS 通知成员已被移出组，查[成员移出时的 GMK 处理](../groups/removed-member-gmk.md)，不要把换用户或令牌到期当作移出成员的必要条件。

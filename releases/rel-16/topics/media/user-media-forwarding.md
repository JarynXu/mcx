# 收到的媒体能转给谁？什么时候是把实时组通信转给组广播组？

先看**媒体原来从哪里收到**，再看要转给谁。以下是 Rel-16 的 Stage 1 业务要求，讲的是用户或终端**转发已经收到的内容**，不是组呼服务器把发言人的流复制给组员。[3GPP TS 22.280 V16.8.0，§§5.19.1–5.19.2，印刷页 28（PDF 第 29 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

| 原来收到的是什么 | 业务须提供的转发办法 |
| --- | --- |
| 用户在一个 **MCX 组内**收到媒体 | 让获授权的 MCX 用户把这份媒体转给另一位 MCX 用户，或另一个 MCX 组。[R-5.19.2-001](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。 |
| 用户**从一位 MCX 用户**收到媒体 | 让获授权的 MCX 用户把这份媒体转给另一位 MCX 用户，或一个 MCX 组。[R-5.19.2-002](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。 |
| UE **在 MCX 组通信中收到实时通信**，该 UE 当前用户获授权 | 让这台 UE 把收到的实时通信转给**组广播组（Group Broadcast Group）**。这一条不要求把已经结束的历史通信重播给组广播组。[R-5.19.2-003](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。 |

## 从甲组转给乙组，成员资格和授权是两件事

§5.19.1 的业务描述说，转发受相关授权约束；**在组与组之间转发时，用户须是两边组的成员**。例如，甲在消防组收到一段视频，想转给急救组，不能只查他是不是消防组成员，也不能凭他已是两个组的成员就认定已获转发授权。只把内容转给另一位用户，或从一位用户收到内容再转给一组，不能仅凭有一个组就套“两组成员”的条件。这里说的是组成员资格，不把它等同于通信中已归属该组；也不据此补写组广播组的成员配置或核权步骤。[§5.19.1，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

视频、消息、文件和流媒体是业务描述列出的可转发内容。列出这些类型，不等于任一用户获准转发任一份内容。前两项没有规定自动转发，也没有规定转发必须实时；后一项明确限定了收到的是实时组通信，不规定转发时延。机制存在不能证明目标用户已获准、实际收到或查看。[§§5.19.1–5.19.2，印刷页 28](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=29)。

## 哪些业务适用这三条？

在这一版规范中，**MCVideo 和 MCData 的适用表都列出上述三项**；MCPTT 的表 A.1 将 §5.19.2 标为 **NA**。这表示不能用本条要求 MCPTT 支持这三项，不是说其他规范不能另行定义 MCPTT 的相关能力。这些条文不规定使用 SIP、HTTP 还是 RTP，不给转发字段，也不说明离网如何实现。[MCPTT，表 A.1，印刷页 65](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=66)；[MCVideo，表 B.1，印刷页 76](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=77)；[MCData，表 C.1，印刷页 87](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=88)。

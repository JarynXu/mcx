# 在网 MCPTT、MCVideo 的发送队列怎样排序，组通信排队后如何查队位？

队位回答的是“现在排第几”。即使排在第一，也不表示已经获准发送。TS 22.280 V16.8.0（Release 16，Stage 1）分别规定业务怎样排序、何时提供队位，以及组通信继续时通知谁。[第 6 章：在网范围，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)；[§6.2.2，印刷页 30（PDF 第 31 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=31)。

## 哪些因素决定排序？

| 依据 | MCX 业务的职责 |
| --- | --- |
| 通信和请求用户（R-6.2.2-001） | **须**按通信类型（如组通信、私通信）、紧急程度（如普通组通信、MCX 紧急通信、迫近危险通信）和请求用户的属性（如优先级）排列发送请求。若是组通信，还须考虑业务组的属性（如优先级）。 |
| 辖区（R-6.2.2-002） | 如果已知 MCX 业务组和 MCX 用户在各自辖区内活动，业务**可以**给这些组和用户的通信较高优先级。 |
| 工作时段或值勤（R-6.2.2-003） | 如果已知处于工作时段或正在值勤，业务**可以**给相应业务组和用户的通信较高优先级。 |

组通信和私通信只是类型示例。只有组属性这一项带有“若是组通信”的条件。条文没有给这些因素设权重，也没规定同级请求谁在前。知道某名用户正在辖区内值勤，还不能断定他的请求会排在另一笔请求之前。[§6.2.2，-001 至 -003，印刷页 30](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=31)。

## 入队后，谁能撤回，业务何时给队位或指示？

- **取消自己的请求（R-6.2.2-004）。** 用户的发送许可请求已入队，业务须允许该用户取消自己的请求。这一条没有授予代他人取消的权限。
- **给出该用户的当前队位（R-6.2.2-005）。** 如果组通信的发送请求已入队，业务须应请求提供该 MCX 用户当时在队列中的位置。条文不要求每次名次变化都主动推送，也没有要求给出其他人的位置或预计等待时长。
- **通信继续时收到指示（R-6.2.2-006）。** 如果组通信请求已入队，通信继续时，业务须向请求人发出指示。这里没有“先查询队位”的条件。只看到队位答复，不能判定通信已经继续；本项也没规定继续指示必须使用发送许可消息，或必须单独发一条消息。

[§6.2.2，-004 至 -006，印刷页 30](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=31)。规范性[表 A.1（MCPTT），印刷页 65](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=66) 和[表 B.1（MCVideo），印刷页 76](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=77) 的 §6.2.2 行分别列全六项；[表 C.1（MCData），印刷页 87](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=88) 的同一行明确标为 **NA**。这不等于 MCData 没有发送请求队列：[§6.19.1.1 的排队、拒绝与移除](onnetwork-transmit-request-queuing-and-rejection.md)也适用于 MCData，另规定自撤、获授权用户代撤及出队后已经开始通信的通知。

若问业务是否须支持按优先级**排队和保留**，见[§6.8.1 -006](../bearers/onnetwork-service-preemption.md)；它不提供本节的排序依据。只有要核对某项业务实际采用的协议时，才查[普通在网 MCPTT 客户端的话权排队](on-network-floor-client.md)或[普通预安排 MCVideo 组呼的队位与授予](../mcvideo/prearranged-group-queue-position.md)。这些 Stage 3 程序有各自的前提，不是本节要求的共同步骤。

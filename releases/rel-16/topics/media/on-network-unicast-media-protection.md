# 在网单播的加密语音和话权，各在哪一段处理？

**参与服务器能解开话权消息，却转发 RTP 而不解密其负载，这两件事可以同时成立。** 先区分语音 RTP、RTCP APP 承载的话权消息，再看这笔消息实际经过哪两个功能。以下限 TS 24.380 V16.9.0 的在网单播，适用于目标组不是临时组组成组的组呼，以及在网私呼。PF 是参与 MCPTT 功能，CF 是控制 MCPTT 功能。[§13.1，印刷页 226–228](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=227)

## 加密语音：PF 和 CF 不解密 RTP 负载

呼叫已协商语音媒体保护时，PF 和 CF 都须转发加密的 RTP 流，不解密其负载。组呼的终端语音用该组的 **GMK / GMK-ID** 保护，私呼改用 **PCK / PCK-ID**。这两类密钥都不是下表的话权密钥。只见 PF 没解密语音负载，不能判它解密故障；也不要把这条要求读作 RTP 报头或整个包必然逐字节不变。若终端仍无声，另外确认收到的是本呼叫的媒体流，再核对终端的解密和播放结果。[§13.1，印刷页 226–228](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=227)；[§13.3.2 第 1 项，印刷页 229](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=230)；[§13.3.4 第 1 项，印刷页 235](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=236)

## 话权消息：分别查终端侧和控制侧

| 实际链路 | 查什么条件 | 条件成立后各端的动作 |
| --- | --- | --- |
| 终端 ↔ 服务该终端的 PF | 已协商**该段单播话权保护**，且 PF 已经由 SIP 收到这台终端生成并提供的 **CSK / CSK-ID**。 | PF 对发往终端的话权消息加密，对从终端收到的话权消息解密。 |
| PF ↔ CF | 已协商**这段服务器间话权保护**；判断哪一端，就查 **SPK / SPK-ID** 是否已配置在那一端。 | PF 发往 CF 时加密、从 CF 收到时解密；CF 以同样的收发方向规则处理与 PF 的往来。 |

两段话权保护须分别确认。一份记录可以覆盖两段，但仅证明一段已协商，不能证明另一段也已协商。看到 PF 从终端解开一条话权消息，查得的是这一端的接收处理，不能替 PF 到 CF 的发送、CF 的实收或它的解密签字。对应规则也不保证每一条话权消息都会原样逐条转发。条文用列出的密钥及其标识导出保护所需的材料，不应把抓包中的标识值直接当成原始密钥或据此断定上下文一致。排障时对照实际链路、收发方向、该段协商和保护上下文的状态，不需要抄录密钥值。[§13.1、§13.2，印刷页 227–229](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=228)；[§13.3.2 第 2、4 项，印刷页 229–230](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=230)；[§13.3.4 第 2A、4A 项，印刷页 235–236](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=236)

如果观察到的是 **RTCP SR、RR 或 SDES**，那是媒体控制，不是 RTCP APP 话权消息。即使媒体控制在对应链路也使用 CSK 或 SPK，仍要检查**媒体控制**所用的协商，不能援引话权那一条。这里不推定协商或材料缺失时的回退方式，也不解释 MBMS、离网、临时组组成组或预建立会话的专用控制保护。[§13.1，印刷页 226–228](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=227)；[§13.3.2 第 7–8 项，印刷页 230–231](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=231)

若查的是临时组组成组在网呼叫中实际承担非控制功能的一端，读[临时组的非控制功能](temporary-group-noncontrolling-media-protection.md)，分别核对加密 RTP、话权和媒体控制。

保护层已核实、仍有持有者语音中断时，读[控制侧等 RTP 的计时器](on-network-floor-media-timeouts.md)；终端已处理话权消息、要判断能否开始发送时，读[终端话权状态](on-network-floor-client.md)。若所查记录是 SIP 里的敏感业务正文，另读[SIP XML 的保密和复制](../calls/sip-xml-confidentiality-copy.md)。

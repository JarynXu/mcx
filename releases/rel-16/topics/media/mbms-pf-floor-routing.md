# 已报 MBMS 监听，为什么参与服务器还单播话权？

**最新收到的监听报告说 listening，不代表这台终端的全部下行都要走组播。** 参与 MCPTT 功能（PF）先看这个包所关联的通话是否用多媒体广播多播业务（MBMS）子信道，再按包是话权控制还是 RTP 语音分别判断。以下只谈 TS 24.380 V16.9.0 在网 PF，按需会话已建立，或预建立会话实际在用。[§6.4.1–6.4.3，印刷页 101–103](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=102)

## 话权要发给终端：先查消息是哪一种

从终端话权参与者收到的上行话权消息，PF 须立即转给话权控制服务器。下行消息来自话权控制服务器、且关联的通话没用 MBMS 子信道时，PF 须立即转给终端。别拿系统支持 MBMS 或收到通告，代替“这场通话在用这条子信道”。[§6.4.2 第 1、2 项，印刷页 101–102](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=102)

关联通话已用 MBMS 时，按第 3 项对**这台终端**判断。下面的「三类消息」仅指 **Floor Idle（空闲）、Floor Taken（有人持有话权）、Floor Release Multi Talker（多讲者释放）**。

| 实际看到的条件 | PF 怎样处理 |
| --- | --- |
| 消息不属于三类，例如给某终端的 Floor Granted。 | 立即向终端话权参与者转发。 |
| 该终端尚未报告 listening，或 PF 最新收到它的报告为 not-listening。 | 立即向终端话权参与者转发。 |
| 属三类之一，要求保护 MBMS 下行话权消息，且 PF 已判定该终端不支持 MuSiK。 | 立即向终端话权参与者转发。即便该终端报告了 listening，这个条件仍可成立。 |
| 三个条件都成立：最新实收报告为 listening；消息属三类之一；不要求该项保护，或 PF 已判定该终端支持 MuSiK。 | 交给 §10.2 的 MBMS 子信道程序。进入程序不表示这条消息一定再次发送。 |

前三行是独立的转发入口；最后一行要同时核对监听、消息类别和保护条件。PF 没有记录能证明是否支持 MuSiK，不能直接填成“不支持”。别用通告、其他终端的监听报告或另一通话的记录代替本次判断。[§6.4.2 第 3(a)、3(b) 项及注，印刷页 102](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=103)

## 同一个终端，RTP 可以走 MBMS，话权仍单播

PF 从控制功能（CF）或非控制功能（NCF）实际收到下行 RTP 后，若相关通话没有用 MBMS 子信道，或终端未报告 listening、最新报告为 not-listening，PF 按相应分支立即转发给终端。通话用 MBMS 且该终端最新报告 listening，则进 §10.2。**这条 RTP 规则没有话权的 MuSiK 判据。** 因此同一个报告 listening 的终端，在保护被要求且 PF 已确认它不支持 MuSiK 时，RTP 可以按 §10.2 走 MBMS，三类话权消息却仍单播。先看实际处理记录，不能仅凭这种混合路径判定配置错了，也不能证明终端已收到任何一包。[§6.4.2 第 3(a)(iv) 项与 §6.4.3，印刷页 102–103](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=103)

## PF 回的 Ack，不是终端回的

在 §10.2 的**活动通话**分支，发往监听终端的 Floor Idle 或 Floor Taken 真正送上 MBMS 时，PF 把出向确认位设为 0。若入向请求确认，由 **PF** 向 **CF** 回 Floor Ack（Source 1）。重复序号可能不会再下发，但入向按要求回 Ack 仍适用。因此见到这个 Ack，不表示 PF 再次下发，更不表示终端收到；缺一个终端 Ack 也不能在此判它未收到。多讲者释放的专条没有同样的置位和回 Ack 步骤，不能给它照搬 Idle/Taken 的规则。RTP 已发送过的判断也不是话权序号比较。[§10.2.3.2、§10.2.3.3、§10.2.3.3a，印刷页 206–207](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=207)；[§10.2.3.5，印刷页 208](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=209)

已进入 MBMS 活动会话，要核对[去重和 PF 确认](mbms-floor-ack-and-rtp-duplicates.md)；要查哪份报告属于这个承载，读[监听与应用控制信令](../bearers/mbms-application-control-signalling.md)；已确认消息走单播、要查加密保护，看[在网单播语音与两段话权](on-network-unicast-media-protection.md)。

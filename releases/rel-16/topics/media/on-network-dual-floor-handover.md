# 在网双话权交接：甲松开一般话权，乙要重新抢话吗？

不用。这里的组呼已经在网运行双话权，不支持 `multi-talker`，不讨论音频切入。甲是一般话权中被覆盖的人，乙是仍持有覆盖话权的人。服务器收到甲的 `Floor Release` 后，可能给同一听众先发 `Floor Idle`、再发 `Floor Taken`，同时终止覆盖状态机。**终止的是覆盖实例，乙仍持有话权，直到这次发言结束。** 不能拿这条 Idle 登记为整组已经空闲。[TS 24.380 V16.9.0，§6.3.4.4.6，印 61](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=62)；[§6.3.4.3.2，印 56–57](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=57)；[§6.3.6.3.9 注，印 101](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=102)。

## 哪些人会收到 Idle 和 Taken？

**看服务器发送前的配置。** 一般仲裁器 G 在 `Floor Taken` 收到甲的 Release，先要求媒体分发器停止转发甲的 RTP，并停止甲仍在运行的 T2 和 T20；然后进入 §6.3.4.3.2 所指的入口。从非 `Start-stop` 状态进入，且双话权状态机 D **实际存在**，才按下面这支处理，不是只看组配置写了“支持双话权”。[§6.3.4.4.6，印 61](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=62)；[§6.3.4.3.2，印 56–57](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=57)。

1. G 删除与一般话权关联的已存 `Track Info`（若有），给**配置为收听甲**的参与者发 `Floor Idle`。
2. G 给**配置为只收听甲**的参与者发 `Floor Taken`。他们是上一组人的子集；两种消息都要求递增序号。未请求隐私时，Taken 的获准者身份是乙。只收听乙的参与者，不是这两项发送所列的对象。
3. G 设为 `Floor Taken`，再向 D 发送终止指令（Terminate），不是停在 `Floor Idle` 等乙补发申请。

抓包若只见 Idle，先核收件者原来听谁、另一条通知是否发送或在本端实收。此处规定的是服务器发送及状态变化，不证明终端已收到通知、已改播乙或能听到语音。[§6.3.4.3.2，D 存在分支第 1–5 项，印 56](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=57)及[印 57](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=58)。

## 覆盖实例结束时，乙的计时怎样移交？

要看到 **D 实收 Terminate**。若 **T11** 正在运行，把 **T1** 的值设为 T11 的值并启动 T1；若 **T12** 正在运行，把 **T2** 的值设为 T12 的值并启动 T2。两项各查各的运行状态；某个 D 定时器未运行，不据此条启动其对应的 G 定时器。规范写“值”，没有在本条规定是余时、经过时长或完整配置时长。此后 D 释放为它保留的媒体资源，停掉与它关联的运行定时器，回到 `Start-stop`。这不等于乙失去本次发言权。[§6.3.6.3.9，印 100](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=101)及[印 101](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=102)。

若**松开的是乙**，D 实际收到乙的 Release，§6.3.6.3.6 则要求媒体分发器停止转发乙的 RTP，且按该分支处理 D 资源和通知；不能按 Terminate 给乙移交计时。若实收的是 T11 或 T12 到期事件，查[覆盖话权的两个到期分支](on-network-dual-floor-timeouts.md)。若是普通按需组呼、唯一持有者的 Release 来自直接关联的客户端，且没有 D，则查[一般话权持有者主动松开](on-network-holder-release.md)；如果工单问怎样把第二个发言者纳入话权控制，查[双话权怎样建立](on-network-dual-floor-entry.md)。[§6.3.6.3.6，印 99–100](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=100)。

## 非控制侧还存着覆盖者 SSRC，收到 Taken 后哪些人会看到通知？

上文看的是控制侧 G 和 D。这里另看**非控制功能（NCF）的服务器接口实际收到 CF 发来的 Floor Taken，且报文没有 Track Info**。不要求 CF 先收到一般持有者的 Release，也不能拿服务器内部的 D 终止事件代替实收。P 指本 NCF 在这场会话内面向一个终端的话权参与者接口。以下限双话权相关的普通在网组呼，不讨论多人发言或音频切入。[TS 24.380 V16.9.0，§6.5.4.9 注 1 及第 2 项，印刷页 109–111](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=110)；[§6.5.5.1，印刷页 113](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=114)。

| CF 的来向 Taken | NCF 在这场呼叫中向谁发 |
| --- | --- |
| **已存双话权获准者 SSRC，来向无 Floor Indicator 或 G=0** | 第 2(d)(i) 项写明：发 **Taken** 给本场所有本地 P，**但排除只听覆盖一路**的参与者。只听覆盖一路的终端没见到这条 Taken，符合该发送范围，不能直接记为丢包。G=0 或无 Indicator 并不按这条删除已存 SSRC。 |
| **来向有 Floor Indicator 且 G=1** | 先保存来向 **获准话权参与者的 SSRC 字段**，关联到双话权。按本地策略，向收听覆盖 RTP 的参与者发 **Taken**；另向只收听覆盖 RTP 的参与者发一条 **Idle**，把这条出向 Idle 的 G 位设为 0。两份出向消息均按分支填写本地序号值加 1。 |

第 2(d)(i) 项的**发送句**写 Taken，后面的字段与序号说明却写 “The Floor Idle message”。收件范围的发送句有明文，字段说明的对象有这处差异；不能把它改写成该分支另发一条 Idle，也不能据此断定这份 Taken 必按那两项改写字段。首位置 0 是无 Track Info 分支对**下发 Taken**的规定；若原来向 Taken 首位为 1，NCF 自己须向 CF 确认。查字节时保留[普通 Taken 页说明的 Ack 代码差异](on-network-noncontrolling-floor-grant.md)，不能从 CF 收到确认推出某台终端已经收件。[§6.5.4.9 第 2(a)–(e) 项，印刷页 110–111](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=111)。

**定向、合成和实收要分开。** G=1 时分别按本地策略确定两种消息的收件人；条文没有说两组互斥。只听覆盖一路的终端若看到 Taken 和 G=0 的 Idle，两份都可能来自同一条入向 Taken 的不同下发动作，并不需要 CF 发过 Idle；要确定本次来源，再核对 NCF 的入向记录、当时收听策略和向这台终端的实际发包，不能从条文推出这两份一定送到或有固定到达顺序。这里的 Idle 是 NCF **发出**的，不是 NCF **从 CF 实收**的。明确删除缓存的是另一个入口：NCF **实收 CF 的无 Track Info、且 G=1 的 Floor Idle**，按 §6.5.4.8 第 2(b)(ii) 项处理；那条 Idle 的被动队列清理也不能搬给本段的出向合成。若要判某台终端已经收到覆盖语音，要另对本场缓存、实际 RTP 的 SSRC、分发器报告、收听策略和终端收包，不能用 Taken 或合成 Idle 替 RTP 作证。[§6.5.4.8 第 2(b)(ii) 项及第 3 项，印刷页 109](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=110)；[§6.5.4.9 第 2(d)(ii) 项，印刷页 110](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=111)；[§6.5.4.12 第 2–3 项，印刷页 111](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=112)。

# 跨系统组呼：伙伴有三个组员，组宿主要发几条媒体流？

**组宿主向服务这三个组员的同一台伙伴业务服务器发一条流，由伙伴业务服务器复制并分发。** 这里讲 MCPTT、MCVideo 的通用互联程序，取由伙伴侧复制媒体的组呼情形。一条数的是两个业务服务器之间的媒体流，不是组员数，也不是网络包数。[3GPP TS 23.280 V16.7.0，Rel-16 Stage 2，§10.14.4.1，印 209](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=210)；[§10.14.4.2，图 10.14.4.2-1、步骤 3b–3c，印 210](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=211)。

甲、乙是互联的 MC 系统。甲是组 G 的主系统，A 在甲接受业务并发起这次组呼。B、C、N 由乙的同一业务服务器服务，四个客户端都已归属 G。乙是**组 G 的伙伴系统**，却可以是 B、C、N 各自的主系统；他们中也可以有人成功迁入乙。判断这张图是否适用，看成员此刻由谁服务，不要求全员迁移。[§10.14.4.2 引言、前提 1，印 209](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=210)；[前提 2–3、注 2 及图，印 210](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=211)。

**先分清许可和发送。** 这通组呼已建立，话权控制或传输控制以及媒体路径均已建立。A 请求向 G 发媒体，甲的组宿主业务服务器向 A 授予话权或发送许可。若记录停在授予，只能确认 A 获准；A 发出媒体另有一步。[§10.14.4.2 步骤 1、2、3a，印 210](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=211)。

| 图中步骤 | 谁发给谁 | 此处看什么 |
| --- | --- | --- |
| 3a | A → 甲的组宿主业务服务器 | A 把媒体流发给宿主。 |
| 3b | 甲的组宿主业务服务器 → 乙的业务服务器 | 宿主发一条流，接收方是服务 B、C、N 的服务器，不是某一位组员。 |
| 3c | 乙的业务服务器 → B、C、N | 乙复制媒体，向它服务的这些组员分发。分发可用单播或组播承载。 |

所以，乙向三人分别单播，与甲只向乙发一条流并不矛盾。若日志只显示乙收到这条流，证据止于乙服务器，不能判断 C 收到还是没收到。即使另有乙向 C 发出的记录，也不能据此登记 C 已收到或播放；要判断 C 的结果，得查 C 这一端。[§10.14.4.2 图 10.14.4.2-1、步骤 3a–3c、注 3，印 210](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=211)。

**换个问题，就要换依据。** 上述流数只算这次从甲宿主到乙这一台服务服务器的逻辑传递；换成乙方发言或由乙的多台服务器服务，不宜沿用图中的流数。图还省略了拓扑隐藏，不能从这条箭头数出物理链路或判定没有网关。§10.14 是 MCPTT、MCVideo 的通用互联程序，具体业务还要结合各自专规。[§10.14.4.2 引言、注 1，印 209](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=210)；[§10.14.1，印 205](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=206)。

- 若组主系统已提供组配置，伙伴采用本地设置，问的是**伙伴如何按这份本地配置核准已归属成员的呼出，或转给该成员的宿主来话**，查[伙伴如何按本地组配置准入](../groups/partner-group-call-admission.md)。逐通授权与建路不是媒体已发送的证据。
- 若是**两台服务器为同一组呼请求同区 MBMS 承载**，查[同一组呼的重复广播](../bearers/same-group-call-broadcast.md)；若组会话原走单播，要判是否**已换到动态 MBMS 下行**，查[动态承载通告与路径切换](../bearers/mbms-dynamic-group-downlink.md)。这两题都不按跨系统箭头数终端收件。
- 若是主、伙伴系统的两个 **MCData 业务服务器之间共享文件地址**，或两个**内容服务器之间共享文件正文、元数据**，查[跨系统文件分发中的参考点](../mcdata/intersystem-fd-url-content.md)。伙伴客户端拿到 URL 或向伙伴内容服务器下载，是客户端这一端的事，不能据此认定两台服务器已共享正文。

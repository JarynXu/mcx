# 多路组通信和私通信怎样排呈现顺序？紧急组通信何时自动呈现？

终端能同时接收几路，不决定用户先听到或看到哪一路。对终端的**呈现顺序**，MCX 业务须提供机制，让 MCX 业务管理员和/或获授权用户分别处理以下三种比较。三项依据均为 [§5.4.2，印刷页 16](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=17)。

| 比较哪些通信 | 对象的范围 | 要求 |
| --- | --- | --- |
| 组通信与组通信 | 同一 MCX 业务用户配置（User Profile）内的多个业务组 | 能为这些组的通信安排呈现顺序（R-5.4.2-004）。 |
| 私通信与私通信 | 多场 MCX 私通信 | 能为这些私通信安排呈现顺序（R-5.4.2-004A）。 |
| 组通信与私通信 | 用户配置内业务组的通信，加上 MCX 私通信 | 能把这两类通信放在一起安排呈现顺序（R-5.4.2-004B）。 |

分别排好几个组、再排好几场私通信，还没有回答“一路组通信和一路私通信同时到，先呈现哪一路”。这是 -004B 单列的比较。“用户配置内”限定的是业务组；-004A 没有这个组条件。三项都不指定默认赢家，也没有要求终端停止接收排在后面的通信。

**什么情况下必须自动呈现？** 用户已归属的一个组有紧急组通信，而此人已经在优先级较低的组通信或私通信中，业务须确保用户自动**听到或看到该紧急组通信**。只通知“有紧急通信”没有交代其内容是否呈现。该要求没有规定结束原通信、撤销话权或抢占其资源。[R-5.4.2-007，印刷页 16](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=17)。

一名用户能否同时**参与**多场紧急组通信，是另一项要求：业务须能根据功能别名中有意义的要素，限制或允许这种参与。条文没有指定具体要素或统一上限，也没有规定多场紧急组通信之间的呈现顺序。[R-5.4.2-007a，印刷页 16](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=17)。

3GPP TS 22.280 V16.8.0（Release 16，Stage 1）把这些要求列在在网与离网共用的[第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。[表 A.1（MCPTT），印刷页 62](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=63)和[表 B.1（MCVideo），印刷页 73](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=74)列出 -004、-004A、-004B；[A.1 续页，印刷页 63](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=64)和[B.1 续页，印刷页 74](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=75)列出 -007、-007a。[表 C.1（MCData），印刷页 84](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=85)列出全部五项。

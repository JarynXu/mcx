# MCPTT 话权消息的位置：没有坐标时怎么查，多话者按什么顺序对人？

在普通在网 MCPTT 组呼中，抓到 `Floor Request` 或 `Floor Taken` 的位置字段，不代表收到经纬度。遇到多话者的 `Floor Taken`，也不能只为有坐标的人保留位置条目。下面只看终端初次请求及 T101 限内重发、服务器仲裁进入 `G: Floor Taken` 时发给其他参与者的通知。不是 LMS 位置上报。

## 一个话者：字段缺失和明确不提供是两种结果

| 在哪里抓到消息 | 应核对什么 |
| --- | --- |
| 终端按 PTT 发 `Floor Request`；或未到 C101 上限，T101 到期重发 | 两个发送步骤都要求带 `Location`。如果当前说话者的位置不可用，或 MCPTT 用户档案不允许报告，仍带字段，`Location Type=0`。位置可用且获准上报时，按类型表填类型和值。 |
| 服务器仲裁进入 `G: Floor Taken`，只有一人获准，给其他参与者发 `Floor Taken` | 这里也要求带 `Location`，按同样的可用性和用户档案判定它的类型和值。`Granted Party's Identity` 和功能别名分别有不请求隐私的条件，不能拿 ID 或别名缺失代替位置类型的判定。 |

[TS 24.380 V16.9.0 §6.2.4.3.5，印刷页 38–39](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=39)；[§6.2.4.4.5，印刷页 40](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=41)；[§6.3.4.4.2 第 3(a) 项，印刷页 59](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=60)。

先看字段是否存在，再看类型。Type 0 表示 **Not provided**，没有位置值，不是坐标 (0, 0)，也分不出是没有可用位置还是不准发送。非零位置类型也不一定是经纬度：表中还有 ECGI、跟踪区、PLMN、MBMS 服务区、MBSFN 区等，地理坐标是 Type 6。确认抓包完整、方向和发送分支正确后，如果必带的字段在报文上确实缺失，不能把它当作 Type 0。如果只在解析器界面看不到字段，先回到报文核对。[§8.2.3.21，表 8.2.3.21-3，印刷页 159–160](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=160)。

## 多话者：没有位置也不能删掉该人的条目

服务器支持多话者、当前有多人获准时，同一条占权通知中，`Floor Indicator` 的 I 位为 1，有 `List of Granted Users`、`List of SSRCs` 和 `List of Locations`。位置条目数必须等于获准用户数，位置列表与用户列表的顺序必须一致。如果这条消息列出甲、乙、丙，乙的位置不可用或不允许报告，位置列表仍是三项，**第二项保留为 Type 0**，第三项仍对应丙。不能删掉乙、补实际坐标、另按位置类型排序，或从另一个时刻的通知拼接列表。[§6.3.4.4.2 第 3(b) 项，印刷页 59](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=60)；[§8.2.3.17 获准用户列表，印刷页 157](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=158)；[§8.2.3.22 位置列表，印刷页 160–161](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=161)。

排错时，对同一条 `Floor Taken` 核对 `No of users`、`Number of Locations` 和逐项顺序。规范也要求这条消息的 SSRC 列表按同一用户顺序，核对时仍以获准用户列表为准。若只剩甲和丙的两个位置项，不能猜哪项属于谁；本节未规定出错后的接收处置。匹配成功说明该消息如何声明身份与位置，不证明终端此刻重新定位、任何一方收到媒体，或 LMS 收到位置报告。[§8.2.9，印刷页 168–169](https://www.etsi.org/deliver/etsi_ts/124300_124399/124380/16.09.00_60/ts_124380v160900p.pdf#page=169)。

如果抓到的是[终端向 LMS 的按配置位置上报](../location/event-reporting-configuration.md)，不要用这套话权字段解释。如果要核对[终端的请求重发与授予通知](on-network-floor-client.md)，先看终端状态；若收到的是[多话者专用的放权消息](on-network-release-multi-talker.md)，本页的生成分支不适用。

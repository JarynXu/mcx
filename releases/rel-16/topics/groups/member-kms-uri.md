# 同一组成员有三个业务 ID：少了一项 KMSUri，该用哪个值？

先看**这个成员、这项业务**的组配置。若其中已给出业务 ID 所属安全域的 KMSUri，就用该值。只有确认这项参数缺失，才按表 A.4-1 注 3，采用表 A.6-1 的在网初始 MC 业务 UE 配置中标识的 KMSUri。另一个业务的成员记录不提供这个缺省值。〔[表 A.4-1，成员行，印刷页 214](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=215)；[注 3，页 215](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=216)〕

例如，在网业务核对时，同一成员的三项业务 ID 均已提供。对应 UE 的初始配置记载，密钥管理服务器（KMS）的 Server URI 为乙。甲、乙在这里指材料中两个不同的 URI，不是规范指定的地址。

| 业务 | 手头的组配置材料 | 能确定什么 |
| --- | --- | --- |
| MCPTT | 成员的 MCPTT 项列有 KMSUri 甲 | 用甲。初始配置里有乙，不能用乙覆盖甲。 |
| MCVideo | 已核对完整的成员 MCVideo 配置，其中没有 KMSUri 参数 | 按注 3 用乙。依据是初始配置，不是把 MCPTT 的甲复制过来。 |
| MCData | 导出只含成员的 MCData ID，没有导出 KMSUri 这一栏 | 值未定。先查完整的 MCData 成员配置；找到显式值就用它，证实缺失才按注 3。 |

**如果已证实 MCVideo 项缺失，却没拿到 UE 的初始配置呢？** 取值规则已确定，具体 URI 还不知道。表 A.6-1 的位置是“应用平面服务器标识信息 → 密钥管理服务器 → Server URI”。身份管理、配置管理、MCVideo 等服务器也有名为 Server URI 的行，不能抄用。规范给出字段及含义，不提供现场实例的地址。[表 A.6-1，印刷页 218](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=219)

## 为什么不从业务 ID 或组内优先级取缺省？

表 A.4-1 在“组成员名单”下按 MCPTT、MCVideo、MCData 分支。每个分支下，**业务 ID、该 ID 所属安全域的 KMSUri、用户在组内的优先级是同级字段**。例如 MCVideo ID 和 MCVideo 的 KMSUri 都标为两层子项；KMSUri 不嵌在 ID 这个值里。[§A.1 层级说明，印刷页 211](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=212)

注 2 标在业务 ID 行：对于该成员已配置的每项 MC 业务，均须提供相应的业务 ID。注 3 只标在三个安全域 KMSUri 行上。已配置业务却确实少了 ID，不能用初始配置的 URI 代填；组内优先级也没有注 3 给出的缺省。注 1 另说，名单仅在获授权用户请求时提供，不默认发给用户。一次用户侧导出没有成员详情，不能拿来证明某个成员字段原本没有。〔[成员行，页 214](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=215)；[三条表注，页 215](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=216)〕

## UE 列是 N，为什么注 3 还指向 UE 的配置？

看的是两份配置。表 A.4-1 列的是**在网和离网共用的组配置**。三个成员 KMSUri 行的配置对象依原表顺序为：**MC 业务 UE：N；MC 业务服务器：Y；组管理服务器（GMS）：Y**。这项组参数不需要配置给 UE，需要配置给后两类功能实体。N 不禁止 UE 通过其他配置知道该 URI；Y 不表示所有服务器都收到过这项数据，也不是某次报文的必带标志。〔[§A.1 列定义，页 211](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=212)；[§A.4，页 212](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=213)；[表题，页 213](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=214)〕

表 A.6-1 列的则是**在网初始 UE 配置**。注 3 引用其中的 KMS Server URI，没有把表 A.6-1 变成离网操作流程，也没有把成员行变成 UE 的必配组参数。即使知道 URI，也不能断定终端已连接这台 KMS、该 URI 可达或已取得密钥。这些是运行结果，需要另外的运行证据。

若要查**谁可请求成员名单，如何区分成员和已归属成员**，见[主动查询组名单](group-list-query.md)。若材料是**GMS 发给已订阅客户端的更新通知**，要判断其中可带哪些组相关密钥材料或配置引用、何时保存，见[终端获取组配置与更新通知](client-group-configuration.md)。两页都不提供成员 KMSUri 的现场取值。

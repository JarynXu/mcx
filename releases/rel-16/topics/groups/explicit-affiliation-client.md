# 显式组归属：本客户端的建立、解除与状态观察

- 固定 TS24.379 V16.14.0 的在网显式归属，主体为本用户在本客户端的兴趣及查询；不展开授权修改他人、协商式命令、隐式归属或规则引擎全流程。
- 客户端发布、订阅、NOTIFY 接收及必要服务器处理按各自入口适用；失败、抑制、部分接受与状态处理中间态不以已归属或已进呼为共同前提。
- 只说明本版归属控制与证据边界；不覆盖完整外部 SIP/RFC、组管理、配置获取、安全实现或媒体会话生命周期。

## 发布的是本客户端完整兴趣，不是选中组或已进呼

- 条件：本用户在本客户端请求显式归属、解除归属，或根据已收到的 affiliated 状态及到期时间刷新兴趣；手动解除请求也可进入抑制分支。

希望获知变更成功或拒绝时，客户端须先启动 §9.2.1.3 的状态确定，再启动变更。手动解除时先检查用户配置：归属由规则满足而激活，且 manual-deaffiliation-not-allowed-if-affiliation-rules-are-met=true，两者同时成立才抑制该用户请求。可发送的 PUBLISH 指向服务本用户的 O-PF PSI，mcptt-request-uri 写本用户 MCPTT ID，P-Preferred-Service 标识 MCPTT。PIDF 的 entity 是用户 ID，tuple id 是客户端 ID，affiliation 的 group 是组 ID；正文包含该客户端仍感兴趣的全部组，不是只列新增组。仍有至少一个组时 Expires=4294967295，已无任何组时 Expires=0；不填写 affiliation 的 status/expires 属性，并生成全局唯一 p-id。

规范强度：客户端请求构造、发送及满足双条件时抑制为 SHALL；被抑制时可提示用户是 NOTE 中的 can，不要求总是提示。
- 边界：本页不展开规则引擎、授权改变他人归属或协商式命令。规则激活只在手动解除守卫中保留，不把它作为所有显式归属的前提。
- 边界：选组是另一动作：§10.1.4.2.2 将需要时的归属与随后改变 selected group 分步处理。这里只比较两种责任，不据此补出远程选组全部许可或缺字段规则。
- 边界：PUBLISH 是兴趣发布，不是组呼 INVITE；也不因组已选中便断言客户端已归属。

依据：3gpp-ts-24.379-v16.14.0 §9.1;9.2.1.1–9.2.1.2 full，印刷页 167,168,169；3gpp-ts-24.379-v16.14.0 §9.3.1.2 per-user syntax，印刷页 194；3gpp-ts-24.379-v16.14.0 §10.1.4.2.2 steps1–2 (selected-group comparison only)，印刷页 309。

## PUBLISH 200 早于实际状态处理

- 条件：用户服务器收到符合 §9.2.2.2.3 opening 的 presence PUBLISH；各拒绝、200 后检查、非零或零期限状态处理分别适用，不把这些分支串为同时满足。

该入口要求 PF PSI、指向所服务用户的 mcptt-request-uri、MCPTT P-Asserted-Service、presence Event 及 per-user PIDF。本页自身变更通过 O-PF 方向从 P-Asserted-Identity 识别发起用户；一般入口仍规定不同用户且未获修改许可时 403 并停止。Expires 缺失或为小于4294967295的非零值时 423/Min-Expires=4294967295 并停止；零值另走撤销分支。随后先发 200，再检查 PIDF entity 是否等于所服务用户，不等即停止后续。因此 200 不证明正文身份一致或归属完成。身份一致后按用户、客户端、组分层处理：保留仍请求的未过期条目；被省略且原为 affiliated/affiliating 的未过期条目转解除中并设两倍 timer F 的期限；新请求或已过期组进入 affiliating。非零分支还按同一用户跨客户端的未过期 affiliating/affiliated 组去重计数，超过 N2 按服务策略缩减。零期限将该客户端原有组条目转解除中。候选列表替换原列表后，按 step17 列明的变化调用服务器间发布，再以 handled p-id 调用用户通知程序。

规范强度：所述构造、发送、检查、条件停止和状态处理为 SHALL；未把说明性边界改成新的协议动作。
- 边界：客户端全量兴趣不保证每组被接受；N2 策略不是固定按提交次序删组。
- 边界：step14(a)(iii) 字面使用 group element，其他分支及 §9.3.1.2 使用 group attribute；此处保留组状态责任，不提供修订后的可执行 XML 模板。
- 边界：本节把 candidate expiration interval 与响应中的 candidate expiration time 分别写出，本文不补一套未给出的取值算法。状态字面另有 deaffiliating 与 de-affiliating 拼写差异，不据此创造两个业务状态。

依据：3gpp-ts-24.379-v16.14.0 §9.2.2.2.2–9.2.2.2.3 full，印刷页 172,173,174,175,176。

## 组所有者仍有独立接收、成员资格和结果证据

- 条件：用户服务器被实际调用向组所有者发布，或收到该发布的失败；组所有者收到符合 §9.2.2.3.3 opening 的 PUBLISH。各方向和结果事件分别适用。

用户服务器向目标组 CF PSI 发布，mcptt-request-uri 改为组 ID，mcptt-calling-user-id 是被处理用户 ID，P-Asserted-Identity 是服务器 PSI；per-group PIDF 的 entity 为组、tuple id 为用户、client 属性为客户端。归属发布使用最大 Expires，解除使用0；此服务器产生自己的 current p-id，不能直接假定它就是客户端 p-id。向组的发布发生 timer F 到期或收到3xx/4xx/5xx/6xx时，按 §9.2.2.2.6 删除该用户各客户端下匹配该组的条目。组所有者检查 Expires、组是否存在、用户是否成员，失败按各分支拒绝并停止；通过后先发200，再核 PIDF entity 与 tuple用户身份，不一致则停止后续。非零期限分支更新该用户的客户端名单及期限，零期限分支执行用户条目删除，然后按组通知程序处理。因此服务器间200同样不证明通知已到终端，更不证明已经进入组呼。

规范强度：所述构造、发送、检查、条件停止和状态处理为 SHALL；未把说明性边界改成新的协议动作。
- 边界：组存在性依赖 TS24.481 组管理；本页不实现该查询或外部 SIP 发布机制。§9.2.2.3.1 另明示本版不规定 CSC-3 的归属/解除部分。
- 边界：组所有者 §9.2.2.3.3 step10 删除条件字面使用 served MCPTT ID，而前文 step2 定义 handled MCPTT ID；这里不静默补身份别名或提供可直接照抄的删除算法。selected expiration time 的选择也不由本文补默认。
- 边界：客户端侧与服务器间发布各有状态及 p-id，不承诺原子跨服务器提交、全部失败恢复或媒体释放。

依据：3gpp-ts-24.379-v16.14.0 §9.2.2.2.6 full，印刷页 177,178；3gpp-ts-24.379-v16.14.0 §9.2.2.3.1 NOTE;9.2.2.3.2–9.2.2.3.3 full，印刷页 188,189,190；3gpp-ts-24.379-v16.14.0 §9.3.1.2 per-group syntax，印刷页 194,195。

## 一次读取、持续观察与解除归属是不同请求

- 条件：客户端查询本用户在本客户端的归属状态、重新订阅或退订观察；或服务器处理该订阅、客户端收到相应有效 per-user PIDF NOTIFY。不是要求每一事件都发生。

初始 SUBSCRIBE 指向自己的 O-PF PSI，mcptt-request-uri 为被查询的本用户，含 MCPTT P-Preferred-Service 与 Accept: application/pidf+xml；查询本客户端还带按客户端 ID 限定 tuple 的 simple-filter。要当前及后续通知时 Expires=4294967295，只取当前状态时为0；对话内重新订阅用最大值、退订用0，仍接受 PIDF。因此 SUBSCRIBE 的0不是 PUBLISH 的撤销兴趣。用户服务器按 §9.2.2.2.4 的地址、服务、用户和 presence Event 分类接收，自身/获准身份检查后返回200，并在订阅期通知变化。生成用户通知时不包含已过期或 deaffiliated 的组条目，遵循客户端过滤；由变更程序带 handled p-id 调用时写入该 p-id。客户端收到符合协议且携带 per-user PIDF 的 NOTIFY 后，逐客户端、逐组确定归属状态；若有 p-id，它标识触发该通知的 PUBLISH，而不是把整条通知简化为所有请求组均成功。

规范强度：所述构造、发送、检查、条件停止和状态处理为 SHALL；未把说明性边界改成新的协议动作。
- 边界：schema 的线上 statusType 只有 affiliating、affiliated、deaffiliating；deaffiliated 是服务器状态，用户通知生成程序排除该状态条目，不强求终端收到字面 deaffiliated。
- 边界：收到带 p-id 的通知只解决关联问题，仍须读各组状态。未带 p-id 不得凭时间接近认定属于某次发布。
- 边界：这里只给 TS 本版规定的观察与载荷责任，不补 RFC3903/3856/6665/4661 的全部刷新、重排、丢包和错误恢复。

依据：3gpp-ts-24.379-v16.14.0 §9.2.1.3 full，印刷页 169,170；3gpp-ts-24.379-v16.14.0 §9.2.2.2.4–9.2.2.2.5 full，印刷页 176,177；3gpp-ts-24.379-v16.14.0 §9.3.1.2 per-user syntax and statusType schema，印刷页 194,196；3gpp-ts-24.379-v16.14.0 §9.3.2.2 per-client restriction syntax，印刷页 197。

## 状态同步按身份与既有状态判断，不能用一个成功标志替代

- 条件：用户服务器通过 §9.2.2.2.7 查询组所有者并接收 per-group NOTIFY；或其他程序实际调用归属检查。通知处理与检查是替代事件，不以全部归属成功作为前提。

服务器间状态查询以组 CF 为目标，正文携组 ID 与被处理用户 ID，并按用户 ID 过滤；组所有者的订阅接收仍检查期限、组存在和成员资格，通知携客户端及到期信息。用户服务器收到该通知时，只有匹配用户/客户端/组且原为未过期 affiliating 的条目，才按所列条件转 affiliated 并设置下次发布时间。原为未过期 affiliated 或 deaffiliating 且通知缺该用户/客户端的条目转 deaffiliated、期限置当前；原为 affiliating 的缺项还要求通知 p-id 与条目 affiliating p-id 匹配。实际检查也须分角色：§9.2.2.2.11 的参与功能按发起用户、请求内客户端 ID 和目标组查状态，把 affiliating 或 affiliated 判为归属；§6.3.6 的组侧检查则要求组、用户、客户端条目都匹配且用户条目未到期。不能把参与功能的中间状态判断等同于组侧最终状态或客户端已经接听。

规范强度：所述构造、发送、检查、条件停止和状态处理为 SHALL；未把说明性边界改成新的协议动作。
- 边界：§9.2.2.2.11 step1 查用户条目，却在1(a)字面说 group information entry；不修订该字样，也不把 §6.3.6 的到期守卫移植到其未列条件处。
- 边界：§9.2.2.2.7 描述组侧通知如何更新用户服务器状态，但正文未在末尾显式追加调用 §9.2.2.2.5。用户订阅期通知责任另见 §9.2.2.2.4；本页不由此补即时转发顺序、p-id 跨腿等值或同步完成时限。
- 边界：成员资格、归属状态、受邀及接听是不同层次。§6.3.5.5 还按人数上限等选择受邀成员，归属不是全员已经加入的证明。

依据：3gpp-ts-24.379-v16.14.0 §9.2.2.2.7 full，印刷页 179,180,181；3gpp-ts-24.379-v16.14.0 §9.2.2.3.4–9.2.2.3.5 full，印刷页 190,191；3gpp-ts-24.379-v16.14.0 §9.2.2.2.11 full，印刷页 183；3gpp-ts-24.379-v16.14.0 §6.3.5.5;6.3.6 full，印刷页 135,136；3gpp-ts-24.379-v16.14.0 §9.3.2.2 per-user restriction syntax，印刷页 197,198。

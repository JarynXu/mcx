# 特定业务组怎样限制成员？已配置的终端怎样为日后离网通信补参数？

**限制谁能进组，与给终端补参数，是两件事。** 前者决定别人能不能访问某个组，后者让一台已配置的终端在离网前收到所需参数。两项都是 3GPP TS 22.280 V16.8.0（Release 16，Stage 1） [第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)的组配置要求。

**限制成员。** 业务须让 MCX 业务管理员能限制谁可以成为特定业务组的成员，使其他用户不能访问这些组。调度员、主管也没有绕过这项限制的特权；这不表示他们一律不能入组。这一项管的是哪些人，而不是组内最多容纳多少人，也不是成员此刻是否归属该组。见 [R-5.1.3-001，印刷页 13](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=14)。

**在网补配，离网使用。** UE 已妥善配置、获授权且在网运行时，业务须使它能接收日后离网发起和参加**所选业务组通信以及私通信**所需的应用层参数。业务组 ID、组密钥是例子，不是每次必传的两个字段。条后附注说明这里的“运行时”场景：设备已经配好，但原配置之外的业务组、用户或两者要参加后续离网通信。这里要求的是在网时能够补收；它没有规定离网后从服务器取参数，用哪种协议，或某次通信一定能建立。见 [R-5.1.3-002，印刷页 13](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=14) 及其附注。

**逐项核对业务表。** [表 A.1（MCPTT），印刷页 62](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=63)、[表 B.1（MCVideo），印刷页 73](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=74)、[表 C.1（MCData），印刷页 84](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=85) 的 §5.1.3 行第一格均逐字列出 `R-5.1.3-001`。第二格也都有内容，印为 `R5.1.3-002`，正文印为 `R-5.1.3-002`：三表的小节和数字均对应，只有 R 后少一条连字符。对于 -002，能确认的是三表都有这个异写项，而不是表内逐字列出了正文编号，也不是整节 NA。

若问[在网时整个组的成员人数上限](onnetwork-group-limits-and-state.md)，须另看数量要求。若问离网直连前如何[预配用户配置档、组和密钥](../bearers/offnetwork-direct-ue-preparation.md)，那是终端的准备条件。[Stage 2 客户端取得或订阅组配置](client-group-configuration.md)说明具体流程，不是本条指定的唯一补配方式。

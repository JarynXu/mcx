# MC 用户怎样归属 LMR 定义的组？查不到组映射时，谁可以拒绝？

**请求里用 MC 业务组 ID；跨到 LMR 一侧的标识转换由 IWF 做。** 此处的用户在 MC 系统，目标互通组定义在 LMR 系统。IWF 须已连接并获准与 MC 系统互通，两侧组标识和用户标识的映射也须事先配置。依据为 3GPP TS 23.283 V16.8.0（Release 16，Stage 2）[§10.1.2.4，前提与注 1，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=20)。

1. MC 业务客户端带一个或多个 **MC 业务组 ID** 向 MC 业务服务器请求归属。服务器检查这些 ID 是否对应 LMR 系统定义的互通组，再按图示向 IWF 发组归属请求。客户端不直接向 LMR 系统提交本节的请求。[图 10.1.2.4-1，步骤 1–3，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=20)
2. **有互通许可，不等于用户已获准归属。** IWF 可以把请求转给 LMR 系统，后者可以检查客户端能否归属。若 IWF 不认识这个 MC 业务组 ID，或虽认识却没配置到 LMR 组标识的映射，IWF 都可以拒绝。已有映射配置不证明这一个组号已配对。条文没有规定拒绝码，也没有把转发或检查写成每次必做。[§10.1.2.4，注 2–3，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=20)
3. **成功时分两段看结果。** IWF 向 MC 业务服务器说明已成功归属 LMR 组。随后，MC 业务服务器保存该客户端对所请求互通组的归属状态，再向客户端返回 MC 业务组归属响应。只知道一条回应到了，不能跳过对结果和 MC 状态的核验；这里没有写拒绝后怎样存储、回复或重试。[步骤 4，印刷页 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=20)；[步骤 5–6、注 4，印刷页 20](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/16.08.00_60/ts_123283v160800p.pdf#page=21)

无线侧怎样实际办理归属不在本节范围。若要[从这一组解除个人归属](lmr-hosted-mc-deaffiliation.md)，走对应解除流程；若组定义在 **MCPTT**，看[另一个方向的 LMR 归属](mc-hosted-lmr-affiliation.md)。若关心[是否加入已经进行的组呼](../calls/lmr-interworking-group-late-entry.md)，归属结果不能代替晚入或入呼结果。

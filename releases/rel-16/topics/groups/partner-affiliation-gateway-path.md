# 本人申请归属伙伴组：只有一侧要隐藏拓扑，请求和响应走哪个网关？

甲为客户端 C 提供 MC 业务；C 的用户要归属乙系统定义的 G 组。**只有乙要求隐藏拓扑，请求可以从甲业务服务器直达乙网关，响应从乙网关直达甲业务服务器。只有甲要求隐藏，请求经甲网关直达乙组宿主，响应从乙组宿主直达甲网关。** 两种情况下，最后把归属响应发给 C 的都是甲业务服务器，不是网关。这里的“乙组宿主”是乙内负责 G 的业务服务器。网关可以转送请求，却不能替它准许用户归属 G。[TS 23.280 V16.7.0，Rel-16 Stage 2，§10.8.3.2a.1–.2，印 153](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=154)；[注 1，印 154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=155)；[注 2–4、步骤 9–13，印 155](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=156)。

## 两侧都要隐藏时，先找组所在的系统，再找系统里的组宿主

图 10.8.3.2a.2-1 画的是一个例子：C 已在甲获准使用业务，G 的组宿主在甲的伙伴系统乙，甲乙都要求隐藏拓扑，也都已配置为允许这样做。**已获准使用业务，不等于获准归属 G。** 对这一项 MC 业务，功能描述要求定义 G 的乙系统授权；是否还须甲系统授权有条件。图中这套程序却列有甲的检查，不能略去。[功能描述、图前说明和前提 1–4，印 153](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=154)。

| 步骤 | 查谁做了什么 |
| --- | --- |
| 1–2 | C 为自己的用户向甲业务服务器申请归属 G。甲业务服务器按用户配置查该用户能否归属 G，还查 N2，即这个用户可同时归属的业务组总数是否超限。 |
| 3–4 | 甲业务服务器确定目标组宿主，认出 G 属于另一个系统。因甲要求隐藏，选甲网关代理 G 的组宿主，把请求交给甲网关。代理不等于实际宿主迁到了甲。 |
| 5–6 | 甲网关确定 G 的主系统是乙，把归属请求转给乙网关。此时尚不能认定乙组宿主收到请求。 |
| 7–9 | 乙网关确定乙内哪台业务服务器是 G 的宿主，把请求转给它。乙组宿主按组配置核查这名用户是否获准归属 G。 |

[图和步骤 1–6，印 154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=155)；[步骤 7–9，印 155](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=156)。图中是业务角色，不能据五条竖线要求部署五台设备；图前编者注说，网关是业务服务器的角色还是独立实体，在该版这个程序中尚待研究。

两侧都隐藏时，响应从**乙组宿主**发出：先给乙网关（10），乙网关转给甲网关（11），甲网关转给甲业务服务器（12），最后甲业务服务器转给 C（13）。若跟踪记录止于甲网关收到响应，可以确认这次响应已到甲网关；这还不能证明 C 已收到。反过来，若 C 有能与本次归属响应对应的收件记录，即使甲业务服务器缺日志，也能确认 C 已收。单凭 C 的收件不能逐跳还原甲业务服务器的收转，不能据此签整条回程，更不能把缺日志记为甲没转发。若手里只有甲业务服务器向 C 发出的记录，可以确认它已发，C 是否收到仍待核。[步骤 10–13，印 155](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=156)。

## 只有一侧要求隐藏：请求看注 1、2，响应另看注 3、4

| 已确认的条件 | 请求怎样到组宿主 | 响应怎样回到 C |
| --- | --- | --- |
| 甲不要求，乙要求 | 注 1：C 仍向甲业务服务器申请。甲业务服务器在第 4 步**可直接给乙网关**，省步骤 **5、6**。乙网关找出并转给乙组宿主。 | 注 4：乙组宿主先回乙网关，乙网关**直接给甲业务服务器**，甲业务服务器再给 C。 |
| 甲要求，乙不要求 | C 经甲业务服务器把请求送到甲网关。甲网关找到 G 的主系统，在第 6 步**直达乙组宿主**，省步骤 **7、8**。注 2 原文说，直达组宿主可发生在第 4 或第 6 步；本行保留甲网关，对应第 6 步。 | 注 3：乙组宿主**直接给甲网关**；后者转给甲业务服务器，再由甲业务服务器给 C。 |

两条请求注写明省去哪两个编号步骤；两条响应注写的是**直接发给谁**，没有列“响应省略的步号”。不能只把请求箭头倒过来当作响应依据。也不能因为抓包只见一个网关，就倒推另一侧一定没要求隐藏；先核两侧的要求，再针对相应节点查记录。该节没有给出双方都不要求隐藏的通用路径，不把两条注拼成第三条规则。[注 1，印 154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=155)；[注 2–4、步骤 10–13，印 155](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=156)。

## 客户端收到了响应，组管理服务器也收到更新了吗？

不能这样结单。在用拓扑隐藏办理本人归属伙伴组的这套程序中，步骤 9 规定乙组宿主**可以**向保存组配置的组管理服务器（GMS）订阅组策略，接收 GMS 的策略通知。这条消息给宿主的是判断依据。另有反方向的要求：宿主**必须**向 GMS 发送组动态数据通知请求（notify group dynamic data request），更新这名用户对 G 的归属状态。图中只画出宿主的授权检查，没画这条更新。它不因没订阅策略就可省略，也不是宿主经网关给客户端的归属响应。[图 10.8.3.2a.2-1，印 154](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=155)；[步骤 9–10，印 155](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=156)。

例如，只见乙组宿主收到组策略、C 收到归属响应：这能证明各自收到了那一项，不能证明 GMS 已收到这名用户的状态。查宿主对同一用户、同一组的发送记录，再查 GMS 的收件记录；缺一方记录，就保留那一项未知。若另有宿主本次发送失败的明确记录，应记该次发送失败，不能据此抹去 C 已收到的响应。本节是 Stage 2 功能程序，消息名称不规定 SIP 方法、编码或抓包字段。

若用户在**自己的主系统**申请归属伙伴组，且**两地无需隐藏拓扑**，读[无需拓扑隐藏时的本人归属](partner-group-affiliation.md)，那一页有自己的组策略订阅条件和更新步骤，不套用本例“可订阅策略、图外另报状态”的说法。若是**获授权者替别人强制变更**伙伴组的归属、两人的客户端和主业务服务器同属一个主系统，读[替他人改变伙伴组归属](remote-partner-group-affiliation.md)。若**成员已归属**，组主系统已向伙伴提供组配置，伙伴采用本地设置并为该成员服务，要查的是[这一次跨系统组呼的准入](partner-group-call-admission.md)，不是这次归属申请。

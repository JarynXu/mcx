# 组配置和终端配置各走哪个 CSC 参考点？只看到 SIP 能判断配置成功吗？

不能。即便已知终端在网，组管理和配置管理两边的订阅、通知都用 SIP-1 和 SIP-2。只看「SIP」分不出是哪种配置，更看不出哪一端已保存。识别参考点要知道两件事：**谁在配置什么，以及终端当时在网还是离网。** 这里的 CSC 编号表示 MC 业务应用面上两个功能之间的关系，不是一笔配置事务的结果。[TS 23.280 V16.7.0，Release 16，Stage 2，§7.5.2.1、§7.5.2.3，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39)；[§7.5.2.5 末段，印刷页 39](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=40)。

| 终端状态 | 配什么、谁参与 | 应用面参考点及信令要求 |
|---|---|---|
| 在网 | 组相关数据。组管理服务器可以配置组管理客户端上的数据；反过来，组管理客户端也可以配置服务器上的组数据。 | **CSC-2**。订阅或通知相关信令须使用 SIP-1 和 SIP-2 传输、路由；其余信令须使用 HTTP-1 和 HTTP-2。[§7.5.2.3，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39) |
| 在网 | 配置管理客户端与配置管理服务器之间，支持两件不同的事：MC 业务配置终端（UE）；终端用不属组管理的业务资料（例如策略）配置 MC 业务应用。后者的执行者是终端，应用不是 CSC-4 的服务器端点。 | **CSC-4**。订阅或通知相关信令须使用 SIP-1 和 SIP-2 传输、路由；其余信令须使用 HTTP-1 和 HTTP-2。[§7.5.2.5 标题、首段和第一项，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39)；[第二项和末段，印刷页 39](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=40) |
| 离网 | 组管理客户端与组管理服务器之间的组数据管理，仍支持上述两个配置方向。 | **CSC-12 对应 CSC-2**。区别是不支持订阅或通知，因此不要求使用 SIP-1 和 SIP-2；非订阅、非通知信令沿用 CSC-2 的 HTTP-1 和 HTTP-2 要求。[§7.5.2.12，印刷页 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)；[§7.5.2.3，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39) |
| 离网 | 配置管理客户端与配置管理服务器之间，为离网的 MC 业务客户端提供所需配置；仍区分业务配置终端和终端用非组资料配置应用。 | **CSC-11 对应 CSC-4**。同样不支持订阅或通知，因此不要求使用 SIP-1 和 SIP-2；非订阅、非通知信令沿用 CSC-4 的 HTTP-1 和 HTTP-2 要求。[§7.5.2.11，印刷页 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)；[§7.5.2.5，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39)及[续页 39](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=40) |

**怎样读一次实际记录？** 假设在网的甲组管理客户端向组管理服务器发出一笔更新组 G 数据的请求。可以归到 CSC-2 的「客户端配置服务器」方向，记下甲发过请求；不能据此断定甲获准改动、服务器已保存，或乙端已取得新数据。反过来，若证据只到「设备已离网」，CSC-11、CSC-12 的定义也不会替这台设备产生一次下载记录。「不要求用 SIP-1 和 SIP-2」不是禁止离网终端使用任何 SIP，更不是取消配置能力。[§7.5.2.3 的两项支持能力，印刷页 38](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=39)；[§7.5.2.11、§7.5.2.12 各自的例外，印刷页 40](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=41)。

若已有具体请求或响应，要判[组管理服务器是否保存](store-group-configuration.md)、[终端是否取得并保存组配置](client-group-configuration.md)，或[拿到的是设备配置还是用户配置档](../identity/ue-configuration-retrieval.md)，再查相应流程。

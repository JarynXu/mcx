# MC 业务组 ID 指向哪里？SIP 的公共业务标识能否兼指这个组？

看一份组资料时，先分清它标识的是组、组里的某个用户，还是处理该组信令的业务服务器。三者回答的问题不同。

**组定义在哪，成员属于哪？** MC 业务组 ID 必须是 URI，在该项 MC 业务内全局唯一。它代表一组业务用户，指示定义该组的 MC 系统以及该系统中定义该组的 MC 业务服务器。客户端可用组 ID 寻址整个组。比如，“河桥组”定义在甲系统，成员小林的 MC 业务 ID 却指向乙系统，这两项记录并不冲突。成员可以属于同一系统，也可以分属不同系统；识别每位成员所属的系统，要看那位成员自己的 MC 业务 ID。组 ID 标识成员的集合，但只给出组 ID 这个值，并没有列出集合里有哪些人。〔[§8.1.3.1，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=45)〕

**SIP 核心靠什么路由？** 公共业务标识（PSI）用于路由 MC 系统的 SIP 信令。每个 MC 业务组 ID 都必须映射到定义该组的 MC 业务服务器的一个 PSI；映射由 MC 业务服务器管理。若索引只留下“组 G → PSI P”，它说明 G 与该服务器信令标识的对应关系，不是 G 的成员表，也没有说明某人是否已归属 G，或参加了 G 的哪一场组呼。要回答这些问题，分别看对应的成员名单、归属记录或该次呼叫的参加记录。〔[§8.2 末段、§8.3.2 首段，印刷页 46](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=47)〕

**什么时候能把 P 也用作应用层的组标识？** 如果 MC 业务提供方与归属移动网络（PLMN）的运营方在同一信任域，SIP 信令控制面的 PSI **可以**同时标识应用层的组 ID。即使双方同域，规范也没有要求一定这样用，更没有要求两栏字符串相等。若要标识的是另一信任域中的应用层组 ID，则不得用 PSI 兼做这项标识。禁止的是跨域兼指，不是取消每个组 ID 的映射要求。资料若没有写信任域，不能仅凭一条映射就认定 P 能兼作 G 的应用层标识。〔[§8.3.2 末段，印刷页 46](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=47)；[§5.1.2，不同信任域规则第 2 项，印刷页 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=19)〕

要分清个人的公共用户身份和业务用户 ID，见[跨业务用户身份](../identity/cross-service-user-mapping.md)。要判断新建普通组时由谁决定组 ID，见[普通组创建](normal-group-creation.md)；要区分两种名单，见[组成员与已归属成员查询](group-list-query.md)。

# 只看组配置通知，能判断终端是否已保存新配置吗？

不能。收到通知说明组管理服务器（GMS）向终端的组管理客户端报告了一次更新，不能据此判定本机已经保存或尚未保存**组配置**。在获取流程中，客户端请求配置，GMS 返回配置数据，最后由客户端保存。通知里也可以直接带**组相关密钥材料**，那是另一项有条件的保存动作。〔图 10.1.5.2-1、10.1.5.3-2，印刷页 79–80〕

## 同组不同地址，是不是用了不同的 GMS？

组管理客户端代表用户管理组。**同一组各成员的组管理客户端，必须为这个组使用同一个 GMS**。这里的 GMS 指功能实体，不等于一台物理服务器。核查时先对齐组 ID，再查各客户端处理这个组时实际用了哪个 GMS 功能实体。只比较两个端点的地址，不管地址相同还是不同，都不能回答这个问题。例如，同一业务提供方的甲、乙都为红组取配置，虽用了不同地址，若能确认两处对应同一 GMS，就符合同组要求；若确认实际用了两个不同的 GMS，则不符合。两套系统的 GMS 为同一组交换配置，是服务器之间的事，不能拿来替代甲、乙的客户端记录。〔§7.4.1，印刷页 31；§§7.4.2.2.3–4，页 32〕

**同一用户加入两个组**，其组管理客户端可以为红组和蓝组使用不同 GMS，也可以使用同一个。规范允许一个客户端与多个 GMS 建立关系，并不要求每个组各配一个。确认找对了红组的 GMS，回答的是“向谁取”；即使该 GMS 已向甲返回红组配置，甲是否保存仍要看甲端对这次配置的保存记录。〔§7.4.2.2.4，页 32；§10.1.5.2、图 10.1.5.2-1，页 78–79〕

## 终端怎样取得本用户适用的配置？

规范给出两个可以发起获取的时机。一是业务授权后，**配置管理客户端**已经收到组清单，而**组管理客户端**仍需要这些组的配置。二是 GMS 通知有新的组配置信息可取。两种情形都要看获取流程自己的前提：GMS 已收到并保存组配置数据；MC 业务终端已注册业务，且组管理客户端需要下载适用于当前用户的配置。组清单不是配置数据，首次获取也不以订阅为前提。〔§10.1.5.2 引言、前提，页 78–79〕

组管理客户端向 GMS 请求时，**组 ID 和组配置信息引用都必带**。客户端还可指定请求哪些业务（MCPTT、MCVideo、MCData 中的一项或多项）；省略这个字段表示请求**该组定义的全部业务**，不是所有组，也不意味着每个组都定义了三项业务。GMS 的获取响应必带组 ID 和组配置数据。最后由组管理客户端保存收到的配置；只见到响应，并不足以确认客户端已完成这一步。〔表 10.1.2.3-1 及注、10.1.2.4-1，页 62；图 10.1.5.2-1、步骤 1–3，页 79〕

## 订阅成功，终端得到了什么？

GMS 已存有组配置时，组管理客户端可为**已获授权的组**订阅更新。请求必带组 ID，可指定所请求的业务；省略业务字段的含义与获取请求相同，但订阅请求表没有列出组配置信息引用。GMS 返回组 ID 及成功或失败的结果，二者都必带。成功确认的是这次订阅请求，不是配置正文，也不表示组配置刚刚变化。〔§10.1.5.3、图 10.1.5.3-1，页 79；表 10.1.2.5-1 及注、10.1.2.6-1，页 62〕

## 通知里带什么，客户端要保存什么？

GMS 发出通知时须满足两个前提：客户端已订阅组配置信息；GMS 已**收到并保存新组配置信息**，或已**生成并保存新组相关密钥材料**，或两者兼有。规范没有规定订阅与保存谁先发生，也没有说必须向新订阅者补发过去的更新。GMS 发给客户端的通知必带组 ID；**组信息引用、组相关密钥材料这两项各自可选，但至少带一项**。因此只含组 ID 不符合通知表；带引用也不是带了配置正文。〔§10.1.5.3 通知前提，页 79；表 10.1.2.7-1 及注，页 63〕

客户端向 GMS 回复组 ID 和本次通知的结果（成功或失败），都是必带项。若 GMS 在通知中提供了组相关密钥材料，客户端在回复后保存**收到的材料**。若 GMS 通知的是有新组配置可用，客户端**可以**另按 §10.1.5.2 获取配置，不是每次通知后都必须下载。例如，通知只带组 ID 和材料，不能单凭这条通知断言有新配置要下载；通知只带组 ID 和引用，也不能凭成功回执断言客户端已经下载、保存新配置。〔表 10.1.2.8-1，页 63；图 10.1.5.3-2、步骤 1–3 及图后说明，页 80〕

这里的双方是**终端客户端和 GMS**。若两端都是 GMS，查[伙伴系统取得组配置并订阅更新](partner-group-configuration.md)；若问题是新成员为什么发起配置请求，查[组成员名单变动](group-membership-notification.md)；若要看组状态或哪些用户已归属，查[组动态数据订阅](group-dynamic-data.md)。这些是不同的问题，不是终端每次下载的后续步骤。

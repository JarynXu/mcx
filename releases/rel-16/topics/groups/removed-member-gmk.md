# 成员被移出组后，终端何时必须删除组主密钥（GMK）？

终端（UE）收到配置管理服务器（CMS）的用户配置档更新，得知自己已不再是组 G 的成员。它还要核对两件事：与 G 相关的组通信是否都已结束；G 使用的 GMK 是否还被该用户保留成员资格的其他组共用。通信均已结束、也没有这样的共用时，终端**必须立即以安全方式删除 G 的 GMK**。〔§5.7.3，印刷页 61–62；移出条款见第 62 页〕

例如，用户仍是 H 组的成员。如果 H 组与 G 组共用同一把密钥，不能根据这条移出规则要求终端立即删除它。如果 H 组用的是另一把密钥，H 组的成员资格本身就不影响 G 的密钥删除条件。

**同一组 ID 用于多项业务时，按组 ID 判断。** 假设 G 同时用于 MCPTT 和 MCVideo。语音组呼已结束，视频组通信仍在进行，就不能因语音结束要求终端删除 G 的所有 GMK。与 G 相关的通信均已结束，且 G 关联的 GMK 均不与用户仍是成员的其他组共用时，终端必须立即以安全方式删除这些 GMK。本条不规定每项业务各有一把密钥，也没有给出多把密钥部分共用时的逐把处理算法。〔§5.7.3，印刷页 62〕

**GMS 换不换钥是另一件事。** 成员被移出后，组管理服务器（GMS）可按该组的安全配置决定是否更新其 GMK。终端的删除义务不以 GMS 换钥为前提。即使已经观察到 GMS 换了钥，也不能据此认定某台终端已删除原密钥。〔§5.7.3，印刷页 62，移出段及其后 GMS 段〕

若只看到 GMS 的成员变动通知，或终端清理了本地组配置，见[成员通知与本地配置](group-membership-notification.md)。这两种现象都不能证明终端收到了 CMS 的移出更新或已删除 GMK。用户离开某次呼叫、解除业务归属，也不能单独证明用户已被移出成员名册；移出一名成员不等于删除整个组。

依据：[3GPP TS 33.180 V16.13.0，Release 16，§5.7.3，印刷页 61–62](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf)（ETSI，2026-02）。这里说明的是成员移出的安全过程，不是对某台终端执行结果的认定。

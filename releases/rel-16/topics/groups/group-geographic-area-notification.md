# MCPTT 组地理区域通知：进区会归属吗？离区 200 能证明已解除吗？

参与 MCPTT 功能（PF）判定终端进出预设的组地理区域后，向该终端发 SIP MESSAGE。这个通知、终端确认已收到通知、随后办理组归属，是不同的事件。这里讨论 TS 24.379 V16.14.0 的组地理区域，不是紧急告警区。〔§§6.2.0.1、6.3.2.4.2、12.1.1.4，印 56、104–105、449〕

## 先读正文：哪个用户，哪一个组，进还是出？

确认是这条 PF 发给客户端的区域通知后，核对 `application/vnd.3gpp.mcptt-info+xml` 正文：

| 字段 | 在这条通知中的含义 |
| --- | --- |
| `mcptt-request-uri` | 目标用户的 MCPTT ID。外层 SIP Request-URI 则是与该 ID 关联的公共用户身份。 |
| `associated-group-id` | 进出区域所涉及的 MCPTT 组 ID。不要用用户 ID 代填。 |
| `group-geo-area-ind` | `true` 是进区，`false` 是离区，不是归属成功或失败。 |

紧急告警区的通知也用 SIP MESSAGE，但识别字段是 `emergency-alert-area-ind`，走[紧急告警区通知](../calls/area-alert-notification.md)的处理，不借用这里的归属分支。只看到 MESSAGE 和一个真假值，还不能分类。〔§6.2.0.1，印 56；§6.3.2.4.2 第 4、8 项，印 104–105〕

## 200 确认通知；离区才调用这里的解除程序

客户端收到组地理区域通知，要给发出通知的 PF 回 **SIP 200 (OK)**。PF 收到与本次通知对应的 200，按**原通知**的 `group-geo-area-ind` 记录客户端收到了进区或离区通知。这一份 200 不表示归属系统已经确认变动。〔§6.3.2.4.2 末段，印 105；§12.1.1.4 第 1 项，印 449〕

在 **`true` 进区**分支，§12.1.1.4 规定是否显示提示，没有要求客户端仅凭该通知自动发起归属。其他[位置或别名触发的归属规则](client-rules-affiliation.md)仍要看其自身条件。在 **`false` 离区**分支，除提示处理外，客户端还须按 §9.2.1.2 对 PF 指定的组执行解除归属程序。提示并非收到通知的必要证据：没有环境监听时可显示；有环境监听（包括 MCVideo 的环境监听业务）时，本条不允许显示进出提示。离区的程序调用不以显示提示为前提。〔§12.1.1.4 第 2 项，印 449；§9.2.1.2，印 168–169〕

## 离开 G、仍关心 H：不是用 Expires: 0 清掉全部组

§9.2.1.2 的 PUBLISH 描述目标用户在该客户端**仍关心的全部组**。例如离开 G 后仍关心 H，且只剩 H，正文列 H；只要至少还有一组，`Expires` 就写 `4294967295`。只有目标用户在该客户端不再关心任何组时才写 `0`。不要把退出一个组的地理通知当成清空全部组的命令。若需确认归属变动成功或被拒，要按归属程序先启动 §9.2.1.3 的状态确定程序，再核对结果；不能拿区域通知的 200 或发出的 PUBLISH 来代替。〔§9.2.1.1 末段、§9.2.1.2 第 4–6 项，印 168–169〕

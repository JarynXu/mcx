# 在网 MCX 业务组的优先级：管理员能配置什么？

要配的是**组传输的优先级层级和特性**，还是**业务组之间的相对优先级**？如果问题是比较业务组的子集，还要看管理员对哪些比较对象有权限。以下限 3GPP TS 22.280 V16.8.0（Release 16，Stage 1）的在网 MCX 业务。[第 6 章，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)；[§6.8.1，印刷页 39（PDF 第 40 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。

| 要配置什么 | MCX 业务须提供的能力 |
| --- | --- |
| **组传输的层级和特性** | 业务须提供机制，让 MCX 业务管理员建立 MCX 业务组传输的优先级层级和特性。这里不是组成员配置，也不是给组传输及其关联用户建立抢占层级。[R-6.8.1-007，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| **业务组相对于其他业务组的优先级** | 业务须让 MCX 业务管理员能对 MCX 业务组相对于其他 MCX 业务组设定优先级，**传输和呈现都要支持**。条文未定两个方面是否共用排序，也没有规定按动态、实时的方式配置。[R-6.8.1-008，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |
| **业务组子集相对于其他子集的优先级** | 业务须让 MCX 业务管理员能为某个任务关键组织的一部分 MCX 业务组设置相对优先级。比较对象是该管理员权限所及的、任务关键组织的 MCX 业务组的其他子集。-009 没有写入 -008 的传输、呈现两个方面。[R-6.8.1-009，印刷页 39](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=40)。 |

例如，任务关键组织 O 有两批业务组，比较对象那批在管理员权限内。为一批业务组设置相对于另一批的优先级，查 -009。这个例子不替条文确定两侧子集能否分属不同组织，也不把设置目标子集的权限放开。-009 不授予跨组织或超出权限的操作权，也未就这类操作给出一般性禁止。对照单个业务组时，若只知道 G1 的传输优先级高于 G2，不能从 -008 推出呈现也这样排序；知道配置也不等于知道某次通信先呈现、建立或发生抢占。

**适用业务：** 表 A.1（MCPTT）、B.1（MCVideo）、C.1（MCData）的 §6.8.1 行均列出这三项。[表 A.1，印刷页 67](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=68)；[表 B.1，印刷页 78](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=79)；[表 C.1，印刷页 89](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=90)。

要查[在网组通信动态、实时确定相对优先级](onnetwork-group-communications-priority.md)，读 §6.4.7；它不是管理员配置步骤。要查[组传输及其关联用户的抢占层级](../bearers/onnetwork-service-preemption.md)，读 §6.8.1 -003，不用它替代 -007。这三个配置要求不规定优先级表、权重、合法值、层级表示或每个组都必须实际配置。

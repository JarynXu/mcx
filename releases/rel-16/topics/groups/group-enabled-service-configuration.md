# 组配置怎样覆盖已启用的业务？一次获取只选 MCPTT 说明什么？

红组启用了 MCPTT 和 MCVideo。甲在获取组配置时只请求 MCPTT，乙没有填请求业务字段。要判断红组的配置是否完整，先看**红组启用了什么**；要判断甲、乙这次分别请求了什么，再看**各自的请求**。

## 查组配置：每项已启用的业务都要有专用配置

组配置由各业务共用的数据和业务专用配置组成。一个组至少启用一项 MC 业务；启用了哪项，就必须为哪项提供专用配置。红组可以不启用 MCData，但不能因为眼下没有客户端请求 MCVideo，就省略已启用的 MCVideo 的配置。若已核实同一红组确实启用了 MCVideo，且红组的完整配置确实缺少 MCVideo 专用配置，这就不符合表 A.4-1 注 4。[TS 23.280 V16.7.0，Rel-16，Stage 2，§10.1.5.4，印刷页 80](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=81)；[§A.4，印刷页 212](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=213)；[表 A.4-1 注 4，印刷页 215](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=216)。

## 查一笔获取：只请求一项，不等于组只启用一项

获取请求必须带组 ID 和组配置信息引用。客户端可以用可选字段指定要取的一项或多项业务。甲只填 MCPTT，就只提出了对 MCPTT 组配置的请求。若乙省略该字段，则请求红组**已定义的全部业务**的组配置；本例是 MCPTT 和 MCVideo，不是把 MCData 也算进去。[表 10.1.2.3-1 及注，印刷页 62](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=63)。

只抓到甲的请求或只观察到这次交易里的 MCPTT 数据，不能断言红组没启用 MCVideo，也不能断言 GMS 缺少 MCVideo 配置。要复核组配置，核对组 ID、该组的业务启用清单，以及对应的完整组配置。要复核终端，则分开看请求范围、收到的数据及本地保存结果；看到请求或响应不能代替保存证据。这几条 Stage 2 规则不规定每项业务的子字段，也不能仅凭缺少一个业务区块判定具体的报文编码错误。[表 10.1.2.4-1，印刷页 62](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=63)；[§10.1.5.2，图 10.1.5.2-1，印刷页 79](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=80)。

要看[终端何时取、何时保存配置](client-group-configuration.md)，查获取流程。要看[组成员某项业务的 KMSUri 缺省值](member-kms-uri.md)，查成员字段；它与组是否启用该项业务是两个问题。

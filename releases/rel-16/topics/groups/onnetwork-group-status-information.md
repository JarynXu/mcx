# 在网 MCX 组里有人归属或接收吗？怎么区分另一用户的归属组和所选组？

**有人归属这个组、有人在接收、某个用户选中了这个组，是不同的判断。** 3GPP TS 22.280 V16.8.0（Release 16）在 §6.4.2 给的是在网 Stage 1 业务要求。用它判断业务应提供哪些能力，不用它确认某次通信是否已经开始、某人是否已经参加或收到媒体。[第 6 章标题，印刷页 29](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=30)；[§6.4.2，印刷页 31（PDF 第 32 页）](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。

## 按查询对象区分归属、接收状态和所选组

| 谁要确定什么 | 业务须提供的能力 |
| --- | --- |
| **获授权的 MCX 用户**想知道哪些组有别的用户归属 | 能确定哪些 MCX 业务组至少有另一位 MCX 用户已归属。[R-6.4.2-001，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。 |
| **获授权的 MCX 终端**想知道哪些组有成员在接收 | 能确定哪些组至少有一位**活跃接收成员**。[R-6.4.2-002，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。 |
| **获授权的 MCX 终端**要判断某一组的接收成员在场数量 | 能确定该组有数量 `Nc1` 的接收成员在场。信息性附录表 E.1 只解释 `Nc1` 指在场接收成员的数量，不给定数值。[R-6.4.2-003，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)；[表 E.1 的 Nc1 行，印刷页 96](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=97)。 |
| **获授权的 MCX 终端**要知道特定接收成员是否在场 | 能确定某一组指定的一名或多名接收成员在场。[R-6.4.2-004，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。 |
| **获授权的 MCX 用户**想知道另一用户归属哪些组、选了哪些组 | 业务须分别提供机制，让用户确定另一位 MCX 用户已归属的组和已选择的组。不能拿一份结果代替另一份；这些要求没有规定替目标用户变更组状态。[R-6.4.2-006、007，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。 |

例如，甲是获授权的 MCX 用户，系统记录另一用户乙已归属 G 组。这支持“G 组至少有另一位用户已归属”的判断。不知道乙是否在接收时，不能说 G 组有活跃接收成员，也不能仅凭归属确定特定接收成员在场或在场接收数量。同样，获授权的终端确认有一位活跃接收成员，也不能证明有足够的人参加或组通信已获准开始。只有 002 明写“活跃”；003、004 不能套上该词作为额外条件。003 不规定查看每个组精确人数、如何比较 `Nc1`、是否配置阈值，或用人数决定能否建呼。

## 只有自己归属，还要核对组是否处于条文说的“无成员”情形

若用户正在使用或监听某 MCX 业务组，该组处于条文所说的“无成员”情形，**且该用户是该组唯一已归属的用户**，业务须通知该用户这两个状态。只知道他是唯一归属者，不足以单凭该项要求判定必须发这份通知。“无成员”保留原条款的表述，不改作“组配置的成员名单为空”，也不拿“没有活跃接收成员”或“没有网络接收者”替代。声音和/或视觉是通知例子，不是规定界面、消息字段或定时。[R-6.4.2-005，印刷页 31](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=32)。

**适用业务：** 本版附录表 A.1、B.1、C.1 将这七项适用于在网 MCPTT、MCVideo 和 MCData。业务需要提供机制，不等于已观察到实际状态、某次查询一定返回结果，或离网部署提供同样机制。[MCPTT，表 A.1，印刷页 65](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=66)；[MCVideo，表 B.1，印刷页 76](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=77)；[MCData，表 C.1，印刷页 87](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=88)。

要查一个组的成员或已归属成员**名单**，读[组名单查询](group-list-query.md)；查实际 MCPTT 信令时，区分[组动态数据订阅](group-dynamic-data.md)、[远程更改所选组](remote-selected-group-client.md)和[MBMS 发出的组呼进行状态](../calls/mcptt-mbms-group-status.md)。这些是另有条件的功能或信令，不是把 §6.4.2 直接映射成已有的请求、订阅或通知。

# GMS 撤销组安全上下文：收到 GMK 的终端还能用它吗？

不能。终端按流程验证消息并解出 GMK 的关联参数后，如果其中的 `Status` 表示这把密钥已撤销，就不得使用这把密钥和对应的密钥标识。终端能从消息中提取 GMK，不等于它可以继续用来通信。这里的撤销是组管理服务器（GMS）通知组内终端停用指定的组安全上下文，不是配置管理服务器（CMS）把用户移出组。[3GPP TS 33.180 V16.13.0（Release 16）§5.7.2 撤销段，印刷页 61](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=62)；[§5.2.4 接收段，印刷页 44](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=45)。

## 撤销走同一个组配置通知，状态放在密钥参数里

图 5.7.2-1 中，终端和 GMS 先取得各自的身份密钥材料。GMS 向组内终端发 `Notify group configuration request`，在 MIKEY 载荷内封装组主密钥（GMK），消息还提供 GUK-ID。载荷面向终端对应的 MC 业务用户身份加密，由 GMS 签名；GMK 的关联参数用 GMK 加密。要撤销组安全上下文，GMS 重复图示程序，并在 GMK 关联参数的 `Status` 中标明撤销。[§5.7.2、图 5.7.2-1、步骤 0–1 及撤销段，印刷页 60–61](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=62)。

`Status` 是 4 个八位组。按表从最低有效位编号，**位 0 的值为 `0` 表示已撤销，为 `1` 表示未撤销**。位 1 另表密钥是否与安全网关共享，不改变位 0 的含义。未定义的位须忽略。位 0 为 `1` 只回答是否标了撤销，不能代替消息核验。[附录 E.6.9、表 E.6.9-1，印刷页 168](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=169)。

## 能解出密钥参数，还要看检查结果和撤销状态

步骤 2 要求终端验签、取出 GMK、GUK-ID 和 GMK-ID，检查 GMK-ID 是否与现有 GMK 的标识重复。终端用 GMK 解出关联参数，从中取出组 ID，再到配置档查该组的 `Server URI`，核对是否对应本次的 GMS 身份。任一检查失败，终端须向 GMS 返回错误；关联参数解密失败时，这把密钥也要拒绝。撤销段没有定义重复标识的例外，也没规定发送撤销时应沿用还是更换 GMK-ID。[§5.7.2 步骤 2 及撤销段，印刷页 61](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=62)；[§5.2.4、图 5.2.4-2，印刷页 44](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=45)。

一份有效关联参数显示已撤销时，不得使用其中对应的分发密钥 `K` 和标识 `K-ID`。在这个组流程中，`K` 是 GMK，`K-ID` 是 GMK-ID。GUK-ID 是面向收件端的另一种标识。[§5.7.1 关于密钥及标识的段落，印刷页 60](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=61)。步骤 2 为成功处理规定了 `Notify group configuration response`；单见请求或响应，不能证明终端已停用或安全删除该密钥，也不能证明其他终端已处理。撤销段不规定自动发放替代 GMK，也没有给出撤销专用的重试条件或具体错误码。[§5.2.4 接收段，印刷页 44](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=45)；[§5.7.2 步骤 2 及撤销段，印刷页 61](https://www.etsi.org/deliver/etsi_ts/133100_133199/133180/16.13.00_60/ts_133180v161300p.pdf#page=62)。

若收到的是 CMS 用户配置档中的成员移出，先查[成员被移出时的 GMK 删除条件及 GMS 是否换钥](removed-member-gmk.md)。若在查[跨域重组中新 GMK 的生成与分发](partner-regroup-gmk.md)或[终端关机、退出、令牌到期后的密钥保存与删除](../identity/ue-key-persistence.md)，分别读对应规则。不要拿这条停用要求代替成员状态或设备删除证据。

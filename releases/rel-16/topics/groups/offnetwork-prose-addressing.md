# 离网业务组的 ProSe 地址：有了二层组号，为什么还要查组播 IP？

终端的配置导出里，甲组名下列着一个 ProSe 二层组号；工具也支持填写组播 IP，但只有乙组填了地址。**这份材料能核实甲组的二层组号，不能核实甲组的组播 IP。** 应按甲的业务组 ID 去找它与组播 IP 的对应记录。工具能填写某项，不等于甲组已填；导出里没显示，也不足以判定终端实际漏配。[3GPP TS 23.280 V16.7.0，Release 16，Stage 2，§8.1.3.2，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=45)。

**查的是哪两个值？** 离网时，MC 业务组 ID 标识要通信的组。标准建议（should）把这个 ID 解析到该组的 **ProSe 组播 IP 地址**和 **ProSe 二层组号（Layer-2 Group ID）**。两者均按业务组 ID 预配。图 8.1.3.2-1 把业务组 ID、组播 IP、二层组号画成三个关联的框；图中的值是例子，没有给出从二层组号换算 IP 的公式，也没有规定映射基数。[§8.1.3.2 第 1、2 段，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=45)；[图 8.1.3.2-1，印刷页 45](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=46)。

**两项都配好，知道什么？** 同一业务组的成员终端可借助这两项配置，经 ProSe 直通开展一项或多项业务通信，数量取决于组配置。使用 IPv4 还是 IPv6，由策略决定，不由插图所举的 IPv4 地址决定。若甲组的两项关联都已核实，可以确认它们对应哪个组；要确认某个成员已加入一场通信或收到文件，还得看那次通信的记录。[§8.1.3.2 第 1 段，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=45)。

**谁提供业务组 ID 到离网 ProSe 组播 IP 和二层组号的映射？** 在线配置由**组管理服务器（GMS）**提供，离线配置由**配置管理服务器（CMS）**提供。若问映射怎样交付，条文说宜经终端内的 UICC 卡、经 ProSe 功能提供，或由应用服务器交付。三者不是先后步骤；看到 UICC 不能反推这次采用哪种配置模式。供应方提供的是预配数据，不表示每次离网直通都要联系供应方。GMS 如何从 ProSe 功能取回该组的组播 IP 和二层组号，本规范没有规定取回机制。[§8.1.3.2 第 2 段及注，印刷页 44](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/16.07.00_60/ts_123280v160700p.pdf#page=45)。

手里若是组 ID 对应的 SIP 公共业务标识（PSI），那是[在网业务服务器的寻址](group-id-psi-mapping.md)，不能抵作离网 ProSe 的两个值。若问配置管理与组管理能否合设、能否同时为同一终端配置，读[离线配置的功能与部署条件](offnetwork-configuration-roles.md)。若问题是后来者如何参加已在进行的离网视频组呼，读[MCVideo 的主动与被动加入](../mcvideo/offnetwork-group-join.md)。已知这次是**离网 MCData 组文件分发**，要判断某位成员的回信是否报告下载完成，读[离网 MCData 组文件分发](../mcdata/offnetwork-group-fd.md)。在网组文件分发应查相应的在网程序；若只知道组员回了信，先查清这次分发是在网还是离网。

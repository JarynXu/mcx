# 同一安全域的两台 GMS：组配置用 HTTP，订阅通知用 SIP，怎么区分？

先确认两端在这笔信令里都是组管理服务器（GMS），再查两端是否属于同一安全域。两个设备名分属不同 MC 系统，不能代替安全域信息。还要分清记录对应的是一次配置交换，还是对变化的订阅或通知。〔TS 23.280 V16.7.0，Stage 2，§§7.5.2.7、7.5.2.16，印 39–40〕

## 两台 GMS 在同一安全域：都是 CSC-7，按信令用途分开找

- 不是订阅或通知的组管理信令，用 **HTTP-1、HTTP-2、HTTP-3** 传送和路由。排查非订阅、非通知的组配置交换时，看这一类信令。
- 组管理的订阅或通知信令，用 **SIP-2、SIP-3** 传送和路由。HTTP 侧找不到变更通知，不能据此判没订阅或漏发。

两类都是 **CSC-7**。§7.5.2.7 写的是同一安全域内 GMS 之间的组管理信令，未另要求两端属于同一个 MC 系统。若只知道两套系统的名称不同，仍要查安全域，不能因此改判为 CSC-16。若一端是组管理**客户端**，不套用这对 GMS 的参考点，见[客户端组配置与终端配置的参考点](csc-group-ue-configuration.md)。〔§7.5.2.7，印 39〕

## 两台 GMS 跨安全域：同为 HTTP，也不能靠协议名称认出 CSC-16

**CSC-16** 的两端是不同 MC 系统、不同安全域的 GMS。它们共享的组配置还须对应可参加互联 MC 组呼的组。满足这些条件时，非订阅、非通知信令也用 **HTTP-1、HTTP-2、HTTP-3**。只知道存在 HTTP 交换或两系统能互联，未确认目标组可参加互联组呼，不能据此归为 CSC-16。〔§7.5.2.16，印 40〕

跨系统共享互联组配置的订阅或通知，不把同域 CSC-7 的 SIP 分支照搬过去。看 **GMS 与 MC 网关服务器之间的 CSC-19（SIP-2、SIP-3）**，以及**不同 MC 系统、不同安全域的两侧网关之间的 CSC-21（SIP-3）**。订阅前提、更新通知与保存结果见[伙伴系统如何取得与更新组配置](partner-group-configuration.md)。参考点标的是角色和信令用途，不是物理跳数、协议方法或成功凭据；要判断某次请求的结果，另核对对应事务和接收方的记录。〔§§7.5.2.7、7.5.2.16、7.5.2.20、7.5.2.22，印 39–41〕

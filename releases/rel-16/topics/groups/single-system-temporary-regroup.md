# 把几个现有组临时合在一起：哪些组可以重组，谁收到通知？

把 A 组和 B 组合成临时组 T，和把甲、乙加入 A 组不是同一件事。重组请求列的是 A、B，成功后得到 T 的组 ID；成员增删不为这次操作另建临时组。

组管理客户端、组管理服务器（GMS）、MC 业务服务器和组成员都属于同一个 MC 系统。发起客户端已取到各组成组的配置，向其中一个组成组的 GMS 请求重组。图以两组为例，同一过程也适用于更多组。〔§10.2.4.1，印刷页 96–97〕

## 业务有交集，还要过哪些检查？

请求列出要合并的组 ID。所有组成组须至少共用一项 MC 业务；可指定共同业务的子集，未给业务列表时适用全部共同业务。只要一项请求的业务不是所有组成组共有，就须拒绝整次组建，不能删掉该项后当作成功。

GMS 按组策略检查发起者的权限。组成组本身不得是临时组，也不能已被编入另一个临时组。如果系统策略不允许纳入处于紧急状态的组，就不能纳入任何这样的组；它不是对所有系统无条件生效的禁令。

例如 A 支持 MCPTT、MCData，B 只支持 MCData。请求 MCData 满足共同业务条件；不列业务时也只适用 MCData。若同时请求 MCPTT 和 MCData，则要拒绝，不是只开 MCData。

依据：§10.2.2.3 表 -1 及注 2（87 页）；§10.2.4.1 前提及步骤 1–2（96–97 页）；§10.2.4.4 第一组规则（101 页）。

## 新建的是什么？广播和双向有何不同？

GMS 新建并保存临时组的 ID、组成组 ID、优先级、安全级别和广播属性。各组的业务类型不完全相同时，GMS 求交集并保存临时组的业务列表，请求所选业务仍限于共同项。发起者可指定安全级别和优先级；两者都未指定时，GMS 须取组成组中最低的安全级别、最高的优先级。该步骤没有为只省略一项的情形另写完整规则。

广播重组用于单向通信，只有获授权的 MC 业务用户可发，其他成员只收；非广播重组可双向收发。这描述的是通信方式，不意味着重组时已经建立呼叫或分配了某成员的话权。

§10.2.4.1 步骤 1 描述客户端指明是否广播；表 10.2.2.3-1 对广播信息元素标 O，不据此规定省略该元素的编码或默认值。

依据：§10.2.4.1，96 页及 97 页步骤 1、3；表 10.2.2.3-1，87 页。

## 哪两类接收方拿到组成组 ID，谁再把 ID 带回？

| 方向与用途 | 必选（M） | 可选（O） |
| --- | --- | --- |
| GMS → MC 业务服务器：重组通知（表 10.2.2.8-1） | 组成组 ID 列表、临时组 ID | 启用的 MC 业务列表、广播重组指示 |
| GMS → 组成组已归属成员的组管理客户端：成员通知（表 10.2.2.14-1） | 组成组 ID 列表、临时组 ID | 优先级、安全级别、广播重组指示 |
| 上述成员的组管理客户端 → GMS：逐成员回执（表 10.2.2.15-1） | 组成组 ID 列表、临时组 ID、优先级、安全级别 | 广播重组指示 |

两类接收方都能从通知中知道 T 由哪些组组成，成员回执也要把这些组 ID 带回 GMS。组成组 ID 列表不是用户名单。发给成员时可选的优先级和安全级别，在成员回执中却是必选项。成员通知和回执的表都没有列 MC 业务列表或操作结果。

业务服务器若收到业务列表，保存并按其中类型提供服务。GMS 另向各组成组中已归属的成员发通知，由成员各自回执，并由 GMS 向发起方返回操作结果（见下一节）。图示最后是这些已归属成员分别向 GMS 请求临时组配置，包括安全、优先级等参数。名册上的人不能仅凭成员资格算作已归属；回执也不说明某人已入呼。

依据：表 10.2.2.8-1（方向见 88 页、表见 89 页）、表 10.2.2.14-1 和 10.2.2.15-1（90 页）；图 10.2.4.1-1 及步骤 4–6、8（97–98 页）。

## 发起者从成功或失败的响应中能知道什么？

发起方的组管理客户端收 GMS 给出的操作结果，和各成员给 GMS 的回执方向不同。表 10.2.2.4-1 的结果为必选：成功时必须带临时组 ID，失败时不得带；业务列表可选。在图示建组成功流程的步骤 7，响应若携带该列表，发起客户端保存并按所列业务类型发起相应业务。这一步不说明失败响应的业务列表应怎样处理。该表不列组成组 ID 列表。失败响应不能证明临时组已创建，也不能证明成员已收到通知。

依据：表 10.2.2.4-1 及注（88 页）；§10.2.4.1 步骤 7（97 页）。

## 什么不是这次建组？

给现有组添加或移出具体用户，改变的是既有组名册，见[组成员变动通知](group-membership-notification.md)。若组成组分属主、伙伴系统，应看 §10.2.4.2 的跨系统建组，不把伙伴 GMS 往返列入这里的同系统步骤。若目标是拆除已经建好的临时组，§10.2.4.3 另有拆除流程：图以前述跨系统建组为前提，注中只在组成组来自不同系统时才执行步骤 7–9。不要把这张图反过来当作同系统建组流程，或从中推出本页没有给出的完整同系统拆除过程。

依据：§§10.2.6.1–2，102–104 页；§10.2.4.2，98 页；§10.2.4.3，100–101 页。

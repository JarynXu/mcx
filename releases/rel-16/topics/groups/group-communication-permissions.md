# 谁能请求面向一个或多个组的通信？哪些成员能选择向组发送？

管理员准许甲请求一场面向 G、H 两个组的通信，与管理员把甲列为“可选择向 G 发送”的组成员，授权的是不同动作。

| 条款 | 谁获得什么权限 |
| --- | --- |
| [R-5.17-002，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28) | MCX 业务须提供机制，让业务管理员能授权**用户**请求一场面向**一个或多个业务组**的组通信。本条写的是用户，没在这里附加“已归属成员”条件，也没说非成员的请求必获准。 |
| [R-5.17-008，印刷页 27](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=28) | MCX 业务须让管理员能配置**哪些组成员**获准**选择向某个业务组发送**。管理员配置权限，获准成员作出选择。仅有成员资格，不说明甲已获这种授权。 |

两项都规定业务应给管理员什么能力，没有规定这两种授权须用两个凭据、按什么顺序办理，或取得一种就自动取得另一种。允许提出请求不等于业务已经建立通信；有权选择向某组发送，也不表示用户已作出选择、已取得话权或对端已收到内容。

仅凭[组成员名单](group-membership-administration.md)，还不能判定某人已获具体授权。若问[在网时管理员怎样把组对指定成员设为只收](onnetwork-administrative-group-settings.md)，另查 §6.4.9。在同系统普通在网单话权 MCPTT 组呼中，某个请求是否实际因只收而被拒，要按相应 [Stage 3 的 SDP、组文档与话权拒绝](../media/on-network-receive-only-priority.md)判断；不能据此改写 MCVideo 或 MCData 的要求。

3GPP TS 22.280 V16.8.0（Release 16，Stage 1）把 §5.17 放在在网、离网共用的[第 5 章，印刷页 12](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=13)。规范性表 [A.1（MCPTT），印刷页 64](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=65)、[B.1（MCVideo），印刷页 75](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=76)、[C.1（MCData），印刷页 86](https://www.etsi.org/deliver/etsi_ts/122200_122299/122280/16.08.00_60/ts_122280v160800p.pdf#page=87) 的 §5.17 行均列出 -002 和 -008。

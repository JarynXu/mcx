# 互通当前发言者位置：话权不等于公开许可

TS23.283 V19.5.0，Release19，Stage2。

## MC客户端1、客户端2及IWF参与进行中组呼；客户端1为当前发言者且服务器已取得其位置

客户端1取得话权后，服务器检查发言者的位置共享隐私策略；允许时才向客户端2及IWF提供位置。floor taken携带位置是可选途径，不是获得话权后的无条件披露。 [§10.11.2](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## MC客户端1、客户端2及IWF参与进行中组呼；LMR用户通过IWF作为当前发言者

IWF取得话权后，服务器检查当前IWF用户的位置共享隐私策略，以决定能否提供给其他MCPTT用户。服务器如何获取LMR用户位置不在此条款范围，不能把该过程补写成自动测量。 [§10.11.3](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 发言者的位置该给谁？只有一条 Floor Taken 怎么判断？

先认这一轮的发言者，再看 **MCPTT server** 检查谁的位置共享策略、位置该给谁。两支都是已有组呼，图中有 MCPTT 客户端 1、客户端 2 和 IWF。查规范不需要现场记录。

| 当前发言者 | 话权与隐私 | 常规位置提供（步骤 3） | 可选的 `Floor Taken` 带位置 |
| --- | --- | --- | --- |
| **MCPTT 客户端 1（§10.11.2）** | 前提写明 server 已取得客户端 1 的位置。1 为客户端 1 取得话权；2 为 server 查该发言用户在说话时的位置共享策略。 | 允许时，server 向 **客户端 2 与 IWF** 提供客户端 1 的位置。图 10.11.2-1 的位置框也覆盖这两端，不含发言的客户端 1。 | 同样列 **客户端 2 与 IWF**，正文再次明写须策略许可。可带位置，不是每条消息必带，也没有要求常规方式之外再发一份。 |
| **IWF 所代表的 LMR 用户（§10.11.3）** | 1 为 IWF 取得话权；2 仍由 server 查**当前发言的 IWF 后方用户**的位置共享策略，不查网关本身或接收者的策略来替代。NOTE 明写 server 如何取得该 LMR 用户的位置不在范围内，题名没有补出一条 IWF→server 的取位消息。 | 正文写 server 向 **客户端 1 与客户端 2** 提供该用户位置；图 10.11.3-1 的位置框不覆盖 IWF。第 3 步没逐字重写正向的“策略允许时”，但第 2 步检查就是为了判断能否提供，不是反向可跳过这项检查。 | 正文同一步的可选句却写 **客户端 2 与 IWF**。保留这句与常规提供的区别：不替原文把 IWF 改成客户端 1，不把两个列表合并，也不据图裁定这条可选消息的精确接收集合。 |

**看现场记录，分开判断话权、许可、有没有带位置和谁收到。** 只有话权授予、普通 `Floor Taken`、发言者 ID 或接收方在组里，都不能证明本次带了位置。若已经认出某条消息带的是本次发言者的位置，才可据该条记录说它承载了位置；server 发出、某一接收端实收和另一端实收是不同的事实。需要关联多条记录时，对齐同一组呼、发言轮次、实际发言者与对应端点；不能把上一轮位置、另一终端实收或相同位置值算给这次。即使实收到这份位置，也不能从中还原策略检查、测量时刻或上游取位方式。

条款链接：[§10.11.1 与 §10.11.2 前提、图和步骤，印刷页 152–153（PDF 第 153–154 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=153)；[§10.11.3 前提、NOTE、图和步骤，印刷页 153–154（PDF 第 154–155 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=154)。§10.11.1 只指向 TS 23.379 §10.6.2.7 的一般流程；两支步骤指向 TS 23.379 附录 A.3（隐私策略）和 §10.9.1.3.1（可选的信息载体）、TS 23.280 §10.9.3.6（位置提供）。这些是依赖入口，不是这里核过的字段、测量、权限实现或其他流程。

问 LMS 与 IWF 之间另一笔[按需查询、报告或通知](location-query.md)，按该笔消息处理；问[晚到的 LMR 发言者标识](late-talker-id.md)，不要用标识更新当位置已发送。

## 使用边界

TS23.280位置分发与TS23.379隐私配置、floor taken编码仅被引用，未在本主题核验。

§10.11.3可选floor taken一句列出客户端2与IWF，和该节总体LMR到MC叙述不完全一致；本主题不据此确定反向可选消息的精确接收集合。

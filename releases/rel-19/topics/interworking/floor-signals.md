# 互通话权消息：状态、队列与单播控制

ETSI正式发布的TS23.283 V19.5.0，Release19，Stage2。此处解释信息流，不是协议状态机。

## 解释授予、空闲或占用通知

granted表示相应请求获准可传媒体，并含允许发送时长；idle表示无人获授话权；taken表示另一用户获授。收到taken不等于自己获准发送。 [§10.5.2.3, 10.5.2.8, 10.5.2.10](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 区分取消请求、释放与撤销

request cancel针对队列中的话权请求；release表示媒体传输完成并释放话权；revoked撤销当前持有者的话权。它们都不能直接当作全呼叫释放。 [§10.5.2.5, 10.5.2.9, 10.5.2.11](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

### 排队取消的三类消息和确认

**取消谁的排队请求，看取消请求里的目标列表；不要看应答、通知或确认里的 `MCPTT ID` 猜目标。** TS 23.283 V19.5.0 的这三种消息和通用话权确认均可走 **IWF → MCPTT floor control server** 或反向。谁发消息和字段里的身份是什么角色，分开看。身份在互通中可代表 LMR 用户、IWF 或 MCPTT 用户；取决于互通方式及消息源、目的。查规范无需抓包。[§§10.5.1、10.5.2.1，印刷页 103](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=104)。

| 信息流 | 用来做什么 | 表里要看哪些字段 |
| --- | --- | --- |
| **IWF floor request cancel**（.5） | 请求取消队列中的话权请求。 | `MCPTT ID`（M）是取消请求者；`List of MCPTT IDs`（M）另列被要求取消的目标。别名（O）描述请求者。表没有要求确认的字段。 |
| **IWF floor request cancel response**（.6） | 回应原取消请求。 | `MCPTT ID`（M）是**原取消请求发起者**，不是当前应答发送人；别名（O）也属请求者。`Acknowledgement required`（O）说明是否要求话权参与者确认。没有目标列表、逐目标结果或取消成功/失败字段。 |
| **IWF floor request cancel notify**（.7） | 通知话权请求由管理员或话权控制服务器取消。 | `MCPTT ID`（M）和别名（O）按表字面是**管理员**的；不因消息由控制服务器发送，就把它解释为服务器 ID 或被取消者。可带 `Acknowledgement required`（O）；没有被取消者列表或原取消请求的应答结果。 |

三个表都把 `Source identifier` 列为可选，用于识别通信，只有媒体复用时才出现；复用也不会把 O 变成必选。这不是取消事务 ID。[§§10.5.2.5–.7；表 10.5.2.5-1、10.5.2.6-1，印刷页 104](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=105)；[表 10.5.2.7-1，印刷页 105](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=106)。

**需要通用确认，要看收到的那条控制消息是否明确要求。** .6/.7 的可选确认指示只有在表明“要求”时才是依据，不能仅凭字段出现、消息名称或发送方已发就判要确认。.5 的表没有该字段，但取消业务应答 .6 仍是另一条信息流。§10.5.2.12 写双向的 IWF floor acknowledgement；NOTE 说话权控制服务器可在每条带有要求确认指示的信息流后发送。通用确认不限于取消场景，也不因 NOTE 就改为只能由服务器发。确认表只有**确认发送者**的 `MCPTT ID`（M）和其别名（O），没有 `Source identifier`、被取消者列表或结果。[§10.5.2.12、NOTE 和表 10.5.2.12-1，印刷页 106](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=107)。

例如，A 请求从队列取消 B、C 的请求，匹配的 .6 仍识别 A。只见 .6 或通用确认，不能判 B、C 都已移出队列；.7 报告管理员或服务器取消，也不靠管理员 ID 确定移除的是谁。查现场要对上这次通信、操作、对象、方向和实际收件；发送、收到应答/通知、队列条目实际移除分别取证。普通话权申请的 `rejected`（.4）可带拒绝原因，但不能拿来给取消应答补结果。查询队列位置、交还或撤销当前话权、整通呼叫释放也不是这三种消息。这里不规定失败状态、无确认处理、排队算法或 Stage 3 编码。[§10.5.2.4，印刷页 104](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=105)。

## MCPTT服务器和客户端支持话权请求排队

须支持查询队列位置的信息流；queue position info说明请求已排队及其位置，不是话权授予。 [§10.5.2.13–14](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 停止或恢复指定通信对指定客户端的单播媒体

stop表示该单播媒体不需再发给指定客户端；resume由话权控制服务器请求恢复向该客户端发送。作用域不是停止整个组呼或撤销所有参与者话权。 [§10.5.2.15–16](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 边界

身份可代表LMR用户、IWF或MC用户，需结合互通模式及消息方向解释（§10.5.2.1）。

未覆盖排队算法、优先级仲裁、本地过滤及完整话权转换；MCPTT基础机制依赖TS23.379。

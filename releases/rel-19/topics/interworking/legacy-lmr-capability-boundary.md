# 传统 LMR 互通：模拟 FM 和数字常规系统能传什么？

**先看这次用的是哪种 LMR 无线方式，再问哪项能力。** 传统常规模拟 FM 的本地语音不用语音编解码器（codec），但互通可用 MCPTT 转码。模拟 FM 的 LMR 用户与 MC 用户之间不能端到端加密；某些数字常规系统（如 P25 conventional）可以支持，不等于某台设备或这次通话已经开启。[TS 23.283 V19.5.0，Rel‑19 Stage 2，§10.13.1 与 §10.13.2 NOTE 4，印刷页 164–165（PDF 第 165–166 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=165)。

| 要判断的问题 | 本版能判到哪里 |
| --- | --- |
| 这种无线系统是否在互通范围内？ | §10.13.1 说代表 LMR 用户的 IWF 可以与符合 TIA-603-D 的传统模拟 FM 互通。数字常规、集群模拟 FM、非标准的传统常规或集群系统也可支持，条件是符合本 TS 23.283。类别和标准适用不证明具体设备合规。 |
| 本地频率、音调和 MCPTT 组 ID 是一回事吗？ | 常规模拟 FM 可用频道、FM 频率、亚音频数据标组；其他常规系统可用本地 Group ID、其他协议元素或音调。IWF 配有传统常规 LMR 的组、用户信息，把对应标识转换成 MCPTT Group ID、MCPTT User ID。LMR 内部怎样识别组不在范围内。映射也不等于某人已归属、加入或此刻在发言。 |
| 模拟 FM 能有发言者 ID 或紧急指示吗？ | §10.13.1 说发言者 ID 和优先指示一般不可得，不是禁止。§10.13.2 NOTE 3 说一些常规模拟 FM 的主叫 ID、紧急等方案可在符合本规范时支持，例如多音、Type 99。不能从设备标签、已配置映射或走了紧急呼叫流程，就说此端实际给出了优先指示或发言者 ID。 |
| 数字常规 P25 一定传位置、短数据和发言者 ID 吗？ | NOTE 2 举某些数字常规系统原生支持组 ID、用户 ID、短数据和优先指示，没列位置。不要用此清单认定具体产品支持或禁止某项功能。NOTE 2、3 都保留通话开始后才取得发言者 ID 的情况，未规定固定等待时间或自动发更新。 |

[§10.13.1/.2、NOTE 1–4，印刷页 164–165（PDF 第 165–166 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=165)。频道、频率、亚音频数据是本地组方式的例子；本页没有核 TS 22.179 [3] 的数据定义或 TIA-603-D [9] 的设备实现。[§2 [3]、[9]，印刷页 11（PDF 第 12 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=12)。

## 一段被保护，不代表两端都受同一层保护

例如 MC 端到 IWF 有加密，IWF 解开这一层语音再转码。即使另一段也加密，这一层仍不是 LMR 用户与 MC 用户之间的端到端加密。§3.1 的定义只让所选终接端解密；不从模拟 FM 的跨端限制反推 MC 段或所有链路明文。实际是数字常规时，也须核参与端、配置和加密的实际终点，不能从 P25 型号或算法名称下结论。[§3.1，印刷页 12（PDF 第 13 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=13)。需要读[加密转码](encrypted-transcoding.md)或[私呼加密](private-encryption.md)时，按各自前提，不把示例当所有呼叫的做法。

## 可用流程不等于无线设备自动提供所有信息

§10.13.2 列出可用的归属、组管理（含重组）、预安排／chat／广播组呼、优先呼叫（紧急、迫近危险）和私呼。一些模拟或数字常规系统的私呼方案在符合本规范时可互通。主叫／发言者 ID、优先指示、E2EE、位置与 SDS 在同节是**有限制可用的功能**，不是统一具备或统一不支持。若现场只看到发言者 ID 后来出现，先核哪一端何时拿到；[同一次媒体传输怎样更新及向谁通知](late-talker-id.md)是 §10.13.3 的另一问，不凭“可能晚到”推必然更新或已实收。[§10.13.2，印刷页 165（PDF 第 166 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=166)；[§10.13.3，印刷页 166（PDF 第 167 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=167)。

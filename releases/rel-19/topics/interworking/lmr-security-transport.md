# LMR 安全消息：透明载荷与 MCData 承载

TS23.283 V19.5.0，Release 19，Stage 2。

LMR安全信息可在IWF与具备LMR感知能力的MC客户端之间传递，不要求MC服务服务器理解载荷。

## 选择跨MC系统的LMR安全消息承载

端到端消息在业务语义上独立，但3GPP传输仅通过MCData实现；不能据业务独立推断任何MC服务都有同一传输实现。 [§10.12.2.1](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## MC客户端已注册，用户已认证且获授权使用MC服务服务器

客户端发起时，经MC服务服务器转发给IWF；IWF发起时反向经服务器转给客户端。安全消息内容对MC业务透明，内容和格式不在3GPP范围；转发不等于服务器解释或完成LMR密钥管理。 [§10.12.2.2–3](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 构造Non-3GPP security message信息流

发送与目标安全实体对应的两个MC service ID及透明载荷为必需；LMR type一般标为可选，但向MC客户端发送时必需。 [§10.12.1.1](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 四段方向中哪些字段必带

**先分端到端方向和眼前这条消息。** TS 23.283 V19.5.0 §10.12 的端到端双方是 IWF 和具备 LMR 感知能力的 MC 业务客户端；通过 MC 业务服务器转递。在业务含义上独立于具体 MC 业务，但本规范只通过 MCData 实现 3GPP 传输。识别出一条 Non-3GPP security message 或只查表，不要求先获得完整端到端记录。

| 谁发起 | 第 1 步 | 第 2 步 |
| --- | --- | --- |
| MC 业务客户端（§10.12.2.2） | MC 业务客户端 → MC 业务服务器 | MC 业务服务器 → IWF |
| IWF（§10.12.2.3） | IWF → MC 业务服务器 | MC 业务服务器 → MC 业务客户端 |

表 10.12.1.1-1 的导语列出这四个逻辑方向，两图的四个箭头都叫 Non-3GPP security message。不从名称判断谁发起。两支前提都写 **MC 业务客户端已注册，用户已认证且获准使用 MC 业务服务器**；IWF 发起也不例外。该前提不等于看到消息就证明服务器已实际检查或用户已获权。

| 信息元素 | 按这一版怎么读 |
| --- | --- |
| **MC service ID（M）** | 支持**发送方 LMR 安全实体**的 MC 业务身份。 |
| **MC service ID（M）** | 支持**目标 LMR 安全实体**的 MC 业务身份。 |
| **LMR type（O）** | LMR 技术类型，TETRA、P25 是例子。表标 O，描述另写「向 MC 业务客户端发送时必带」。 |
| **Payload（M）** | 表称不透明载荷（Opaque payload）。透明指经 MC 业务转递，不指 MC 业务能理解载荷内容。内容与格式不在 3GPP 范围。 |

服务器转发时，它是这一腿的发件端；表中的两个身份仍按所支持的 LMR 安全实体区分，不能从设备名、来向或下一跳自动填成服务器／网关 ID。表没有要求两个取值必须不同，也没有定义它们的线级字段名。

**已辨认是 server→MC 业务客户端，这一腿明确满足 type 的必带条件。** 完整记录中若缺该项，另一腿有 type 也不能替代；记录不完整时，没见到 type 不是证据。若实际确认是向 IWF 送消息，不触发这条针对 MC 业务客户端的必带条件。若手上只有 IWF→server 一腿、最终目的在客户端，保留原文 “toward”：条款没另写中间哪一腿必须先带、逐跳如何继承，不能从最终方向断言每一腿都必带，也不把表改成「只在最后一腿允许带」。出现 type 不证明技术已支持、实际加密状态或处理结果；本表没限定技术枚举或缺项时的默认、拒绝方式。

两支第 2 步均写服务器**转发消息内容**。只看到发起端发出，不能判断服务器已收、已转发或目标实际收到；要关联两步，按同一消息、实际角色和各节点证据核对。本段不保证整份消息或外层字段逐字节复制，图没有另写应答，不因此排除底层确认。透明内容不等于规定它如何加密，也不证明端点已使用、写入或更新任何密钥。问[加密语音的 MC 层处理](encrypted-transcoding.md)或[LMR 格式媒体的承载](lmr-encrypted-interworking-architecture.md#需要传-lmr-格式媒体时走哪里)，不把本节传输套到媒体上；不从 MCData 承载补出一个 SDS 消息类型或 Stage 3 规则。

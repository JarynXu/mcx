# LMR 互通：IWF 的规范边界

适用：Release 19，TS 23.283 V19.5.0。

本规范覆盖 MC 与陆地移动无线电（LMR）系统互通，包括 MCPTT、MCCoRe 及 MCData 的 SDS 范围；不能由此推定所有 MCData 业务已被覆盖（§1，p11）。

规范定义 IWF 与 MC 系统之间的参考点及交互，不规定 IWF 自身的结构和功能实现。IWF 连同 LMR 在接口交互中视作对等互联 MC 系统，但这不是强制的部署模型（§1、§4，p11、13）。

“User homed in the IWF”指在 MC 系统中代表 LMR 用户的 MC service ID；不要把这个身份模型直接当成用户终端的物理驻留位置（§3.1，p12；后半句为建模提示）。

## IWF-1 到 IWF-4 各连什么？位置接口可不可以没有？

先认**逻辑端点和要办的事**。TS 23.283 V19.5.0 §7.2 的图画的是互通**应用平面**。它不等于部署连线，也不说明现场哪条已经启用。查参考点定义不需要抓包。

| 参考点 | IWF 的对端 | 这条参考点的范围 |
| --- | --- | --- |
| **IWF-1** | MCPTT server | 与 MCPTT 系统对等互通。功能是 **MCPTT-3 的子集**，另有本规范规定的差异；信令面沿用 **MCPTT-3 的协议**，本规范另有规定的除外。相同的信令协议不等于接口完全相同。 |
| **IWF-2** | MCData server | 用于 **SDS**。这里按端点与业务选入口；具体功能子集与信令面的区别见 [SDS 参考点](sds-addressing.md)。 |
| **IWF-3** | 组管理服务器（GMS） | 用于互通组管理，**基于 CSC-16**，有本规范规定的差异。原文没有像 IWF-1 那样另写“采用同样的信令面协议”。 |
| **IWF-4** | 位置管理服务器（LMS） | 用于交换位置。**可选的是 IWF-4 参考点的支持**，原文理由是互通的 LMR 系统不一定支持位置信息。不从缺这条接口推出 MC 系统没有 LMS、其本地位置业务不可用，或这次实际交换了位置。 |

[§7.2 与图 7.2-1，印刷页 14（PDF 第 15 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=15)；[§7.3.1、§7.4.1–.4，印刷页 15（PDF 第 16 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=16)。

图中公共服务核心还列了配置、身份和密钥管理服务器，但没有为它们逐一画出带号的 IWF-x 连线。图上的 IWF-3 和 IWF-4 分别止在 GMS 和 LMS，不是另接到整个核心。不要据此新增参考点，也不能说不允许通过其他网元获得这些服务。§7.3.1 写 IWF 支持对等 MCPTT、MCData 的大部分功能及必要的协议转换和标识映射；没有规定 IWF 内部实现，也不等于每种业务都支持或现场每条消息都完成了转换。

**遇到组管理消息，要分开读架构和消息表的导言。** §7.4.3 把 IWF 与 GMS 之间的组管理参考点命名为 **IWF-3**。§10.2.1.1 却把该节随后列出的组管理信息流写为 **IWF-1**，把其他参考点指向 TS 23.280 [5]。这两个字面都保留。查已知的信息流，按[组配置](group-configuration.md)或[更新订阅与通知](configuration-updates.md)找对应条款；看到 GMS 角色或一张表，不能自行把另一处编号改掉，也不据此确定报文在现网走哪条接口。判现场再核实际角色、交互、使用的参考点及接收记录。[§10.2.1.1，印刷页 23（PDF 第 24 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=24)。

IWF 与 LMS 的实际交互，按[索要和事件通知](location-query.md)、[订阅](location-subscription.md)或[取消订阅](location-unsubscribe.md)分流。不要用 IWF-4 的可选性替代[发言者位置的隐私判断](talker-location.md)。本节不决定 SIP、HTTP、端口、内部路由或物理部署。

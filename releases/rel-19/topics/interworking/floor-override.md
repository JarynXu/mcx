# 无法通知旧发言者时的话权覆盖

ETSI正式发布的TS23.283 V19.5.0，Release19，Stage2。

共同前提：组定义在MCPTT，服务器主控且配置支持覆盖及新旧双方同时发送；会话已建立且进行中，IWF代表的旧发言者持有话权并发媒体；旧发言者无法收到话权被占用或撤销的通知。

## 发生上述覆盖过程

较高话权优先级的MC用户请求经仲裁获准，服务器向其发granted并向其他参与者发taken。旧LMR用户无法获知变化而继续发送；谁收到新、旧或两路媒体由配置决定，不能断言所有人都混音接收。 [§10.5.4](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 新覆盖者停止发送，旧发言者仍在发媒体

话权授回旧发言者，音频路由到当前全部话权参与者；这不是任意抢占场景都适用的自动恢复规则。 [§10.5.4 NOTE3](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 新发言者什么时候获准，什么时候开始发送？

这里是 §10.5.4 的图示覆盖。组由 MCPTT 定义，MCPTT server 主控，已建立的会话仍在进行。服务器配置了覆盖，也允许覆盖者和被覆盖者同时发送。发言中的 B 由 IWF 代表，是原先获授话权的 LMR 用户。图的步骤 1 写授给 IWF，正文写由它代表的 B 已获授并在发语音，不读成两个话权持有人。适用本例的是旧电台**无法被告知**占用或撤销，不能用一次没抓到通知推断这种能力。 引言也举了 MCPTT 和 LMR 用户同时获权的情况；图示分支以 B 已经获授并在发送开始。

| 要查的事实 | 图 10.5.4‑1 和正文各步 |
| --- | --- |
| **A 要发言，还是已经发出请求？** | 步骤 2 的 A 相对 B 有较高话权优先级，想发语音；实际请求是步骤 3，A 向话权控制服务器发 Floor Request。优先级和发言意向不代发送，也不证明 server 已收。 |
| **谁允许覆盖？** | 步骤 4 由主控服务器仲裁并接受 A 的请求。原文举例按收到的请求中的话权优先级信息判断；不能从“较高”推出无条件通过，也不据此写死比较算法。 |
| **授予、提示、讲话是哪三件事？** | 5a 是 server 向 A 发 Floor Granted；6a 是由该授予触发的 A 用户提示；7 才写 A 在原已建会话开始发语音。5a 出站不是 A 实收或已经发出用户提示。提示已发也不证明用户看到或听到。图 7 的媒体横条不决定实际包经过哪条腿或哪位参与者收到。 |

例如只确认 server 已发 5a，可以记录授予消息已发；问 A 是否收件、是否发出用户提示、A 何时开始送语音，要分别取证。只查规则或一条已识别的请求、授予或提示，不必先找到媒体。要判断多条观测是不是本次覆盖，再核同一会话、实际 A/B 角色、端点和对应事件。5b 的占用通知、B 无法获知与双路接收配置，见 [losing audio 页的 §10.5.4 对照](losing-audio-classification.md)。

## 授回旧发言者要同时满足什么？

**A 停止发送时，B 仍在发语音。** NOTE 3 在这两个条件成立时把话权授回 B，并把音频路由给**当时的全部话权参与者**。只知道 B 在覆盖开始前曾发言，不能替“此刻仍在发”。只见 A 的静音意向或一条释放信令，也不能替实际停止。B 若已停或其当前状态未知，不能用本注认定已授回；不据此否定其他适用规则。

这里说的是按条件授回和路由，不指定新的 Floor Granted／Revoked 消息序列、停发检测办法或实际回包。参与者范围是当时仍在话权过程中的人，不能照抄静态组名单或覆盖开始时的名单。路由到这些参与者不证明终端实收或听到；要判断实际授回、转送或收音，各查对应状态或媒体证据。覆盖**期间**两路媒体分配的 NOTE 2，不替这个授回分支。

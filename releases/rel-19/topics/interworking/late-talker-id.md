# LMR 发言者标识晚到：什么时候更新，谁会收到？

**先报 IWF 的预配置 ID，取得实际发言者标识后，再在同一次媒体传输中更新。** TS 23.283 V19.5.0 的这两支不要求先释放再授予话权。看到 ID 改变也不能单独判换了发言者、开了另一通呼叫或重授话权。

这里查 **Rel‑19 Stage 2，§10.13.3.1–.2**：传统模拟 FM 的 LMR 用户发起互通组呼，开始时不知道该用户的发言者标识。服务器和 IWF 都掌握组信息，IWF 已配置跨系统组与用户标识映射；图中的 MCPTT 客户端均已注册，用户已认证、获准使用业务，参与用户已归属该组。按**互通组定义侧**分支，不按发起者或当前发言者属于哪边分。查规则无需抓包。§10.13.3 的总述说这项更新机制也可用于规范写明的其他 MCPTT 媒体传输；不把这两个特定示例当成所有 LMR 或 MCPTT 呼叫的规则。[§10.13.3、§10.13.3.1–.2 前提，印刷页 166、168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=167)。

| 互通组定义侧 | 起初怎么报 | 得到实际标识后怎么报 |
| --- | --- | --- |
| **MCPTT（§10.13.3.1）** | IWF 的建呼请求 **1** 带预配置 IWF MCPTT ID 和隐式话权请求。媒体面建立（6）后，因有隐式请求且无人竞争，MCPTT server 给 IWF 发 Granted，并向已归属 MCPTT 用户发带预配置 ID 的 Floor Taken（两者都是 **7**）。面向其他已归属 LMR 用户的 IWF Floor Taken 是独立的 **8**。 | 实际媒体开始后，IWF 得到标识（**9**），发 **10：IWF Talker ID Update → server**。server 用新 ID 向已归属 MCPTT 用户发 Floor Taken（**11**）；向 IWF 的逐已归属 LMR 用户通知是另一条 **12**。 |
| **LMR（§10.13.3.2）** | IWF 对每个已归属 MCPTT 用户发建呼请求 **1**，也用预配置 IWF MCPTT ID 和隐式话权请求。媒体面建立（5）后，因有隐式请求且无人竞争，IWF 以逐名已归属 MCPTT 用户的 **6：IWF Floor Taken → server** 告知 IWF 持有话权；server 在 **7** 向相应客户端报预配置 ID。不是 MCPTT server 给 IWF 授予话权。 | 实际媒体开始后，IWF 得到标识（**8**），仍按每个已归属 MCPTT 用户发 **9：IWF Floor Taken → server**；server 在 **10** 向相应用户报新 ID。步骤 10 正文称新标识来自 “IWF talker ID update”，步骤 9 和图 9a/9b 都写 Floor Taken。不因此多加一条 Update，也不把 MCPTT 定义分支的步骤 10 名称移过来。 |

**MCPTT 定义分支的 8 和 12，各看当笔是否满足两个条件：**除了主叫，还有其他已归属 LMR 用户，且 server 已收到这些人的逐人归属。只有主叫归属、IWF 代表归属、静态成员名单或只有前一轮发过 8，都不能替当笔 12 的条件；12 也不能反证 8。正文没有另定代理汇总通知，不因图上各有一支虚线就断定数量，也不拿末句“每名已归属 LMR 用户”给主叫另补一份。LMR 定义分支的逐人对象是**已归属的 MCPTT 用户**，不是按 LMR 成员数。两支的备注均涉及该通话里的其他话权参与者，不把它读为所有静态成员或现场已实收。[§10.13.3.1 步骤 7–12、NOTE 6–7 与图 10.13.3.1-1，印刷页 167–168](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=168)；[§10.13.3.2 步骤 6–10、NOTE 4–5 与图 10.13.3.2-1，印刷页 169–170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=170)。

## 怎样区分已取得真实标识和已经发出更新？

- **媒体面建立不等于实际媒体开始。** 先核本次话权、相关端点及实际传输，再区分 IWF 知道了新 ID、IWF 发通知、server 实收、server 转告及目标实收。已知新 ID 不等于已发更新。规范不给出 IWF 如何取得标识，部分系统到通话结束才知道；不能凭没有看到中途更新就断障，也不造等待时限或回放规则。
- **认这一条消息，别只认 ID。** 普通建呼、初次占用、同一传输里的补标识及另一次话权授予要对上会话、对象、动作和方向。表 10.5.2.17-1 的 IWF Floor Talker ID Update 必带正使用话权的 MCPTT ID；功能别名可选，Source identifier 可选且仅在媒体复用时出现。这张表不改写 LMR 定义分支 9 的名称，字段或 ID 本身也不证明媒体到达、重授话权或允许分享位置。[§10.5.2.17，表 10.5.2.17-1，印刷页 107–108](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=108)。

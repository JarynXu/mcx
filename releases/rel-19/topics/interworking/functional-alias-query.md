# IWF 查询功能别名：查谁的别名，还是查别名对应谁？

**两种查法都带请求者的 MC service ID。** 要知道 B 激活了哪些功能别名，用 B 的 MC service ID 查；手上只有某个功能别名，用该别名反查相关 MC service ID 及状态。查到的结果不改变别名状态。

适用：TS 23.283 V19.5.0 Rel‑19 Stage 2 §10.14.3.2，发起者是归属 IWF 的用户，在 MC 系统用 MC service ID 代表该 LMR 用户。§10.14.1 将功能别名列为支持 TS 22.179 的系统的可选功能；规范给出这个流程，不等于部署已支持。查规范无需抓包。[§3.1，印刷页 12](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=13)；[§10.14.1，印刷页 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=171)。

## 请求：分清发起者与查询目标

图 10.14.3.2-1 的步骤 1 是 **IWF → MC service server**。表 10.14.2.1-1 里有两个名为 `MC service ID` 的信息元素。**请求者 ID 必选（M）**，**被查者 ID 可选（O）**；被查的 `Functional alias` 也是可选（O），不是请求者 ID 的替代品。步骤 1 写的是用被查用户 ID 或别名选目标。

表中两项分别标 O，并未定义两项都不带时查谁，也未规定两项同时出现时的组合或优先规则。**只有请求者 ID 不等于查询自己。** 查 B 时，请求者即使写的是 A，结果仍按 B 读。[§10.14.2.1 表 10.14.2.1-1，印刷页 170](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=171)；[§10.14.3.2 图 10.14.3.2-1、步骤 1，印刷页 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=174)。

## 核权后取结果，按原请求解释应答

步骤 2 由 **MC service server 检查这名 IWF 归属用户是否有权作本次查询**；通过后才按相应用户 ID 或别名检索。IWF 已连通、请求已发、字段齐全，都不能代替这次核权。表中说结果信息来自功能别名管理服务器；图没有画请求者直接访问它，也没规定业务服务器怎样访问它。

| 原请求的查询目标 | 响应的 `Query result` |
| --- | --- |
| 一个 MC service user 的 ID | 该用户已激活的功能别名标识列表。 |
| 一个功能别名 | 该别名对应的 MC service ID 及状态；不预设只有一名用户，也不把列出的状态一律当成已激活。 |

响应表把**发起查询者的 MC service ID 和 `Query result` 列为必选**；被查者 ID、被查别名仍是可选字段。回显了目标不等于带了结果；少了一个可选回显也不等于查询失败。步骤 3 正文说服务器向归属 IWF 的发起用户返回结果；图画的是 **MC service server → IWF**，没有单列 IWF 到用户侧的消息或确认。判断现场，只将同一请求者、查询目标和方向下能匹配的响应作为本次查询结果。服务器发出、IWF 实收和请求者看到结果分别取证；不发明线上关联字段。这里未规定未授权、找不到目标、空结果或响应缺失各自的错误码和处理办法，不能根据这些现象反推某一原因。[§10.14.2.2 表 10.14.2.2-1，印刷页 170–171](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=172)；[§10.14.3.2 步骤 2–3，印刷页 173](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=174)。

**查询结果不是用户名、通讯录、用户配置、唯一所有权或以后仍有效的保证。** 已激活信息也不证明这次查询触发了激活、取得接管权限或建立了持续订阅。实际收到 `IWF functional alias status notification` 或接管应答，要按各自操作认，不当成本次查询回应。[§§10.14.2.7–.9 表 10.14.2.7-1 至 10.14.2.9-1，印刷页 172](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=173)；[§10.14.3.5，印刷页 175–176](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=176)。

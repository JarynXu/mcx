# 组话权本地过滤：通过预选不等于最终授予

ETSI正式发布的TS23.283 V19.5.0，Release19，Stage2。

## 组归属LMR；MC侧配置本地过滤；双方用户已归属，互通组呼进行中且话权空闲

示例先在MC侧选中客户端1并拒绝客户端2，再将选中的请求交IWF作最终决定；须待最终granted传回客户端1后才开始发送。 [§10.5.5](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 组归属MCPTT且已在GMS定义；LMR侧本地过滤；双方用户已归属，互通组呼进行中且话权空闲

多个LMR请求先依本地策略仲裁，只向MC侧呈现一个请求。MC服务器仍作最终仲裁；示例MC用户胜出并不构成MC用户永远优先的规则。 [§10.5.6](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 组定义在LMR，MC配置不本地过滤而转交竞争请求；双方用户已归属，互通组呼进行中且话权空闲

MC服务器把竞争请求都交IWF作最终决定，再把针对各用户的授予、拒绝和占用通知送回；不在MC侧先淘汰一个请求。 [§10.5.7](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## 组定义在MCPTT，LMR侧配置转交全部竞争请求；双方用户已归属，互通组呼进行中且话权空闲

此过程还要求IWF不代理LMR用户归属，所有LMR组归属均透传给MC服务器；不能把它直接套到IWF代理归属模式。 [§10.5.8 preconditions](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf)

## MCPTT 组主控：拒绝和占用通知分别按谁发？

**Reject 按被拒的请求；Taken 告知听众话权给了谁。** 不能用两者的条数互推。这里对照 §10.5.6／.8 的两个互通组呼示例：组归属／定义在 MCPTT，双方参与者已归属该组，通话已建立且话权空闲。两支都是 **MCPTT 话权控制 server 作最终仲裁**；有本地筛选的那支先在 LMR 侧挑要送给它的请求。判现场分支看该组实际过滤配置和归属方式，查条文或读一条已辨明的消息不用等齐全链。跨腿配对才核同一通信、该次话权操作、角色及接口两端。

- **有本地筛选（.6）：**组已在 GMS 定义。客户端 1 原生请求是 **2：客户端 → server**，**3：IWF → server** 是另一条请求。若有多个 LMR 用户想发话，NOTE 假定 LMR 系统根据本地策略先仲裁，只向 MCPTT 侧呈现一个请求，不是对所有互通呼叫规定只转一条。server 在 **4** 最终裁决，本例选择客户端 1；**5** 向 IWF 报它转来的请求被拒，**6** 向客户端 1 发 Granted，**7** 分别向原生客户端 2 与 IWF 发 Taken。IWF 收到的被拒报告和占用通知不冲突：前者针对本次请求，后者告知获授的是客户端 1。只观察到一条 IWF 请求，不足以确认本地筛选已开启或 IWF 在代理组归属。[图 10.5.6-1、前提、步骤 2–9 和 NOTE，印刷页 111–112（PDF 第 112–113 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=112)。
- **不筛选（.8）：**该支配置为把所有竞争请求转交 MCPTT。IWF 不替 LMR 用户作归属，所有 LMR 组归属逐人透传。**3：IWF → server** 的请求按申请话权的 LMR 用户各发一条，带 IWF 转换的该用户 MCPTT ID。server 在 **4** 选择客户端 1；**5** 对每个经 IWF 转来而被拒的请求向 IWF 各发一条 IWF Floor Rejected，**6** 向客户端 1 发原生 Granted，**7** 向原生客户端 2 发 Taken，另对每名已归属 LMR 用户向 IWF 发一条 Taken。比如 LMR 用户 A、B 都申请并被拒，C 已归属但没申请：5 不为 C 发拒绝，7 仍有为 C 发送的占用通知。Taken 表里的 MCPTT ID 指获授方，不是拿它当 C 的收件 ID，IWF 是这里的接口收件端。[图 10.5.8-1、前提及步骤 2–3，印刷页 114（PDF 第 115 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=115)；[步骤 4–9 和 NOTE，印刷页 115（PDF 第 116 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=116)；[Taken 的字段角色，表 10.5.2.10-1，印刷页 105（PDF 第 106 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=106)。

**.8 的 NOTE 只谈 Taken。** 若 IWF 已代表本组 LMR 用户归属，原文说只向 IWF 发一条 IWF Floor Taken；这不是主流程的前提，也不授权代理归属时照搬 .8 逐人请求或拒绝。只见一条 Taken，不能反推出代表归属，也不能把它认成一人的拒绝、授予或终端实收。要区分发送份数，核该组实际归属及相应消息记录。

两支 **6 的授予、7 的占用、8 的用户提示、9 的语音**各自取证。.6 的步骤 9 写分发给已归属成员（包括 IWF）；.8 写包括 LMR 用户，但图的 IWF 媒体箭头止于 IWF。没有接收侧证据，不能从 server 已发、IWF 已收或同名消息推另一端已收、听到或发送了媒体。原文例示到达先后或请求优先级可参与仲裁，不规定固定算法、优先级赢家或 SIP／RTCP 映射。若实际是 LMR 定义侧，按本页 .5／.7 的反方向决策；若问字段或确认，读[话权消息](floor-signals.md)，若问代理与逐人归属，读[互通归属](affiliation-representation.md)。

## LMR 组主控：谁拒绝竞争请求，哪条才是最终授予？

**同样是客户端 2 收到拒绝，可能是 MCPTT 本地筛掉了请求，也可能是它的请求已经过 IWF 仲裁。** §10.5.5／.7 都是双方参与者已归属、互通组呼正在进行且话权空闲时的例子。MCPTT 侧按配置先筛选或分别转交自己这侧的请求；**最终仲裁由 IWF 与 LMR 系统协同完成**。判现场分支要核组的归属／定义侧、实际过滤配置和相应步骤；查规则或单条已辨明的消息不必拿齐两侧记录。

| 条款 | 往 IWF 送什么？ | 回来的消息、原生消息各给谁？ |
| --- | --- | --- |
| **.5，组归属 LMR，MCPTT server 本地筛选** | 客户端 1、2 分别向 server 发原生请求 **2**。server 在 **3** 本地选客户端 1，图 **4** 由 server 向客户端 2 发原生拒绝。**5** 仅转本例选中的客户端 1 请求（server → IWF），不是向 IWF 请求拒绝客户端 2。 | IWF 与 LMR 系统协同仲裁后，在 **6** 向 server 发 IWF Floor Granted；server 在 **7** 向客户端 1 发原生 Granted、**8** 向客户端 2 发原生 Taken，告知谁获授。步骤 3 的本地选中不授予话权；步骤 4 的本地拒绝也不等 IWF 对客户端 2 回拒绝。 |
| **.7，组定义在 LMR，MCPTT 不做本地筛选** | 两个原生请求都是 **2：客户端 → server**；**3** 将两个竞争请求分别转给 IWF，由 IWF 与 LMR 系统协同仲裁，本例选客户端 1。没有 .5 的先筛掉一个。 | **4 全在 IWF → server 这一侧，但有三条消息**：为客户端 1 的 Granted、为客户端 2 的 Rejected、为客户端 2 的 Taken。原生腿分别是 **5** 拒绝客户端 2、**6** 授予客户端 1、**7** 通知客户端 2 话权给了别人。Reject 和 Taken 都可给客户端 2：前者答它自己的请求，后者告知客户端 1 获授，不是再给客户端 2 许可。 |

**.7 的 NOTE 按其他已归属客户端发送 Taken，不按竞争者计数。** 还有其他已归属同组的 **MCPTT 客户端**时，IWF 为每个这样的客户端向 server 发一条 IWF Floor Taken；不要求这些客户端也提出请求。静态成员资格不代替归属。这里的箭头到 server 为止，不据此补从 server 到其他客户端的原生消息或判这些客户端已实收。不要把 .8 的 LMR 归属透传前提或代理 Taken 数量规则套过来。[§10.5.7 步骤 4 和 NOTE，印刷页 113（PDF 第 114 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=114)。

**别按编号跨分支认消息。** .5 的 **6** 是 IWF 授予、**7** 是原生授予；.7 的 **6** 已是原生授予、**7** 是给另一客户端的占用通知。两支最终获授者分别在 .5 的 **9 → 10**、.7 的 **8 → 9** 通知用户再开始语音。两个图都只把互通媒体画到 IWF。实况只看到一个原生拒绝或没有采到某条跨网请求，不能断过滤方式；能识别一条应答，也不能替另一腿实收、用户提示或实际媒体。按同一通信、当次话权请求、各自角色和接口证据关联，别从图中顺序或示例优先级补运行时调度。问通用字段读[话权消息](floor-signals.md)，若实际由 MCPTT 主控，读本页的 .6／.8。

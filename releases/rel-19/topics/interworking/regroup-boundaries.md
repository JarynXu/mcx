# 跨 MC/LMR 重组：接纳、所有权与信息边界

适用：Rel19，TS23.283 V19.5.0，Stage2 MC/LMR 互通。仅下列结论已对照原文。

MC 发起的重组要求客户端已取得组成组配置，且 MC 与 IWF 各至少定义一个组成组。GMS 检查用户授权和组策略；临时组输入会被拒绝，IWF 也可因组成组处于紧急状态、已参与重组，或不支持相关能力等条件拒绝，不能把请求发出当成接纳（§10.2.2.2，步骤1–4）。

这些跨系统流程不会由 IWF 或 MC GMS 向对侧分享各自管理组的用户信息（§10.2.2.2 步骤4；§10.2.2.3 注）。实际执行重组的 GMS 拥有产生的临时组（§10.2.2.4）。

## 重组的应答、成立通知和撤组通知分别证明什么？

**看这一笔应答的是哪件事。** 接纳重组、通知对方临时组信息、回应撤组通知，是三个不同的操作。这里查 **TS 23.283 V19.5.0，Rel‑19 Stage 2** 的 IWF‑1，端点是 **组管理服务器（GMS）和 IWF**。§10.2.1.2–.7 的六张表均列两个方向。只查一条已识别的消息，不用先找到对应回复；同方向、同组或同一个 Result 名字都不能决定消息类型。例如撤组通知 .2 和查组配置 .8 都可只列一个组 ID，含义不同。

| 要查什么 | 请求／通知 | 对应类型的应答表 |
| --- | --- | --- |
| **申请重组（.4/.5）** | .4 只列必带的组成组 ID 列表（MC service group ID list）。它不是新临时组的 ID，也不是用户列表。 | .5 列 M 的组成组 ID 列表和 Result（接纳或拒绝）。单个临时组 ID 在表中标 O，表注规定：**Result 表示重组成功时必须带，否则不得带**。不能只看 O 当任意省略，也不能只凭没抓到这个 ID 判断失败。 |
| **通知临时组（.6/.7）** | .6 同时列 M 的组成组 ID 列表和临时组 ID；Priority level、Security level 都是 O，描述的是临时组要求的级别。 | .7 也列这两个 M 的组字段，**Priority level、Security level 都为 M**；不列 Result。通知没带这两项，不能按表把应答的 M 也视为 O。这张表没给如何确定、补齐或沿用具体值的规则。 |
| **撤组通知（.2/.3）** | .2 只列 M 的被撤临时组 ID，不列组成组或成员名单。它是撤组通知，不是要某人退出呼叫的请求。 | .3 列 M 的临时组 ID 和 Result。这个 Result 指**通知的成功或失败**，不是说哪个组成组被删除、用户已退出或整通呼叫释放。 |

[接口、撤组通知与重组请求／应答，§10.2.1.1–.5，印刷页 23（PDF 第 24 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=24)；[临时组通知、应答和查组配置对照，§10.2.1.6–.8，印刷页 24（PDF 第 25 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=25)。

例如申请将 **A、B** 重组，匹配的 .5 报告成功并给临时组 **D**，说明这一笔应答的结果和临时组身份。它不是 .6 通知已到另一端，也不是成员已归属或已有媒体。MC 发起的 §10.2.2.2 示例分别写 **4：IWF 回应**和**5：GMS 创建并保存临时组**；不能从 .5 表注证明 GMS 已保存，也不用步骤顺序猜 ID 分配时点。该示例步骤 5 的级别规则另按其条件读，不能填成 .7 应答表的默认参数。[§10.2.2.2 步骤 4–5，印刷页 27–28（PDF 第 28–29 页）](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=28)。

D 的 .3 若报告成功，只能读作对应撤组**通知**的结果。应答写了什么、该端是否发出、另一端是否收到，分别判断。要把多条消息归到同一次重组或撤组通知，再核实际类型、组、角色、端点和关联上下文；同一组 ID 不够。

§10.2.1.6 的 Security level 注指向 TS 23.280 的媒体及话权控制保护参数配置；不据此判断保护已启用或级别算法。§10.2.1.1 对其他参考点也只引 TS 23.280。问本流程的授权、检查和组所有权，读本页开头；若实际是[预配置重组](preconfigured-regroup.md)或[整通组呼释放](group-call-release.md)，读各自流程，不套这里的 Result。

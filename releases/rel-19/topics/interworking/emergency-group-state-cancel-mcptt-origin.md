# MCPTT 定义的互通组取消紧急状态：会清告警吗？谁确认？

**通话结束不取消组的紧急状态。** TS 23.283 V19.5.0（Rel-19 Stage 2）§10.6.2.3.2 规定：MCPTT 用户明确请求取消，由 MCPTT server 检查授权、清组状态；只有同时请求取消该用户本人的紧急告警时，server 才在这一步一起清告警。server 给取消发起端的应答与 IWF 回给 server 的应答是两笔。

这里限**组定义在 MCPTT 的互通组**，且该组实际仍在进行中紧急状态。另一 MCPTT 客户端已归属（图 client 2）；IWF 已接入并获准互通，且配置了组和用户身份映射。发起取消的是 client 1 的 MCPTT 用户，本节没有要求他是原紧急呼叫的发起者；无论是谁，步骤 3 仍要核这次取消授权。NOTE 3 讲的是组状态，不要求另有仍在通话的媒体；已挂断但状态仍在，仍核对上述其他条件。NOTE 1 的单 server 代表用户本属与组托管两个角色，不规定同机。查规范不需要抓包。[§10.6.2.3.2 前提和 NOTE 1–3，印刷页 129](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=130)。

## 本地清组状态、清本人告警和调整优先级

步骤 2 是 **client 1 → MCPTT server** 的组状态取消请求，附带取消本人告警的指示可选。步骤 3 核发起者获准取消该组的紧急状态；在成功流程中，步骤 4 清组状态。**请求同时指定清本人告警**，server 才在步骤 4 一起取消这个告警；不因不带指示就把该步骤说成自动清告警，也不由此处理他人的告警。步骤 5 调整底层承载优先级，此组紧急状态不再需要优先处理；不能从这里推出所有其他优先原因被清除、实际承载已达某值或媒体已停。[图 10.6.2.3.2-1 和步骤 1–5，印刷页 130](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=131)。

## 已收到确认，能推出什么

表 10.6.1.11-1 的 IWF **请求**列必带的 MCPTT ID（取消者）及组 ID，可选的 `Alert indicator` 只指取消者本人的告警。步骤 6 没给从步骤 2 复制告警指示的规则。表 10.6.1.12-1 的 IWF **应答**只列两项 ID，不列 `Result` 或告警指示；组 ID 的说明重复了 “in-progress”，不据此补字段。总表允许双向信息流，本支具体方向看 6/7；同组同取消者也不能单独配对多条逐人请求。

判断现场信令要对同次请求、组、取消者、事务、端点和方向。接收端实际发出的匹配回包可佐证那端收到原请求，不证明另一端实际收到这个回包。确认信令不需要媒体；确认 server 本地状态、IWF 或 LMR 应用、实际承载及 RTP 停止或继续，要看各自证据。不能把已收 7 或 9 写成全组取消成功或话权已释放。[表 10.6.1.11-1、10.6.1.12-1，印刷页 120–121](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=121)；[步骤 4–9，印刷页 130](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=131)。

若实际取消的是[迫近危险组状态](imminent-peril-group-state-cancel.md)，那一支的图示要求 client 1 曾发起、并以步骤 5 为发起端确认下界，有自己的组播 ACK 和 IWF 回包条件，不与本支交换。若问[紧急建呼](emergency-group-setup-mcptt-to-mcptt.md)、[整体组呼释放](group-call-release.md)或[原生 MCPTT 的紧急状态取消](../emergency/group-inprogress-cancel.md)，按各自条件查。仅取消独立告警也不同，另查 §10.6.5。LMR 用户发起或组定义在 LMR 时看本版 §§10.6.2.3.1、.3、.4，本页不展开这些分支或映射 SIP、错误码、完整失败流程。[其他互通取消分支，印刷页 128–132](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=129)；[迫近危险取消，印刷页 137–139](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=138)；[独立紧急告警取消，印刷页 142–143](https://www.etsi.org/deliver/etsi_ts/123200_123299/123283/19.05.00_60/ts_123283v190500p.pdf#page=143)。

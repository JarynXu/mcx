# 离网私呼结束：逐端响应、超时和清除标识

## 适用范围

- 固定TS24.281 V19.3.0 §10.3，两个已确定用户之间普通离网私呼，选择自动应答路径；不处理发现邻居、组呼加入、手动应答、video pull、紧急、网关或在网SIP/PF/CF流程。
- 目标MCVideo ID和所需离网传输配置已经具备，具体发现、地址解析及ProSe承载取得未核。每个私呼控制状态机以MCVideo user ID为粒度，同时私呼数受配置MaxCallNc10限制；不创造数值或超限响应。
- P0无私呼控制实体；P1非进行中且忽略同call id；P2等呼叫响应；P3等释放响应；P4正在通话；P5为pending。必须按claim的本地角色、状态、消息及call-id条件执行，不能把一端状态当两端同时成立。
- 普通媒体与transmission control只保留24.281声明的接口。TS24.581 V19.2.0的离网媒体过程未核；TS24.379、24.483、33.180及RFC细节未核，不声称已闭合发送/接收许可、首帧、完整互通或安全算法。

## 用户释放先进入等待

适用条件：本地客户端P4，用户要求释放普通离网私呼。

客户端发PRIVATE CALL RELEASE，携所存call和双方ID；CFP3置1、启动TFP3并进P3。用户提出释放的这个入口未列立即终止媒体，不应改写为点击停止即双方停止播放。

- 发起建立前取消另有P2入口，不等同此P4释放；不套BYE或SIP200。

依据：3GPP TS24.281 V19.3.0 §10.3.2.4.5.1，印刷页 366。

## 接收端与请求端分别停止

适用条件：分别观察P4客户端收到来自originating MCVideo user的PRIVATE CALL RELEASE，或发送RELEASE后处于P3且收到对应RELEASE ACK的端。

P4客户端收到来自originating MCVideo user的RELEASE后，先发RELEASE ACK，再终止本地媒体、启动TFP7并进P1；P3请求端收到ACK则停运行中的TFP3、终止媒体、启动TFP7并进P1。两端按各自事件处理，不存在由单一ACK证明两个播放器同步清空的结论。

- 未核缓冲帧、应用显示及底层资源释放过程；不能把terminate media解释为已撤回历史视频。
- 接收分支保留原文originating发送者限定，不扩成任意对端，不据此补双向释放算法。

依据：3GPP TS24.281 V19.3.0 §10.3.2.4.5.4;10.3.2.4.5.5，印刷页 367。

## 释放重传、时长和标识清理

适用条件：P3等待释放响应；或P4的TFP5到期；或P1的TFP7到期。

P3的TFP3到期走释放重传、增加CFP3并继续等待；达CFP3上限的专节则要求终止媒体、启动TFP7并进P1。P4中TFP5到期也直接终止媒体、启TFP7、进P1。P1在TFP7到期后清除所存call identifier并进P0，不能把P1和彻底清标识的P0混为一态。

- 一般重传与上限专节的重叠触发优先级不裁决；原文将CFP3称timer、将TFP3括注称request retransmission，保留差异。
- TFP5到期段未列向对端发送RELEASE，不自行补成完整双方通知流程。

依据：3GPP TS24.281 V19.3.0 §10.3.2.4.5.2;10.3.2.4.5.3;10.3.2.4.5.6;10.3.2.4.5.7，印刷页 366、367、368。

## 原文差异与未核边界

§10.3.2.4.5.2 step3;10.3.2.4.5.3 opening，印刷页 366、367：CFP3写timer，TFP3括注request；保留变量名与局部功能，不造新计时器。

§10.3.2.4.2.2/.4;10.3.2.4.3.3/.5;10.3.2.4.5.2/.3，印刷页 357、358、361、362、366、367：一般超时重传与计数上限出口并列，未写完整优先级，不裁决同时满足的执行调度。

## 证据边界

- 仅已确定用户间自动应答的有限离网信令路径，不是可直接实现的完整协议或媒体指南。

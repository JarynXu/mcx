# 服务器复制 XML 时：明文复制、成功解密与出口重加密

TS 24.282 V19.7.0 的 MCData server 收到 SIP request，需把其中 XML 元素或属性不作业务修改地复制到新的 outgoing SIP request，按 6.5.1.2 的例外进入 6.5.2.5。

入站仍有 6.5.1.4 的先行验证约束；本主题不是允许在验签失败后继续转发。出口配置按 6.5.2.3.2 区分 server-client 与 server-server。

## 明文元素有独立复制规则

适用条件：在本复制入口中处理不含 EncryptedData 的 XML 元素。

6.5.2.5 step1 要求复制到 outgoing request 的同一 XML body。这不是把所有入站密文作为不透明字节复制的规则；被加密的 URI 属性仍有 step3。此具体步骤也没有写因出口开启保护而把所复制的明文元素一律重新加密。

- 与 6.5.2.1 的一般全选敏感字段规则之间不补写修复算法；不能从 step1 推导绕过配置要求接收未保护内容。

依据：§6.5.1.2;6.5.2.5 step1 and step3，印刷页 124、127、128。

## 加密元素按出口重新保护

适用条件：本复制入口中的 XML 元素按 6.5.2.4.1 被识别为已加密；接收处理未阻断。

服务器按 6.5.2.4.2 解密，只有成功才进入该元素的后续步骤。若出口机密性开启，按相应密钥重新加密并放入 outgoing request；若关闭，则放入解密内容。入口有密文不保证出口仍有密文，也不意味着服务器无法取得明文。

- CSK/SPK 的角色仅沿用本条已有密钥前提，不重复其生成、分发或 KMS 流程。
- 出站完整性仍由 6.5.1.3 在发送前独立处理；不能以入站签名代替出口所需签名。

依据：§6.5.2.5 step2;6.5.2.3.2;6.5.2.2，印刷页 124、125、127。

## 加密URI属性单独处理

适用条件：本复制入口中的 XML URI 属性按 6.5.2.4.1 被识别为已加密；接收处理未阻断。

服务器按 6.5.2.4.3 解密 URI，只有成功才继续：出口开启机密性则按 6.5.2.3.4 重加密属性值，关闭则放入解密值。元素和属性的分支不能相互替代。

- 属性解密 helper 未明示完整失败响应；参数文字有不一致，见本页来源中的未解细节。本文不提供可执行 URI 编解码器。
- 透明复制正文不等于允许复用旧签名；出站完整性按 6.5.1.3 另行判断。

依据：§6.5.2.5 step3;6.5.2.4.3;6.5.2.3.4，印刷页 126、127、128。

## 证据边界

- 仅覆盖本页指定XML程序；不替代身份绑定、TLV或用户数据保护，外部算法、配置获取和密钥准备仍须分别核验。

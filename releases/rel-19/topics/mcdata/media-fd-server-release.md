# 媒体面FD的服务器主动释放：BYE、原因与逐段资源收尾

TS24.282 V19.7.0 Release19 Stage3，普通在网媒体面FD，直接one-to-one或预安排组，使用§13.2.3.2服务器主动且无预告的释放入口。排除HTTP FD、用户主动取消、第三方授权、紧急、跨域及预告延期。

既有通信和对应对话已成立；按本地策略与配置处理具体释放条件。CF、PF、客户端按各自事件承担动作，不以一个端点的信令结果代表全部参与端。

## 不必等原主叫取消，服务器可按策略释放

普通在网媒体面FD正在进行，服务器按策略及配置判断是否采用无预告释放；分别适用直接one-to-one或预安排组条件。

§13.2.3.2.1明确把媒体面FD纳入服务器主动释放。§13.2.3.1允许依据配置不预先通知客户端，且调用§13.2.2.2.4.1/.2的策略。两种通信均在媒体面报告达到传输时间上限、单次请求传输数据上限，或通信只剩一名/没有参与者时要求释放。普通组还包括按本地策略发起者离开，以及未满足最小affiliated组成员数；不能将这两个组条件套给one-to-one。

这里的触发不是原主叫BYE，也不是文件已传完。参与者数与affiliated成员数不是同一集合；策略值和媒体上限报告的内部生成未核。 只取普通预安排组，不扩ad hoc；是否采用预告/延期是另一配置和过程，本页不展开。

依据：TS24.282 V19.7.0 §13.2.3.1;13.2.3.2.1;13.2.2.2.4.1;13.2.2.2.4.2，印刷页328,330,331。

## CF、PF和客户端分别承担BYE及原因处理

CF已决定对本页范围的媒体面FD采用§13.2.3.2无预告释放；后续PF收到CF的BYE、客户端收到服务器BYE，各自满足对应接收入口。

CF SHOULD调用§13.2.2.2.4.4，并SHALL加入适当Reason文本。该helper要求先与TS24.582媒体面交互释放，再生成并发送BYE；若整个组通信需要释放，向通信全部参与者发送BYE，而不只是静态成员列表。PF SHOULD调用§13.2.2.2.3.2生成BYE，PAI设为自身PSI并向客户端发送；入站含Reason时SHALL复制到出站。客户端SHOULD调用§13.2.2.2.2.2，先回200再释放对应媒体面资源；BYE含Reason时SHALL向用户告知原因。

SHOULD调用不是无例外SHALL；在采用helper时，其内部动作仍按原强度执行。CF的原因示例包括数据量或时间限制，没有在此指定统一cause值，不套用其他失败码。 TS24.582在本条只是媒体交互依赖引用，具体FD停止字节传输的内部动作未核。CF发送文字称向MCData client，PF的实际接收入口另明确来自CF；不把该措辞改造成绕过PF的拓扑。

依据：TS24.282 V19.7.0 §13.2.3.2.2;13.2.3.2.3;13.2.3.2.4;13.2.2.2.2.2;13.2.2.2.3.2;13.2.2.2.4.4，印刷页327,328,329,331。

## 200、资源释放和删除文件不是同一证据

分别观察本页媒体面FD释放链中PF收到客户端对BYE的200，或CF收到对应BYE的200，或判断释放是否证明文件成功接收/删除。

PF收到对应200后，向CF应答其入站BYE，并释放与CF段及终接客户端段的相应媒体面资源。CF收到对应200后释放与终接PF段相应媒体面资源。客户端回200在其资源释放步骤之前，单个200不是所有段释放完毕的聚合证明。客户端helper的NOTE允许部分已接收数据被存储和处理，因此这一释放链不等于历史文件撤回。媒体面BYE过程也没有调用HTTP停止专节的FILE DELETED通知或TRANSMISSION STOPPED消息，不将两条承载链互换。

不从允许处理部分数据推导任意不完整文件已可消费；不把资源释放证明成完整文件已收到、应用已验收或物理文件已删除。 SIP失败/重传、媒体交互完成判据、跨段同步与存储API未核；本主题不提供完整媒体实现。

依据：TS24.282 V19.7.0 §13.2.2.2.2.2;13.2.2.2.3.2;13.2.2.2.4.4;13.2.3.2;13.2.3.3.4，印刷页327,328,329,331,332。

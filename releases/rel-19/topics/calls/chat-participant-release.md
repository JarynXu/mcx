# 普通 chat 退出与移除：复用释放链，但区分一人、全组和预建立承载

TS24.379 V19.4.0，进行中的普通在网 chat 组呼。

不涉及临时组或重组、不涉及非主控功能桥接、广播、远程发起、紧急或 imminent peril 扩展，也不覆盖用户迁移退出。

这里处理已经建立的业务呼叫退出或移除，不是取消尚未完成的呼叫建立，也不是直接拆除预建立 SIP dialog。

## 按需会话主动退出

适用条件：用户要求退出通过 on-demand signalling 建立的 chat 会话。

客户端由 §10.1.2.2.3.1 进入 §6.2.4.1：媒体交互后发 BYE，Request-URI 为要退出的业务会话身份，收到 BYE 200 后再交互媒体。发起参与功能收到客户端 BYE 时由 §10.1.2.3.3.1 进入 §6.3.2.1.6，生成发往控制功能的 BYE；下游 200 到达后转送客户端并处理控制侧资源。这里真正复用了预安排退出使用的 helper。

依据：§10.1.2.2.3.1;10.1.2.3.3.1;6.2.4.1;6.3.2.1.6。

## 预建立承载中的主动退出

适用条件：用户要求退出预建立会话承载的 chat 业务会话。

§10.1.2.2.3.2 调用 §6.2.4.2：客户端发对话外初始 REFER；Request-URI 标识服务服务器上的预建立会话，Refer-To 标识要退出的业务会话并带 method=BYE，Target-Dialog 标识预建立 dialog；Refer-Sub=false，Supported=norefersub。发送前和收到 REFER 2xx 后分别执行媒体交互。

依据：§10.1.2.2.3.2;6.2.4.2。

## REFER检查和提前响应

适用条件：参与功能收到客户端用于预建立 chat 退出的 REFER，Refer-To URI 的 method=BYE。

§10.1.2.3.3.2 调用 §6.3.2.1.7。PAI 中 PUI 无对应 MCPTT ID 绑定时，拒绝 403/Warning141 并停止。绑定存在时，先发 REFER 200，再生成发往控制功能的 BYE；故该 200 不证明下游退出已完成。请求同时带 Refer-Sub=false 与 Supported=norefersub 才由该分支抑制隐式订阅；响应带 Supported=norefersub，并在请求 Refer-Sub=false 时回相同值。

依据：§10.1.2.3.3.2;6.3.2.1.7。

## 收到退出后判断全组是否释放

适用条件：chat 控制功能收到某参与者腿的 BYE。

§10.1.2.4.2 调用 §6.3.3.2.4：先交互媒体释放相应腿资源并回复 200，再检查适用于 chat 的整组释放策略。需全组释放时进入 §6.3.3.1.5，所收 BYE 含 mcptt-info 时复制到生成的 BYE；无需全组释放时，SHALL 通知仍在会话中且订阅 conference event package 的所有客户端。

依据：§10.1.2.4.2;6.3.3.2.4;6.3.8.1。

## 控制功能主动移除

适用条件：控制功能判定某 chat 客户端需要移除，或根据 §6.3.8.1 判定整个 chat 会话需要释放。

§10.1.2.4.3.2/.3 都调用 §6.3.3.1.5，但移除一名参与者与释放全组的对象不同，只有后者向全部参与者发 BYE。主动移除客户端成功后，§10.1.2.4.3.3 允许 MAY 向 conference 订阅者发移除通知，不等同于收到参与者 BYE 且全组不释放时的 SHALL。

依据：§10.1.2.4.3.2;10.1.2.4.3.3;6.3.3.1.5;6.3.3.2.4 step5。

## 终接按需会话释放

适用条件：终接参与功能收到控制功能针对 on-demand chat 会话的 BYE。

§10.1.2.3.4.1 调用 §6.3.2.2.8.1：先交互媒体释放控制侧资源，再生成客户端 BYE；收到客户端 BYE 200 后向控制功能回复 200，再处理客户端侧资源。客户端收到 chat 释放 BYE 由 §10.1.2.2.3.3 调用 §6.2.6，交互媒体并回应 200。

依据：§10.1.2.3.4.1;10.1.2.2.3.3;6.3.2.2.8.1;6.2.6。

## 终接预建立承载保留

适用条件：终接参与功能收到控制功能 BYE，且业务会话 ID 对应与该参与功能具有预建立会话的用户。

§10.1.2.3.4.2 调用 §6.3.2.2.8.2：断开控制侧媒体资源、回 BYE 200、解除客户端资源与控制侧资源的连接，并保留面向客户端的预建立会话。chat 在此与预安排复用同一保留承载分支。

依据：§10.1.2.3.4.2;6.3.2.2.8.2。

## 证据边界

- 以上复用关系均有 chat 章节的明确引用，不以相似名称推断；不包含 chat 建立、准入及加入触发。
- §6.3.2.1.6 的 200 响应段把角色称为 terminating MCPTT function；保留文字错位，不新增实体跳转。
- 这些条款未给出归属永久保留或自动撤销的普遍结论。Stage2 interworking/chat-release 的归属不变结论有其 IWF 场景，不能移植为本页 Stage3 保证。
- TS24.380 媒体与话权、TS24.229/RFC 事务超时与竞态未独立核验。
- BYE 构造中的参与功能 PAI、存在时复制 mcptt-info 等通用细节仍适用；不能用 CANCEL 代替此已建立业务退出。
- 这是退出业务呼叫的 REFER，不是第 8 章拆除预建立 dialog 的 BYE。
- 该 helper 写无绑定，未另写绑定过期检查；不要从建立程序移植 404 或过期分支。
- 单人退出并不自动等于全组结束，也不保证全组继续；不能把通知对象扩大到所有配置成员或所有 affiliated 用户。
- de-affiliation、接纳更高优先级用户是本条给的移除示例，不是完整判定算法；不从 PUBLISH 200 推导移除已完成。
- 所生成客户端 BYE 的 PAI 为参与功能 PSI，收到的 mcptt-info 存在时复制；完整媒体清理成功条件依赖未核 TS24.380。
- 不能改写成向客户端转发 BYE 并拆除预建立 dialog。真正拆除另见第 8 章及现有 preestablished-session-lifecycle。

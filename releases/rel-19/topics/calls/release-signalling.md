# 私呼结束：CANCEL、BYE与预建立会话保留

仅TS24.379 V19.4.0 §§11.1.3–11.1.4及所列共同程序；区分释放一次私呼与拆除预建立会话。

## 按需会话由客户端结束

适用条件：用户请求释放按需私呼。

仍在建立时发CANCEL并停止本释放步骤；否则与媒体层交互，发送Request-URI为待释放MCPTT session identity的BYE。

依据：§11.1.3.1.1；6.2.5.1；6.2.6。

## 收到释放请求

适用条件：客户端收到按需私呼的BYE。

与媒体层交互并向服务器回200。此200响应的是BYE，不表示重新接听。

依据：§11.1.3.1.1.2；6.2.6。

## 预建立会话内释放呼叫

适用条件：客户端请求释放预建立会话内的私呼。

与媒体层交互后发对话外初始REFER。Request-URI指预建立会话的服务器PSI，Refer-To指待释放的MCPTT session identity并带method=BYE；Target-Dialog标识预建立会话，Refer-Sub=false，Supported含norefersub。收到REFER的2xx后还须按24.380与媒体层交互；不能把这条REFER等同于直接拆除预建立对话。

依据：§11.1.3.1.2.1；6.2.5.2。

## 参与功能保留客户端侧预建立会话

适用条件：参与功能收到控制功能的BYE，且MCPTT session id对应与其有预建立会话的用户。

先与媒体层交互以断开控制功能侧媒体资源，向控制功能回200，再断开客户端侧资源与控制功能侧资源的连接，并保持面向客户端的预建立会话。该规则同时被服务器发起释放流程引用。

依据：§11.1.3.2.2.2；11.1.4.3.2.2。

## 服务器结束的适用边界

适用条件：判断能否套用服务器发起私呼结束流程。

服务器的释放触发引用§6.3.8.2，发BYE引用§6.3.3.1.5；本页未展开触发算法。§11.1.4.1另注明无话权控制的私呼仅由客户端发起结束，不能把本节服务器路径无条件套用。

依据：§11.1.4.1、11.1.4.3.1、11.1.4.4。

## 证据边界

- SIP事务重传、CANCEL竞态、REFER RFC及TS24.229未完整核对；不提供通用事务实现。
- 24.380媒体层具体状态与服务器§6.3.8.2触发条件尚未展开，不能由信令响应推断资源已全部回收。

# MCPTT 服务器请求单播资源：端点与完成证据

## 适用范围

- 固定 TS23.289 V19.7.0，Stage2；在网 5GS 普通 MCPTT 单播语音会话建立。
- 不涵盖 MBS、离网、紧急升级、预建立/聊天模式独立媒体资源流程、漫游或 EPS 互通。
- 这是架构和信息流要求，不是 Stage3 可运行报文、PCF 授权响应、PCC 规则至 QFI/包过滤器的完整绑定实现，也不是语音已接收的证据。

## 客户端与媒体锚点参数

适用条件：选择 MC-service-server-based 建立；客户端与媒体锚点信息须区分。

客户端提供资源详情：初始请求含 SDP offer 及客户端 IP/端口；建立确认含最终协商媒体参数，包括来自 SIP core 的 SDP answer 中媒体锚点 IP/端口。

- 不是仅凭 MCPTT ID 就能绑定；具体 SDP 字段、NAT 和 IP 改变未核。

依据：3GPP TS 23.289 V19.7.0 §7.2.3.1;7.2.3.2 steps 1,5，印刷页 44、45。

## 服务器资源请求与路径

适用条件：服务器模型；已取得流程中的媒体参数。

服务器向 PCF（N5/Rx）或 NEF（N33）请求资源；QoS 信息包括媒体类型、带宽、优先级、应用标识、资源共享及网络切片信息。并发会话资源共享可用。

- 不补造字段编码、切片选择值、5QI 到 ARP/GFBR 数值或授权决策算法。

依据：3GPP TS 23.289 V19.7.0 §7.2.3.1;7.2.3.2 steps 6,7，印刷页 44、45。

## 会话进度不委托SIP core申请资源

适用条件：服务器模型的 session progress 经 SIP core 转发。

该 session progress 不请求 SIP core 代为申请网络通信资源；不能把它读成 §7.2.2 的代理资源申请。

- 图中 transmission-control-resources 标签不能推翻该正文注释；不推定具体 SIP 方法/状态码。

依据：3GPP TS 23.289 V19.7.0 §7.2.3.2 steps 3–5 and NOTE，印刷页 45。

## 建立确认与资源分配结果

适用条件：完整服务器模型的信息流。

客户端建立确认之后才有服务器资源请求和 PCC 程序；第 8 步才描述会话建立且资源已分配。

- 客户端确认、请求发出或授权概念均不能单独证明第 8 步，更不能证明 RTP 到达、可听语音或完整端到端质量；失败码与失败分支需另核。

依据：3GPP TS 23.289 V19.7.0 §7.2.3.2 steps 5–8，印刷页 45。

## 证据边界

- TS23.503/23.502/23.228 的完整授权、拒绝、流绑定、规则安装及接口编码未核。无法提供可运行 N5/Rx/N33 请求或验证 QFI 与 SDP 五元组映射。
- TS23.289 引用其他规范不等于已核精确组合；不声称与既有 TS23.501 V19.8.0 或 TS23.280 V19.10.1 完整互通。
- 普通会话认证、MCPTT 业务权限、floor grant 与媒体收发仍须分别核验，资源管理页不取代它们。

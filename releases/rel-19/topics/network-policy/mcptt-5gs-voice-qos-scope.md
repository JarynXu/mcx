# MCPTT 语音进 5GS：语音 QoS 与 SIP 信令的边界

## 适用范围

- 固定 TS23.289 V19.7.0，Stage2；在网 5GS 普通 MCPTT 单播语音会话建立。
- 不涵盖 MBS、离网、紧急升级、预建立/聊天模式独立媒体资源流程、漫游或 EPS 互通。
- 这是架构和信息流要求，不是 Stage3 可运行报文、PCF 授权响应、PCC 规则至 QFI/包过滤器的完整绑定实现，也不是语音已接收的证据。

## 语音及MCPTT信令与SIP-1分开

适用条件：5GS MCPTT 语音及 MCPTT-4/MCPTT-9 信令；另识别 SIP-1。

语音及上述 MCPTT 信令的 QoS flow 须用 5QI 65；SIP-1 须用 69。§4.3.3 的 5GS 要求替代 TS23.379 对应要求。

- 不是 QFI=65；也不能把所有控制流量归为 SIP-1。

依据：3GPP TS 23.289 V19.7.0 §4.3.2;4.3.3.1;4.3.3.2，印刷页 13、14。

## 直连PCF与经NEF路径

适用条件：MCPTT 系统需要确定 QoS flow 参数。

可经 N5 或 Rx 直接与 PCF 交互，或经 N33 使用 NEF 间接路径。

- 允许该路径不等于 PCF 已批准；本页不证明各路径 Stage3 等价。

依据：3GPP TS 23.289 V19.7.0 §4.3.3.2，印刷页 14。

## 资源管理者由部署选择

适用条件：选定资源管理部署模型后。

资源管理可由 SIP core 或 MC service server 承担；不能从服务方与运营商的管理关系直接推定是哪一种。

- 两种流程不能叠成必须重复发两次请求。

依据：3GPP TS 23.289 V19.7.0 §6.3.2.1;6.3.2.2;6.3.2.3，印刷页 39。

## SIP core模型的参数交换

适用条件：选择 SIP-core-based 会话建立；并发资源共享仍为 MAY。

服务器评估资源需求并在 session progress 中请求资源；SIP core 经 N5/Rx 与 PCF 直接交换媒体类型、带宽、优先级、应用标识及资源共享信息。

- 不把另一模型的 N33、切片字段自动补进本条；单独客户端 OK 不是媒体接收证明。

依据：3GPP TS 23.289 V19.7.0 §7.2.2，印刷页 43、44。

## 证据边界

- TS23.503/23.502/23.228 的完整授权、拒绝、流绑定、规则安装及接口编码未核。无法提供可运行 N5/Rx/N33 请求或验证 QFI 与 SDP 五元组映射。
- TS23.289 引用其他规范不等于已核精确组合；不声称与既有 TS23.501 V19.8.0 或 TS23.280 V19.10.1 完整互通。
- 普通会话认证、MCPTT 业务权限、floor grant 与媒体收发仍须分别核验，资源管理页不取代它们。

# 位置报告与组目标

已核所列同版官方条款，并通过独立复核与有限问题验证。Release：19。来源：TS 23.280 V19.10.1。核查范围及限制见[来源清单](../../sources.json)。

## 谁在报告，谁在接收

LMC（位置管理客户端）向 LMS（位置管理服务器）提供位置。LMS 汇总面向同一目标的报告触发请求。某位订阅用户取消订阅后，停止的是向该用户交付报告；不能据此关闭目标用户向其他接收者的全部报告。

依据：§10.9.1，印刷页186。本文不规定完整订阅 API、鉴权实现或并发控制。

## 报告不一定是经纬度加精度

报告的位置数据应伴随测量时间，准确度可选；所列位置数据至少提供一项，不能假定每次都有经纬度。收到通知也不等于刚执行了新测量，应结合位置数据的测量时间判断。

依据：§10.9.2.2 各报告表及 §10.9.3.6.1。这里不推导应用可接受的时效阈值。

## 组目标随归属变化

本段限单一 MC 系统；LMS 已订阅组动态数据，请求者已订阅且获准请求目标的位置。以组为目标设置报告触发时，LMS 使用当前已归属成员及其后续变化，而不是一次读取静态成员名单后永久沿用。解除归属后，相应的组报告触发应取消。

依据：§10.9.3.3，印刷页209–210。组事件通知也限当前已归属成员，见 §10.9.3.6.1。跨系统组目标不在本页范围。

## UE label 有接收方向限制

在规定的非空配置条件下，发往客户端及跨 LMS 的相关消息携带 UE label；发给 MC service server 的位置消息不包含该标签。不能从一个方向的可选字段表复制出所有方向都必带的编码规则。

依据：§10.9.2.2、§10.9.3.6.1。具体消息字段仍需对应协议阶段的规范支持。

相关：[触发覆盖与恢复](trigger-override.md)。本页没有将核心网定位接口或其他 Release 的规则并入上述流程。

[同版官方原文：ETSI TS 123 280 V19.10.1 (2026-05)](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf)。报告表见印刷页188–189，事件通知见214页。

## SIP 注册能证明位置配置已下发吗？

不能。下文限 **Rel‑19 TS 23.280 V19.10.1，Stage 2**。主系统单域示例中，信令 UA 向 SIP 核心完成 SIP 注册。示例另列可选的第三方注册，接收方是 MC 业务服务器。两条注册记录都不能证明位置管理客户端（LMC）已在位置管理服务器（LMS）登记，也不能证明 LMS 已发配置或 LMC 已收到配置。[§10.6.1，图 10.6.1‑1 及步骤 3，印刷页 132–133](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf#page=134)。

### 哪一步发配置，哪一步报位置

在单一 MC 系统的事件触发上报流程里，LMS 给 LMC 提供初始位置规则或后续更新。用这条消息下发时，LMS 可单播给一台 LMC，也可通过 MBMS 组消息给多台 LMC。**适用用户档已包含这份配置，就不用另发配置消息。** 只知道 SIP 注册成功，不能判断适用用户档有没有配置，也不能据此给下发设定时限。[§10.9.3.1，图 10.9.3.1‑1 步骤 1、注 2，印刷页 207–208](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf#page=209)。

“初次注册”和收到位置配置，是**可能触发 LMC 上报**的事件。适用规则配置了该事件，且事件确实发生，LMC 就按步骤 2–3 报告 LMS 指定且它能取得的信息。只见 LMS 发出消息，不能当作 LMC 已收到。条款没有把“初次注册”指定为 IMS SIP 注册、LMC 向 LMS 登记或 MC 业务授权，也没说这些事件会自动触发 LMS 发配置。[§10.9.3.1，印刷页 207 的事件示例、页 208 步骤 2–4](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf#page=208)。

### 两种参考点，不要只按 SIP 或 HTTP 认消息

| 已确认的通信 | V19.10.1 的分工 |
| --- | --- |
| LMC 与 LMS 间的 **CSC‑14**，如 LMS 接收 LMC 的位置报告 | 使用 **HTTP‑1 / HTTP‑2** 参考点。 |
| LMS 与 MC 业务服务器间的 **CSC‑15**，消息内容为**组动态数据**订阅或通知 | 该部分用 **SIP‑2**，例如为取组归属状态。看到这条 SIP 信令，不代表 LMC 做了位置订阅。 |
| 同一 **CSC‑15** 上的其他信令，例如业务服务器向 LMS 请求或接收位置 | 使用 **HTTP‑1 / HTTP‑2** 参考点。不因涉及用户、组或别名就转成上述 SIP 例外。 |

HTTP‑1、HTTP‑2 是客户端到代理、代理到服务器的两个参考点名，不是 HTTP/1、HTTP/2 版本声明。CSC‑14 的参考点规定也不能抹去 §10.9.3.1 所列的 MBMS 组配置选项。[§§7.5.2.14–15，印刷页 50–51](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf#page=51)；[§§7.5.3.5–6，印刷页 55](https://www.etsi.org/deliver/etsi_ts/123200_123299/123280/19.10.01_60/ts_123280v191001p.pdf#page=56)。

这里只判断各流程及通信属于哪一段。不用这份 Stage 2 文本判断 LMS 登记的 HTTP 方法、成功码、回调地址或时限，也不据此认定 Release 19 没有这些协议过程。

[另查 TS 24.283 V19.3.0 的注册与配置回调](lms-registration-configuration.md)：仅当问题转为 LMS_Reporting 的 HTTP 注册、配置通知或匹配应答时使用。该独立协议主题不判定本段“初次注册”对应哪个事务。
